Функция: входные данные, результат и контракт

Цель: по объявлению и описанию функции понять, какие данные ей передать и какой результат получить.

Функция даёт имя законченной операции. Например, sum(a, b) вычисляет сумму двух чисел. Это позволяет использовать одну реализацию в разных местах программы и проверять её отдельно.

В записи int sum(int a, int b) первое int — тип результата, sum — имя, а a и b — параметры. В вызове sum(10, 32) числа 10 и 32 — аргументы: значения, передаваемые параметрам.

Сначала договоримся о поведении

  • Предусловие: оба аргумента — целые числа от −1000 до 1000 включительно.
  • Результат: их математическая сумма.
  • Побочные эффекты: функция не читает ввод, ничего не печатает и не меняет переменные вызывающего кода.

Такое описание называют контрактом. Здесь это понятное человеку соглашение, а не специальный синтаксис языка. Оно ограничивает входные данные так, чтобы сумма помещалась в int. Проверку ввода выполняет main.

#include <iostream>

// Contract: -1000 <= a, b <= 1000. Returns their sum.
int sum(int a, int b) {
    return a + b;
}

int main() {
    int a = 0;
    int b = 0;
    if (!(std::cin >> a >> b) || a < -1000 || a > 1000 ||
        b < -1000 || b > 1000) {
        std::cerr << "input error\n";
        return 1;
    }
    const int total = sum(a, b);
    std::cout << total << '\n';
    return 0;
}

Ввод: два целых числа, например 10 32. Вывод: 42 и перевод строки. При неверном вводе программа пишет input error в поток ошибок и завершается с кодом 1.

При вызове sum(a, b) управление переходит в функцию. Оператор return a + b; вычисляет результат, завершает этот вызов и передаёт значение в total. Затем main выводит его. Возврат значения и печать — разные действия: результат можно сохранить, сравнить или передать следующей функции.

Самостоятельно

Предскажите ответы для 0 0, -1000 1000 и 1000 1000. Затем создайте по этому образцу функцию difference, которая возвращает разность первого и второго аргументов при том же предусловии.

Разбор

Суммы равны 0, 0 и 2000. Для difference достаточно вернуть a - b; результат лежит от −2000 до 2000. Проверки входных данных остаются в main. Если функция сама печатает разность, это уже другой интерфейс: использовать её результат в следующем вычислении будет неудобно.

В этом уроке мы пишем свободные функции на уровне пространства имён. Функции могут также быть членами классов; к этому вернёмся в разделе об ООП.

Объявление, определение и вызов

Цель: расположить код так, чтобы компилятор знал интерфейс функции до её использования.

Объявление сообщает имя функции, тип результата и типы параметров: int minimum(int left, int right);. Точка с запятой завершает объявление; тела здесь нет. Определение содержит тело в фигурных скобках и одновременно является объявлением.

В этой полной программе перед main стоит объявление, а реализация находится ниже. Контракт minimum: принять любые два значения типа int и вернуть меньшее; при равенстве вернуть это общее значение. Функция не выполняет арифметику, способную переполнить тип.

#include <iostream>

int minimum(int left, int right);

int main() {
    int a = 0;
    int b = 0;
    if (!(std::cin >> a >> b)) {
        std::cerr << "input error\n";
        return 1;
    }
    std::cout << minimum(a, b) << '\n';
    return 0;
}

int minimum(int left, int right) {
    if (left < right) {
        return left;
    }
    return right;
}

Ввод: два представимых в int целых числа. Для 7 -2 вывод равен -2; для 4 4 — 4. В самом вводе используйте обычный знак минуса -.

Что проверяет компилятор

На месте вызова должно быть видно подходящее объявление. Благодаря ему компилятор проверяет аргументы и знает тип выражения minimum(a, b). Объявления и определение должны согласовываться по типам. Имена параметров в объявлении можно опустить: int minimum(int, int);. Имена в определении нужны, чтобы обращаться к параметрам в теле.

Несколько согласованных объявлений допустимы. В одной единице трансляции допускается не более одного определения этой функции. Единица трансляции — исходный файл после обработки его #include и других директив. Для вызываемой обычной функции определение должно существовать в программе или подключённой библиотеке; одно объявление не создаёт реализацию. Правила нескольких определений в разных единицах трансляции рассмотрим для inline в следующем шаге.

Имена и чтение чужого кода

  • Выбирайте имя по действию или результату: minimum, count_positive. Имя не может начинаться с цифры.
  • Не придумывайте имена с двойным подчёркиванием или с подчёркиванием и следующей заглавной буквой: они зарезервированы. Имена, начинающиеся с подчёркивания, зарезервированы и в глобальном пространстве имён: там нельзя вводить свою _func.
  • В C++14 и новее допустимо объявление auto calculate(); с выводимым типом результата. До использования, которому нужен этот тип, компилятор должен увидеть определение. В первых собственных функциях пишите тип явно.
  • Функции одного имени с различными списками типов параметров могут образовывать перегрузки, например варианты с двумя и тремя int. Различия только в типе результата недостаточно.

Самостоятельно и разбор

Перенесите определение minimum целиком перед main и удалите отдельное объявление. Программа по-прежнему работает: определение уже сообщает интерфейс. Если оставить реализацию после main и удалить объявление перед ним, вызов окажется без видимого объявления — это ошибка компиляции.

constexpr, inline и static: разные свойства функции

Цель: различать возможность вычисления константы, правила определений и видимость реализации. Для обычной функции ни одно из этих ключевых слов не обязательно.

constexpr: функция пригодна и для константных вычислений

constexpr разрешает вычислить подходящий вызов при вычислении константного выражения. Оно не означает, что каждый вызов обязательно выполнится во время компиляции: результат может зависеть от введённых пользователем данных.

Пример совместим с C++17 и C++20. Контракт: основание от −10 до 10, целая степень от 0 до 18. В этих пределах промежуточные произведения помещаются в long long. По соглашению интерфейса нулевая степень даёт 1, включая power(0, 0); это явно выбранное правило данной функции.

#include <iostream>

// Contract: -10 <= base <= 10, 0 <= exponent <= 18.
// This interface defines base^0 as 1, including 0^0.
constexpr long long power(long long base, int exponent) {
    long long result = 1;
    for (int i = 0; i < exponent; ++i) {
        result *= base;
    }
    return result;
}

static_assert(power(2, 10) == 1024);
static_assert(power(0, 0) == 1);

int main() {
    long long base = 0;
    int exponent = 0;
    if (!(std::cin >> base >> exponent) || base < -10 || base > 10 ||
        exponent < 0 || exponent > 18) {
        std::cerr << "input error\n";
        return 1;
    }
    std::cout << power(base, exponent) << '\n';
    return 0;
}

static_assert проверяет константное выражение во время компиляции. Вызов в main принимает данные из ввода: для 2 10 он печатает 1024, для -2 3 — -8. Отрицательная степень не входит в контракт: её нельзя незаметно трактовать как нулевую.

inline: правило размещения определения

inline позволяет при соблюдении правила одного определения разместить согласованные определения одной функции в нескольких единицах трансляции — например, через общий заголовочный файл. Это не разрешение написать два определения в одном исходном файле. inline также не гарантирует подстановку тела на месте вызова: решение об оптимизации принимает компилятор. Функция с constexpr неявно является inline.

static у свободной функции

На уровне пространства имён static задаёт внутреннее связывание: имя функции относится к этой единице трансляции. Поэтому в разных .cpp могут существовать разные такие функции с одним именем. Это другое применение static, чем у локальной переменной, сохраняющей состояние между вызовами.

Что пока достаточно узнавать

noexcept в объявлении сообщает, что исключение не должно выходить из функции. Нарушение этого обещания приводит к завершению через std::terminate, а не к автоматическому исправлению ошибки. Сначала мы освоим обычные функции; условные спецификации noexcept, шаблоны и свойства методов классов понадобятся в соответствующих разделах.

Самостоятельно и разбор

Проверьте 0 0, 0 5, -2 4 и 10 18: ответы 1, 0, 16 и 1000000000000000000. Почему нельзя просто снять ограничения ввода? Дополнительные множители могут привести к переполнению, а отрицательная степень требует другого математического результата и, как правило, другого типа. Изменение контракта требует изменения реализации и проверок.

Шаг на Stepik · Новая версия · Исходная версия

Возврат значения и время жизни результата

Цель: вернуть результат вычисления так, чтобы вызывающий код мог безопасно использовать его после завершения функции.

Тип перед именем функции описывает результат вызова. Для обычного вычисления удобно вернуть значение. В примере square принимает число от −1000 до 1000 и возвращает его квадрат как long long.

#include <iostream>

// Contract: -1000 <= value <= 1000. Returns value squared.
long long square(int value) {
    const long long result = 1LL * value * value;
    return result;
}

int main() {
    int value = 0;
    if (!(std::cin >> value) || value < -1000 || value > 1000) {
        std::cerr << "input error\n";
        return 1;
    }
    const long long answer = square(value);
    std::cout << answer << '\n';
    return 0;
}

Ввод: одно целое число из указанного диапазона. Для -12 программа печатает 144. Множитель 1LL переводит умножение в тип long long до вычисления произведения: один лишь широкий тип переменной результата не расширяет уже выполненное умножение.

Локальный объект result существует во время выполнения функции. При return result; значение результата вызова формируется до уничтожения локального объекта. Переменная answer в main получает самостоятельное значение; возвращаться к уничтоженному объекту ей не нужно.

Почему нельзя вернуть ссылку на этот result

Ссылка обозначает уже существующий объект; это не отдельная копия его значения. Если заменить тип результата square на const long long&, та же строка return result; будет возвращать ссылку на локальный объект. При выходе из функции его время жизни закончится. Читать значение через такую висячую ссылку нельзя. const не продлевает время жизни локального объекта, на который возвращают ссылку. Та же опасность возникает при возврате его адреса.

Возврат ссылки бывает полезен, когда объект принадлежит вызывающему коду или живёт заведомо дольше использования результата. Тогда срок жизни объекта — часть контракта. Для первого решения числовой задачи выбирайте возврат значения. Возврат контейнера по значению также допустим: современные правила C++ позволяют избежать лишнего копирования или переместить результат; не следует ради предполагаемой экономии возвращать ссылку на локальный контейнер.

return завершает текущий вызов

После выполненного return остальные операторы тела в этом вызове не выполняются. У обычной функции с результатом каждая возможная ветвь нормального завершения должна вернуть значение. Достижение конца такой функции без возврата, кроме особого правила для main, приводит к неопределённому поведению. Функция с типом void может дойти до конца или выполнить return; без значения.

Самостоятельно и разбор

Уберите локальную переменную и напишите return 1LL * value * value;. Результат и его безопасность сохранятся. Проверьте входы 0, −1000 и 1000: ответы 0, 1000000 и 1000000. Затем объясните, почему return result; безопасен при типе результата long long и опасен при const long long&: важен объявленный способ возврата, а не одинаковое написание этой строки.

Декомпозиция показана через композицию чистых функций и отдельную проверку ввода в main.

Шаг на Stepik · Новая версия · Исходная версия

Декомпозиция: одна операция — одна понятная функция

Цель: разделить задачу на вычисления и взаимодействие с пользователем, затем собрать решение из вызовов.

Пусть нужно найти максимум трёх целых чисел. Выделим maximum_of_two, возвращающую большее из двух значений, и используем её в maximum_of_three. При равенстве можно вернуть любой из равных аргументов: результат один и тот же. Обе функции работают с любыми значениями int, не изменяют аргументы и не обращаются к потокам.

#include <iostream>

int maximum_of_two(int a, int b) {
    if (a > b) {
        return a;
    }
    return b;
}

int maximum_of_three(int a, int b, int c) {
    return maximum_of_two(maximum_of_two(a, b), c);
}

int main() {
    int a = 0;
    int b = 0;
    int c = 0;
    if (!(std::cin >> a >> b >> c)) {
        std::cerr << "input error\n";
        return 1;
    }
    std::cout << maximum_of_three(a, b, c) << '\n';
    return 0;
}

Ввод: три целых числа, представимых в int. Для -7 -2 -9 вывод равен -2; для 4 4 1 — 4.

Внутренний вызов maximum_of_two(a, b) даёт одно число. Внешний сравнивает его с c. Так результат одной функции становится аргументом другой. Из-за return в первой ветви maximum_of_two отдельный else не обязателен: если первый возврат не выполнен, функция возвращает b.

Граница ответственности

main читает вход, проверяет успешность чтения и печатает ответ. Вычисляющие функции получают уже готовые значения. Благодаря этому их можно вызвать из другой программы или проверить на наборе значений без имитации диалога с консолью. Перенос std::cin внутрь maximum_of_two сделал бы повторный вызов неожиданно зависимым от нового ввода.

return 0; в main сообщает среде об успешном завершении. Это не математическое доказательство правильности ответа. В наших примерах ошибка чтения приводит к сообщению в std::cerr и коду 1; вычисление вызывается только после проверки ввода.

Самостоятельно

Предложите тест, который обнаружит ошибочную замену максимума на минимум. Затем выразите максимум четырёх значений через уже готовую функцию от двух аргументов.

Разбор

Для 1 9 3 правильный ответ 9, а минимум дал бы 1. Нужны также тесты, где максимум находится первым и последним, все числа отрицательны или равны. Максимум четырёх можно получить как maximum_of_two(maximum_of_two(a, b), maximum_of_two(c, d)). Все вложенные вызовы здесь только вычисляют значения, поэтому их взаимный порядок не меняет ответ.

Не дробите программу ради количества функций: отдельная функция полезна, если у неё есть ясное назначение, небольшой интерфейс и проверяемый результат.

Шаг на Stepik · Новая версия · Исходная версия

Область видимости: передавайте данные явно

Цель: отличать локальные переменные разных функций и передавать нужное значение через параметр.

Имя, объявленное внутри main, не становится автоматически доступным в теле другой функции. Для передачи данных используйте параметры, а для результата — return.

#include <iostream>

// Contract: -1000 <= value <= 1000. Returns twice the value.
int doubled(int value) {
    const int result = 2 * value;
    return result;
}

int main() {
    int value = 0;
    if (!(std::cin >> value) || value < -1000 || value > 1000) {
        std::cerr << "input error\n";
        return 1;
    }
    const int result = doubled(value);
    std::cout << value << ' ' << result << '\n';
    return 0;
}

Контракт: doubled получает целое от −1000 до 1000, возвращает удвоенное значение и не меняет переменные вызывающего кода. Для ввода 7 программа выводит 7 14.

Здесь есть разные объекты с одинаковыми именами. value в main содержит исходный ввод; параметр value принадлежит вызову doubled. Точно так же result в теле функции и result в main — две разные переменные. Совпадение имён не создаёт между ними общую память.

Как читать вложенные блоки

Локальное имя доступно после объявления до конца соответствующей области видимости, включая вложенные блоки, если его не скрыло другое объявление. Если во внутреннем блоке заново объявить переменную с тем же именем, это будет отдельный объект: внутреннее имя временно скрывает внешнее. Для понятного учебного кода лучше выбирать различающиеся имена, когда оба значения важны.

Обычную именованную свободную функцию нельзя определить внутри тела другой функции. В наших примерах определения располагаются на уровне пространства имён, а вызовы — внутри main или другой функции.

Нужны ли глобальные переменные?

Общую константу можно объявить на уровне пространства имён перед функциями, которым она нужна. Тогда имя доступно им, если не скрыто. Однако изменяемая глобальная переменная создаёт неявную зависимость: результат вызова может зависеть от того, кто раньше изменил общее состояние. Параметр делает входные данные видимыми в месте вызова и облегчает проверку.

Область видимости имени в одном исходном файле не означает его автоматическую доступность во всех файлах проекта. Для нескольких файлов нужны подходящие объявления и правила связывания — они рассматриваются далее.

Самостоятельно и разбор

Переименуйте параметр value функции в number и исправьте обращение к нему в её теле. Нужно ли менять имя value в main? Нет: аргумент передаёт значение, а не имя переменной. Если попытаться из main обратиться к локальному имени другой функции, которого в main нет, компилятор сообщит об ошибке. Верните нужное значение через интерфейс.

Параметры по значению и аргументы по умолчанию

Цель: читать вызов функции с пропущенным последним аргументом и размещать значение по умолчанию в одном месте.

Параметр типа int получает собственное значение. Присваивание такому параметру внутри функции само по себе не меняет переменную вызывающего кода. Поэтому небольшие входные числа удобно передавать по значению.

У scaled два параметра: число и множитель. Если второй аргумент не указан, используем 3. Контракт: оба значения находятся от −1000 до 1000; функция возвращает произведение как long long и ничего не печатает.

#include <iostream>

// Contract: -1000 <= value, factor <= 1000. Returns their product.
long long scaled(int value, int factor = 3);

int main() {
    int value = 0;
    int factor = 0;
    if (!(std::cin >> value >> factor) || value < -1000 || value > 1000 ||
        factor < -1000 || factor > 1000) {
        std::cerr << "input error\n";
        return 1;
    }
    std::cout << scaled(value) << ' ' << scaled(value, factor) << '\n';
    return 0;
}

long long scaled(int value, int factor) {
    return 1LL * value * factor;
}

Ввод: число и множитель. Для 4 5 вывод — 12 20: первый вызов использует множитель 3, второй — явно переданный 5. Для -4 0 вывод — -12 0.

Где пишется значение по умолчанию

Значение должно быть видно в объявлении на месте вызова. Поэтому здесь оно задано в объявлении перед main; в определении ниже его не повторяют. Определение тоже является объявлением: если оно стоит до всех вызовов и отдельного объявления нет, значение можно записать прямо там.

Повторно задавать аргумент по умолчанию в той же области видимости нельзя, даже если повторить то же число. В первом объявлении обычной функции после параметра с умолчанием все следующие параметры тоже должны иметь умолчания. Поэтому void f(int a = 1, int b); — неправильное первое объявление.

Пропускают последние аргументы. Запись scaled(4) допустима; оставить «пустое место» перед вторым аргументом нельзя. Значение по умолчанию не создаёт вторую функцию и не меняет количество параметров определения.

Разбор

Присваивание параметру factor внутри тела повлияло бы на текущий вызов, но не изменило бы ни переменную factor в main, ни правило следующего вызова без второго аргумента.

Передача по значению и изменяемой ссылке

Цель: выбрать интерфейс по тому, должна ли функция менять объект вызывающего кода.

Параметр int value содержит отдельное значение. Параметр int& value — ссылка на уже существующий изменяемый объект. Присваивание через такую ссылку меняет этот объект.

#include <iostream>

// Both functions require -1000 <= value <= 1000.
int incremented(int value) {
    value += 1;
    return value;
}

void increment(int& value) {
    value += 1;
}

int main() {
    int value = 0;
    if (!(std::cin >> value) || value < -1000 || value > 1000) {
        std::cerr << "input error\n";
        return 1;
    }
    const int next = incremented(value);
    std::cout << value << ' ' << next << '\n';
    increment(value);
    std::cout << value << '\n';
    return 0;
}

Контракт обеих функций: исходное число от −1000 до 1000. incremented возвращает число на единицу больше и не меняет аргумент; increment изменяет сам аргумент и имеет тип результата void.

Для ввода 5 программа выводит две строки:

5 6
6

После первого вызова исходный value равен 5, а next равен 6. Во втором вызове параметр-ссылка обращается к объекту value из main; теперь он становится равен 6. У void-функции результатом действия служит изменение состояния, отдельного числового значения вызов не даёт.

Что можно передать

  • incremented(5) допустим: аргументом может быть значение выражения.
  • Если объявлено const int fixed = 5;, вызов incremented(fixed) допустим: копируется значение.
  • Для increment нужен изменяемый объект подходящего типа. Вызовы increment(5) и increment(fixed) недопустимы: обычная изменяемая ссылка int& не связывается с такими аргументами.

Если задача состоит в вычислении одного нового значения, возврат результата часто делает код понятнее. Изменяемая ссылка уместна, когда изменение переданного объекта — явная цель операции, например очистка контейнера. Для чтения большого объекта без копии используем ссылку на const в следующем шаге.

Оговорка о значении: копия указателя всё ещё может указывать на общие данные. Передача указателя по значению не копирует массив и не запрещает менять элементы через этот указатель. Случай встроенных массивов разберём отдельно.

Самостоятельно и разбор

Поменяйте порядок двух вызовов: сначала выполните increment(value), затем получите next = incremented(value). Для начального 5 исходная переменная станет 6, а новое значение — 7. Возвращаемое значение не изменяет исходный объект автоматически: это происходит только при явном присваивании, например value = incremented(value);.

const-ссылка: читать контейнер без его копирования

Цель: различать входной параметр, изменяемый параметр и самостоятельный результат функции.

Для небольшого числа обычно достаточно передачи по значению. Когда функция только читает контейнер, удобно принять const std::vector<int>&: она обращается к исходному вектору без создания его копии и не может изменять элементы через этот параметр.

Контракт sum: не более 1000 элементов, каждый от −1000 до 1000; результат — сумма типа long long; исходный вектор остаётся прежним. Для пустого вектора сумма равна нулю.

#include <cstddef>
#include <iostream>
#include <vector>

// Contract: at most 1000 elements; each element is in [-1000, 1000].
// Returns their sum, leaves the vector unchanged; empty sum is 0.
long long sum(const std::vector<int>& numbers) {
    long long total = 0;
    for (int value : numbers) {
        total += value;
    }
    return total;
}

int main() {
    int count = 0;
    if (!(std::cin >> count) || count < 0 || count > 1000) {
        std::cerr << "input error\n";
        return 1;
    }
    std::vector<int> numbers(static_cast<std::size_t>(count));
    for (int& value : numbers) {
        if (!(std::cin >> value) || value < -1000 || value > 1000) {
            std::cerr << "input error\n";
            return 1;
        }
    }
    std::cout << sum(numbers) << ' ' << numbers.size() << '\n';
    return 0;
}

Ввод: количество элементов, затем сами элементы. Для 4 7 -3 0 2 вывод — 6 4: сумма и размер вектора. Для 0 вывод — 0 0. Если элементов не хватает или нарушен диапазон, программа сообщает об ошибке.

Как выбирать параметр

НамерениеОбычный выборПример
Прочитать небольшое значениеПередача по значениюint value
Прочитать вектор без его копииСсылка на constconst std::vector<int>& values
Изменить переданный векторИзменяемая ссылкаstd::vector<int>& values

const относится к доступу через этот параметр: он не делает исходный изменяемый вектор навсегда константным. Внутри sum нельзя записать numbers[0] = 5 или вызвать изменяющий вектор push_back. Вызывающий код после возвращения может менять свой вектор как обычно.

Если параметр записан как const int value, это отдельное значение, которое нельзя переназначить внутри тела. Такая запись не означает передачу по ссылке и не требует константного аргумента. Для типа int форма const int& обычно не даёт учебного или практического выигрыша перед обычным int.

Шаг на Stepik · Новая версия · Исходная версия

Массив в параметрах: адрес не заменяет размер

Цель: передать последовательность без потери границ и отличать невладеющий указатель от контейнера.

В списке параметров обычной функции записи const int values[] и const int* values задают один и тот же тип параметра. При вызове со встроенным массивом функция получает указатель на первый элемент; весь массив не копируется. Длина в типе такого параметра не сохраняется.

Поэтому sizeof(values) внутри такой функции — размер указателя, а не количество элементов. Если в условии теста явно дано sizeof(int*) == 8, результат будет 8. Размер указателя зависит от реализации; в программе нельзя подставлять 4 или 8 как универсальную величину.

Явный размер и пустая последовательность

Контракт sum_array: не более 1000 элементов от −1000 до 1000. При положительном count указатель должен обозначать начало доступной последовательности минимум из count элементов. При нулевом размере допустим nullptr: функция не обращается к памяти и возвращает 0.

#include <cstddef>
#include <iostream>
#include <iterator>

// Contract: count <= 1000; elements are in [-1000, 1000].
// For count > 0, values points to at least count readable int elements.
// For count == 0, values may be nullptr; the result is 0.
long long sum_array(const int* values, std::size_t count) {
    long long total = 0;
    for (std::size_t i = 0; i < count; ++i) {
        total += values[i];
    }
    return total;
}

int main() {
    int numbers[5]{};
    for (int& value : numbers) {
        if (!(std::cin >> value) || value < -1000 || value > 1000) {
            std::cerr << "input error\n";
            return 1;
        }
    }
    std::cout << sum_array(numbers, std::size(numbers)) << '\n';
    std::cout << sum_array(nullptr, 0) << '\n';
    return 0;
}

Ввод: ровно пять требуемых чисел. Для 1 2 3 4 5 вывод — две строки: 15 и 0. В main имя numbers ещё обозначает сам массив, поэтому std::size(numbers) из C++17 возвращает 5. Внутри функции тот же приём для параметра-указателя недоступен.

Нельзя передать размер больше реально доступного диапазона: указатель сам его не проверит. Второй распространённый интерфейс — пара указателей на начало и на позицию за концом одного диапазона. Для настоящего массива std::begin(numbers) и std::end(numbers) из <iterator> дают эти границы; указатель за последним элементом не разыменовывают.

Нулевой символ '\0' завершает корректную C-строку, но не является общим признаком конца произвольного массива чисел. Не пытайтесь угадать длину по значениям элементов. Для нового кода, где уместен владеющий контейнер, std::vector хранит свой размер; функция может принять его по const&. В C++20 для невладеющего представления диапазона есть std::span; здесь достаточно освоить явную пару «указатель и длина».

Двумерные данные без ручного управления памятью

Встроенный int table[3][5] при преобразовании даёт указатель на строку типа int (*)[5], а не int**. Эти типы нельзя взаимозаменять. Для таблицы с размерами, известными во время выполнения, покажем владеющий контейнер: вектор строк. Он освобождает память автоматически.

#include <cstddef>
#include <iostream>
#include <vector>

// Contract: at most 20 rows, at most 20 elements in each row;
// each element is in [-1000, 1000]. Empty rows are allowed.
long long sum_matrix(const std::vector<std::vector<int>>& matrix) {
    long long total = 0;
    for (const auto& row : matrix) {
        for (int value : row) {
            total += value;
        }
    }
    return total;
}

int main() {
    int rows = 0;
    int columns = 0;
    if (!(std::cin >> rows >> columns) || rows < 0 || rows > 20 ||
        columns < 0 || columns > 20) {
        std::cerr << "input error\n";
        return 1;
    }
    std::vector<std::vector<int>> matrix(
        static_cast<std::size_t>(rows),
        std::vector<int>(static_cast<std::size_t>(columns)));
    for (auto& row : matrix) {
        for (int& value : row) {
            if (!(std::cin >> value) || value < -1000 || value > 1000) {
                std::cerr << "input error\n";
                return 1;
            }
        }
    }
    std::cout << sum_matrix(matrix) << '\n';
    return 0;
}

Ввод: число строк и столбцов от 0 до 20, затем элементы от −1000 до 1000 в порядке строк. Для 2 3 1 2 3 4 5 6 вывод — 21. Для нуля строк или столбцов сумма равна 0. Контракт вычисляющей функции допускает и строки различной длины в тех же пределах; main здесь строит прямоугольную таблицу.

Самостоятельно и разбор

Что произойдёт при попытке «исправить» длину в sum_array выражением sizeof(values) / sizeof(values[0])? Получится отношение размеров указателя и элемента, а не длина входной последовательности. Правильное исправление — сохранить размер в интерфейсе или принять подходящий контейнер. Чтобы написать функцию изменения элементов, понадобился бы указатель int* или изменяемая ссылка на контейнер и отдельный контракт изменения.

Рекурсия: базовый случай и движение к нему

Цель: проверить завершение рекурсивной функции, допустимый диапазон результата и максимальную глубину вызовов.

Рекурсивная функция вызывает саму себя для более простого случая той же задачи. Для факториала неотрицательного целого числа используются правила 0! = 1 и n! = n × (n - 1)! при n > 0.

Контракт: принимаем только 0 ≤ n ≤ 20 и возвращаем n! как unsigned long long. Этот диапазон выбран так, чтобы результат помещался и при минимально гарантированной для этого типа разрядности в 64 бита. Вход проверяется до вызова и до преобразования к беззнаковому типу.

#include <iostream>

// Contract: 0 <= n <= 20. Returns n!, including 0! = 1.
unsigned long long factorial(unsigned int n) {
    if (n == 0) {
        return 1;
    }
    return n * factorial(n - 1);
}

int main() {
    int n = 0;
    if (!(std::cin >> n) || n < 0 || n > 20) {
        std::cerr << "input error\n";
        return 1;
    }
    std::cout << factorial(static_cast<unsigned int>(n)) << '\n';
    return 0;
}

Ввод: одно целое число от 0 до 20. Для 5 ответ 120; для 0 — 1. Для 20 ответ 2432902008176640000. Значения −1 и 21 отклоняются.

Как возвращается результат

Для factorial(3) вычисление сводится к 3 * factorial(2), затем к 2 * factorial(1) и 1 * factorial(0). Базовый вызов возвращает 1; при возвратах получаются 1, 2 и 6. У каждого вызова есть собственное значение параметра n.

Здесь легко проверить три условия: базовый случай n == 0 возвращает готовый ответ; при каждом рекурсивном шаге неотрицательное n уменьшается на 1; предел 20 ограничивает глубину цепочки 21 вызовом. Простого наличия if недостаточно: изменение аргумента должно действительно приближать к базовому случаю.

Программа выполняет n умножений. В обычной реализации незавершённые вызовы требуют дополнительной памяти, пропорциональной глубине. Рекурсия не даёт бесконечного стека: без ограничения глубины даже корректная формула может исчерпать ресурсы. Переполнение целого типа — отдельная проблема, которую базовый случай сам по себе не решает.

Самостоятельно

Напишите итеративную функцию с тем же контрактом. Затем объясните, почему наивная рекурсия по всем числам диапазона до двух миллиардов — плохой план для задач, расположенных дальше в уроке.

Разбор

Итеративная версия начинает с unsigned long long result = 1; и умножает результат на числа от 1 до n. При n == 0 цикл не выполняется: получается нужная единица. Число умножений остаётся линейным, но цепочки вложенных вызовов нет. Для огромного диапазона нужны анализ структуры задачи и более быстрый алгоритм; перенос того же полного перебора из цикла в рекурсию не ускоряет его.

В последующих темах рекурсия естественно появится в деревьях и разделении задачи на части. Кроме прямого вызова по имени, функцию можно передавать другой функции через указатель на функцию; это отдельный способ организации интерфейса, а не обязательное свойство рекурсии.

Область видимости, время жизни и static

Цель: различать три вопроса: где доступно имя, когда существует объект и сохраняется ли его состояние между вызовами.

Область видимости определяет, где можно найти имя. Время жизни — период существования объекта. Длительность хранения описывает, как долго доступна память для него. Эти понятия связаны, но не заменяют друг друга: локальное имя может обозначать объект, который сохраняется между вызовами.

Автоматическая и статическая локальная переменная

#include <iostream>

int next_local() {
    int counter = 0;
    return ++counter;
}

// Demonstration: called twice; the counter must not overflow int.
int next_static() {
    static int counter = 0;
    return ++counter;
}

int main() {
    const int local_first = next_local();
    const int local_second = next_local();
    const int static_first = next_static();
    const int static_second = next_static();
    std::cout << local_first << ' ' << local_second << '\n';
    std::cout << static_first << ' ' << static_second << '\n';
    return 0;
}

Ввод не требуется. Программа выводит:

1 1
1 2

В next_local каждый вызов создаёт свой автоматический counter со значением 0. В next_static оба вызова работают с одним статическим объектом: после первого вызова значение 1 сохраняется, после второго становится 2. В примере каждая функция вызывается дважды; для произвольного счётчика нужно отдельно обеспечить отсутствие переполнения.

Имена обоих counter доступны только внутри своих функций. Ключевое слово static не делает локальное имя глобальным. Автоматический локальный объект уничтожается при выходе из блока; статический сохраняется между вызовами и имеет длительность хранения, охватывающую выполнение программы. Нельзя выводить из этого обязательное физическое выделение памяти «на стеке при каждом вызове»: стандарт описывает поведение объектов, а реализация может оптимизировать хранение.

Когда происходит инициализация

Динамическая инициализация локального статического объекта выполняется при первом достижении объявления и после успешного завершения не повторяется. Нулевая и константная инициализация могут происходить раньше; в нашем static int counter = 0; используется константная инициализация. Не следует учить общее правило «все static обязательно создаются ровно при первом вызове».

Переменные уровня пространства имён без thread_local также имеют статическую длительность хранения. Их имена видны в соответствии с объявлениями и правилами области видимости. Зависеть от порядка динамической инициализации обычных глобальных объектов из разных .cpp без специальных гарантий нельзя: порядок файлов в проекте сам по себе таких гарантий не даёт.

Связывание и const — другие свойства

const ограничивает изменение объекта через соответствующее имя или ссылку; оно не означает extern. extern не делает объект константным. У обычной переменной const int на уровне пространства имён без extern и inline по умолчанию внутреннее связывание. В следующем шаге понадобится разделять объявления в заголовке и определения в исходном файле.

Самостоятельно и разбор

Предскажите результаты третьих вызовов: next_local() снова даст 1, next_static() даст 3. Почему это важно для тестов? Результат функции со скрытым статическим состоянием зависит от истории предыдущих вызовов. Если счётчик является данными задачи, обычно понятнее хранить его у вызывающего кода и передавать явно по изменяемой ссылке.

В примере вызовы намеренно записаны отдельными операторами. В C++17/20 нельзя в общем случае считать, что аргументы одного вызова вычисляются слева направо. Не связывайте правильность выражения с неподтверждённым порядком побочных эффектов.
