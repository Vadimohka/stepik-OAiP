# Функции: интерфейсы, проверяемые примеры и декомпозиция

Пакет обновляет 12 существующих текстовых шагов модуля 7 курса 86957. В уроках 770590 и 770591 переработаны все текстовые шаги; в уроке 770592 — вводный шаг об области видимости и хранении. Пакет опубликован и сверён через Stepik API; дата и область проверки указаны в [manifest.json](manifest.json).

## Что улучшено

Учебная последовательность теперь строится от контракта функции к объявлению, возврату, декомпозиции, параметрам, массивам и рекурсии. Каждый шаг содержит цель, полную программу, формат ввода и результата, самостоятельную вариацию и разбор. Вычисления отделены от консольного ввода и вывода, кроме специально обсуждаемых действий с изменяемым состоянием.

Все поля `.step`, кроме `block.text`, сохранены. ID, временные отметки и свойства блоков не менялись. Исходный снимок `courses/86957/` пакет не редактирует. Готовые изменения перечислены в [changes_functions.json](changes_functions.json); развёрнутый просмотр создаётся в [preview.html](preview.html).

### Важные технические решения

- Программы совместимы с C++17 и C++20. `std::span` только упомянут как дальнейшая возможность C++20; он не требуется для запуска примеров.
- Входные диапазоны явно ограничивают арифметику. Для произведений сначала выбирается широкий тип (`1LL * value * factor`), а затем выполняется умножение.
- Обновлённая целочисленная `constexpr`-степень обрабатывает нулевую степень, включая явно оговорённое `power(0, 0) == 1`. Отрицательная степень отклоняется. Ранее исправленная ошибка нулевой степени не возвращается.
- Факториал имеет контракт `0 <= n <= 20`, проверку до преобразования к беззнаковому типу и максимум 21 вложенный вызов.
- Матрица использует владеющий `std::vector<std::vector<int>>`. Отдельно объясняется, почему встроенный двумерный массив не преобразуется в `int**`.
- Опасный возврат ссылки на локальный объект объясняется как ошибка интерфейса. В комплекте нет исполняемой программы, намеренно вызывающей неопределённое поведение.

## Проверка

Из корня репозитория:

```sh
python improvements/86957/functions-2026-11-23/verify.py --compiler g++
```

Дополнительный компилятор, если установлен:

```sh
python improvements/86957/functions-2026-11-23/verify.py --compiler clang++ --report validation-clang.json
```

По умолчанию проверяются оба стандарта. Для отдельного запуска можно указать `--std c++17` или `--std c++20`; параметр допускает повторение. Относительный путь `--report` отсчитывается от каталога пакета.

Верификатор:

1. Сравнивает все поля подготовленных `.step` с `baseline/steps`, разрешая изменение только `block.text`. Для готового пакета с манифестом отсутствие базового файла является ошибкой. Обращение к текущему снимку курса допускается только при первичной подготовке пакета без манифеста.
2. Извлекает все блоки `language-cpp` из HTML и точно сравнивает их с 13 файлами в `examples/`, включая окончания строк. Каждый файл должен иметь набор сценариев в `cases.json`; лишний или пропавший блок приводит к ошибке.
3. Компилирует с `-Wall -Wextra -Wpedantic -Werror -O2 -DNDEBUG` во временный каталог.
4. Сверяет код завершения, стандартный вывод и поток ошибок для 105 сценариев на стандарт: 26 компиляций и 210 запусков для одного компилятора.
5. Сохраняет SHA-256 входных файлов, включая базовые `.step`, и убеждается, что они не изменились во время проверки.

Перед началом создаётся отчёт `status: running`, `all_passed: false`. Успешный результат записывается только после всех проверок; исключение, несовпадение результата или ошибка компилятора дают `failed`. Старый успешный отчёт не сохраняется как актуальный результат нового неудачного запуска. Проверки результата не зависят от C++ `assert` или Python `assert`.

В этой среде проверка выполнена GCC 14.2.0: **26 компиляций, 210 запусков, все успешны**. Второй компилятор не установлен и не заявлен как проверенный. В изолированных копиях пакета дополнительно подтверждены четыре отрицательных сценария верификатора при запуске Python с `-O`: неверный ожидаемый вывод, несовпадение HTML с `.cpp`, отсутствующий компилятор и пропавший базовый шаг при наличии манифеста. Каждый дал ненулевой код завершения, `failed` и `all_passed: false`.

Это проверка подготовленных текстов и сопровождающих программ. Она не заменяет проверку оформления после импорта на Stepik и не проверяет скрытые тесты существующих задач платформы.

## Методическая граница и дальнейшая работа

Самостоятельные задания внутри текста имеют разбор, но не являются новыми автоматически оцениваемыми шагами. Соседние вопросы и задачи не изменялись. В тексте сохранены сведения, необходимые для существующих вопросов об `auto`, `inline`, `constexpr`, `static`, значениях по умолчанию, превращении массива в указатель и времени жизни ссылки.

Следующий этап модуля — прямая практика разработки интерфейсов функций, согласование сложности существующих задач и перенос библиотечного материала на переносимый учебный проект. Конкретные шаги и ограничения оценки перечислены в [notes_functions.md](notes_functions.md).
