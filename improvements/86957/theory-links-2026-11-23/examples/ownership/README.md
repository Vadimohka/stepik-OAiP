# LINKS: классы, ссылки и владение

Авторская проверка адресных уточнений в модулях 12–15. Самостоятельных заданий учащимся здесь нет; код учебных программ в семи изменённых шагах сохранён побайтно.

```sh
python3 improvements/86957/theory-links-2026-11-23/examples/ownership/verify.py
```

Нужны Python 3.10+, GCC с C++17/C++20 и UBSan. Скрипт записывает новый отчёт `../../validation/ownership.json`; параметр `--report` задаёт другой файл. Исторические результаты T5/T5B не заменяются.

Скрипт сверяет SHA-256 всех 59 прочитанных текстовых шагов, их соответствие снимку `course.json`, изменение только `block.text`, идентичность всех блоков `pre` (код и вывод) и существование внутренних ссылок. Смысловая проверка предпосылок и переходов задокументирована в `../../review_ownership.json`; автоматическая проверка адреса не подменяет её.

`base_destruction.cpp` — полная программа только для авторской проверки нового объяснения. Она проверяет освобождение через виртуальную базу у `unique_ptr`, перемещение и пустое владение, сохранение группы владения при преобразовании `shared_ptr<Derived>` в `shared_ptr<Base>`, истечение слабого наблюдателя и уничтожение полного производного объекта при создании `shared_ptr<Base>` из `Derived*`. У последней базы деструктор намеренно невиртуальный: удалитель сохраняет исходный тип. Недопустимый вариант с первоначальным сырым `Base*` не исполняется.

В каждом стандарте компилируется одна программа и запускаются четыре содержательных случая плюс проверка неизвестного режима. Всего — две компиляции и десять запусков. `assert` включены, применены `-Wall -Wextra -Wpedantic -Werror` и UBSan. Это конечный набор проверок GCC/Linux; он не подтверждает Windows/MSVC, macOS, многопоточную работу или весь интерфейс стандартных владельцев.

Перечень первичных источников и различие нормативных правил и рекомендаций указаны по шагам в `../../changes_ownership.json`. Все нормативные ссылки закреплены на N4659/N4861; C++ Core Guidelines используются только как рекомендации.
