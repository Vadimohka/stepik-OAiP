# Авторская проверка адресных изменений T2/T3 и LINKS

Проверка относится к новой редакции 28 текстов модулей 4–9. Она не добавляет ученику упражнений и не меняет опубликованные задания.

```sh
python3 improvements/86957/theory-links-2026-11-23/examples/types/verify.py
```

Нужны Python 3.10+ и GCC с C++17/C++20 и UBSan. Компилятор можно задать переменной `CXX`. Сеть не требуется.

`bounds.cpp` извлекается из полной программы шага 3212920. Проверяются все четыре допустимых индекса, соседние недопустимые индексы, большие положительное и отрицательное значения, пустой и нечисловой ввод, непредставимое целое. Входы `1x`, `1 2` и `2 trailing text` подтверждают прежний контракт: программа читает первое целое и остаток потока не использует. У обнаруженной ошибки теперь код завершения 1, у успешного доступа — 0.

`auto_aliases.inc` точно повторяет новый фрагмент шага 3214974. `semantic_checks.cpp` включает его в авторскую обвязку: проверяются типы `auto`, `auto&`, `const auto&`, наблюдаемые значения 7, 7, 9 и два ожидаемых отказа при попытке записи через `const`-ссылки. В той же обвязке проверяются конкретные пояснения типов `nullptr`, различия `vector<int>(3, 0)` и `vector<int>{3, 0}`, безопасные побитовые примеры. Отрицательный знаковый сдвиг вправо проверяется только в C++20; неопределённое поведение не выполняется.

Перед компиляцией проверяющий скрипт сопоставляет все 28 новых `.step` с опубликованными исходниками: единственное изменяемое поле — `block.text`. Во всех шагах, кроме трёх явно перечисленных, `pre/code` сохранены точно. В 3212920 изменена только ветвь возврата ошибки; в 3214974 добавлен один фрагмент, прежняя программа сохранена; в 3213209 исправлен только комментарий, где указатель ошибочно назывался массивом.

Новый `validation.json` содержит версии инструментов, хеши текста и исходников, все входы, наблюдаемый вывод и коды завершения. Исторические отчёты не заменяются. Эта проверка не является новым запуском всех программ T2/T3, не проверяет Windows/MSVC или macOS и не подтверждает живой Stepik.
