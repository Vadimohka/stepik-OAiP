# Адресная авторская проверка LINKS: алгоритмы и ресурсы

В девяти текстовых шагах изменены объяснения и переходы. Все блоки `<pre>` совпадают с текущим снимком побайтно; самостоятельных заданий учащемуся не добавлено.

Запуск из корня репозитория:

```sh
python3 improvements/86957/theory-links-2026-11-23/examples/algorithms/verify.py
```

Требуются Python 3.10+ и GCC с C++17/C++20 и UBSan. Сеть, CMake и GoogleTest этому адресному запуску не нужны. Результат нового запуска записывается в `../../validation/algorithms_current.json`, отдельно от исторических `validation.json`.

`contracts.cpp` проверяет наблюдаемый договор: тип результата вставки у BST/AVL/RB, сохранение значения дубликата, возможность вставить ключ после удаления и независимость возвращённой `ItemTable::find` строки от последующей замены, rehash и удаления записи. Заголовки берутся из сохранённых T6-примеров только после сверки с листингами эффективной редакции. Из полного BST-примера во временный заголовок извлекаются определения до `main`; код этих определений сохраняется.

`stream_switching.cpp` проверяет две допустимые границы чтения/записи: через flush и через позиционирование. Проверены общая позиция, нормальный EOF как с `failbit`, так и после успешного числового извлечения с одним `eofbit`, восстановление состояния для намеренного продолжения, пустой файл и ошибка открытия отсутствующего файла. Конечные байты файлов проверяются независимо от вывода программы. Неправильные переходы с неопределённым поведением не запускаются.

Это четыре компиляции и четыре исполнения (по два исходника в двух стандартах), с проверкой точного вывода и файлов. Они не повторяют весь исторический набор T4/T6 и не являются новой проверкой Windows/MSVC, macOS, всех прежних программ или существующих оцениваемых заданий. Асимптотика не выводится из этих запусков: основания приведены в `review_algorithms.json` и журнале правок.
