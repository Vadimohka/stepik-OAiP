# Продолжение теоретической редакции курса 86957

Пакет продолжает принятый план без новых упражнений, оцениваемых заданий или видео. База — актуальный на момент восстановления `main`, коммит **d96e5b9cffa65010c53894a9b65b1a497cb6b58a**. Он уже содержит публикацию первых 88 теоретических редакций; этот факт учтён, прежние пакеты не публикуются повторно.

Точное состояние работы, сохранённые SHA и следующий шаг ведутся в одном [документе прогресса](../theory-review-2026-11-23/PROGRESS.md). Самостоятельное значение имеют два состояния: файлы в GitHub и подтверждённое содержимое Stepik.

## Исходники и область изменения

- [Манифест](manifest.json) фиксирует фактические части, уникальные ID и SHA-256.
- [Журнал изменений](CHANGES.md) и [превью](preview.html) представляют включённые редакции.
- `steps/` содержит существующие текстовые шаги, в которых меняется исключительно `block.text`.
- `baseline/` хранит точные исходные байты; `base_source_index.json` закреплён на дереве базового коммита. Индекс сверяется непосредственно с Git.
- `changes_*.json` и `review_*.json` содержат причины правок, источники, глубину проверки и известные ограничения.
- [SCOPE](review_scope.json) различает 12 ранее адаптированных текстов функций и 25 адаптаций quality. Пересечения считаются по ID.
- `recovery/` сохраняет исходное состояние плана и обнаруженную историю до продолжения работы.

Учебные ID, типы, позиции, стоимость, настройки заданий, проверяющие программы и видеошаги сохраняются. Модуль 20 вне объёма. Исторический опубликованный пакет `theory-2026-11-23` остаётся неизменным. Шесть точечных исправлений его некорректно сгенерированных ссылок включены в новую редакцию и явно считаются пересечением, а не шестью новыми уникальными шагами курса. Ещё одно пересечение — адресное уточнение ролей N/P/G/U в T6 без изменения кода.

## Проверка

```sh
python3 tools/build_theory_upgrade.py --check
python3 tools/render_course_tree.py
python3 tools/render_course_tree.py --check
```

Общий контроль проверяет оба теоретических пакета. Для сохранения одного законченного блока доступны `--package theory-continuation-2026-11-23 --parts ...`; `--check` всегда использует состав уже записанного манифеста. Опубликованный пакет защищён от изменения состава, исходных копий и целевых байтов.

Авторские проверки новых блоков находятся в `examples/<part>/README.md` и `verify.py`. Они проверяют заявленную совместимость C++17/C++20, соответствие кода тексту, обычные и существенные граничные случаи. Отчёты фиксируют точные входы и не объявляют проверенными все старые программы или оценочные задания курса.

Повторные проверки прежних T1/T3/T6 запускаются отдельным инструментом:

```sh
python3 tools/recheck_theory_examples.py
```

Он выполняет неизменённые проверяющие скрипты в изолированных копиях и сохраняет новые результаты в `validation/recheck/`, не заменяя исторические `validation.json`. Нужны Python 3.10+, GCC и CMake 3.22+; путь к CMake можно передать через `CMAKE`. GoogleTest получает закреплённый коммит официального репозитория. Текущий повторный запуск прошёл на Linux/GCC 14.2, включая GoogleTest для обоих стандартов; это не новый запуск на macOS или Windows.

Нормативные положения сверяются с закреплёнными N4659 и N4861. [Отчёт редакторов N4859](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2020/n4859.html) подтверждает содержательное соответствие N4861 и C++20 DIS N4860, несмотря на формальное название первого проекта C++23. C++ Core Guidelines используются как рекомендации.
