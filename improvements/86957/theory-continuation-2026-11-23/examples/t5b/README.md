# T5B: категории выражений, ссылки и владение

Авторские проверки объясняющих примеров модулей 14–15. Это не новые задания учащимся и не проверяющие программы Stepik. Ни существующие оценочные шаги, ни настройки оценивания не изменены.

## Запуск и границы

Из корня репозитория:

```sh
python3 improvements/86957/theory-continuation-2026-11-23/examples/t5b/verify.py
```

Нужны Python 3.10+ и GCC с C++17/C++20 и UndefinedBehaviorSanitizer. Сеть не нужна. `--report /absolute/path/report.json` позволяет сохранить отдельный протокол нового запуска; по умолчанию создаётся `validation.json` в этой папке. Протоколы прежнего опубликованного пакета не затрагиваются.

В ходе проверки сверяются:

- все 14 редакций: в `.step` изменено исключительно `block.text`;
- точное соответствие проверяемых полных программ блокам C++ в текстах;
- компиляция с `-Wall -Wextra -Wpedantic -Werror` и UBSan в обоих стандартах;
- заявленные выводы и коды завершения, в том числе три пути RAII, неверная команда и отсутствие ввода;
- пустое владение, перемещение пустого владельца, замена ресурса, самоприсваивание, переход к нулю сильных ссылок, слабая ссылка на самого себя, истёкшие наблюдатели и константный источник;
- отклонение недопустимого копирования `unique_ptr`, привязки `int&&` к именованной rvalue-ссылке/константному объекту и возврата именованного объекта с запрещёнными copy/move.

Первый сохранённый итоговый запуск: **24 компиляции, 32 исполнения, 8 ожидаемых отказов компиляции**. Точные время, версия компилятора, платформы, результаты и SHA-256 входов приведены в `validation.json`. Устранение NRVO отключено для двух соответствующих программ через `-fno-elide-constructors`: это проверяет различие обязательного прямого создания prvalue и допустимого возврата перемещаемого вектора без NRVO.

## Технические источники

Правила проверены по закреплённым версиям проекта стандарта [N4659](https://timsong-cpp.github.io/cppwp/n4659/) для C++17 и [N4861](https://timsong-cpp.github.io/cppwp/n4861/) для согласованных формулировок C++20. N4861 формально открывает цикл C++23, однако [официальный отчёт N4859](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2020/n4859.html) подтверждает совпадение содержательной части с N4860, C++20 DIS. Новейший изменяемый draft не использован как замена правилам C++17/20.

Основные проверенные разделы: `[basic.lval]`, `[conv.lval]`, `[dcl.init.ref]`, `[class.temporary]`, `[forward]`, `[temp.deduct.call]`, `[dcl.init]`, `[class.copy.ctor]`, `[class.copy.assign]`, `[class.copy.elision]`, `[lib.types.movedfrom]`, `[unique.ptr]`, `[util.smartptr.shared]`, `[util.smartptr.weak.obs]`. Точные URL по каждому шагу находятся в `../../changes_t5b.json`.

Правило нуля, предпочтение готовых владельцев и выбор ссылочного интерфейса — рекомендации [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines), а не дополнительные требования языка.

## Ограничения доказательности

Проверены GCC/Linux и конечный набор состояний, а не все возможные программы и реализации. Windows/MSVC и macOS в этом запуске не проверялись. Искусственный отказ выделения памяти и переполнение служебных счётчиков не моделировались. Учебные `shared_ptr`/`weak_ptr` явно однопоточные; их код не претендует на многопоточную корректность или весь интерфейс стандартной библиотеки. Проверки не меняют состояние Stepik и не подтверждают публикацию.
