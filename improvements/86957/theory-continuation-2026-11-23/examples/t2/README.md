# Проверяемые иллюстрации T2

Здесь находятся **37 полных программ** из новой редакции модулей 4–6 и 9:
35 C++17/C++20 и два отдельно помеченных примера исторического интерфейса C11/C17.
Это авторская проверка теории. Учащимся не предлагаются новые задания; учебные
проверяющие программы, оценивание и видеошаги не изменяются.

Исходники и `fixtures.json` воспроизводятся из `../../authoring/t2.py`. Проверка
требует точного совпадения каждого исходника с HTML-кодом соответствующего шага.
Имена `preserved_...` означают сохранённый сильный пример: в тексте вокруг него
самостоятельная проверка заменена готовым разбором. Такие программы проверяются
заново, хотя их код не переписан.

## Запуск

Нужны Python 3.10+ и GCC/G++ с поддержкой C11, C17, C++17 и C++20. Внешние
библиотеки и загрузка из сети не требуются. Из корня репозитория:

```sh
python3 improvements/86957/theory-continuation-2026-11-23/authoring/t2.py --check
python3 improvements/86957/theory-continuation-2026-11-23/examples/t2/verify.py
```

Для явного выбора компиляторов используются `CC` и `CXX` (каждая переменная —
имя одного исполняемого файла, без дополнительных флагов). Компиляция включает
`-Wall -Wextra -Wpedantic -Werror -O2`. Временные бинарные файлы создаются вне
пакета и удаляются после запуска.

## Что проверяется

- Сравнение каждого из 52 новых `.step` с закреплённым исходником `d96e5b9`:
  отличается исключительно `block.text`, тип шага остаётся `text`.
- Полный набор `int main` в изменённых шагах совпадает с 37 исходниками.
  Каждая программа компилируется в двух указанных для неё стандартах.
- Указанные в объяснениях результаты, положительные/отрицательные/нулевые
  значения, ошибочный и неполный ввод, допустимые и недопустимые размеры,
  первый/последний индекс и индекс за границей.
- Для строк: пустая строка и конец ввода, ведущие пробелы, сохранение пустого
  имени, отсутствие/повторение разделителя, C-терминатор и встроенный ноль,
  строгий `from_chars` с недопустимым знаком, пробелами, хвостом и переполнением.
- Содержательные границы библиотечных операций: `array<int, 0>`, исключения
  `at`, `reserve` без изменения размера, `string[size()]`, пустой `substr`,
  пустой образец поиска, сохранность результата при неуспешном `from_chars`.
- Четыре ошибки компиляции в C++17 и C++20: сужение в списке инициализации,
  встроенный массив переменной длины, недостаток места для нуля литерала,
  попытка сложить два литерала как указатели. Отдельно подтверждается, что
  инициализация `char[3]` литералом `"cat"` разрешена в C11/C17, но не создаёт
  C-строку с терминатором.
- Три пути отказа выделения C: `malloc`, `calloc`, `realloc`. Проверяющая
  оболочка детерминированно подставляет отказ функции; при отказе `realloc`
  также отслеживает освобождение прежнего блока. Учебный исходник не меняется.
- Ссылки на уроки/позиции Stepik разрешаются по структуре закреплённого курса.

## Границы проверки

`validation.json` — протокол **этого** запуска с компиляторами, временем и
SHA-256 входных файлов. Он не заменяет исторические отчёты. Фрагменты без
`main` редакторски просмотрены; отдельно компилируются только перечисленные
отрицательные примеры и `checks/contracts.cpp`. Это не утверждение о запуске
всего старого кода или проверке всех 283 текстовых шагов курса.

Основной протокол относится к Linux/GCC. Windows/MSVC и macOS этим запуском не
проверены. Десятичные граничные фикстуры `parse_integer.cpp` используют 63
значащих разряда знакового `long long`; проверка сначала подтверждает это
свойство платформы. Сама учебная программа выражает контракт через диапазон
типа и не полагается на `sizeof(long long) == 8`.

Реальное исчерпание памяти ОС не вызывается. Подстановка отказа проверяет
обработку соответствующих ветвей и сохранение владения, а не поведение
конкретного системного распределителя при нехватке ресурсов.

Основные нормативные опоры указаны у каждого текста в `../../changes_t2.json`.
Для C++17 API `from_chars` дополнительно учтено принятое исправление
[LWG2955](https://cplusplus.github.io/LWG/issue2955) /
[P0682R1](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2017/p0682r1.html):
ранний N4659 ещё показывал прежний заголовок и тип поля ошибки. Новейший проект
стандарта не используется как замена правилам C++17/C++20.
