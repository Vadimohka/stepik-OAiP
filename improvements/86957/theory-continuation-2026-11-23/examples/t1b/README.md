# Авторская проверка T1B

Этот каталог проверяет законченные иллюстрации теории модулей 1–3. Он не добавляет заданий учащимся и не обращается к Stepik.

## Состав

| Исходник | Шаг | Статус и проверяемое объяснение |
|---|---:|---|
| `hello.cpp` | 3173778 | Полная программа; точный вывод, отдельно компиляция и компоновка |
| `missing_definition.cpp` | 3177250 | Намеренно неполный исходный файл: успешное получение объекта и ожидаемый отказ компоновки без определения `twice` |
| `linked_definition.cpp` | 3177250 | Полная законченная программа; определение добавлено, аргумент 0 допустим, вывод отсутствует, код завершения 0 |
| `namespaces.cpp` | 3201236 | Полная программа; два квалифицированных имени и точный вывод |
| `c_library.cpp` | 3201235 | Полная программа; `std::abs(-7)` в представимом диапазоне |
| `checked_input.cpp` | 3215075 | Полная программа; обычный ввод, границы 0/1000, диапазон, ошибочная запись, конец ввода, слишком большое число и явно оговорённый префикс `12x` |
| `formatting.cpp` | 3215081 | Полная программа; основание, точность, экспоненциальная запись, сброс ширины |
| `printf_example.cpp` | 3215092 | Полная программа; соответствие формата и типов, точный вывод и немедленная ошибка вывода |

Итого — 7 исполнимых полных программ и 1 отдельно объяснённый исходник с ожидаемой ошибкой компоновки. Проверка требует точного совпадения этих восьми файлов с соответствующими блоками HTML. Дополнительно в временном каталоге собираются два фрагмента с явно добавленным окружением: вывод после `#include` (3177248) и `scanf` только на представимых значениях (3215092). Фрагмент неоднозначного имени из 3201267 должен не компилироваться; отсутствие точки с запятой проверяет отличие синтаксической ошибки от ошибки компоновки.

Математические проверки используют точные рациональные числа Python, а не приближённые `float`: значения и округление систем счисления, граничный случай цикла, порядок байтов и UTF-8. Это проверки авторских расчётов, не реализация отдельного учебного задания.

Для пояснения CMake выполняются две команды из нового текста 3231227 над неизменёнными файлами полного опубликованного примера 3231317. Исторический пакет не перезаписывается. Проверяется один конкретный старый пример, а не вся старая база программ.

## Запуск

Требуются Python 3.10+, GCC с C++17/C++20, CMake 3.22+ и доступный CMake генератор с его инструментом сборки. Для воспроизводимого отказа `printf` проверка использует Linux `/dev/full` и `stdbuf`. Сетевые загрузки не нужны.

```sh
python3 improvements/86957/theory-continuation-2026-11-23/examples/t1b/verify.py
```

`CXX` и `CMAKE` могут задавать пути к соответствующим исполняемым файлам. Параметр `--report /абсолютный/путь.json` сохраняет отдельный протокол. По умолчанию обновляется только текущий `examples/t1b/validation.json`; исторические `validation.json` не изменяются.

Полные программы собираются с `-Wall -Wextra -Wpedantic -Werror`, UBSan и остановкой при его ошибке. Для обычной двухэтапной сборки используются в точности объяснённые ключи GCC; отрицательные примеры проверяются на ожидаемом этапе. Протокол содержит время запуска, версии инструментов, перечень запусков и SHA-256 входных файлов.

## Границы проверки

Windows/MSVC, macOS и другие локали не проверялись. Платформенный старт, аппаратная инициализация и полный ввод-вывод при любом отказе окружения не моделируются. Ошибка `printf` проверяется с отключённой буферизацией; при обычной буферизации физическая ошибка может проявиться позже. Заведомо неопределённое поведение при переполнении преобразования `scanf` не запускается. Оцениваемые шаги не изменяются. Проверка сверяет 40 новых payload с исходником по всем полям, кроме разрешённого `block.text`, и подтверждает отсутствие пересечения с 32 ID опубликованного T1.
