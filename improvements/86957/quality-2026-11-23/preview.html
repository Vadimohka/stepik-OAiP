Сложность алгоритма: какую работу мы считаем?

После урока вы сможете определить размер входа, посчитать повторяющиеся операции и объяснить, как изменится работа программы при росте данных. Это помогает выбрать алгоритм до того, как медленный вариант упрётся в ограничение времени.

Сначала задайте модель. Для поиска в массиве n — количество элементов, а базовая операция — сравнение элемента с ключом. Для обработки текста размером может быть число символов; для таблицы нужны два параметра: число строк r и столбцов c.

Дополнительную памятьВспомогательный массив при сортировкеУчитываем ли вход, результат и стек рекурсии

В учебной модели арифметика и сравнение машинных целых, доступ по корректному индексу и изменение счётчика имеют стоимость O(1). Это не обещание одинакового числа тактов. Сравнение двух длинных строк уже может зависеть от их длины. Массив из n значений фиксированного типа занимает O(n) памяти; переход с 4 на 8 байт на значение меняет множитель, а не порядок роста.

Один алгоритм — разные входы одного размера

Линейный поиск прекращается при первом совпадении. На непустом массиве лучший случай — ключ находится сразу: одно сравнение. В худшем случае ключ отсутствует или стоит последним: n сравнений. Если ключ заведомо есть и каждая позиция равновероятна, среднее число сравнений равно (n + 1) / 2. Условие о распределении — часть оценки среднего случая.

Слова «лучший», «худший» и «средний» выбирают функцию стоимости, а O или Θ описывают её рост. Сам знак O не означает «худший случай». Измеренное время в секундах дополнительно зависит от машины, компилятора и ввода-вывода.

Проверьте понимание

Программа читает n чисел, хранит весь массив и ищет максимум одним проходом. Что меняется, если хранить только текущий максимум?

Разбор

Оба варианта должны прочитать все числа: линейное число операций. Массив занимает O(n) памяти. Потоковый вариант хранит лишь текущее число и максимум: O(1) дополнительной памяти. Для пустого входа нужно отдельно определить результат: максимума нет.

Термин in-place в этом модуле означает O(1) дополнительной памяти. Если реализация рекурсивная, отдельно учитываем стек вызовов.

Логарифмический рост: сколько раз можно поделить пополам?

Пусть после каждого действия размер оставшейся задачи уменьшается вдвое. Для n = 16 получаем цепочку 16 → 8 → 4 → 2 → 1: четыре деления. При увеличении исходного размера вдвое нужно всего одно дополнительное деление.

Запустите полный пример в режиме C++17 или C++20. Ввод — одно целое 1 ≤ n ≤ 10⁹; вывод — число целочисленных делений на два до значения 1. Некорректный ввод завершает программу с кодом 1.

#include <iostream>

int main() {
    long long n{};
    if (!(std::cin >> n) || n < 1 || n > 1'000'000'000) {
        return 1;
    }
    int divisions{};
    while (n > 1) {
        n /= 2;
        ++divisions;
    }
    std::cout << divisions << '\n';
}

Для ввода 10 программа напечатает 3: 10 → 5 → 2 → 1. Число итераций равно ⌊log₂ n⌋. Для n ≥ 2 это порядок Θ(log n); для n = 1 тело цикла не выполняется. Дополнительная память — O(1).

Логарифмы с любыми фиксированными основаниями больше 1 отличаются постоянным множителем. Поэтому в асимптотической оценке часто пишут O(log n) без основания. При точном подсчёте основание важно.

Связь с бинарным поиском

В отсортированном массиве сравнение с серединой позволяет отбросить примерно половину ещё возможных позиций. Поэтому поиск требует O(log n) сравнений. Это оценка самого поиска, когда порядок данных уже обеспечен. Предварительная сортировка требует отдельной работы: у std::sort — O(n log n) сравнений.

Для одного запроса в неотсортированном массиве линейный поиск за O(n) обычно разумнее подготовки сортировки. Для множества запросов подготовка может окупиться. Реализацию поиска и обработку повторяющихся ключей разберём в уроке «Поиск элемента в массиве».

Самостоятельно: предскажите вывод для 31 и 32, затем проверьте запуском.

Ответ

Для 31 — 4 деления, для 32 — 5. Отличие на единицу возникает при переходе через степень двойки.

Как считать работу циклов

  1. Определите размер входа и операцию, которую считаете.
  2. Найдите число выполнений тела каждого цикла.
  3. Для последовательных участков сложите стоимости; для вложенных проверьте, зависит ли внутреннее число итераций от внешнего счётчика.
  4. Упростите формулу и явно укажите случай входа.

Два вложенных цикла не всегда дают n². Цикл j < i выполняется 0, 1, 2, …, n−1 раз: сумма равна n(n−1)/2. Другой пример — два прохода подряд: их работа складывается, а не перемножается.

В программе C++17/20 считаем только выполнения трёх отмеченных действий ++счётчик. Ввод: два целых 0 ≤ n, m ≤ 1000. Это счёт операций, а не замер времени процессора.

#include <iostream>

int main() {
    int n{};
    int m{};
    if (!(std::cin >> n >> m) || n < 0 || n > 1000 || m < 0 || m > 1000) {
        return 1;
    }
    long long sequential{};
    for (int i = 0; i < n; ++i) {
        ++sequential;
    }
    for (int j = 0; j < m; ++j) {
        ++sequential;
    }
    long long triangle{};
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < i; ++j) {
            ++triangle;
        }
    }
    long long rectangle{};
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < m; ++j) {
            ++rectangle;
        }
    }
    std::cout << "sequential=" << sequential << '\n';
    std::cout << "triangle=" << triangle << '\n';
    std::cout << "rectangle=" << rectangle << '\n';
}

Для 4 3 получаем соответственно 7, 6 и 12. Формулы: n+m, n(n−1)/2, n·m. На растущих положительных размерах соответствующие порядки — Θ(n+m), Θ(n²) и Θ(nm). Для последнего нельзя заменять m на n, пока связь размеров не задана.

Ветвление и досрочный выход требуют отдельного анализа. Если внутренний цикл на каждой итерации делит счётчик на два, число его повторений логарифмическое. Если один индекс только продвигается от 0 до n за всю работу двух циклов, он не делает n шагов заново для каждой внешней итерации.

Самостоятельно

Замените условие внутреннего треугольного цикла на j <= i. Предскажите точное значение счётчика для n = 4 и его порядок роста.

Разбор

Получится 1+2+3+4 = 10; общая формула n(n+1)/2. Точный результат изменился, порядок Θ(n²) сохранился.

Для рекурсивных алгоритмов можно составить рекуррентное соотношение. Например, деление пополам и линейное слияние дают T(n) = 2T(n/2) + Θ(n). Дерево рекурсии разберём на сортировке слиянием. Мастер-теорема применима только к соотношениям установленного вида и при выполнении её условий.

Асимптотика и измерения отвечают на разные вопросы

Асимптотический анализ помогает предсказать рост работы, а измерение показывает поведение конкретной реализации в конкретной среде. Один эксперимент не доказывает оценку для всех входов.

На малом входе квадратичный алгоритм может выполнить меньше операций, чем линейный с большим множителем. Порядок роста не задаёт универсального победителя при каждом n. Даже алгоритмы одного порядка отличаются числом перемещений, доступом к памяти и стоимостью сравнения.

Мини-практикум: подготовьте честное сравнение

  1. Сначала проверьте результат: отсортирован ли массив, сохранены ли все значения и повторы.
  2. Для каждого размера подготовьте одинаковые входы для сравниваемых алгоритмов. Каждый запуск получает исходную копию, а не уже отсортированный результат другого запуска.
  3. Используйте возрастающие размеры и несколько типов данных: упорядоченные, обратный порядок, много повторов, псевдослучайные с фиксированным начальным состоянием генератора.
  4. Запишите компилятор, стандарт, параметры оптимизации и условия запуска. Исключите печать элементов из измеряемого участка; отдельно решите, входит ли копирование входа в сравнение.
  5. Повторите измерения и сохраните исходные значения. Не объясняйте единичный выброс новой асимптотикой.

Для измерения интервалов в C++ подходит std::chrono::steady_clock. Оптимизатор может удалить вычисления, результат которых никак не используется; измерять нужно реально выполняемую полезную работу. Счётчик сравнений помогает объяснить наблюдение, но сам тоже влияет на время, поэтому измерение времени и подсчёт операций лучше проводить отдельно.

Самопроверка

Массив увеличили вдвое, а программа стала медленнее примерно в четыре раза. Доказана ли квадратичная сложность?

Разбор

Нет. Такое наблюдение согласуется с квадратичным ростом, но могло зависеть от ввода, кеша, фоновой нагрузки или иной части программы. Нужны анализ алгоритма, разные размеры и контролируемые условия.

Для выбора решения учитывайте также читаемость, ограничения памяти и необходимые гарантии. Известная стандартная функция обычно служит хорошей точкой сравнения для учебной реализации.

Сортировка: результат, гарантии и цена

Сортировка переставляет элементы в выбранном порядке. Для чисел по неубыванию каждое следующее число не меньше предыдущего. Повторы сохраняются. Пустая последовательность и последовательность из одного элемента уже отсортированы.

После урока вы сможете проследить основные сортировки, объяснить их время и дополнительную память, а в прикладной задаче воспользоваться стандартным алгоритмом. Собственные реализации нужны для понимания инвариантов и анализа; стандартная функция полезна как готовое решение и эталон в проверках.

Начните со стандартного алгоритма

std::sort объявлен в <algorithm>. Пара begin(), end() задаёт полуинтервал: начало включено, конец находится за последним элементом. Вектор не копируется: меняется порядок его элементов.

Полная программа C++17/20. Ввод: целое 0 ≤ n ≤ 1000 и затем n целых значений, представимых типом int. Вывод: те же значения по неубыванию, разделённые пробелами; при n = 0 — пустая строка. Ошибка ввода даёт код завершения 1. Чтение и печать находятся вне сортирующей функции, поэтому их стоимость анализируется отдельно.

#include <cstddef>
#include <iostream>
#include <vector>
#include <algorithm>



int main() {
    int n{};
    if (!(std::cin >> n) || n < 0 || n > 1000) {
        return 1;
    }
    std::vector<int> values(static_cast<std::size_t>(n));
    for (int& value : values) {
        if (!(std::cin >> value)) {
            return 1;
        }
    }
    std::sort(values.begin(), values.end());
    for (std::size_t i = 0; i < values.size(); ++i) {
        if (i != 0) {
            std::cout << ' ';
        }
        std::cout << values[i];
    }
    std::cout << '\n';
}

Например, для 6 3 1 3 -2 1 0 результат — -2 0 1 1 3 3. Стандарт гарантирует для std::sort O(n log n) сравнений, но не предписывает именно quicksort. Эта оценка относится к числу сравнений; сравнивать длинные строки дороже, чем машинные целые.

Что такое устойчивость?

Если записи с одинаковым ключом сохраняют взаимный порядок, сортировка устойчивая. Например, до сортировки по баллу записи идут (Аня, 5), (Борис, 3), (Вера, 5). Устойчивая сортировка оставит Аню перед Верой. std::sort этого не гарантирует; для такой задачи предназначен std::stable_sort. Он сохраняет порядок эквивалентных по сравнению элементов, но имеет собственные требования к ресурсам.

Пузырьковая сортировка: максимум уходит вправо

Сравниваем соседние элементы. Если правый меньше левого, меняем их местами. После полного прохода наибольшее значение рассматриваемой части оказывается на её правом конце. Следующий проход может не трогать этот элемент.

#include <cstddef>
#include <iostream>
#include <vector>
#include <utility>

void bubble_sort(std::vector<int>& values) {
    for (std::size_t end = values.size(); end > 1; --end) {
        bool swapped = false;
        for (std::size_t i = 1; i < end; ++i) {
            if (values[i] < values[i - 1]) {
                std::swap(values[i], values[i - 1]);
                swapped = true;
            }
        }
        if (!swapped) {
            return;
        }
    }
}

    int n{};

        return 1;

    for (int& value : values) {
        if (!(std::cin >> value)) {
            return 1;
        }
    }
    bubble_sort(values);
    for (std::size_t i = 0; i < values.size(); ++i) {
        if (i != 0) {
            std::cout << ' ';
        }
        std::cout << values[i];
    }
    std::cout << '\n';
}

void insertion_sort(std::vector<int>& values) {
    for (std::size_t i = 1; i < values.size(); ++i) {
        const int value = values[i];
        std::size_t position = i;
        while (position > 0 && value < values[position - 1]) {
            values[position] = values[position - 1];
            --position;
        }

    }
}

        std::cout << values[i];
    }
    std::cout << '\n';

Быстрая сортировка: разбиение относительно опорного

Quicksort выбирает опорное значение и перераспределяет элементы вокруг него. Затем части сортируются рекурсивно. Отдельное слияние двух упорядоченных частей, как в merge sort, не требуется.

Удобная схема для понимания — три группы: меньше опорного, равны ему, больше него. Для [4, 2, 4, 1, 5, 4] и опорного 4 это группы [2, 1], [4, 4, 4] и [5]. Рекурсивно обрабатываются только первая и третья. Здесь показана логическая группировка; реализация может переставлять элементы внутри исходного массива, не создавая три новых контейнера.

От чего зависит время?

  • Если разбиения сбалансированы, получается порядка log n уровней по O(n) работы: O(n log n).
  • Если на массиве различных значений каждый раз отделяется лишь один элемент, размеры задач равны n−1, n−2, …. Суммарная работа становится Θ(n²).
  • При равномерном случайном выборе опорного на каждом шаге для различных ключей ожидаемое время — O(n log n). Это не гарантия для каждого запуска.

Выбор первого элемента как опорного может быть особенно неудачен на уже отсортированном входе. Много одинаковых ключей — отдельный важный тест: трёхчастное разбиение обрабатывает равные элементы вместе, а не повторяет над ними ту же работу.

Какие свойства нужно проверять в реализации?

  1. Разбиение сохраняет все элементы и формирует заявленные группы.
  2. Рекурсивные поддиапазоны строго уменьшаются. Для размера 0 или 1 рекурсия останавливается.
  3. Равные опорному значения не приводят к зацикливанию индексов.
  4. Учитывается стек: у обычной рекурсии он имеет O(log n) ожидаемой глубины при указанной случайной модели, но может вырасти до O(n) в худшем случае.

Обычный quicksort с обменами неустойчив: элементы с равными ключами могут поменять взаимный порядок. Название «быстрая» не означает «самая быстрая для любых данных». std::sort даёт собственную гарантию O(n log n) сравнений и не обязан использовать только обычный quicksort.

Сортировка слиянием: сначала половины, затем общий порядок

Делим диапазон пополам, отдельно сортируем обе половины и объединяем их. Диапазон из 0 или 1 элемента уже готов. Для слияния поддерживаем два индекса: они указывают на первые ещё не перенесённые элементы левой и правой половин.

Слияние [1, 4] и [2, 3] выбирает по порядку 1, 2, 3, а затем копирует оставшуюся 4. Каждый элемент попадает в результат один раз: работа слияния линейна по суммарному размеру половин.

Полная программа C++17/20. Ввод: целое 0 ≤ n ≤ 1000 и затем n целых значений, представимых типом int. Вывод: те же значения по неубыванию, разделённые пробелами; при n = 0 — пустая строка. Ошибка ввода даёт код завершения 1. Чтение и печать находятся вне сортирующей функции, поэтому их стоимость анализируется отдельно.

#include <cstddef>
#include <iostream>
#include <vector>

void merge_range(std::vector<int>& values, std::vector<int>& buffer,
                 std::size_t first, std::size_t last) {
    if (last - first < 2) {
        return;
    }
    const std::size_t middle = first + (last - first) / 2;
    merge_range(values, buffer, first, middle);
    merge_range(values, buffer, middle, last);

    std::size_t left = first;
    std::size_t right = middle;
    std::size_t destination = first;
    while (left < middle && right < last) {
        if (values[right] < values[left]) {
            buffer[destination++] = values[right++];
        } else {
            buffer[destination++] = values[left++];
        }
    }
    while (left < middle) {
        buffer[destination++] = values[left++];
    }
    while (right < last) {
        buffer[destination++] = values[right++];
    }
    for (std::size_t i = first; i < last; ++i) {
        values[i] = buffer[i];
    }
}

void merge_sort(std::vector<int>& values) {
    std::vector<int> buffer(values.size());
    merge_range(values, buffer, 0, values.size());
}

int main() {
    int n{};
    if (!(std::cin >> n) || n < 0 || n > 1000) {
        return 1;
    }
    std::vector<int> values(static_cast<std::size_t>(n));
    for (int& value : values) {
        if (!(std::cin >> value)) {
            return 1;
        }
    }
    merge_sort(values);
    for (std::size_t i = 0; i < values.size(); ++i) {
        if (i != 0) {
            std::cout << ' ';
        }
        std::cout << values[i];
    }
    std::cout << '\n';
}

Границы: [first, last) включает начало, но не конец. Две части [first, middle) и [middle, last) не пересекаются и вместе покрывают исходный диапазон. Размер равен last−first, поэтому одинаковая проверка обслуживает и пустой, и одноэлементный вход.

Инвариант слияния: уже заполненная часть буфера упорядочена и содержит наименьшие из обработанных элементов двух половин. После окончания одной половины оставшиеся элементы другой уже идут в нужном порядке. При равных значениях выбирается левая половина: это сохраняет устойчивость.

Для данной реализации с делением пополам время — Θ(n log n) при растущем n. На каждом уровне суммарно обрабатывается Θ(n) элементов, уровней Θ(log n). Буфер выделяется один раз и занимает O(n); стек вызовов — O(log n); общая дополнительная память — O(n).

Это свойства показанного алгоритма с буфером. Существуют более сложные теоретические варианты слияния на месте, поэтому утверждение «любая merge sort обязательно требует линейного буфера» слишком сильное. Они выходят за рамки этой реализации.

Итеративная heapsort без ручной памяти: безопасные индексы, инварианты, линейное построение кучи и разграничение операций поиска.

Сортировка кучей: максимум в корне

Двоичная max-heap — почти полное бинарное дерево: все уровни, кроме последнего, заполнены, последний заполняется слева направо. Ключ родителя не меньше ключей его детей; равные значения разрешены. Поэтому максимум находится в корне.

Дерево удобно представить внутри того же массива. При нумерации с нуля дети индекса i находятся по индексам 2i+1 и 2i+2, если эти индексы меньше текущего размера кучи. Это логическая структура данных; слово «куча» здесь не обозначает область динамической памяти.

  1. Строим max-heap снизу вверх, начиная с последнего внутреннего узла.
  2. Меняем корень с последним элементом ещё активной кучи: максимум занимает окончательное место.
  3. Уменьшаем активную часть и восстанавливаем свойство кучи просеиванием корня вниз.
  4. Повторяем, пока остаётся больше одного элемента.

Полная программа C++17/20. Ввод: целое 0 ≤ n ≤ 1000 и затем n целых значений, представимых типом int. Вывод: те же значения по неубыванию, разделённые пробелами; при n = 0 — пустая строка. Ошибка ввода даёт код завершения 1. Чтение и печать находятся вне сортирующей функции, поэтому их стоимость анализируется отдельно.

#include <cstddef>
#include <iostream>
#include <vector>
#include <utility>

void sift_down(std::vector<int>& values, std::size_t root, std::size_t count) {
    while (root < count / 2) {
        std::size_t child = 2 * root + 1;
        if (child + 1 < count && values[child] < values[child + 1]) {
            ++child;
        }
        if (!(values[root] < values[child])) {
            return;
        }
        std::swap(values[root], values[child]);
        root = child;
    }
}

void heap_sort(std::vector<int>& values) {
    for (std::size_t start = values.size() / 2; start > 0; --start) {
        sift_down(values, start - 1, values.size());
    }
    for (std::size_t count = values.size(); count > 1; --count) {
        std::swap(values[0], values[count - 1]);
        sift_down(values, 0, count - 1);
    }
}

int main() {
    int n{};
    if (!(std::cin >> n) || n < 0 || n > 1000) {
        return 1;
    }
    std::vector<int> values(static_cast<std::size_t>(n));
    for (int& value : values) {
        if (!(std::cin >> value)) {
            return 1;
        }
    }
    heap_sort(values);
    for (std::size_t i = 0; i < values.size(); ++i) {
        if (i != 0) {
            std::cout << ' ';
        }
        std::cout << values[i];
    }
    std::cout << '\n';
}

В sift_down сначала выбирается больший из существующих детей. Если родитель уже не меньше него, свойство кучи восстановлено. Иначе меняем элементы и продолжаем ниже. Проверка root < count / 2 означает, что у узла есть левый ребёнок; индексы детей вычисляются только после неё.

Инвариант основного цикла: первые count элементов образуют max-heap, а оставшийся суффикс уже отсортирован и содержит извлечённые максимумы. Просеивание не трогает готовый суффикс.

Построение снизу вверх занимает O(n): большинство узлов находятся низко и просеиваются совсем недалеко. Затем выполняется до n−1 извлечений по O(log n), поэтому худшее время ограничено O(n log n). Показанная итеративная реализация использует O(1) дополнительной памяти и неустойчива. У рекурсивной версии просеивания дополнительно учитывался бы стек.

Поиск начинается с контракта

Перед выбором алгоритма ответьте на четыре вопроса: что ищем, упорядочены ли данные, сколько будет запросов и какой результат нужен при повторениях или отсутствии элемента.

В этом уроке ищем целое значение key в последовательности. Индексы отсчитываем с нуля. Линейная функция будет возвращать индекс первого совпадения, а при отсутствии — values.size(). Это значение находится за допустимыми индексами; разыменовывать его нельзя. В бинарном поиске сначала найдём позицию вставки через lower_bound, а затем отдельно проверим совпадение. Обе программы выводят первый индекс или «не найдено»; пустой диапазон всегда даёт «не найдено».

Все три функции объявлены в <algorithm>. Итератор указывает место в диапазоне; end() — позиция за последним элементом. Для вектора разность итератора и begin() даёт индекс. Сначала проверьте, что результат не равен end(), затем обращайтесь к элементу.

Цена подготовки тоже входит в решение задачи

Один запрос к несортированному массиву можно выполнить линейным поиском за O(n). Для q запросов независимый линейный поиск даёт верхнюю оценку O(qn). Сортировка один раз и затем бинарный поиск дают O(n log n + q log n) сравнений. Выигрыш зависит от числа запросов, стоимости сравнений и возможности менять порядок.

Сортировка меняет индексы: найденная позиция относится к отсортированной последовательности. Если нужен исходный индекс, сохраните его вместе со значением или используйте поиск, не переставляющий вход. Повторная сортировка перед каждым запросом обычно уничтожает смысл такой подготовки.

Для вектора и встроенного массива бинарный поиск делает O(log n) шагов при сравнении за O(1). В диапазонах без произвольного доступа число сравнений остаётся логарифмическим, но продвижений итераторов может быть O(n).

Линейный поиск: проверяем по одному

Просматриваем элементы слева направо и возвращаем индекс при первом совпадении. Сортировка не нужна, исходный порядок сохраняется. Если совпадений нет, возвращаем размер последовательности — индекс за её концом.

Полная программа C++17/20. Ввод: 0 ≤ n ≤ 1000, затем n целых значений типа int и искомый ключ того же типа. Вывод: первый индекс или строка not found. Ошибочный ввод даёт код завершения 1.

#include <cstddef>
#include <iostream>
#include <vector>

std::size_t first_index(const std::vector<int>& values, int key) {
    for (std::size_t i = 0; i < values.size(); ++i) {
        if (values[i] == key) {
            return i;
        }
    }
    return values.size();
}

int main() {
    int n{};
    if (!(std::cin >> n) || n < 0 || n > 1000) {
        return 1;
    }
    std::vector<int> values(static_cast<std::size_t>(n));
    for (int& value : values) {
        if (!(std::cin >> value)) {
            return 1;
        }
    }
    int key{};
    if (!(std::cin >> key)) {
        return 1;
    }
    const std::size_t position = first_index(values, key);
    if (position == values.size() || values[position] != key) {
        std::cout << "not found\n";
    } else {
        std::cout << position << '\n';
    }
}

Для 4 8 2 8 5 8 программа выводит 0. Возвращается первое из двух совпадений. Для пустого массива цикл сразу пропускается, функция возвращает 0, равный размеру.

Инвариант: перед проверкой индекса i ни один элемент на индексах [0, i) не равен ключу. Поэтому найденное совпадение действительно первое. Если цикл завершился, проверены все элементы.

Лучший случай на непустом массиве — одно сравнение, худший — n. При равновероятной позиции заведомо присутствующего ключа среднее равно (n+1)/2. Дополнительная память функции — O(1); память самого входного вектора в эту величину не включена.

В прикладной программе ту же задачу решает std::find(values.begin(), values.end(), key). Он возвращает итератор на первое совпадение или values.end() и выполняет не более n проверок равенства. Собственная функция показывает, как устроен этот простой поиск.

Самостоятельно

Измените функцию так, чтобы она возвращала индекс последнего совпадения. Сохраните договорённость о результате при отсутствии и не меняйте вход. Проверьте пустой массив, одно значение и повторения.

Подсказка и проверка

Можно хранить последний найденный индекс, первоначально равный размеру, и обновлять его при каждом совпадении. Для [8, 2, 8, 5] и ключа 8 получится 2. Ранний выход после первого совпадения больше не подходит.

Бинарный поиск и первая подходящая позиция

Для этого урока входной массив должен быть отсортирован по неубыванию. Найдём границу: первый индекс, на котором значение не меньше ключа. Если на этой позиции находится сам ключ, это его первое вхождение. Иначе ключ отсутствует.

Работаем с полуинтервалом [left, right). Начальные границы — 0 и размер массива, поэтому пустой вход не требует отдельного случая. Индекс middle = left + (right−left)/2 избегает переполнения суммы границ.

Полная программа C++17/20. Ввод: 0 ≤ n ≤ 1000, затем n значений типа int по неубыванию и искомый ключ. Вывод: первый индекс или not found. В учебной оболочке некорректный ввод и нарушение сортировки дают код завершения 1.

#include <cstddef>
#include <iostream>
#include <vector>
#include <algorithm>

std::size_t lower_bound_index(const std::vector<int>& values, int key) {
    std::size_t left = 0;
    std::size_t right = values.size();
    while (left < right) {
        const std::size_t middle = left + (right - left) / 2;
        if (values[middle] < key) {
            left = middle + 1;
        } else {
            right = middle;
        }
    }
    return left;
}

int main() {
    int n{};
    if (!(std::cin >> n) || n < 0 || n > 1000) {
        return 1;
    }
    std::vector<int> values(static_cast<std::size_t>(n));
    for (int& value : values) {
        if (!(std::cin >> value)) {
            return 1;
        }
    }
    int key{};
    if (!(std::cin >> key)) {
        return 1;
    }
    if (!std::is_sorted(values.begin(), values.end())) {
        return 1;
    }
    const std::size_t position = lower_bound_index(values, key);
    if (position == values.size() || values[position] != key) {
        std::cout << "not found\n";
    } else {
        std::cout << position << '\n';
    }
}

Возвращаем 1. При равенстве поиск продолжался влево, поэтому найдено первое вхождение, а не произвольное совпадение.

Инвариант: все индексы меньше left содержат значения меньше ключа; все индексы начиная с right — значения не меньше ключа. Неопределённая часть находится между границами. На каждой итерации она строго уменьшается. При left == right граница найдена.

Сама функция требует O(log n) сравнений и O(1) дополнительной памяти. Проверка std::is_sorted в main занимает O(n): она включена для наглядной диагностики предусловия. В серии запросов к неизменному массиву порядок проверяют или обеспечивают один раз, а не перед каждым поиском. Чтение всего ввода тоже линейное.

Стандартная функция std::lower_bound возвращает такую же границу итератором. Её результат может указывать на большее значение, поэтому «итератор не равен end()» ещё не означает наличие ключа. Для проверки только наличия предназначен std::binary_search.

Файл как источник данных: сначала операция, затем проверка

Цель: выбрать поток для чтения или записи и прочитать текстовый файл целиком, сохранив пробелы и пустые строки.

Поток связывает программу с источником или получателем данных. Оператор >>, оператор << и функция std::getline работают по знакомому принципу и с консолью, и с файлами. Заголовок <fstream> предоставляет:

ТипНазначение
std::ifstreamЧитать файл.
std::ofstreamЗаписывать файл.
std::fstreamЧитать и записывать один файл; режим нужно выбирать осознанно.

Начнём с names.txt в рабочем каталоге программы. В файле две строки: Ada Lovelace и Alan Turing. Программа выведет их с номерами:

1: Ada Lovelace
2: Alan Turing

Полная программа read_lines.cpp, C++17 и C++20:

#include <cstddef>
#include <fstream>
#include <iostream>
#include <string>

int main() {
    std::ifstream in{"names.txt"};
    if (!in) {
        std::cerr << "Cannot open names.txt\n";
        return 1;
    }

    std::string line;
    std::size_t number = 0;
    while (std::getline(in, line)) {
        std::cout << ++number << ": " << line << '\n';
    }
    if (in.bad() || !in.eof()) {
        std::cerr << "Cannot read names.txt\n";
        return 2;
    }
}

std::ifstream in{"names.txt"} сразу пытается открыть файл. Проверка if (!in) обнаруживает неудачу. Если файла нет, программа выводит сообщение в std::cerr и завершается с ненулевым кодом; она не выдаёт пустой файл за успешный результат.

std::getline(in, line) читает до перевода строки, удаляет разделитель из потока и сохраняет остальные символы в line. Поэтому имя с пробелом не разрывается на два слова. Пустая строка тоже является строкой и получает номер. Последняя непустая строка читается и без завершающего перевода строки.

Почему условием цикла служит чтение

while (std::getline(in, line)) допускает тело цикла только после успешного извлечения строки. eof() сообщает о конце ввода, уже обнаруженном операцией. Это не предсказание следующего чтения. Условие while (!in.eof()) может допустить обработку после неудачного чтения, а при другой ошибке — вовсе не остановить цикл.

После цикла проверяем, чем он закончился: bad() означает серьёзную ошибку потока; отсутствие eof() означает, что цикл остановился не из-за обычного конца файла. Для getline пустой файл — нормальный случай: ни одной строки и никакого вывода. Разбор чисел имеет дополнительные ошибки формата; к ним вернёмся в следующем уроке.

Кто закрывает файл

Объект файлового потока владеет открытым файлом и закрывает его при уничтожении. Это пример RAII: время жизни ресурса связано со временем жизни объекта. Закрытие происходит при обычном выходе из области видимости, при return и при раскрутке стека из-за исключения. Аварийное завершение процесса не даёт тех же гарантий. Проверку ошибок сохранения обсудим отдельно: автоматическое закрытие не делает запись безошибочной.

Все полные программы этого урока можно собирать так, заменяя имя файла:

g++ -std=c++20 -Wall -Wextra -Wpedantic read_lines.cpp -o read_lines

Для C++17 замените c++20 на c++17. В Linux/macOS запуск — ./read_lines; в Windows имя исполняемого файла и команда запуска зависят от оболочки.

Открытие, пути и проверка сохранения

Цель: выбрать режим открытия, найти файл относительно рабочего каталога и отличить успешное открытие от успешного завершения записи.

Имя "report.txt" задаёт относительный путь. Он отсчитывается от текущего рабочего каталога процесса, который может отличаться от каталога исходника и исполняемого файла. При запуске из терминала это обычно каталог, из которого вы запустили программу; IDE задаёт его в настройках запуска. Если файл «пропал», сначала проверьте рабочий каталог. Использование конкретного диска вроде D:\ делает пример зависимым от компьютера.

Пример: отчёт готов только после проверки

Программа создаёт или перезаписывает report.txt. Выполняйте её в учебном каталоге. Ожидаемое содержимое файла — две строки count 3 и sum 42; сообщение saved появляется только после проверки закрытия.

Полная программа write_report.cpp, C++17 и C++20:

#include <fstream>
#include <iostream>

int main() {
    std::ofstream out{"report.txt"};
    if (!out) {
        std::cerr << "Cannot open report.txt\n";
        return 1;
    }

    out << "count 3\n" << "sum 42\n";
    out.close();
    if (!out) {
        std::cerr << "Cannot finish report.txt\n";
        return 2;
    }
    std::cout << "saved\n";
}

Первая проверка обнаруживает ошибку открытия. Вторая выполняется после close(): часть ошибок вывода может обнаружиться только при передаче накопленных данных или закрытии файла. Успешное открытие через is_open() ещё не доказывает успех всех дальнейших операций.

Мы явно вызываем close(), чтобы проверить результат завершения записи до сообщения об успехе. Для простого чтения обычно достаточно автоматического закрытия. Эти способы дополняют друг друга: RAII освобождает ресурс, а проверки позволяют сообщить пользователю об ошибке.

Буфер, flush и состояние потока

Файловый поток работает через потоковый буфер; конкретное накопление и момент передачи данных зависят от реализации и настроек. out.flush() запрашивает синхронизацию буфера, после чего нужно проверить out. std::endl добавляет перевод строки и вызывает flush(); если немедленная синхронизация не нужна, достаточно '\n'. Ни flush(), ни успешный close() сами по себе не обещают сохранность при отключении питания.

Оператор вывода возвращает ссылку на тот же поток: результат out << 42 имеет тип std::ostream&. Благодаря этому можно записать цепочку out << count << ' ' << sum.

Существующий шаг на Stepik · Новый .step · Исходный .step

Интерфейс C: распознаём и проверяем ручное владение

Цель: читать код с std::FILE*, правильно проверять результаты и объяснять отличие от объекта std::ofstream. Основной способ для новых учебных программ — стандартные потоки C++.

В существующих библиотеках встречается интерфейс C из <cstdio>. std::fopen возвращает std::FILE* при успешном открытии и nullptr при ошибке. Сам вызов не выводит диагностическое сообщение за программу. Указатель обозначает библиотечный поток; это не прямой адрес файла на диске.

Полная программа записывает Hello, files! и перевод строки в message.txt. Режим "wb" создаёт файл для двоичной записи либо удаляет прежнее содержимое.

Полная программа c_write.cpp, C++17 и C++20:

#include <cstdio>

int main() {
    std::FILE* file = std::fopen("message.txt", "wb");
    if (file == nullptr) {
        std::fputs("Cannot open message.txt\n", stderr);
        return 1;
    }

    const char message[] = "Hello, files!\n";
    const std::size_t size = sizeof message - 1;
    const std::size_t written = std::fwrite(message, 1, size, file);
    const int closed = std::fclose(file);
    if (written != size || closed != 0) {
        std::fputs("Cannot finish message.txt\n", stderr);
        return 2;
    }
}

std::fwrite(buffer, size, count, file) возвращает количество полностью записанных элементов размером size, а не логическое «успех/ошибка». В примере размер элемента равен 1, поэтому результат одновременно равен числу записанных байтов. std::fread работает аналогично для чтения. Если size равен 8 и возвращено 3, полностью обработаны три восьмибайтовых элемента.

Последний нулевой символ массива message нужен для C-строки в памяти; в файл его здесь не записываем. Поэтому число записываемых элементов равно sizeof message - 1.

std::fclose выполняется даже при неполной записи. Только после него проверяются оба результата. Не объединяйте запись и закрытие так, чтобы короткое замыкание && или || пропускало fclose. Успешное закрытие возвращает 0; ненулевой результат означает ошибку.

Указатель std::FILE* сам по себе не закрывает файл при выходе из области видимости. Здесь ответственность лежит на программе. После fclose этот поток больше нельзя использовать или закрывать повторно. В более сложном коде ручное владение легко нарушить на раннем return или при исключении; именно эту обязанность берут на себя владельцы ресурсов, в том числе файловые потоки C++.

std::fprintf/std::fscanf выполняют форматированный вывод/ввод; std::fwrite/std::fread передают блоки данных заданного размера. Выбор функции и режим открытия — разные решения.

Дописать, перезаписать или сдвинуть позицию?

Цель: предсказать изменение файла по режиму открытия. Это полезнее, чем запоминать названия флагов отдельно от результата.

Режим C++Аналог fopenПоведение
in"r"Чтение; файл должен существовать.
out или out | trunc"w"Запись с усечением; отсутствующий файл создаётся, если это разрешено.
out | app"a"Каждая запись в конец; существующие данные сохраняются.

Два разных «конца файла»

app направляет каждую запись в конец файла. ate перемещает позицию в конец один раз, после открытия; затем можно позиционироваться иначе. ate не отменяет усечение, которое следует из остальных флагов. В режиме app попытка предварительно изменить позицию записи не превращает дописывание в перезапись середины.

Пример 1: журнал

Если journal.txt содержит строку 5 с завершающим переводом строки, после запуска он содержит строки 5 и 7. Повторный запуск добавит ещё одну строку 7. Если последнего перевода строки в исходном файле не было, программа сама его перед записью не добавит: к 5 присоединится 7.

Полная программа append_line.cpp, C++17 и C++20:

#include <fstream>
#include <iostream>

int main() {
    std::ofstream out{"journal.txt", std::ios::app};
    if (!out) {
        std::cerr << "Cannot open journal.txt\n";
        return 1;
    }

    out << "7\n";
    out.close();
    if (!out) {
        std::cerr << "Cannot finish journal.txt\n";
        return 2;
    }
}

Создайте text.txt ровно с пятью символами ABOBA. Следующая программа получает LUCIA: четыре новых символа заменяют первые четыре старых, а последний A остаётся. Это не вставка и не усечение. Если файла нет, открытие не удаётся.

Полная программа overwrite_prefix.cpp, C++17 и C++20:

#include <fstream>
#include <iostream>

int main() {

        std::cerr << "Cannot finish text.txt\n";
        return 2;

}

Формат файла: байты получают смысл по договорённости

Цель: отличить представление данных от режима открытия и объяснить, почему binary не сохраняет объект C++ автоматически.

Файл хранит последовательность байтов. Формат описывает, как читать их: где начинаются записи, какие есть поля, как записаны числа и строки, какие версии поддерживаются. Формат может быть текстовым или двоичным. Текст тоже хранится в байтах, но его символы интерпретируются в согласованной кодировке.

Представление числа 42Что должен знать читатель
Текст 42Кодировку, десятичную систему, разделитель следующего значения.
Фиксированное двоичное полеШирину поля, знаковость, порядок байтов и допустимые значения.

Расширение имени файла помогает людям и программам выбрать обработчик, но не заменяет формат. Содержимое .exe можно прочитать как байты; загрузчик конкретной ОС разбирает его формат и заголовки. Из этого не следует, что ОС обязана сама понимать структуру любого пользовательского файла. Даже образ файловой системы можно рассматривать как файл со сложным двоичным форматом.

Что именно делает binary

Флаг std::ios::binary выбирает двоичный режим открытия. Он избегает специфичных для платформы преобразований текстового режима, например преобразований перевода строки. Он не выбирает формат ваших значений.

Фрагмент внутри функции, после подключения <fstream>:

std::ofstream out{"answer.dat", std::ios::binary};
// Здесь и далее нужно проверять состояние, как в предыдущем уроке.
out << 42 << '\n';

Оператор << здесь всё равно форматирует число как текст 42. Бинарный режим не превращает эту запись в копию машинного представления int.

Кодировка — отдельная часть формата

Для обмена текстом заранее договоритесь, например, об UTF-8 и разделителях строк. std::string хранит последовательность элементов char; её размер не обязан совпадать с количеством букв в UTF-8. Переход к wchar_t и wifstream не означает автоматического правильного чтения любого UTF-8-файла: преобразования и кодировки должны быть согласованы. В наших небольших числовых примерах используются обычные десятичные цифры и пробельные разделители.

Почему нельзя просто записать sizeof объекта

Структуры и классы будут подробно изучаться дальше. Уже сейчас запомните ограничение: копия памяти объекта — не универсальный формат хранения. Между полями могут быть байты выравнивания; размеры типов и порядок байтов зависят от реализации. Указатель хранит адрес текущего процесса, а не данные по этому адресу. Внутреннее представление std::string или std::vector тоже нельзя сохранять как готовую строку или последовательность простым сбросом памяти.

Для переносимых данных записывают логические значения по явно описанному формату. Например: «первая строка — версия; каждая следующая — имя без пробелов и целая оценка от 0 до 100». Нужны правила для пустого файла, неверной записи, повторов и неизвестной версии. Для реальных обменных форматов обычно используют готовые библиотеки соответствующего формата.

Позиция в файле и проверяемое позиционирование

Цель: различать последовательное чтение и переход к позиции, не смешивая файловое смещение с адресом памяти.

При последовательном чтении позиция продвигается по мере извлечения данных. Для обычного двоичного файла из байтов удобно нумеровать позиции от 0: первый байт имеет смещение 0, а позиция в конце находится после последнего байта. Не каждый источник поддерживает произвольные переходы; результат позиционирования нужно проверять.

Операция C++Назначение
tellg() / seekg(...)Получить / изменить позицию чтения.
tellp() / seekp(...)Получить / изменить позицию записи.
std::ios::begОтсчитывать смещение от начала.
std::ios::curОтсчитывать от текущей позиции.
std::ios::endОтсчитывать от конца.

Последний байт обычного двоичного файла

Для этого примера создайте letters.bin ровно с пятью однобайтовыми символами ABCDE, без перевода строки. Программа выведет E. Она рассчитана на обычный файл, поддерживающий позиционирование. Пустой файл, отсутствие файла или ошибка перехода не считаются успешным чтением.

Полная программа last_byte.cpp, C++17 и C++20:

#include <fstream>
#include <iostream>

int main() {
    std::ifstream in{"letters.bin", std::ios::binary};
    if (!in) {
        std::cerr << "Cannot open letters.bin\n";
        return 1;
    }

    in.seekg(-1, std::ios::end);
    if (!in) {
        std::cerr << "Cannot seek letters.bin\n";
        return 2;
    }
    char last = '\0';
    if (!in.get(last)) {
        std::cerr << "Cannot read letters.bin\n";
        return 3;
    }
    std::cout << last << '\n';
}

seekg(-1, std::ios::end) означает «на одну позицию до конца». Нулевое смещение от конца оказалось бы уже за последним байтом. Если в файл добавить перевод строки, последним байтом станет он, а не E.

В текстовом режиме числовое смещение не следует безоговорочно считать номером символа: влияют преобразования режима и кодировка. Для возвращения к ранее сохранённой позиции используйте значение, полученное tellg(), и проверяйте ошибки. Произвольный переход в середину UTF-8-последовательности не является переходом к «следующей букве».

Короткий мост к интерфейсу C

std::fseek(file, offset, origin) возвращает 0 при успехе и ненулевое значение при ошибке. Имена точек отсчёта — SEEK_SET, SEEK_CUR, SEEK_END; их не нужно определять самостоятельно. std::ftell возвращает позицию типа long, а при ошибке — -1L. Для текстового потока это значение нельзя считать универсальным количеством байтов. Оно тем более не является указателем на память.

Когда последовательный формат проще

Если записывать значения переменной длины, нельзя найти «пятую запись», просто умножив 4 на sizeof типа в памяти. Нужно разобрать предыдущие записи, хранить индекс смещений или выбрать формат фиксированных полей. При частичном обновлении файл может остаться в промежуточном состоянии после сбоя; проверки версии, длины и допустимых значений помогают заметить повреждение, но не заменяют продуманную процедуру сохранения.

Существующий шаг на Stepik · Новый .step · Исходный .step

Числовой файл: проверяем весь вход, затем выдаём результат

Цель: отличить конец файла от неверного значения, обработать пустой вход и выбрать проверки, которые ловят ошибки на границе файла.

Задача: прочитать numbers.txt и вывести количество чисел и их сумму. Зафиксируем формат:

  • Десятичные целые числа от −1 000 000 до 1 000 000 включительно; необязательный знак + или -.
  • Разделители — пробелы, табуляции или переводы строк. Не более 1 000 000 чисел.
  • Пустой файл или только пробельные символы допустимы: ответ 0 0.
  • Дроби, буквы, частично корректные значения вроде 12abc и превышение ограничений — ошибка. Частичный результат при ошибке не выдаём.

Для файла 10 -3 5 ответ равен 3 12. Сумма хранится в long long: по ограничениям её модуль не превосходит 1012, что помещается в гарантируемый диапазон этого типа.

Полная программа sum_numbers.cpp, C++17 и C++20:

#include <cstddef>
#include <fstream>
#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::ifstream in{"numbers.txt"};
    if (!in) {
        std::cerr << "Cannot open numbers.txt\n";
        return 1;
    }

    long long sum = 0;
    std::size_t count = 0;
    std::string token;
    while (in >> token) {
        std::istringstream field{token};
        long long value = 0;
        char extra = '\0';
        if (!(field >> value) || (field >> extra) ||
            value < -1'000'000 || value > 1'000'000) {
            std::cerr << "Invalid integer\n";
            return 2;
        }
        if (count == 1'000'000) {
            std::cerr << "Too many integers\n";
            return 3;
        }
        ++count;
        sum += value;
    }
    if (in.bad() || !in.eof()) {
        std::cerr << "Cannot read numbers.txt\n";
        return 4;
    }
    std::cout << count << ' ' << sum << '\n';
}

Зачем сначала читать слово

in >> token извлекает одно слово до пробельного разделителя. Затем std::istringstream из заголовка <sstream> позволяет разобрать это слово теми же операторами ввода, что и обычный поток.

  1. field >> value должен успешно получить целое число. Он отвергает отсутствие числа и значение, не помещающееся в long long.
  2. После числа не должно остаться дополнительного символа: успешное field >> extra означает лишний хвост, например abc в 12abc.
  3. Проверяем диапазон значения и ограничение количества, затем обновляем сумму.
  4. После завершения чтения слов проверяем состояние самого файла. Только затем выводим итог.

Простая конструкция while (in >> value) полезна, если формат корректного входа гарантирован. Но при проверке произвольного числового файла нельзя считать любой eof() после неудачного чтения доказательством успеха: слишком большое число в самом конце может одновременно установить признаки конца файла и ошибки преобразования. Разделение извлечения слова и разбора значения позволяет явно отвергнуть такой случай.

Для строки целиком используйте getline, как в предыдущем уроке. При смешивании >> и getline учитывайте оставшийся перевод строки. Для нового формата часто проще выбрать один способ чтения записей. Не добавляйте std::ws автоматически перед getline, если начальные пробелы или пустые строки имеют смысл.

Контейнер, алгоритм и итератор: как они работают вместе

После шага вы сможете передать диапазон элементов стандартному алгоритму и проверить результат поиска до обращения к нему. Предполагается, что вы уже знакомы с std::vector, циклами и функциями.

В разговоре о C++ словом STL обычно называют связанную систему стандартных контейнеров, итераторов и алгоритмов. Стандартная библиотека шире: в неё также входят строки, потоки, умные указатели и другие средства. Дополнительную «библиотеку STL» для этих примеров устанавливать не требуется.

  • Контейнер хранит данные и управляет временем жизни своих элементов. Например, std::vector<int> хранит последовательность чисел.
  • Итератор обозначает позицию в последовательности. Он похож на указатель по способу использования, но не обязан быть указателем.
  • Алгоритм выполняет действие над подходящим диапазоном: ищет, сортирует, копирует. Например, std::find работает с разными контейнерами через их итераторы.

Диапазон [begin, end)

begin() обозначает начало, а end() — позицию после последнего элемента. Левая граница включена, правая исключена. У пустого контейнера они равны. Разыменовывать end() нельзя. Поэтому результат std::find сначала сравнивают с концом диапазона: совпадение означает, что элемент не найден.

Полная программа: сортировка и поиск

Пример работает в C++17 и C++20. Ввод: n от 0 до 1000, затем n целых чисел и искомое число. Все числа по условию лежат от −10⁶ до 10⁶; повторения разрешены. Программа выводит отсортированную последовательность и результат поиска. Для n = 0 первая строка вывода пустая. При невозможности прочитать обязательное число программа завершается с кодом 1.

#include <cstddef>
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    int n = 0;
    if (!(std::cin >> n) || n < 0 || n > 1000) {
        return 1;
    }
    std::vector<int> values;
    for (int i = 0; i < n; ++i) {
        int value = 0;
        if (!(std::cin >> value)) {
            return 1;
        }
        values.push_back(value);
    }
    int key = 0;
    if (!(std::cin >> key)) {
        return 1;
    }

    std::sort(values.begin(), values.end());
    for (std::size_t i = 0; i < values.size(); ++i) {
        if (i != 0) {
            std::cout << ' ';
        }
        std::cout << values[i];
    }
    std::cout << '\n';

    const auto it = std::find(values.begin(), values.end(), key);
    std::cout << (it != values.end() ? "found" : "missing") << '\n';
}

Вывод:

found

std::find выполняет линейный поиск и не использует отсортированность данных. Здесь сортировка нужна для вывода. Для поиска в отсортированном векторе можно использовать std::lower_bound, разобранный в модуле поиска. Наличие общих итераторов не означает, что любой алгоритм подходит любому контейнеру: std::sort требует изменяемых элементов и итераторов произвольного доступа. Его можно применять к вектору, но не к std::set; множество само поддерживает порядок.

Выбор контейнера начинается с нужных операций

Цель: отличать позицию от ключа, множество от словаря и осознанно решать, сохранять ли повторения. Во всех примерах этого урока достаточно C++17; указанные возможности C++20 отмечены отдельно.

В set элемент сам является ключом. В map ключ связан со значением: например, слово связано с количеством его появлений. У разных ключей значения могут совпадать. Контейнеры multiset и multimap позволяют хранить несколько элементов с эквивалентными ключами. Это нужно, когда отдельные повторные записи имеют значение, а не когда достаточно одного счётчика.

Практика: убрать повторения и вывести числа по порядку

Ввод: 0 ≤ n ≤ 1000, затем n целых чисел от −10⁶ до 10⁶. Вывод: количество разных чисел и строка с этими числами по возрастанию. Для пустого набора вторая строка пустая. Программа проверяет чтение обязательных данных.

#include <iostream>
#include <set>

int main() {
    int n = 0;
    if (!(std::cin >> n) || n < 0 || n > 1000) {
        return 1;
    }
    std::set<int> values;
    for (int i = 0; i < n; ++i) {
        int value = 0;
        if (!(std::cin >> value)) {
            return 1;
        }
        values.insert(value);
    }

    std::cout << values.size() << '\n';
    bool first = true;
    for (int value : values) {
        if (!first) {
            std::cout << ' ';
        }
        std::cout << value;
        first = false;
    }
    std::cout << '\n';
}

Для ввода:

6
4 1 4 2 1 4

Получим:

3
1 2 4

Повторная вставка 4 не создаёт новый элемент. При необходимости результат insert позволяет узнать, произошла ли вставка: его поле second равно true только для нового ключа; поле first указывает на вставленный или уже существующий элемент.

При стандартном сравнении целые числа обходятся по возрастанию. В общем случае порядок и эквивалентность определяет компаратор: ключи a и b эквивалентны, если оба сравнения comp(a, b) и comp(b, a) ложны. Это не обязательно то же самое, что a == b. Компаратор обязан задавать строгий слабый порядок; например, <= для целых для этой роли не подходит, поскольку значение нельзя считать строго меньшим самого себя.

Поиск: values.find(key) != values.end(). Начиная с C++20 ту же проверку наличия можно записать values.contains(key). В set нет доступа «элемент номер i» и оператора []. Менять ключ через итератор нельзя: это могло бы нарушить порядок. Для смены значения в простом варианте удаляют старый ключ и вставляют новый.

Что выведет программа для пяти одинаковых чисел? Какой контейнер нужен, если требуется сохранить все пять записей и обходить их по порядку? Почему замена vector на set меняет результат задачи «повторить ввод без изменений»?

Ответ: размер будет 1; для сохранения повторов в упорядоченном наборе подойдёт multiset; set убирает эквивалентные ключи и меняет порядок обхода. Поэтому выбор контейнера — часть решения задачи, а не просто замена синтаксиса.

std::map: счётчик слов и поиск без случайной вставки

После шага вы сможете подсчитать повторения, получить значение по ключу и объяснить, когда операция меняет словарь. Заголовок для std::map — <map>, для std::string — <string>.

Элемент std::map<Key, T> — пара std::pair<const Key, T>. Поле first содержит ключ, поле second — связанное значение. Ключ нельзя присвоить заново через эту пару, а значение можно изменять. Уникальны ключи, но не значения. map и set — самостоятельные контейнеры; один не является наследником другого.

Одна запись — один счётчик

Ввод: 0 ≤ n ≤ 1000, затем n слов и одно слово-запрос. Слово по условию содержит от 1 до 20 строчных латинских букв; пробелы разделяют слова. Вывод: разные слова с частотами по лексикографическому порядку, ответ на запрос и количество ключей. Регистр и пунктуацию программа не нормализует; этот пример не является обработчиком произвольного текста на естественном языке.

#include <iostream>
#include <map>
#include <string>

int main() {
    int n = 0;
    if (!(std::cin >> n) || n < 0 || n > 1000) {
        return 1;
    }
    std::map<std::string, int> counts;
    for (int i = 0; i < n; ++i) {
        std::string word;
        if (!(std::cin >> word)) {
            return 1;
        }
        ++counts[word];
    }
    std::string query;
    if (!(std::cin >> query)) {
        return 1;
    }

    for (const auto& entry : counts) {
        std::cout << entry.first << ' ' << entry.second << '\n';
    }
    const auto it = counts.find(query);
    if (it == counts.end()) {
        std::cout << "not found\n";
    } else {
        std::cout << "count " << it->second << '\n';
    }
    std::cout << "keys " << counts.size() << '\n';
}

Вывод:

В ++counts[word] оператор [] намеренно используется для накопления. Если ключа ещё нет, создаётся значение типа int, инициализированное нулём; затем оно увеличивается. Если ключ есть, увеличивается его текущий счётчик. Это поведение зависит от типа значения: оператор [] не является универсальным способом получить «ноль» для любого класса.

Модель стоимости, сравнение длинных ключей, отдельный запрос и серия; средняя и амортизированная оценки

Существующий шаг на Stepik · Новый .step · Исходный .step

Как сравнивать стоимость операций контейнеров

Цель: назвать размер данных, конкретную операцию и условия оценки, прежде чем записывать O. Для словаря далее n — количество разных ключей, а q — число поисковых запросов.

Оценка «контейнер работает за O(log n)» слишком расплывчата. Поиск, обход всех элементов, вставка одного ключа и построение словаря из входа — разные действия. Например, поиск в std::map логарифмический, а вывод всех его элементов требует линейного числа посещений.

Граница роста и случай входа — разные понятия

  • O(f(n)) — верхняя асимптотическая граница: при достаточно большом n затраты не превышают постоянный множитель f(n).
  • Ω(f(n)) — нижняя граница при достаточно большом n.
  • Θ(f(n)) — одновременно верхняя и нижняя границы одного порядка.

Каждая запись применяется к выбранной функции: затратам в худшем случае, лучшем случае или в среднем при заданной модели входов. Ω не означает автоматически лучший случай. Для последовательного поиска первый элемент даёт Θ(1), а отсутствующий элемент — Θ(n). Худшие затраты этого поиска одновременно O(n) и Ω(n).

Из чего состоит одна «операция»

Для таблицы контейнеров обычно считаем сравнение ключей или вычисление хеша действием постоянной стоимости. С целыми ключами это часто удобная модель. С длинными строками одного количества сравнений недостаточно: сравнение может просмотреть общий префикс, а вычисление хеша обычно обрабатывает символы ключа. Если максимальная длина строки L, грубая верхняя оценка поиска в дереве через сравнения может быть O(L log n). Это объясняет, почему одинаковая запись O(log n) не обещает одинаковое время для целых чисел и строк.

Один запрос и много запросов

Подход к данным, которые далее не меняютсяПодготовкаq запросов

Для одного запроса к неупорядоченным данным линейный поиск часто разумнее предварительной сортировки. Для множества запросов стоимость подготовки может окупиться. Если между запросами нужно вставлять и удалять ключи, надо учесть стоимость этих операций: у вектора двоичный поиск быстр, но вставка в середину требует сдвигов.

Среднее и амортизированное

Средняя оценка зависит от распределения входов или хешей. Амортизированная оценка распределяет общие затраты по последовательности операций: например, отдельный vector::push_back при перераспределении памяти может переместить все элементы, хотя серия добавлений имеет амортизированную постоянную стоимость на добавление. «Амортизированно O(1)» не обещает одинаковую задержку каждого вызова и не является средним по случайным входам.

Самопроверка

  1. Почему O(log n) для map::find не делает вывод всего словаря логарифмическим?
  2. Как оценить n последовательных поисков по n элементам в обычном векторе?
  3. Можно ли из O(1) в среднем заключить, что любой конкретный запрос выполнится за постоянное время?

Ответ: обход посещает n элементов; n·O(n) даёт O(n²) в худшем случае; средняя оценка не исключает дорогого отдельного запроса. Сложность помогает выбирать подход, а измерение реального времени дополняет её для конкретной программы и данных.

std::map или std::unordered_map: порядок, гарантии и практика

Цель: выбрать контейнер под требования задачи и различать гарантии библиотеки и свойства собственной реализации. Ни один вариант не является самым быстрым для всех входов и всех операций.

Гарантии для уникальных ключей

В таблице n — число ключей; сравнение, вычисление хеша и сравнение на равенство считаем действиями постоянной стоимости. Речь об обычной одиночной вставке без подсказки и об удалении по ключу.

КонтейнерПоиск / вставка / удаление по ключуОбход
std::set, std::mapO(log n)В порядке компаратора
std::unordered_set, std::unordered_mapВ среднем O(1), в худшем O(n)Не обещает сортировки и фиксированного порядка

Стандарт не предписывает map конкретную разновидность сбалансированного дерева. У собственной реализации обычного двоичного дерева поиск зависит от высоты h: O(h); без балансировки h может вырасти до n. У списка поиск по ключу — O(n), даже если удаление уже найденного узла само по себе выполняется за O(1). Название абстрактной структуры не заменяет анализ её реализации.

Гарантия erase(iterator) для set/map отличается от поиска и удаления по ключу: она амортизированно постоянная. Для multi-контейнеров удаление всех совпадений зависит ещё и от количества удаляемых элементов. Всегда уточняйте, какая перегрузка и какой результат нужны.

Хеш-таблица: быстрый поиск без требования порядка

Следующая программа отвечает на запрос частоты слова. Условия ввода те же, что в предыдущем примере: 0 ≤ n ≤ 1000, n слов и слово-запрос; слова состоят из 1–20 строчных латинских букв. Выводит только частоту запроса и число ключей. Она не зависит от порядка обхода хеш-таблицы.

#include <cstddef>
#include <iostream>
#include <string>
#include <unordered_map>

int main() {
    int n = 0;
    if (!(std::cin >> n) || n < 0 || n > 1000) {
        return 1;
    }
    std::unordered_map<std::string, int> counts;
    counts.reserve(static_cast<std::size_t>(n));
    for (int i = 0; i < n; ++i) {
        std::string word;
        if (!(std::cin >> word)) {
            return 1;
        }
        ++counts[word];
    }
    std::string query;
    if (!(std::cin >> query)) {
        return 1;
    }

    const auto it = counts.find(query);
    if (it == counts.end()) {
        std::cout << "not found\n";
    } else {
        std::cout << "count " << it->second << '\n';
    }
    std::cout << "keys " << counts.size() << '\n';
}

Для ввода:

5
pear apple pear plum apple
pear

Вывод:

count 2
keys 3

reserve(n) заранее готовит таблицу к предполагаемому числу элементов с учётом коэффициента загрузки; он не вставляет ключи, не запрещает коллизии и не превращает худший случай в O(1). Здесь резервируем верхнюю границу числа разных слов. Приведение к std::size_t выполнено только после проверки, что n неотрицательно.

Коллизия не означает равенство ключей. Разные ключи могут получить одинаковый хеш, поэтому контейнер дополнительно проверяет равенство. Если вы задаёте собственные хеш и сравнение на равенство, эквивалентные ключи должны иметь одинаковый хеш. Для стандартной строки в примере используются готовые согласованные операции.

Вставка может вызвать перехеширование и сделать сохранённые итераторы хеш-таблицы недействительными. Поэтому в примере итератор получают после всех вставок и затем таблицу не изменяют. Указатели и ссылки на существующие элементы при перехешировании сохраняются, но после удаления соответствующего элемента использовать их нельзя. Для начальных программ проще повторно искать элемент после изменения таблицы.

  1. Нужно после каждой правки обходить имена по возрастанию. Какой словарь выбрать?
  2. Нужна только частота введённого слова, порядок не важен. Какие варианты допустимы?
  3. Нужно вывести результаты хеш-таблицы в одинаковом порядке на разных запусках. Чего не хватает?

Самопроверка: map непосредственно даёт упорядоченный обход; для частоты подходят оба словаря, выбор учитывает гарантии, данные и измерения; для фиксированного вывода нужно отдельно собрать и отсортировать ключи либо использовать map. Нельзя писать тест, который требует произвольного порядка обхода unordered_map.

Небольшая практика перед задачей повышенной сложности

Измените программу так, чтобы она читала q запросов (0 ≤ q ≤ 1000) и для каждого печатала только число появлений, включая 0 для отсутствующего слова. Словарь при запросах не должен расти. Проверьте пустой словарь, повторные слова и два одинаковых отсутствующих запроса. Например, для слов apple pear apple запросы apple plum plum должны дать 2, 0, 0, а число ключей остаться 2.

Следующее оценочное задание про упрощённый язык программирования имеет повышенную сложность: помимо словаря оно требует разбора выражений и отслеживания состояния имён. Сначала убедитесь, что умеете решить короткую задачу со счётчиком; сложная задача объединяет несколько навыков и не является первой проверкой синтаксиса map.
