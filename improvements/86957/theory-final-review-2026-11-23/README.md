## Как устроен итоговый пакет

В [манифесте](manifest.json) **55 уникальных шагов в 32 уроках и 15 модулях**:

- **49 шагов** перенесены побайтно из предыдущего подготовленного [LINKS](../theory-links-2026-11-23/manifest.json).
- **6 шагов** получили новую редакцию. Один из них, `3570333`, уже входил в прежние 50 LINKS-шагов.
- Поэтому состав равен объединению `50 ∪ 6 = 55`, а не сумме 56.

В Stepik опубликован единый итоговый пакет. Прежний LINKS и его протоколы сохранены в истории подготовки. Исходник 55 текстов закреплён по опубликованному снимку в `26bbfeb`. Редакторская проверка использовала этот снимок с прежней редакцией LINKS.

Во всех `.step` меняется только `block.text`. **Все 24 исходных `<pre>` внутри шести заново исправленных текстов сохранены побайтно** относительно эффективного входа этого прохода. Новые исходники в `examples/` служат авторской проверке объяснений; это не задания учащимся.

Первые опубликованные пакеты 88 и 191 пересекаются по семи ID и охватывают 272 уникальных текста. Вместе с нынешним пакетом охват редакций составляет **277 уникальных текстов**. Прочитаны все 283; число изменённых текстов не является процентом готовности.

### Покрытие объясняющего кода

[code_coverage.json](code_coverage.json) учитывает **все 340 `<pre>`**. Среди них **148 положительных самостоятельных полных листингов** и **одна составная программа TeachingShared**, собранная из двух фрагментов. Два самостоятельных листинга относятся к C. Многофайловые компоненты, учебный заголовок RB, фрагменты, вывод, команды и ожидаемые ошибки учитываются отдельно.

Для положительных полных программ подтверждены соответствие источнику, нужный язык/стандарт и свежий успешный набор. Там, где старый verifier пишет агрегированный итог, связь обоснована также его закреплённым кодом выбора исходников и новым протоколом запуска; отсутствующий индивидуальный лог не выдумывается.

Закрыты **семь прежних пробелов**: три программы о символьных типах и размерах типов (`3177281`, `3177283`) и четыре программы об указателях (`3212990`, `3212989`). Их полный текст не менялся. Вывод адреса и размеры типов проверяются как наблюдения текущей платформы, а не как универсальные числа.

## Воспроизведение и контроль сохранённого результата

Сначала прочитайте README и `verify.py` соответствующих наборов. Требуются Python 3.10+, GCC с C++17/C++20 и C11/C17, CMake 3.22+. Первое получение закреплённого GoogleTest требует сети. Сведения о полученной зависимости: [validation/dependencies.json](validation/dependencies.json).

Команды ниже воспроизводят проверки подготовки на исходной ревизии [коммит подготовки 5b3946e](https://github.com/Vadimohka/stepik-OAiP/commit/5b3946ed7864ff22231bdbd16a4485ced71e6592). Из актуального `main` проверяются генерация пакетов и дерево курса. Результат публикации хранится отдельно. [Протокол сверки](../../../courses/86957/publication-verification-theory-final-review-2026-11-23.json)

```sh
python3 tools/build_theory_upgrade.py --check
python3 improvements/86957/theory-final-review-2026-11-23/verify_code_coverage.py --check
python3 tools/verify_theory_final.py --check
python3 tools/render_course_tree.py
python3 tools/render_course_tree.py --check
python3 improvements/86957/theory-final-review-2026-11-23/verify_preserved_whitespace.py --check
```

Стандартный `git diff --check` относительно базы обнаруживает девять строк с концевыми пробелами в пяти новых точных копиях старых C++-листингов. Эти байты уже находятся в закреплённых исходных `pre` и сохранены для точной связи с учебным кодом. [Узкое исключение](whitespace_exceptions.json) фиксирует пути, строки и SHA; `verify_preserved_whitespace.py` заново доказывает равенство исходникам и требует, чтобы и рабочая копия, и index давали ровно эти девять замечаний. Любое дополнительное замечание блокирует сохранение. Настройки Git и компиляционные проверки не ослаблялись. [Протокол](validation/preserved_whitespace.json).

Для повторного запуска старых наборов служит [recheck_examples.py](recheck_examples.py). Он требует две отдельные рабочие копии с HEAD `26bbfeb`: одну для T1–T6/продолжения, вторую для LINKS. В первой **только внутри изолированной копии** снимок `courses/86957` восстанавливается из `d96e5b9cffa65010c53894a9b65b1a497cb6b58a`: старый T1B проверяет отличие редакции от объявленной исходной базы. Основная ветка и опубликованный снимок от этого не меняются. Все старые verifier-ы и исходники остаются из `26bbfeb`; runner проверяет эти условия.

```sh
python3 improvements/86957/theory-final-review-2026-11-23/recheck_examples.py \
  --legacy-worktree /absolute/path/to/isolated-legacy \
  --links-worktree /absolute/path/to/isolated-links \
  --cmake /absolute/path/to/cmake --workers 2
```

Новые наборы запускаются через `examples/foundations/verify.py`, `examples/core/verify.py` и `examples/advanced/verify.py`. Повторный запуск создаёт новые датированные результаты и требует обновить их SHA в инвентарях, агрегате и принятии; старые отчёты нельзя молча выдавать за этот новый запуск.
