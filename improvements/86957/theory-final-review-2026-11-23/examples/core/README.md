# Повторная авторская проверка модулей 5–11

Новый независимый проход прочитал все **96 эффективных текстовых шагов**:
снимок курса с наложением уже подготовленных `theory-links`-правок. Состав и
контрольные суммы входов закреплены в `../../review_inputs.json`.

Изменено только объяснение в шаге **3177298**: два определения массива названы
независимыми фрагментами, инициализация отделена от присваивания. Оба листинга
сохранены без изменения. `array_variants.cpp` — авторская оболочка, которая
помещает их в отдельные области видимости; первый массив читается только после
присваивания всем его элементам. Второй вариант проверяется по суммам строк;
для уже существующего короткого примера неполной инициализации проверяются
нулевые незаданные элементы. Отдельная отрицательная проверка подтверждает,
что последовательное помещение двух определений в один блок не компилируется.

Четыре сохранённые полные программы из шагов **3212990** и **3212989** ранее
не имели точного соответствия исходникам в наборах T2/T3/T4/LINKS. Их копии
в этой папке побайтно совпадают с декодированными `pre`-блоками эффективных
текстов. Они впервые включены в этот адресный набор: проверяются перемещения
указателя внутри массива, чтение через указатель на `const`, изменение объекта
через другой допустимый путь и изменение объекта через константный указатель.
Отдельно проверяются ожидаемые отказы компиляции присваивания через указатель
на `const` и присваивания строкового литерала уже созданному массиву `char`
(сохранённый отрицательный фрагмент шага 3214873).

## Запуск

Из корня репозитория:

```sh
python3 improvements/86957/theory-final-review-2026-11-23/examples/core/verify.py
```

Нужны Python 3.10+ и GCC/G++ с C++17/C++20 и UBSan. Можно задать `CXX` как имя
одного исполняемого файла компилятора. Новые результаты сохраняются только в
`../../validation/new_core.json`; исторические отчёты не перезаписываются.

Для всех положительных программ включены `-Wall -Wextra -Wpedantic` и UBSan.
В сохранённом `const_pointer.cpp` переменная `b` нужна только для показанного
в комментарии запрещённого присваивания, поэтому GCC предупреждает о её
неиспользовании. Это предупреждение сохраняется в протоколе; точный исходник
не изменён ради подавления предупреждения. Авторская оболочка массива
дополнительно собирается с `-Werror`.

## Границы результатов

Эта проверка выполняет 10 успешных компиляций, 10 запусков и 6 ожидаемых
отказа компиляции в двух стандартах. Она не подменяет отдельный повторный
запуск T2/T3/T4/LINKS, который организуется интегратором в изолированной копии.
Адрес объекта в выводе зависит от выполнения: проверяются наличие адресной
части и значение `10`, а не фиксированное числовое представление адреса.

Все 125 блоков `pre` независимо учтены в `../../code_inventory_core.json`:
полные программы, компоненты многофайловых программ, фрагменты, ожидаемые
ошибки, вывод, команды и CMake. Наличие записи в инвентаре не означает, что
блок компилировался или выполнялся. Для каждого указана конкретная связь с
исходником/проверкой либо явно указано отсутствие такого соответствия.
Windows/MSVC и macOS в этом запуске не проверяются. Stepik не читается и не
изменяется; новых заданий учащимся нет.
