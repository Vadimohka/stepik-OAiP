Файловый поток: операции, состояние и время жизни

Выберите все верные утверждения о std::ifstream, std::ofstream и std::fstream. Имена in и out обозначают соответствующие потоки. Если не сказано иное, используется обычный файл и стандартная настройка потока: исключения через exceptions() не включены.

Ниже авторский порядок вариантов. Настройка перемешивания на Stepik сохранена.

  1. std::ofstream поддерживает форматированный вывод через <<, как std::cout.
  2. При обычном выходе из области видимости и при раскрутке стека деструктор локального std::ofstream вызывает закрытие связанного файла.
  3. Если out.is_open() вернул true, любая следующая запись в этот файл обязательно будет успешной.
  4. Чтобы проверить завершение записи, можно вызвать out.close(), а затем проверить состояние out.
  5. Успешный out.flush() гарантирует сохранность данных при внезапном отключении питания.
  6. Выражение out << 42 возвращает ссылку std::ostream& на тот же поток, поэтому операции вывода можно объединять в цепочку.
  7. Режимы std::ios::in и std::ios::out можно объединить оператором | для чтения и записи через std::fstream.
  8. В режиме std::ios::app вызов out.seekp(0) позволяет следующей записью заменить начало файла.
  9. Оператор return внутри функции пропускает деструкторы её локальных файловых потоков.
  10. Каждая операция out << значение гарантирует физическую запись данных на накопитель до возврата из оператора.

    Поток может буферизовать вывод; детали передачи данных зависят от реализации и среды. Ни отдельная операция <<, ни стандартный flush() не являются гарантией физической сохранности на накопителе.

Проверяем чтение, а не угадываем конец файла

Выберите все верные утверждения. Поток in успешно открыт на чтение и начинает работу в исправном состоянии; исключения через exceptions() не включены. line имеет тип std::string, value — int. В примерах со строками используется обычный вызов std::getline(in, line) с разделителем '\n'.

Ниже авторский порядок вариантов. Настройка перемешивания на Stepik сохранена.

  1. В цикле while (std::getline(in, line)) тело выполняется после успешного чтения очередной строки.
  2. Условие while (!in.eof()) само по себе гарантирует, что чтение внутри тела цикла даст очередное корректное значение.
  3. Для пустого файла первый вызов std::getline(in, line) считается успешным и даёт одну пустую строку.
  4. Если содержимое файла — один символ перевода строки '\n', первый успешный вызов std::getline даст пустую строку.
  5. Непустая последняя строка без завершающего '\n' всегда теряется при чтении через std::getline.
  6. В условии if (in >> value) тело if выполняется только после успешного чтения числа в value.
  7. Если файл открыт, проверять результат in >> value не нужно: неверный числовой текст превращается в корректное значение автоматически.
  8. Если после неудачного чтения числа in.eof() равно true, это всегда означает нормальное окончание ввода без ошибки данных.
  9. Установленный badbit после чтения указывает на серьёзную ошибку потока, которую нельзя считать обычным окончанием данных.
  10. Обычный вызов std::getline(in, line) сохраняет разделитель '\n' последним символом line.
Для преподавателя: ключ и обратная связь

  1. Верно. В цикле while (std::getline(in, line)) тело выполняется после успешного чтения очередной строки.
    Сначала вызывается std::getline, затем проверяется состояние возвращённого потока. Это связывает обработку данных с результатом конкретной операции чтения.
  2. Неверно. Условие while (!in.eof()) само по себе гарантирует, что чтение внутри тела цикла даст очередное корректное значение.
    eof() отражает уже обнаруженный конец ввода. Предыдущая проверка не предсказывает успех следующего чтения; возможны как конец файла, так и ошибка формата.
  3. Неверно. Для пустого файла первый вызов std::getline(in, line) считается успешным и даёт одну пустую строку.
    В пустом файле не извлекается ни символа, ни разделителя. Чтение завершается неуспешно, и тело цикла while (std::getline(...)) не выполняется.
  4. Верно. Если содержимое файла — один символ перевода строки '\n', первый успешный вызов std::getline даст пустую строку.
    Разделитель извлекается из потока, но не добавляется в line. Поэтому пустая строка в файле отличается от полного отсутствия данных.
  5. Неверно. Непустая последняя строка без завершающего '\n' всегда теряется при чтении через std::getline.
    Если перед концом файла прочитаны символы строки, std::getline возвращает её. Может быть установлен eofbit, но он сам по себе не означает неуспех операции.
  6. Верно. В условии if (in >> value) тело if выполняется только после успешного чтения числа в value.
    Оператор извлечения возвращает поток. Его проверка в условии учитывает failbit и badbit, поэтому обработка числа связана с успешным результатом чтения.
  7. Неверно. Если файл открыт, проверять результат in >> value не нужно: неверный числовой текст превращается в корректное значение автоматически.
    Открытие файла не проверяет его содержимое. Неподходящий токен или число вне диапазона int вызывает ошибку извлечения; полученное значение нельзя считать успешно прочитанными данными.
  8. Неверно. Если после неудачного чтения числа in.eof() равно true, это всегда означает нормальное окончание ввода без ошибки данных.
    Ошибка преобразования может произойти одновременно с достижением конца файла. Например, последний числовой токен может выходить за диапазон int. Одной проверки eof() недостаточно для подтверждения корректности данных.
  9. Верно. Установленный badbit после чтения указывает на серьёзную ошибку потока, которую нельзя считать обычным окончанием данных.
    Флаг badbit проверяется методом bad(). В учебном цикле после завершения чтения нужно отличать ошибку потока от ожидаемого конца файла и от ошибки формата.
  10. Неверно. Обычный вызов std::getline(in, line) сохраняет разделитель '\n' последним символом line.
    std::getline извлекает найденный разделитель из потока, но не сохраняет его в строке. Если при выводе нужен перевод строки, его добавляют явно.

Режим открытия и формат данных

Выберите все верные утверждения. Рассматриваем стандартные файловые потоки C++ и формат файла, который должен быть понятен программе чтения. Под переносимостью понимаем возможность обмена между реализациями, у которых могут различаться размеры типов и представление данных.

Ниже авторский порядок вариантов. Настройка перемешивания на Stepik сохранена.

  1. Даже если std::ofstream out открыт с std::ios::binary, выражение out << 42 по-прежнему выполняет форматированный вывод числа.
  2. Флаг std::ios::binary автоматически переводит все записываемые строки в UTF-8.
  3. Для корректного обмена текстом записывающая и читающая программы должны согласовать кодировку.
  4. Расширение имени .txt само заставляет std::ifstream игнорировать указанный режим std::ios::binary.
  5. Запись sizeof(T) байтов объекта структурного типа T всегда создаёт переносимый формат, если файл открыт в двоичном режиме.
  6. Побайтовая запись самого объекта std::string гарантированно сохраняет его текст так, что другой процесс сможет восстановить строку тем же дампом.
  7. При разработке собственного двоичного формата нужно описать порядок полей, границы записей и представление чисел.
  8. Текстовый формат тоже требует правил: например, разделителей полей и способа записи чисел.
  9. Если записать числовое значение указателя в файл, другой процесс сможет использовать его для доступа к тому же объекту.
  10. Версия собственного формата помогает читателю определить, какую схему записей нужно использовать; её тоже следует проверять.

    При развитии формата структура записей может измениться. Версия позволяет выбрать поддерживаемую схему или сообщить, что файл имеет неподдерживаемый формат.

std::move и константный источник

Что выведет программа? Рассматриваем C++17 или новее; создание векторов завершается успешно.

#include <iostream>
#include <utility>
#include <vector>

int main() {
    const std::vector<int> source{4, 5};
    std::vector<int> destination = std::move(source);
    destination[0] = 1;
    std::cout << source[0] << ' ' << destination[0] << '\n';
}

Выберите один верный ответ.

Ниже авторский порядок вариантов. Настройка перемешивания на Stepik сохранена.

  1. 4 1: destination получает независимую копию элементов source.
  2. 1 1: оба вектора после std::move используют одни и те же элементы.
  3. Программа не компилируется: std::move запрещено применять к константному объекту.
  4. Результат чтения source[0] нельзя предсказать: любой вызов std::move опустошает источник.
Для преподавателя: ключ и обратная связь

Верные варианты: 1. Это ключ авторского блока; фактическое оценивание платформы здесь не воспроизводится.

  1. Верно. 4 1: destination получает независимую копию элементов source.
    std::move(source) сохраняет const. Перемещающий конструктор вектора не принимает такой источник, но конструктор копирования принимает его по const&. Изменение копии не меняет исходный вектор.
  2. Неверно. 1 1: оба вектора после std::move используют одни и те же элементы.
    Копирование std::vector<int> создаёт независимые элементы. Присваивание destination[0] = 1 не изменяет source[0].
  3. Неверно. Программа не компилируется: std::move запрещено применять к константному объекту.
    std::move можно применять к константному объекту; const при этом сохраняется. Здесь доступен конструктор копирования вектора, поэтому программа корректна.
  4. Неверно. Результат чтения source[0] нельзя предсказать: любой вызов std::move опустошает источник.
    std::move сам не меняет объект. В этой программе выбирается копирование, поэтому source сохраняет оба элемента. Неуточнённое состояние после реально выполненного перемещения к этому случаю не относится.

Обратная связь при верном ответе: Верно: std::move сохраняет const, поэтому здесь создаётся независимая копия вектора.

Обратная связь при ошибке: Разделите приведение категории выражения и вызов конструктора: std::move сам не переносит элементы и не снимает const.
