  1. Неверно. После сортировки [2, 1, 2] должно получиться [1, 2]: одинаковые ключи нужно удалить.

    Нет. std::sort не обещает устойчивость. Для [(2, A), (1, X), (2, B)] порядок [(1, X), (2, B), (2, A)] не запрещён его контрактом. Используйте std::stable_sort либо исходный индекс как второй критерий.

    Верно. За первый проход нет обменов, поэтому флаг changed остаётся false и внешний цикл завершается. Это свойство именно реализации с ранней остановкой.
  5. Верно. Сортировка вставками, которая сдвигает только элементы со строго большим ключом, сохраняет порядок равных ключей.
    Верно. Новый элемент не перескакивает через равные ему элементы. Если заменить строгое сравнение на «больше или равно», устойчивость может исчезнуть.
  6. Неверно. При слиянии двух отсортированных частей для устойчивости нужно при равенстве ключей брать элемент правой части раньше элемента левой.
    Нет. Левая часть исходно находилась раньше правой. Для левой [(2, A)] и правой [(2, B)] выбор справа даст B, A и нарушит устойчивость. При равенстве нужно брать слева.
  7. Верно. Изученная рекурсивная сортировка слиянием с одним буфером из n элементов требует O(n) дополнительной памяти с учётом стека.
    Верно. Буфер занимает O(n), стек сбалансированной рекурсии — O(log n). Их сумма имеет порядок O(n). Речь о конкретной реализации урока.
  8. Неверно. Изученная итеративная сортировка кучей обязательно требует отдельного вспомогательного массива из n элементов.
    Нет. Эта реализация переставляет элементы внутри исходного массива и использует фиксированное число переменных: O(1) дополнительной памяти. В ней нет рекурсивного стека.
  9. Верно. Компаратор для сортировки по возрастанию, возвращающий left.key < right.key, возвращает false при равных ключах.
    Верно. Сортировочным алгоритмам нужен строгий порядок. Для равных ключей ни один не считается меньшим другого; знак «меньше или равно» для такого компаратора не подходит.
  10. Неверно. Если quicksort каждый раз выбирает минимальный элемент опорным, его худшее время всё равно равно O(n log n).
    Нет. Получаются части размеров 0 и n−1, затем 0 и n−2 и так далее. Сумма работы имеет порядок n². Это не противоречит гарантии std::sort: библиотечный алгоритм не обязан быть такой реализацией quicksort.

Очередь заявок: сортировка с сохранением порядка

Заявка состоит из двух целых чисел: priority (приоритет) и label (метка). Метка помогает различать заявки, но сама по себе не определяет их порядок и может повторяться.

Отсортируйте заявки по возрастанию приоритета. Заявки с одинаковым приоритетом должны идти в том же относительном порядке, в котором поступили во входных данных. Сохраните каждую заявку: даже полностью одинаковые строки нельзя удалять.

Входные данные

Первое число — n, количество заявок, 0 ≤ n ≤ 100000. Затем идут n пар priority label. Оба числа в каждой паре находятся в диапазоне от −1000000000 до 1000000000 включительно. Числа разделены пробельными символами.

Выходные данные

Выведите все n пар priority label в требуемом порядке; удобно печатать каждую пару на новой строке. Между числами допустимы любые пробельные символы. Если n = 0, вывод не должен содержать чисел.

Как хранить два значения вместе

Структуры подробно рассматриваются позже. Для этой задачи достаточно следующей заготовки: Record объединяет два поля, а обращение record.priority читает приоритет конкретной записи.

struct Record {
    int priority;
    int label;
};

bool by_priority(const Record& left, const Record& right) {
    return left.priority < right.priority;
}

const Record& передаёт запись в функцию без копирования и запрещает менять её через этот параметр. Функция отвечает, должен ли левый приоритет стоять раньше правого; при равных приоритетах она возвращает false.

Записи можно хранить в std::vector<Record> из <vector>. В <algorithm> есть std::stable_sort, сохраняющий порядок равных ключей. Другой подход — запомнить исходный номер каждой записи и применять std::sort с двумя критериями: сначала приоритет, затем исходный номер. Сортировка по метке как второму критерию условию не соответствует.

Разбор образца

У приоритета 1 метки поступили в порядке 9, 4, и этот порядок сохраняется. У приоритета 2 остаётся последовательность 30, 10, 30: повторная заявка не исчезает.

Проверьте контракт поиска

Выберите все верные утверждения. Индексы начинаются с нуля. В вопросах про двоичный поиск используется массив или std::vector<int>, отсортированный по неубыванию, а результатом служит индекс первого вхождения либо −1. Стоимость подготовки, проверки отсортированности и ввода-вывода учитывается отдельно от числа сравнений внутри поиска.

  1. Линейный поиск первого вхождения слева направо можно применять к неотсортированному массиву.
  2. Для изученного двоичного поиска по значению отсортированность массива по неубыванию — достаточное предусловие для любого запроса.
  3. Если std::lower_bound вернул итератор, отличный от end(), искомое значение обязательно найдено.
  4. В [1, 2, 2, 2, 5] первое вхождение 2 имеет индекс 3, если индексы начинаются с нуля.
  5. При контракте «индекс первого вхождения или −1» поиск в пустом массиве возвращает −1.
  6. Для неотрицательных представимых индексов left ≤ right середина left + (right − left) / 2 не требует вычислять потенциально переполняющуюся сумму left + right.
  7. Чтобы всегда найти первое вхождение, достаточно завершать двоичный поиск сразу после любого равенства a[middle] == x.
  8. Если перед каждым запросом сортировать массив, а затем выполнять двоичный поиск, вся обработка одного запроса гарантированно занимает O(log n) времени.

Первое вхождение: много запросов

Дана последовательность целых чисел, уже отсортированная по неубыванию. Для каждого запроса x найдите индекс первого вхождения x. Индексы начинаются с нуля. Если значения нет, выведите −1.

Например, в последовательности [1, 2, 2, 2, 5] первое вхождение 2 имеет индекс 1. Последующие одинаковые элементы не меняют ответ.

Входные данные

Сначала даны числа n и q: длина последовательности и количество запросов; 0 ≤ n ≤ 100000, 0 ≤ q ≤ 100000. Затем идут n элементов последовательности и q значений запросов. Все значения — целые числа от −1000000000 до 1000000000 включительно. Числа разделены пробельными символами. При n = 0 элементов последовательности нет: после n q сразу идут запросы.

Отсортированность гарантирована условием. Не нужно заново сортировать последовательность или проверять её отсортированность перед каждым запросом.

Выходные данные

Выведите ровно q ответов в порядке запросов: индекс первого вхождения либо −1. Удобно печатать каждый ответ на новой строке; любые пробельные разделители допустимы. При q = 0 вывод не должен содержать чисел. Для пустой последовательности ответ на каждый запрос — −1.

На что обратить внимание

Используйте двоичный поиск первого подходящего индекса на полуинтервале [left, right) или std::lower_bound из <algorithm> для std::vector<int>. Найденная граница ещё не означает, что значение существует: сначала убедитесь, что она не равна концу, затем проверьте равенство ключу.

Для одного запроса достаточно логарифмического числа сравнений; для всех запросов — O(q log(n + 1)). С учётом ввода последовательности и вывода ответов полный объём работы составляет O(n + q + q log(n + 1)). Такой подход подходит для верхних границ n и q.
