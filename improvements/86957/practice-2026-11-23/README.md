**Две задачи по программированию заменены по существу.** Их прежние условия, проверяющие программы и тесты полностью сохранены в `baseline/steps/`. Сохранение ID не означает неизменность учебного смысла задачи. Перед публикацией нужно учесть уже выставленные платформой результаты учащихся и проверить согласованность перехода на новое условие; этот пакет не переносит и не обнуляет прогресс.

Для новых задач алгоритмов необходимы объяснения из [пакета качества](../quality-2026-11-23/README.md): применять их следует вместе или после него. В задаче сортировки дан короткий вводный пример `struct` и обычной функции сравнения, поскольку подробный раздел структур находится дальше. Лямбда-выражения для решения не требуются. Допустимы как `std::stable_sort`, так и `std::sort` с исходным индексом в качестве второго критерия. В поиске можно написать двоичный поиск вручную или использовать `std::lower_bound`.

Первая задача остаётся упражнением на рассуждение и вывод. Она не объявляется проверкой навыка чтения входных данных: математический ответ не зависит от `A` и `B`, поэтому считывать их необязательно.

## Проверка заданий

В `graders/` лежат точные копии `source.code` двух новых задач. Генераторы детерминированы: **23 случая для сортировки и 22 для поиска**, включая верхние границы размера. `cases.json` фиксирует имена, назначение, размеры и SHA-256 входов и ответов. Полные большие тестовые файлы воспроизводятся командой проверки; дублировать их в репозитории не требуется.

В `examples/` находятся два независимых варианта решения каждой алгоритмической задачи и эталон первой программы. Авторская проверка:

- сравнивает ответы генератора с независимо построенным результатом;
- проверяет формат `generate/solve/check`, образцы, допустимые границы и обработку пробельных разделителей;
- компилирует эталоны в C++17 и C++20, выполняет все подготовленные случаи;
- требует отклонить 11 характерных неверных реализаций на случаях, не показанных в образцах;
- сверяет точные изменённые поля, ключи вопросов, исходные настройки и контрольные суммы;
- для шага 4643238 отдельно проверяет шаблоны C/C++, неизменность прежних тестов и ответы C++-эталона.

Команды из корня репозитория:

```bash
python3 tools/build_next_upgrade.py
python3 tools/verify_next_upgrade.py
```

Проверки этого пакета отдельно:

```bash
python3 improvements/86957/practice-2026-11-23/verify.py
python3 improvements/86957/practice-2026-11-23/verify_entry.py
```

Для сохранения точных тестовых файлов передайте `--testdata /абсолютный/путь` первому верификатору. Требуются Python 3.10+, GCC с C++17/20 и `gcc` для проверки сохранённого шаблона C. Протоколы: [алгоритмические задания](validation.json), [первая программа](validation_entry.json), [общий прогон обновления](../validation_next.json).

Эти результаты относятся к локальной проверке. Они не подтверждают версию компилятора, лимиты контейнера, начисление баллов или публикацию на Stepik. Идентификатор языка `c++` сохраняется в существующем формате платформы и сам по себе не является обещанием режима C++20. При переносе нужно проверить реальные отправки правильных и неверных решений, перечитать опубликованные блоки и только затем обновить снимок и статусы по [`AGENTS.md`](../../../AGENTS.md).
