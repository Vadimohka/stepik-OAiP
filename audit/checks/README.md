# Воспроизведение замечаний

Проверки относятся к снимку `6ecd4375ed2c4730feacd54f3be5b36670eb3ffe`.
Они фиксируют конкретные несоответствия и контрпримеры, а не доказывают корректность всех программ курса.

## Условия и сохранённые тесты

Из корня репозитория:

```bash
python3 audit/checks/verify_export_checks.py
```

Нужен Python 3 со стандартной библиотекой. Скрипт читает `courses/86957/course.json`, но **не исполняет код из экспорта**.
Он независимо вычисляет результаты и моделирует только явно проверенные операции сравнения строк.

[Сохранённый результат](export_checks_result.json) содержит:

- 11 наблюдений: округление, невыбранная ветвь с делением, перепутанные углы, пробелы перед переносами, нарушения диапазонов и алфавита, объединённые входные строки;
- 11 независимых расчётов для задач с суммарно 99 сохранёнными наборами; расхождений численных/текстовых токенов не найдено;
- отдельную оговорку для шага 4738986: чувствительность к финальному переносу подтверждена локально, предобработка stdout живым сервером Stepik не проверена.

Сравнение токенов в независимых расчётах проверяет содержательный результат. Оно не подтверждает правильность всех требований к пробелам и переводам строк; эти требования исследуются отдельно.

## Выбранные примеры C++

```bash
python3 audit/checks/reproduce_cpp.py
```

По умолчанию используется `g++`; другой исполняемый файл можно передать через `--compiler`.
Проверенная среда: **GCC 14.2.0, libstdc++, Linux x86_64**. В скрипте явно заданы C++11, C++17 или C++20 для каждой проверки.
Временные исполняемые файлы и тестовые файлы создаются в отдельном временном каталоге и удаляются после завершения.

[Сохранённый протокол](cpp_checks_result.json) содержит 14 проверок. Все ожидаемые результаты в указанной среде воспроизведены:

| Пример | Что подтверждено |
|---|---|
| `checks.cpp` | Режим `fstream`, число элементов `fread/fwrite`, тип результата `<<`, размеры структур в выбранном ABI, заполнение `union`, порядок базовых конструкторов, наследование конструктора, неявное перемещение, истёкший `weak_ptr`, раздельные блоки `deque`, `bad_cast` для ссылки |
| `avl.cpp` / `avl_fixed.cpp` | При удалении ключа 2 получается `3:two`; после копирования значения — `3:three` |
| `hash.cpp` / `hash_fixed.cpp` | После заполнения бакета пропускаются вставка и обновление: `1:first`; после удаления неверной проверки — `2:updated` |
| `motion.cpp` | Две равносильные формулы дают разные последние цифры при требуемом `setprecision(20)` |
| `long_float.cpp` | Тип `long float` отвергается |
| `wchar.cpp` | Вывод `wchar_t` в `cout` принимается в C++17 и отвергается в C++20 |
| `array_partial.cpp` | `int a[][2]={1,2,3};` корректен, последний элемент равен нулю |
| `new_char_braces20.cpp` | `new char[]{"Hello"}` корректен |
| `sum_digits.cpp` | Показанный в уроке цикл ошибочно даёт ноль для 1, 10 и 100 |
| `static_cast_reference.cpp` / `reinterpret_numeric.cpp` | Указанные преобразования `int → double&` и `double → unsigned long long` выбранными операторами недопустимы |

Исходники выбранных воспроизведений находятся в [cpp](cpp). Для AVL и хеш-таблицы добавлено минимальное окружение: определения узлов, списков и тестовый `main`. Исследуемые алгоритмические блоки взяты из курса; файлы `_fixed` отличаются только описанной правкой.

Некоторые наблюдения намеренно зависят от ABI: размеры типов, расположение элементов `deque`, последние цифры `long double`. На другой платформе скрипт может сообщить расхождение. Это не превращает наблюдённый размер в требование стандарта.

## Дополнительные протоколы

В [evidence](evidence) сохранены небольшие исходники и диагностические протоколы других адресных проверок. Часть файлов намеренно не компилируется: этим проверяется конкретная ошибка листинга. Исполняемые бинарные файлы в репозиторий не включены.

Опасные примеры с разыменованием недействительных указателей, несовместимым `delete` и чтением неактивного члена `union` **не запускались**. Их оценка опирается на указанные в реестре правила языка.

## Подозрения, которые не стали ошибками

- Шаг 3267786: вывод программы, изображённой на картинке, совпадает со строковым ключом.
- Шаг 4927308: пустой `test_cases` не означает отсутствие проверки. `generate()` задаёт 14 размеров магического квадрата, а checker проверяет свойства произвольного ответа.
- Шаг 3759927: условие прямо просит привести результат к образцу. Поэтому отличие пробелов исходной старой программы от образца само по себе не признано неверным эталоном.
- Шаг 3496771: в иллюстрации намеренно не показан символ `D`, а слово «римскую» взято в кавычки. Необычный ответ для 600 не объявлен доказанной ошибкой обычной римской записи; при обновлении задачи полезно явно определить алфавит и правила.

Отправки решений и изменение проверяющих функций на Stepik в этом проходе не выполнялись.
