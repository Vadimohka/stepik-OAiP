Массив: несколько значений одного типа

Пусть нужно хранить баллы четырёх учеников. Вместо четырёх отдельных переменных удобно использовать последовательность элементов одного типа. У каждого элемента есть индекс: для четырёх элементов это 0, 1, 2 и 3. Элементы массива расположены подряд; размер встроенного массива из четырёх int равен 4 * sizeof(int). Размер самого int зависит от реализации.

В C++ есть встроенные массивы и стандартные контейнеры. В этом уроке познакомимся с обоими способами хранения фиксированного числа элементов:

ЗаписьЧто означает
int values[4]{};Встроенный массив из четырёх нулей. Его размер не меняется.
std::array<int, 4> values{};Стандартный контейнер фиксированного размера. Он знает свой размер, поддерживает копирование и тоже содержит четыре нуля.

Для обычного C++ кода с заранее известным числом элементов удобно начинать со std::array. Подключается заголовок <array>; запись <int, 4> задаёт тип и количество элементов. Если количество выясняется во время работы программы, позже используем std::vector.

Полная программа. Цикл по диапазону перебирает значения по очереди, поэтому для суммы нам не нужен индекс.

#include <array>
#include <iostream>

int main() {
    const std::array<int, 4> scores{10, 20, 15, 5};
    int total{};
    for (int score : scores) {
        total += score;
    }
    std::cout << scores.size() << ' ' << total << '\n';
}

Результат: 4 50. Метод size() возвращает число элементов. const означает, что эту последовательность программа не изменяет.

Проверьте себя. Замените последний балл 5 на 0. Размер останется равен 4, а сумма станет 45. Значение элемента и количество элементов — разные характеристики.

Встроенные массивы нужны для понимания модели памяти и низкоуровневых интерфейсов; их правила разберём в следующих шагах. Они отличаются от правил std::array, поэтому далее будем явно указывать, о каком типе идёт речь.

Массивы в программировании

Терминология этого шага. Здесь рассматривается именно встроенный массив вида T a[N]. Контейнер std::array<T, N> имеет другой тип: он не преобразуется неявно в указатель и поддерживает копирование как целое значение.

Массив — это структура данных, представленная в виде группы ячеек одного типа, объединенных под одним единым именем. Массивы используются для обработки большого количества однотипных данных. Массив имеет собственный тип T[N]. Во многих выражениях он неявно преобразуется в указатель T* на первый элемент; например, в sizeof(a) и &a этого преобразования нет. Подробнее указатели рассмотрим в следующих модулях. Отдельная ячейка данных массива называется элементом массива. Элементами массива могут быть данные подходящего объектного типа; например, числа, указатели или объекты классов. Ограничения на тип элементов рассмотрены далее. Массивы могут иметь одно или несколько измерений. В зависимости от количества измерений массивы делятся на одномерные массивы, двумерные массивы, трёхмерные массивы и так далее до n-мерного массива. Чаще всего в программировании используются одномерные и двумерные массивы, поэтому мы рассмотрим только эти  массивы.

 

Массив является простейшим агрегатным типом. Он моделирует набор однотипных элементов, расположенных подряд в непрерывном отрезке памяти. Массивы в той или иной форме поддерживаются практически всеми языками программирования и неудивительно, что они появились в первых версиях C и затем стали частью C++.

Создание одномерного массива

Одномерный массив — последовательность элементов, к которым обращаются по одному индексу. У массива из 16 элементов допустимы индексы от 0 до 15.

Встроенный массив. В объявлении размер записывают после имени в квадратных скобках. Для обычного определения массива он должен быть положительной целочисленной константой времени компиляции.

int values[4]{};                   // четыре нуля
int scores[4]{10, 20, 15, 5};       // четыре заданных значения
int inferred[]{10, 20, 15, 5};      // размер 4 выведен из инициализатора
int partial[4]{1, 2};              // 1, 2, 0, 0

Это отдельные объявления, которые можно написать внутри функции. У локального массива int values[4]; без инициализатора элементы не инициализированы. Поэтому в новых примерах сразу задаём значения или используем пустые фигурные скобки.

Если n прочитано через std::cin, запись int values[n]; не является стандартным C++17/C++20. Даже const int count = n; не превращает введённое значение в константу времени компиляции. Некоторые компиляторы принимают такие массивы как расширение; для переносимой программы используйте std::vector.

std::array. Число элементов тоже задаётся при компиляции, но контейнер можно копировать и присваивать целиком. Полная программа показывает частичную инициализацию и независимую копию:

#include <array>
#include <iostream>

int main() {
    int raw[4]{1, 2};
    const std::array<int, 4> original{1, 2};
    std::array<int, 4> copy = original;
    copy[0] = 9;

    std::cout << raw[0] << ' ' << raw[3] << '\n';
    std::cout << copy[0] << ' ' << copy[3] << '\n';
}

Вывод:

1 0
9 0

Встроенные массивы нельзя присваивать друг другу оператором =; их элементы можно копировать циклом или подходящим стандартным алгоритмом. Для std::array обычное копирование контейнера выполняет копирование элементов.

Проверьте себя. Почему последнее значение равно 0? Потому что незаданные элементы int в инициализации списком получают нулевые значения. При пяти инициализаторах и размере 4 программа не скомпилируется.

Границы и обход массива

Если элементов N, индексы существующих элементов лежат в диапазоне 0 <= index && index < N. Последний индекс равен N - 1, а не N.

В C++17/C++20 выход за границы встроенного массива или std::array через [] имеет неопределённое поведение. Программа не обязана вывести сообщение или завершиться с ошибкой. Поэтому сначала проверяем индекс и только затем обращаемся к элементу.

Полная программа. Ввод — один целый индекс. Для допустимого индекса выводится элемент, для неверного ввода или индекса — INVALID. constexpr обозначает здесь константу времени компиляции.

#include <array>
#include <iostream>

int main() {
    constexpr int count = 4;
    const std::array<int, count> values{10, 20, 30, 40};
    int index{};
    if (!(std::cin >> index) || index < 0 || index >= count) {
        std::cout << "INVALID\n";
        return 0;
    }
    std::cout << values[index] << '\n';
}

Для ввода 0 получится 10, для 3 — 40, для -1 и 4 — INVALID. Проверка index < count не заменяет проверку index >= 0, когда индекс имеет знаковый тип.

Если индекс не нужен, проще использовать цикл по диапазону. Следующий фрагмент расположен внутри функции; заголовки <array> и <iostream> должны быть подключены:

std::array<int, 4> values{4, 3, 2, 1};
for (int value : values) {
    std::cout << value << ' ';
}

Так же можно обойти встроенный массив. Для встроенного массива стандартные функции std::begin(a) и std::end(a) из <iterator> обозначают начало и позицию после последнего элемента. Разыменовывать std::end(a) нельзя. Сам цикл по диапазону для массива не требует этих вызовов в исходном тексте.

У std::array есть метод at(index), который проверяет границу и при неверном индексе выбрасывает std::out_of_range. Обработку исключений изучим отдельно. Встроенный массив метода at не имеет.

Самопроверка. Проверьте первый индекс, последний, -1 и ровно число элементов. Эти четыре случая помогают обнаружить типичную ошибку <= вместо <.

Как выбрать среду и стандарт C++

Цель шага: получить набор инструментов, которым можно собрать и отладить учебную программу. Для начала достаточно одной удобной среды.

  1. Установите компилятор C++ и средства сборки для вашей ОС.
  2. Выберите IDE либо редактор с поддержкой этого компилятора.
  3. Проверьте сборку небольшой программы, а затем запуск отладчика.
  4. Сохраните команду сборки или настройки проекта, чтобы результат можно было повторить.

Для локальных практикумов курса выбираем C++20 явно: у GCC и Clang это -std=c++20, у MSVC — /std:c++20. IDE и компилятор имеют разные номера версий. Даже при выборе одного стандарта доступность отдельных библиотечных возможностей зависит от установленной реализации.

Большинство базовых примеров использует средства, доступные и в C++17. Если в примере нужна более новая возможность, её стандарт указан отдельно. Дополнения C++23 можно изучать после основы; переключать вводный проект на экспериментальный режим языка для прохождения уроков не требуется.

Задания Stepik: список языков и конфигурацию проверяющей системы смотрите в самом задании. Локальный флаг -std=c++20 не изменяет настройки Stepik и не подтверждает, что её компилятор поддерживает все возможности C++20. В решении используйте возможности выбранной проверяющей системы.

Для учебной работы полезны: переход к диагностике компилятора, понятный вывод программы, точки останова, просмотр переменных, форматирование и навигация по коду. Инструменты генерации сложных классов и другие расширенные функции можно освоить позднее.

Размер во время выполнения: std::vector и динамический массив

Если число элементов становится известно после ввода, фиксированный размер std::array не подходит. Для обычной C++ программы используйте std::vector из заголовка <vector>: он хранит последовательность, её размер и управляет памятью элементов.

Полная программа. Сначала читаем count от 0 до 1000, затем ровно столько целых значений от −109 до 109. Выводим количество и сумму. Ошибка чтения или выход значения за указанные границы даёт INVALID и ненулевой код завершения. При нуле элементов сумма равна 0.

#include <iostream>
#include <vector>

int main() {
    int count{};
    if (!(std::cin >> count) || count < 0 || count > 1000) {
        std::cout << "INVALID\n";
        return 1;
    }

    std::vector<long long> values;
    for (int i = 0; i < count; ++i) {
        long long value{};
        if (!(std::cin >> value) || value < -1000000000LL
                                || value > 1000000000LL) {
            std::cout << "INVALID\n";
            return 1;
        }
        values.push_back(value);
    }

    long long total{};
    for (long long value : values) {
        total += value;
    }
    std::cout << values.size() << ' ' << total << '\n';
}

push_back добавляет элемент в конец, size() возвращает текущее количество. Сумма может достигать 1012, поэтому используется long long. После выхода из области видимости контейнер освобождает свою память; отдельный delete[] не нужен. При раннем return уже созданный контейнер тоже уничтожается.

Для ввода 4 10 -5 20 3 получится 4 28. Проверьте также 0, один отрицательный элемент и неполный ввод. Предельные ограничения относятся к этому примеру; в каждой задаче нужно читать собственные ограничения.

Как устроено ручное выделение

Чтобы понимать низкоуровневый код, рассмотрим new[]. Это фрагмент внутри функции, а не рекомендуемый способ владения коллекцией в прикладном коде:

int* numbers = new int[4]{};  // четыре нуля
numbers[0] = 7;
// Используем только numbers[0] ... numbers[3].
delete[] numbers;             // соответствует new[]
numbers = nullptr;

new int[n] позволяет вычислить n во время выполнения. Полученный int* указывает на первый элемент при ненулевой длине; размер придётся хранить отдельно. Сам размер такого выделенного массива потом не меняется. Изменение размера vector при необходимости связано с получением другого блока памяти.

Инициализация встроенных динамических массивов:

int* a = new int[4];               // элементы не инициализированы
int* b = new int[4]();             // четыре нуля
int* c = new int[4]{1, 2, 3, 4};   // список значений, начиная с C++11
// Каждому успешному new[] должен соответствовать свой delete[].
delete[] a;
delete[] b;
delete[] c;

Это иллюстрация синтаксиса для успешных выделений: если один из последующих new[] выбросит исключение, предыдущие сырые указатели сами память не освободят. Контейнеры и другие владельцы с автоматическим освобождением помогают избежать такой ошибки.

Недостающие элементы int при инициализации списком заполняются нулями. Инициализаторов не должно быть больше длины массива; обнаружимое при компиляции несоответствие делает программу некорректной, а недопустимая вычисляемая длина обычного new[] может привести к std::bad_array_new_length.

Обычный new[] при нехватке памяти сообщает об ошибке исключением std::bad_alloc; вариант с std::nothrow рассматривается отдельно. Для vector выделение памяти также может завершиться исключением. Ни один способ не гарантирует, что в памяти поместится массив любого размера.

Правило пары: new T — delete, new T[n] — delete[]. Несовпадение пары, повторное удаление и обращение после освобождения имеют неопределённое поведение. Нельзя удалять через delete[] память, которой владеет vector.

Таблица: контейнер строк и массив указателей

Для таблицы с определяемыми во время выполнения размерами удобно использовать std::vector<std::vector<int>>: внешний контейнер хранит строки, каждая строка — свой контейнер элементов. Оба уровня сами освобождают память.

Полная программа. Создаём две строки по три нуля и меняем элемент с индексами [0][1]:

#include <cstddef>
#include <iostream>
#include <vector>

int main() {
    std::vector<std::vector<int>> matrix(2, std::vector<int>(3, 0));
    matrix[0][1] = 7;

    for (std::size_t row = 0; row < matrix.size(); ++row) {
        for (std::size_t column = 0; column < matrix[row].size(); ++column) {
            if (column != 0) {
                std::cout << ' ';
            }
            std::cout << matrix[row][column];
        }
        std::cout << '\n';
    }
}

Вывод:

0 7 0
0 0 0

У строк могут быть разные длины, поэтому внутренний цикл использует matrix[row].size(). Элементы каждой отдельной строки vector<int> расположены подряд, но разные строки не обязаны образовывать один непрерывный прямоугольный блок памяти. Если алгоритму нужен именно такой блок, используют один вектор и индекс row * columns + column с проверкой размеров и индексов.

Конструктор std::vector<int>(3, 0) создаёт три нуля. Внешний конструктор создаёт две независимые копии этой строки. Круглые скобки здесь задают количество и значение; фигурные скобки у vector<int> могут означать список самих элементов.

В показанной схеме предполагается успех всех выделений: если создание очередной строки выбросит исключение, ранее выделенные строки и массив указателей нужно освободить отдельно. Поэтому для рабочих решений выше используется контейнер с автоматическим управлением ресурсом.

Выбор хранения и три важных свойства vector

Начинайте с вопроса о задаче, а не о способе вызова аллокатора:

Владение текстовой строкойstd::string, которую подробно изучим в модуле о строках

Контейнер владеет своим ресурсом: его уничтожение освобождает занятую память. Такой подход относится к RAII — время владения ресурсом связано со временем жизни объекта. Умные указатели для отдельных динамических объектов рассмотрим в специальном модуле.

1. size и capacity — разные числа

size() — число существующих элементов. capacity() — сколько элементов можно разместить без нового выделения памяти. reserve(n) резервирует ёмкость, но не создаёт элементы. resize(n) меняет число элементов: при увеличении vector<int> без второго аргумента новые элементы получают нули.

Полная программа.

#include <iostream>
#include <vector>

int main() {
    std::vector<int> values;
    values.reserve(8);
    std::cout << values.size() << ' ' << (values.capacity() >= 8) << '\n';

    values.resize(3);
    values[2] = 7;
    std::cout << values.size() << ' ' << values[2] << '\n';

    std::vector<int> copy = values;
    copy[0] = 1;
    std::cout << values[0] << ' ' << copy[0] << '\n';
}

Вывод:

0 1
3 7
0 1

После reserve(8) размер ещё равен 0: обращаться к values[0] нельзя. Точная ёмкость зависит от реализации, поэтому программа проверяет только capacity() >= 8. После resize(3) существуют три элемента.

2. Копия контейнера владеет своими элементами

В примере изменение copy[0] не меняет values[0]. Копирование vector<int> копирует элементы; это отличается от копирования сырого указателя, когда два указателя обозначают одну область памяти.

3. Адрес элемента может стать недействительным

При перераспределении памяти вектора все прежние указатели, ссылки и итераторы на его элементы становятся недействительными. Это может случиться при push_back, если прежней ёмкости недостаточно. Не сохраняйте адрес элемента через операции изменения контейнера, не проверив правила инвалидирования для конкретной операции. Сам контейнер продолжает существовать; получить новый адрес можно после операции.

Самопроверка. Что изменится при замене resize(3) на reserve(3)? Элементы не появятся, и последующее values[2] = 7 станет недопустимым. Такой ошибочный вариант запускать не нужно: нарушение следует из size() == 0.

Где остаются new, delete и функции C

Ручное выделение нужно понимать для низкоуровневых интерфейсов и реализации владельцев ресурсов. Соблюдайте пары: new/delete, new[]/delete[], успешные malloc/calloc/realloc и free. Смешивать эти семейства для одного выделенного блока нельзя.

new создаёт объект C++, а delete вызывает его деструктор и освобождает выделенную память. Функции malloc и free не выполняют вызовы конструкторов и деструкторов классов. Поэтому ими нельзя заменить обычное создание и уничтожение std::string или std::vector.

Обычный new при неудаче выделения выбрасывает исключение; функции выделения C возвращают нулевой указатель. Выбор API сам по себе не доказывает преимущество в скорости: результат зависит от реализации, типов и операций программы.

std::string: владение строкой и чтение текста

std::string из заголовка <string> хранит последовательность элементов char, знает её длину и управляет памятью. Обычно для текстовых данных в C++ начинайте с этого типа. Копирование создаёт самостоятельное строковое значение, а уничтожение строки освобождает её ресурс.

В отличие от C-строки, содержимое std::string может включать нулевой символ внутри последовательности. Для передачи в интерфейс, ожидающий C-строку, есть метод c_str(); правила его использования рассмотрим далее.

Полная программа. Прочитаем целую строку, сохранив пробелы. Сначала выведем её размер, затем сам текст:

#include <iostream>
#include <string>

int main() {
    std::string text;
    if (!std::getline(std::cin, text)) {
        return 1;
    }
    std::cout << text.size() << '\n' << text << '\n';
}

std::getline читает до перевода строки, удаляет этот разделитель из потока и не добавляет его в результат. Пустая строка, завершённая переводом строки, — допустимый ввод с размером 0. Конец ввода без прочитанных символов — неуспех чтения; программа возвращает 1.

std::cin >> text удобно для одного слова: при обычных настройках потока начальные пробельные символы пропускаются, а чтение заканчивается перед следующим пробельным символом. Поэтому для имени Ada Lovelace нужен getline, если имя должно остаться одной строкой.

Когда перед строкой прочитано число

После std::cin >> group перевод строки обычно остаётся во входном потоке. Если формат требует число на первой строке и текст на следующей, остаток первой строки нужно отбросить:

#include <iostream>
#include <limits>
#include <string>

int main() {
    int group{};
    if (!(std::cin >> group)) {
        return 1;
    }
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');

    std::string name;
    if (!std::getline(std::cin, name)) {
        return 1;
    }
    std::cout << group << '\n' << name << '\n';
}

ignore здесь пропускает остаток первой строки до ' ' включительно. Это соответствует указанному формату и сохраняет пробелы и пустую строку во второй. Не используйте этот приём, если нужный текст должен находиться на той же строке, что и число.

Вариант std::getline(std::cin >> std::ws, name) решает другую задачу: std::ws пропускает все начальные пробельные символы. Он также пропустит пустые строки и ведущие пробелы, поэтому не подходит, когда они значимы.

Самопроверка. В первой программе проверьте обычную строку, пустую строку и строку с пробелами в начале. Во второй — число 7, затем пустую строку. Программа должна сохранить пустое имя, а не искать следующую непустую строку.

Создание строки: значение, копия и повторение

Выбирайте конструктор по смыслу задачи. std::string empty; создаёт пустую строку. Строковый литерал задаёт начальное содержимое, копирование другой строки создаёт независимое значение.

Полная программа.

#include <iostream>
#include <string>

int main() {
    const std::string source = "abcdef";
    std::string empty;
    std::string copy = source;
    copy[0] = 'A';
    const std::string repeated(3, 'x');
    const std::string one_character(1, 'x');
    const std::string part(source, 1, 2);

    std::cout << empty.empty() << '\n';
    std::cout << source << '\n' << copy << '\n';
    std::cout << repeated << '\n' << one_character << '\n' << part << '\n';
}

Вывод:

1
abcdef
Abcdef
xxx
x
bc
  • empty.empty() возвращает true; без std::boolalpha это печатается как 1.
  • Изменение copy[0] не меняет source. Индекс 0 допустим, потому что копия непуста.
  • std::string repeated(3, 'x') создаёт три одинаковых символа. Для одного символа можно написать std::string one_character(1, 'x').
  • std::string part(source, 1, 2) копирует до двух элементов, начиная с индекса 1. Здесь получается bc. Начальная позиция не должна превышать размер исходной строки; иначе выбрасывается std::out_of_range.

В форме «количество, символ» используйте показанные круглые скобки. Фигурные скобки могут выбрать другой конструктор, поэтому механическая замена (3, 'x') на {3, 'x'} меняет смысл.

Строку можно создать из корректной C-строки: const char* text = "Hello";, затем std::string message(text);. Такой конструктор читает до первого нулевого символа, поэтому указатель должен обозначать доступную строку с завершающим нулём. Пустая строка и нулевой указатель — разные вещи.

Проверьте себя. Замените количество 3 на 0 в конструкторе repeated. Получится пустая строка; конструктор не требует хотя бы одного элемента.

Работа со строкой: поиск, границы и длина

Полная программа. Ввод — одна строка вида ключ:значение. Разделим её по первому двоеточию и выведем две части на отдельных строках. Пустая часть допустима; если двоеточия нет, выведем NO_SEPARATOR.

#include <iostream>
#include <string>

int main() {
    std::string text;
    if (!std::getline(std::cin, text)) {
        return 1;
    }
    const auto position = text.find(':');
    if (position == std::string::npos) {
        std::cout << "NO_SEPARATOR\n";
        return 0;
    }
    const std::string key = text.substr(0, position);
    const std::string value = text.substr(position + 1);
    std::cout << key << '\n' << value << '\n';
}

Для name:Ada Lovelace выводятся строки name и Ada Lovelace. Для key: вторая строка пустая. Для a:b:c значение равно b:c: find находит первое вхождение.

Когда образец не найден, find возвращает std::string::npos. Проверяем это значение до прибавления 1 и вызова substr. Тип позиции беззнаковый; auto сохраняет возвращаемый тип и не сужает его до int.

Границы

Для обращения к символам содержимого используйте индексы меньше size(). Метод at(pos) проверяет эту границу и выбрасывает std::out_of_range при pos >= size(). У std::string::operator[] есть отдельное правило: позиция, равная size(), обозначает завершающий нулевой символ; это не элемент текстового содержимого, и записывать туда ненулевое значение нельзя. Индекс больше size() недопустим. Правила std::array и std::vector отличаются: у них индекс, равный размеру, уже за границей.

Не вычисляйте последний индекс пустой строки как size() - 1: беззнаковое вычитание даёт большое значение. Для полного обхода достаточно цикла по диапазону; для back() сначала нужно убедиться, что строка непуста.

UTF-8: длина в байтах и длина текста

std::string сама не распознаёт кодировку и не считает буквы. Если в ней хранится UTF-8, size(), индексы и позиции substr относятся к байтам UTF-8. Буква, а тем более воспринимаемый человеком символ, может занимать несколько байтов. Поэтому побайтовое переворачивание или обрезка по произвольному индексу могут повредить текст. Для алгоритмов по буквам Unicode нужен отдельный разбор кодировки и подходящая библиотека; в задачах этого модуля с ограничением на латинские ASCII-буквы достаточно обычных операций std::string.

Самопроверка. Проверьте строки без двоеточия, только с двоеточием, с пустой правой частью и с двумя двоеточиями. Для каждой заранее запишите ожидаемый результат.

c_str, data и указатели C

S.c_str() возвращает const char* на внутренний буфер с завершающим нулём. Изменять строку через него нельзя. Внутренний нулевой символ завершит строку для обычной функции C, хотя S.size() учитывает и последующее содержимое.

С C++17 data() у неконстантной строки возвращает char*: можно менять существующие элементы с индексами меньше size(), но нельзя менять размер или писать за границы. У константной строки возвращается const char*. Завершающий символ должен оставаться нулём.

Указатели и ссылки на символы зависят от времени жизни строки и могут стать недействительными после её изменения, например конкатенации. Не возвращайте c_str() локальной строки и не освобождайте буфер через delete[]: им владеет сама строка.

Отдельная перегрузка: S.find(ptr, pos, count) принимает const char* ptr и ищет первые count доступных символов по этому адресу, включая нулевые, если они входят в этот диапазон. Объект std::string T вместо ptr сюда не подходит. Форма S.find(ptr, pos) без количества ожидает C-строку с завершающим нулём.

Цель шага: различать рабочие файлы, подготовленные изменения и сохранённую версию. Git — распределённая система контроля версий: обычный локальный репозиторий хранит историю проекта, поэтому коммиты и просмотр истории доступны без подключения к серверу.

Собираем первую программу с CMake

После этого шага вы сможете собрать одну программу из терминала, явно выбрать стандарт C++ и найти исполняемый файл. Нужны три отдельных инструмента: CMake, компилятор C++ и выбранная система сборки, например Make, Ninja или MSBuild. Установка одного CMake не устанавливает автоматически все остальные компоненты.

Установите CMake версии 3.22 или новее по официальной инструкции или через пакетный менеджер своей ОС. Команда cmake --version показывает установленную версию.

Создайте пустую папку проекта и два файла. Содержимое main.cpp:

#include <iostream>

int main() {
    std::cout << "Hello C++\n";
}

Содержимое CMakeLists.txt:

cmake_minimum_required(VERSION 3.22)
project(FirstProgram LANGUAGES CXX)

set(SOURCES main.cpp)
add_executable(hello ${SOURCES})
set_target_properties(hello PROPERTIES
    CXX_STANDARD 20
    CXX_STANDARD_REQUIRED YES
    CXX_EXTENSIONS NO
)

if(MSVC)
    target_compile_options(hello PRIVATE /W4 /permissive-)
elseif(CMAKE_CXX_COMPILER_ID MATCHES "GNU|Clang")
    target_compile_options(hello PRIVATE -Wall -Wextra -Wpedantic)
endif()
  • add_executable создаёт цель сборки hello. Здесь переменная SOURCES содержит имя одного исходного файла, а ${SOURCES} подставляет её значение.
  • Свойства цели задают C++20, запрещают незаметно понижать запрошенный стандарт и отключают запрос расширенного диалекта компилятора. Поддержка отдельных возможностей языка и библиотеки всё равно зависит от установленного компилятора.
  • Предупреждения задаются для конкретной цели через target_compile_options. Флаги GCC/Clang и MSVC различаются; при другом компиляторе нужно посмотреть его документацию. Предупреждения помогают обнаруживать ошибки, но не доказывают правильность программы.

При использовании Make или Ninja выполните из папки с CMakeLists.txt:

cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build

Первая команда настраивает проект и сохраняет служебные файлы в отдельную папку build. Вторая запускает компиляцию и компоновку. Debug — конфигурация, удобная для отладки. Для генератора Visual Studio конфигурацию выбирают на этапе сборки:

cmake -S . -B build
cmake --build build --config Debug

В Linux/macOS при Make или Ninja программа обычно запускается командой ./build/hello. В PowerShell при генераторе Visual Studio — .\build\Debug\hello.exe. Расположение зависит от генератора и настроек. Ожидаемый вывод:

Hello C++

Модульные тесты: проверяем поведение функции

Модульный тест вызывает небольшую часть программы с известными входными данными и сравнивает фактический результат с ожидаемым. Например, функцию подсчёта можно проверить без ручного ввода в консоль. Проверка запуска всей программы и её формата ввода-вывода — отдельная задача.

В этом уроке мы сначала найдём эффективный алгоритм, затем выделим его в функцию и проверим её автоматически. Приложение и тесты будут использовать одну и ту же реализацию. Если скопировать формулу в тест, ошибка может появиться в обеих копиях, а исправление одной копии не изменит другую.

У каждой функции нужен контракт: допустимые входы и ожидаемый результат. Тесты должны включать обычные значения и границы этого контракта. Перед запуском сначала вычислите ожидаемые ответы самостоятельно.

Для первой проверки достаточно стандартной библиотеки и отдельной тестовой программы. Затем CTest позволит запускать её одной командой. Более крупные проекты часто используют библиотеку GoogleTest: она предоставляет именованные тесты, проверки EXPECT_*/ASSERT_* и удобные сообщения об ошибках. Библиотека не привязана к Visual Studio.

Цель урока: собрать приложение и тесты, увидеть успешную проверку, намеренно вызвать её отказ и объяснить, какую ошибку тест обнаружил. Успешные тесты подтверждают проверенные случаи, но сами по себе не доказывают правильность для всех входных данных.

От перебора к формуле и отдельной функции

Пусть число заканчивается ровно k девятками. При прибавлении единицы они превращаются в нули, а соседний разряд увеличивается на один; если разряда не было, появляется ведущая единица. Поэтому сумма цифр меняется на 1 − 9k. Она уменьшается тогда и только тогда, когда k ≥ 1, то есть последняя цифра исходного числа — девятка.

Подходящие числа: 9, 19, 29, …. Среди чисел от 1 до n включительно их ровно (n + 1) / 10, где деление целочисленное. Для n = 8 ответ 0, для 9 и 10 — 1, для 19 — 2. Формула выполняет постоянное число арифметических операций, в отличие от перебора всего интервала.

Оптимизация меняет способ вычисления ради эффективности. Рефакторинг меняет внутреннюю структуру с сохранением наблюдаемого поведения. Далее выделим вычисление из консольной программы, чтобы вызывать его и из приложения, и из тестов.

Создайте в одной папке три файла. interesting.hpp содержит объявление функции и её предусловие. Для локальной функции дополнительно разрешим n = 0: в пустом интервале ответ равен нулю. В задании Stepik граница остаётся 1 ≤ n ≤ 109.

#ifndef INTERESTING_HPP
#define INTERESTING_HPP

// Precondition: 0 <= interval_end <= 1'000'000'000.
long long CountInterestingInInterval(long long interval_end);

#endif

Файл interesting.cpp — единственное определение алгоритма:

#include "interesting.hpp"

long long CountInterestingInInterval(long long interval_end) {
    return (interval_end + 1) / 10;
}

Тип long long позволяет представить все значения заявленного диапазона и промежуточное n + 1. За пределами предусловия функция здесь не проверяется; этот контракт не следует расширять без анализа переполнения.

Файл main.cpp отвечает за ввод и вывод:

#include "interesting.hpp"
#include <iostream>

int main() {
    long long n{};
    if (!(std::cin >> n) || n < 1 || n > 1'000'000'000) {
        std::cerr << "Expected an integer from 1 to 1000000000\n";
        return 1;
    }
    std::cout << CountInterestingInInterval(n) << '\n';
}

Приложение читает одно целое число из диапазона задания и выводит только ответ. При неудачном чтении или недопустимом значении оно сообщает об ошибке в std::cerr и завершает работу с кодом 1.

Первые автоматические тесты и CTest

В папку с interesting.hpp, interesting.cpp и main.cpp добавьте tests.cpp. В нём нет второй копии формулы: тесты подключают заголовок и вызывают функцию из того же interesting.cpp, что и приложение.

#include "interesting.hpp"
#include <iostream>

bool Check(long long input, long long expected) {
    const long long actual = CountInterestingInInterval(input);
    if (actual == expected) {
        return true;
    }
    std::cerr << "n=" << input << ": expected " << expected
              << ", got " << actual << '\n';
    return false;
}

int main() {
    int failures = 0;
    failures += !Check(0, 0);
    failures += !Check(1, 0);
    failures += !Check(8, 0);
    failures += !Check(9, 1);
    failures += !Check(10, 1);
    failures += !Check(18, 1);
    failures += !Check(19, 2);
    failures += !Check(20, 2);
    failures += !Check(99, 10);
    failures += !Check(100, 10);
    failures += !Check(880'055'535, 88'005'553);
    failures += !Check(999'999'999, 100'000'000);
    failures += !Check(1'000'000'000, 100'000'000);
    if (failures != 0) {
        return 1;
    }
    std::cout << "13 checks passed\n";
}

Check возвращает true, если результат совпал. Выражение !Check(...) даёт true при ошибке и при сложении увеличивает счётчик на единицу. Неудачная проверка печатает вход, ожидаемое и фактическое значения. Ненулевой код завершения сообщает системе запуска, что тесты провалились.

Значения 8, 9, 10 и 18, 19, 20 проверяют переход через последнюю цифру 9; 99 и 100 — перенос через несколько разрядов. Есть пустой интервал для локального контракта, минимальный вход задания и большие границы. Ожидаемые ответы записаны явно, а не вычисляются копией проверяемой формулы.

Здесь используются обычные условия, поэтому проверки работают и в сборке Release. Стандартный макрос assert может быть отключён при определении NDEBUG; он не подходит для таких обязательных проверок без контроля настроек.

Добавьте CMakeLists.txt:

cmake_minimum_required(VERSION 3.22)
project(InterestingNumbers LANGUAGES CXX)

add_library(interesting interesting.cpp)
add_executable(interesting_app main.cpp)
target_link_libraries(interesting_app PRIVATE interesting)

include(CTest)
if(BUILD_TESTING)
    add_executable(interesting_tests tests.cpp)
    target_link_libraries(interesting_tests PRIVATE interesting)
    add_test(NAME InterestingNumbers COMMAND interesting_tests)
endif()

set(learning_targets interesting interesting_app)
if(BUILD_TESTING)
    list(APPEND learning_targets interesting_tests)
endif()
foreach(target IN LISTS learning_targets)
    set_target_properties(${target} PROPERTIES
        CXX_STANDARD 20
        CXX_STANDARD_REQUIRED YES
        CXX_EXTENSIONS NO
    )
    if(MSVC)
        target_compile_options(${target} PRIVATE /W4 /permissive-)
    elseif(CMAKE_CXX_COMPILER_ID MATCHES "GNU|Clang")
        target_compile_options(${target} PRIVATE -Wall -Wextra -Wpedantic)
    endif()
endforeach()

Цель interesting содержит общий код. target_link_libraries связывает с ним приложение и тесты. include(CTest) вводит настройку BUILD_TESTING; add_test регистрирует тестовый исполняемый файл. CTest учитывает код завершения: 0 — успех, ненулевой — отказ.

Для Make или Ninja выполните:

cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure --no-tests=error

Для многоконфигурационного генератора Visual Studio:

cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure --no-tests=error

Сначала выполните сборку: обычный запуск ctest сам не пересобирает изменённые исходники. Здесь CTest запускает одну тестовую программу, а внутри неё выполняются 13 проверок. Для просмотра вывода успешного теста добавьте -V; он напечатает 13 checks passed. Параметр --no-tests=error помогает заметить ситуацию, когда тесты вообще не были зарегистрированы.

Фрагмент для проекта с подключённым GoogleTest

Ниже содержимое отдельного файла gtest_assertions.cpp. Он использует объявление из interesting.hpp и ту же реализацию из interesting.cpp, что и приложение. Это не самостоятельная программа: ей нужны GoogleTest и отдельная цель сборки, показанная далее. GTest::gtest_main предоставляет точку входа; не добавляйте в эту цель прежний tests.cpp с собственным main. Готовая цель interesting_tests из предыдущего шага остаётся отдельным практикумом.

#include "interesting.hpp"
#include <gtest/gtest.h>
#include <string>

TEST(InterestingNumbers, HandlesCarryBoundary) {
    EXPECT_EQ(0LL, CountInterestingInInterval(8));
    EXPECT_EQ(1LL, CountInterestingInInterval(9));
    EXPECT_EQ(1LL, CountInterestingInInterval(10));
}

TEST(StringComparisons, ComparesContents) {
    const std::string text{"cpp"};
    EXPECT_EQ(std::string{"cpp"}, text);

    const char expected[] = "cpp";
    const char actual[] = "cpp";
    EXPECT_STREQ(expected, actual);
}

Первый тест содержит три независимые проверки функции на границе переноса разряда. InterestingNumbers — имя набора, HandlesCarryBoundary — имя теста. Оба имени — допустимые идентификаторы C++; согласно рекомендациям GoogleTest выбираем имена без подчёркиваний.

Второй тест иллюстрирует выбор сравнения. Для std::string подходит EXPECT_EQ: сравнивается содержимое строк. Для C-строк, то есть нуль-терминированных последовательностей char, содержимое сравнивает EXPECT_STREQ (или ASSERT_STREQ). Обычное сравнение двух указателей через EXPECT_EQ проверяет адреса. Два разных массива могут содержать одинаковый текст и иметь разные адреса.

К проверке можно добавить пояснение, например EXPECT_EQ(1LL, CountInterestingInInterval(9)) << "carry at 9";. Оно появится в сообщении при отказе. Держите ожидание независимым от реализации: вычислять обе стороны одной и той же формулой не полезнее, чем сравнивать результат с собой.

Если нескольким тестам понадобится одинаковая подготовка, позже можно изучить тестовые фикстуры — классы с общей настройкой. Для текущих проверок они не требуются. Подробности: GoogleTest Primer и справочник проверок.

std::move, std::forward и правило нуля

Цель: отличать разрешение на перемещение от самого переноса ресурса, не угадывать состояние перемещённого объекта и использовать готовые типы для управления ресурсами.

Что делает std::move

std::move из заголовка <utility> приводит выражение к rvalue-ссылке. Для обычного объекта результат — xvalue: выражение, из которого разрешено перемещать. Сам вызов не переносит данные, не освобождает память и не завершает время жизни объекта. Дальше разрешение перегрузки выбирает доступный конструктор, присваивание или другую функцию; возможны перемещение, копирование или ошибка компиляции.

В записи destination = std::move(source); перемещающее присваивание, если оно выбрано, выполняет работу. У именованной переменной source выражение без std::move является lvalue. Применяйте перемещение, когда прежнее содержимое источника больше не требуется. Оно не гарантирует ускорения: стоимость зависит от типа и операции. Кроме того, std::move не снимает const; из константной строки или вектора обычно получается копирование, если оно доступно.

Правило нуля (Rule of Zero)

Если поля класса сами корректно управляют своими ресурсами, обычно не нужно писать собственные деструктор, конструкторы копирования и перемещения или операторы присваивания. Неявные операции работают с полями согласно их типам. Например, std::string и std::vector уже умеют копировать, перемещать и освобождать свои данные.

Полная программа: копия изменяется независимо, а ресурс источника затем передаётся другому объекту.

#include <iostream>
#include <string>
#include <utility>
#include <vector>

struct Group {
    std::string name;
    std::vector<int> scores;
};

int main() {
    Group source{"A", {4, 5}};
    Group copy = source;
    copy.scores[0] = 1;

    Group destination = std::move(source);
    std::cout << copy.scores[0] << ' ' << destination.scores[0] << '\n';
    std::cout << destination.name << ' ' << destination.scores.size() << '\n';

    source = Group{"B", {3}};
    std::cout << source.name << ' ' << source.scores[0] << '\n';
}

Вывод:

1 4
A 2
B 3

В Group нет собственных специальных функций. Изменение копии не меняет исходный вектор. После перемещения поля source — стандартные строка и вектор — остаются в корректном, но в общем случае неуточнённом состоянии. Поэтому программа не предполагает их конкретные длины и не обращается к элементам. Она сначала присваивает source новое значение и только затем читает его. Для пользовательского класса гарантии определяются его реализацией и инвариантами.

Правило нуля не означает, что любой класс копируем. Например, поле std::unique_ptr делает копирование содержащего его класса недоступным, если его специально не реализовать; передача владения перемещением при этом может оставаться доступной.

std::forward: сохранение категории аргумента

Этот подраздел использует шаблоны функций. В template<class T> void relay(T&& argument), где T выводится при вызове, параметр — перенаправляющая ссылка. Имя argument внутри функции само является lvalue. std::forward<T>(argument) сохраняет исходную категорию: lvalue передаётся как lvalue, rvalue — как rvalue. T здесь аргумент шаблона, а argument — аргумент функции.

#include <iostream>
#include <utility>
#include <vector>

void inspect(const std::vector<int>& values) {
    std::cout << "const lvalue reference: " << values.size() << '\n';
}

void inspect(std::vector<int>&& values) {
    std::cout << "rvalue reference: " << values.size() << '\n';
}

template<class T>
void relay(T&& argument) {
    inspect(std::forward<T>(argument));
}

int main() {
    std::vector<int> values{1, 2, 3};
    relay(values);
    relay(std::vector<int>{4, 5});
    relay(std::move(values));
    std::cout << "still present: " << values.size() << '\n';
}

Вывод:

const lvalue reference: 3
rvalue reference: 2
rvalue reference: 3
still present: 3

В последнем вызове relay используется std::move(values), но выбранная inspect только читает размер. Никто не перемещает вектор в другой объект, поэтому его содержимое сохраняется. Ни std::move, ни std::forward сами по себе не обещают экономию копирования.

Продолжительность хранения и время жизни объекта

Цель: различать сам объект-владелец и управляемую им память, выбирать обычное локальное значение, когда динамическое владение не требуется.

Storage duration — продолжительность хранения: свойство, определяющее минимальный потенциальный срок существования памяти объекта. Время жизни объекта связано с его инициализацией и уничтожением. Эти понятия не тождественны: наличие области памяти само по себе не означает, что в ней уже живёт пригодный для использования объект.

Четыре вида продолжительности хранения

  • Автоматическая. Обычные локальные переменные и параметры функций. Полностью построенный локальный объект уничтожается при выходе из своего блока, в том числе при return или раскрутке стека до обработчика исключения. Такое хранение часто реализовано через стек, но стандарт не требует конкретного физического размещения.
  • Статическая. В частности, переменные пространства имён и локальные переменные с static. Их память сохраняется в течение программы. Это не означает, что вся инициализация происходит в самом начале: локальный static с динамической инициализацией инициализируется при первом прохождении через объявление.
  • Потоковая. Переменные с thread_local: свой экземпляр для каждого потока, а память связана с продолжительностью его выполнения. Построенные экземпляры уничтожаются при завершении потока.
  • Динамическая. Память выделяется во время работы программы; обычный new создаёт динамический объект, а соответствующий delete уничтожает его и освобождает память. В прикладном коде этими действиями обычно управляет готовый владеющий тип, например контейнер или умный указатель.

Сначала обычное значение

Для отдельного значения в функции обычно достаточно int count{0}; или Record record{};. Для изменяемой последовательности подходит std::vector. Сам локальный вектор имеет автоматическую продолжительность хранения, а память для его элементов управляется динамически. Его деструктор освобождает эту память автоматически: слово «динамическая» не означает «обязательно освобождаем вручную».

Полная программа возвращает владеющий контейнер по значению:

#include <iostream>
#include <vector>

std::vector<int> make_values() {
    std::vector<int> values{10, 20, 30};
    return values;
}

int main() {
    const std::vector<int> values = make_values();
    std::cout << values.size() << ' ' << values[1] << '\n';
}

Вывод: 3 20. Результат возвращается как полноценное значение. При разрешённой оптимизации NRVO локальная переменная make_values и результат могут быть одним объектом: тогда он живёт до конца соответствующего блока main. Если NRVO не выполнена, вектор перемещается в результат, а локальный объект-источник уничтожается при выходе из функции. В обоих случаях результат не является ссылкой на уничтоженный локальный объект; в main данные принадлежат полученному вектору. Обычная запись return values; здесь достаточна.

Учебный разбор сырого указателя

Следующий фрагмент нужен только для различения времени жизни указателя и объекта. Он предполагает выполнение всех строк без раннего выхода; для практического владения далее используем std::unique_ptr.

int* owner = nullptr;
{
    int* another_name = new int{42};
    owner = another_name;
} // Уничтожена переменная-указатель another_name, но не динамический int.

delete owner; // Уничтожен динамический int и освобождена его память.
owner = nullptr;

Копирование сырого указателя копирует адрес. Оно не создаёт нового объекта и не определяет, кто обязан его уничтожить. Завершение жизни переменной-указателя не вызывает delete для адресуемого объекта.

RAII: ресурс освобождает его владелец

Цель: объяснять освобождение ресурсов при обычном выходе, раннем return и обработке исключения; выбирать между локальным объектом и динамическим владением.

RAII (Resource Acquisition Is Initialization) связывает ресурс с временем жизни объекта-владельца. Владелец получает ресурс при создании или явной передаче владения, а его деструктор освобождает ресурс. Так работают, например, стандартные контейнеры, файловые потоки и умные указатели. Правило относится не только к памяти.

Почему недостаточно поставить delete в конце функции

В учебном фрагменте X, should_stop и work обозначают существующие тип и функции; это не готовая программа для запуска:

X* pointer = new X{};
if (should_stop()) {
    return; // Утечка: динамический X не уничтожен.
}
work();    // Если исключение уходит из функции, delete также пропускается.
delete pointer;

При выходе из блока уничтожается локальная переменная-указатель, но сырой указатель не вызывает delete. Добавлять освобождение во все ветви вручную неудобно и легко ошибиться при последующих изменениях. Объект-владелец делает освобождение частью своей работы.

Сначала локальный объект, затем — динамическое владение при необходимости

Если объект нужен только в текущей функции, начните с X object{};. Если нужно выразить исключительное владение отдельным динамическим объектом, используйте std::unique_ptr; создать его удобно через std::make_unique из <memory>. Если требуется последовательность элементов, чаще подходит контейнер. Эти варианты можно комбинировать.

Полная программа печатает моменты создания и уничтожения. Динамический объект здесь добавлен для сравнения двух способов хранения. Введите normal, early или throw.

#include <iostream>
#include <memory>
#include <stdexcept>
#include <string>
#include <utility>

class Resource {
public:
    explicit Resource(std::string name) : name_{std::move(name)} {
        std::cout << "create " << name_ << '\n';
    }

    ~Resource() {
        std::cout << "destroy " << name_ << '\n';
    }

private:
    std::string name_;
};

void process(const std::string& mode) {
    Resource local{"local"};
    auto owner = std::make_unique<Resource>("dynamic");

    if (mode == "early") {
        std::cout << "early return\n";
        return;
    }
    if (mode == "throw") {
        throw std::runtime_error{"stop"};
    }
    std::cout << "normal end\n";
}

int main() {
    std::string mode;
    if (!(std::cin >> mode) ||
        (mode != "normal" && mode != "early" && mode != "throw")) {
        return 1;
    }

    try {
        process(mode);
    } catch (const std::runtime_error& error) {
        std::cout << "caught " << error.what() << '\n';
    }
    std::cout << "done\n";
}

При вводе early вывод такой:

create local
create dynamic
early return
destroy dynamic
destroy local
done

При вводе throw:

create local
create dynamic
destroy dynamic
destroy local
caught stop
done

Оба полностью построенных локальных объекта уничтожаются в обратном порядке создания: сначала owner, который уничтожает свой динамический Resource, затем local. При исключении это происходит во время раскрутки стека до показанного обработчика. При обычном завершении вместо early return печатается normal end; порядок освобождения тот же. Если ввод отсутствует или команда неизвестна, программа завершается с кодом 1 до создания ресурсов.

Владение и доступ — разные обязанности

Владелец отвечает за завершение времени жизни ресурса. Функция, которой нужно только прочитать объект, обычно принимает const X&; чтобы изменить его — X&. Сырой указатель подходит для невладеющего доступа, в том числе когда допустимо отсутствие объекта. Такой доступ не продлевает время жизни объекта. Умный указатель помогает выразить владение, но не делает любой сохранённый адрес автоматически безопасным.

std::unique_ptr: один владелец, несколько способов доступа

Цель: создавать динамический объект через std::make_unique, передавать владение и отличать эту передачу от временного доступа к живому объекту.

std::unique_ptr<T> из <memory> выражает исключительное владение. Непустой владелец уничтожает управляемый объект при своём уничтожении или замене ресурса. Для обычного std::unique_ptr<T> со стандартным deleter это означает вызов delete. Пустой указатель не уничтожает никакого объекта.

Основной способ создания отдельного динамического объекта — std::make_unique<T>(аргументы_конструктора), доступный с C++14. Эта функция создаёт объект и сразу возвращает его владельца. Для обычного локального значения умный указатель не требуется: T value{}; остаётся хорошим выбором.

Полная программа: доступ не передаёт владение

#include <iostream>
#include <memory>
#include <utility>

struct Record {
    int score{0};
};

void print_score(const Record& record) {
    std::cout << record.score << '\n';
}

int main() {
    Record local{10};
    print_score(local);

    auto first = std::make_unique<Record>();
    first->score = 42;
    Record* observer = first.get();
    print_score(*first);

    auto second = std::move(first);
    std::cout << std::boolalpha << static_cast<bool>(first) << ' '
              << static_cast<bool>(second) << '\n';
    print_score(*observer);

    second.reset();
    observer = nullptr;
    std::cout << static_cast<bool>(second) << '\n';
}

Вывод:

10
42
false true
42
false
  • print_score(const Record&) только читает объект. Она одинаково работает с локальным значением и с объектом, которым владеет умный указатель.
  • first->score и *first обращаются к объекту. В этих строках непустота известна: make_unique успешно завершился и владение ещё не передавалось.
  • first.get() возвращает адрес без передачи владения. observer не обязан и не должен вызывать delete.
  • auto second = std::move(first); передаёт владение. После такого конструктора перемещения first гарантированно пуст. Это конкретная гарантия unique_ptr, а не общее правило для всех перемещённых объектов.
  • Сам объект Record при передаче владения не перемещается в новую область памяти, поэтому observer всё ещё годится для доступа, пока объект жив.
  • second.reset(); уничтожает объект и делает владельца пустым. С этого момента прежний адрес непригоден для разыменования. Присваивание observer = nullptr; очищает только эту переменную; другие сохранённые адреса сами не обновятся.

Пустое состояние и операции

std::unique_ptr<Record> empty; создаёт пустого владельца. Если указатель может быть пуст, сначала проверьте if (empty), а затем используйте * или ->. Проверка не нужна повторно в каждой строке, когда непустота уже следует из логики программы. Обычная запись bool flag = empty; недопустима: преобразование к bool явное. В условии if оно разрешено; для отдельного значения можно написать static_cast<bool>(empty).

Копирование unique_ptr запрещено: два владельца не должны независимо удалять один объект. Для передачи владения используйте перемещение, для временного доступа — ссылку или невладеющий указатель. Не создавайте второй unique_ptr из first.get() и не вызывайте delete first.get(): это нарушает единственность владения и может привести к повторному удалению.

Умный указатель управляет временем жизни, но не проверяет корректность любого доступа. Разыменование пустого владельца или невладеющего указателя после уничтожения объекта недопустимо. Получая ссылку или адрес, всегда выясняйте, кто сохраняет объект живым и до какого момента.

Учебная реализация исключительного владения

Цель: проследить, как деструктор и операции перемещения сохраняют правило «у динамического объекта один владелец», и объяснить запрет копирования.

Ниже сохранён низкоуровневый разбор устройства владельца. LearningOwner — учебный класс для одного объекта, созданного через обычный new T. В рабочем коде выбирайте std::unique_ptr и std::make_unique. Учебный класс не поддерживает массивы, пользовательские deleter, преобразования между типами владельцев и полный интерфейс стандартного класса.

Договоримся о предусловиях: переданный ненулевой адрес принадлежит только этому владельцу; объект не удаляется извне; деструктор T не выбрасывает исключений; разыменование допустимо только у непустого владельца.

#include <cassert>
#include <iostream>
#include <utility>

template<class T>
class LearningOwner {
public:
    explicit LearningOwner(T* pointer = nullptr) noexcept : pointer_{pointer} {}

    ~LearningOwner() {
        delete pointer_;
    }

    LearningOwner(const LearningOwner&) = delete;
    LearningOwner& operator=(const LearningOwner&) = delete;

    LearningOwner(LearningOwner&& other) noexcept : pointer_{other.pointer_} {
        other.pointer_ = nullptr;
    }

    LearningOwner& operator=(LearningOwner&& other) noexcept {
        if (this != &other) {
            T* incoming = other.pointer_;
            other.pointer_ = nullptr;
            delete pointer_;
            pointer_ = incoming;
        }
        return *this;
    }

    explicit operator bool() const noexcept {
        return pointer_ != nullptr;
    }

    T& operator*() const {
        return *pointer_;
    }

    T* operator->() const noexcept {
        return pointer_;
    }

private:
    T* pointer_;
};

struct Item {
    inline static int alive{0};
    int value;
    LearningOwner<Item> child;

    explicit Item(int initial) : value{initial} {
        ++alive;
    }

    ~Item() {
        --alive;
    }
};

int main() {
    {
        LearningOwner<Item> first{new Item{42}};
        LearningOwner<Item> second{std::move(first)};
        assert(!first && second);

        LearningOwner<Item> third{new Item{7}};
        third = std::move(second);
        assert(!second && Item::alive == 1);

        LearningOwner<Item>& same = third;
        third = std::move(same);
        assert(third && Item::alive == 1);
        assert((*third).value == 42);
        std::cout << third->value << '\n';
    }
    assert(Item::alive == 0);
    std::cout << Item::alive << '\n';

    {
        LearningOwner<Item> root{new Item{1}};
        root->child = LearningOwner<Item>{new Item{2}};
        assert(Item::alive == 2);

        root = std::move(root->child);
        assert(root && root->value == 2 && Item::alive == 1);
        std::cout << root->value << '\n';
    }
    assert(Item::alive == 0);
    std::cout << Item::alive << '\n';
}

Вывод:

42
0
2
0

Что обеспечивает единственность владения

  1. Деструктор вызывает delete один раз для своего адреса. Для nullptr такая операция безопасна.
  2. Копирование запрещено через = delete. Простое копирование адреса создало бы двух независимых владельцев одного объекта.
  3. Конструктор перемещения забирает адрес и обнуляет источник. Его будущий деструктор больше не удалит переданный объект.
  4. Присваивание перемещением сначала сохраняет входящий адрес в локальную переменную и обнуляет источник, затем освобождает прежний ресурс получателя и устанавливает сохранённый адрес. Этот порядок нужен, если источник — поле внутри удаляемого объекта, как в root = std::move(root->child): после удаления родителя нельзя читать его поле. Проверка this != &other отдельно сохраняет объект при присваивании самому себе.
  5. noexcept обозначает обещание не выбрасывать исключений. В этих операциях выполняются только работа с адресами и удаление объекта с указанным выше невыбрасывающим деструктором.

Счётчик Item::alive и проверки assert помогают увидеть важные переходы: после замены ресурса жив только один Item, после выхода из блока — ни одного. Псевдоним same намеренно проверяет случай самоприсваивания перемещением. Второй блок проверяет передачу владения от дочернего поля родительскому владельцу: родитель удаляется, а дочерний объект остаётся жив и становится новым корнем. Эти проверки иллюстрируют контракт примера и не превращают учебный класс в полноценную замену стандартной библиотеке.

Здесь специальные функции написаны вручную, потому что сам класс непосредственно управляет ресурсом. Обычный прикладной класс с полями std::string, std::vector или std::unique_ptr обычно следует правилу нуля и поручает эту работу готовым владельцам.
