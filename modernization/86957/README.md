В каждом изменённом `.step` меняется **только `block.text`**. ID, время исходного экспорта, остальные поля блока, позиции и состав уроков сохранены. Оценочные шаги, правильные ответы, ограничения и скрытые тесты не изменяются этим пакетом.

Низкоуровневые массивы и `new[]`/`delete[]` остаются учебной темой. Новые объяснения помогают выбрать стандартного владельца для прикладной задачи и отделить этот выбор от изучения устройства памяти. У каждого законченного примера есть отдельный исходный файл и проверяемый результат; намеренно ошибочная программа обозначена отдельно.

## Стандарт и учебные ориентиры

Для локальных практикумов явно выбран **C++20**, базовые программы дополнительно проверяются в **C++17**. Это решение о совместимости проверенного набора примеров, а не утверждение о поддержке всех возможностей языка установленным компилятором. Настройки компилятора Stepik не менялись и не подтверждены этой локальной проверкой. Новые возможности C++23 могут добавляться отдельными примерами; экспериментальные режимы не являются требованием вводного курса.

Методические ориентиры — [Stanford CS106L](https://web.stanford.edu/class/cs106l/), [Illinois CS128](https://cs128.org/2026b/syllabus-1801), [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines) и официальная документация инструментов. Здесь используются собственные объяснения и примеры, адаптированные к существующей структуре курса. Подробное соответствие источников и решений записано в [методическом плане](CURRICULUM.md).

## Повторить проверки

Нужны Python 3.10+, GCC с поддержкой используемых средств C++20, Git и CMake 3.22+. Основной практикум CTest не требует сторонних библиотек. Команды выполняются из корня репозитория либо из корня распакованного ZIP:

```bash
python3 tools/verify_modernization.py --cmake cmake
```

Для нестандартного расположения CMake передайте путь к его исполняемому файлу. Полный прогон проверяет JSON, сохранение метаданных, совпадение кода в HTML и `.cpp`, результаты запусков на обоих стандартах, практикум Git и CMake/CTest в Debug и Release. Отрицательный контроль должен доказать, что неверное ожидание и неверная формула приводят к отказу тестов.

Режим `--skip-cmake` предназначен только для частичной проверки. Его результат не заменяет полный протокол. Дополнительный пример GoogleTest имеет собственные инструкции и проверку в `examples/snippets/`; он требует внешнюю библиотеку, в отличие от основного CTest-практикума.

Сборка пакета после редактирования:

```bash
python3 tools/build_modernization_package.py
python3 tools/verify_modernization.py --cmake cmake
python3 tools/build_modernization_package.py --archive
```

Первая команда обновляет манифест и превью. Последняя создаёт архив только после успешной проверки и сверяет содержимое ZIP с контрольными суммами. Даты файлов в ZIP фиксированы для воспроизводимой упаковки.

## Практические ограничения

Фактическое основное окружение проверки — Linux, GCC 14.2.0 и CMake 4.4.5. Команды для Windows/MSVC приведены по официальной документации, но в Windows не запускались. Подтверждение отображения и применения новых HTML-текстов на Stepik требует восстановленного авторизованного доступа; локальный протокол этого не подтверждает.

ZIP содержит выбранные шаги, их исходные варианты, примеры и инструменты проверки. Это **пакет изменений**, а не полная выгрузка курса. Исходный экспорт всех 485 шагов находится в репозитории.
