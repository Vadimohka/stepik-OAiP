<h2>Категория выражения и обозначаемый объект</h2>
<p>У выражения есть тип и категория значения. Тип определяет допустимые операции и представляемые значения; категория помогает определить, обозначает ли выражение существующий объект и к какой ссылке оно может привязаться. Это продолжение темы перегруженных операций: для выбора функции важны не только <code>int</code> или <code>std::string</code>, но и способ обращения к аргументу.</p>
<p>Выражение с именем обычной переменной — <strong>lvalue</strong>. Оно обозначает конкретный объект. Например, после <code>int x{7};</code> оба вхождения <code>x</code> в <code>x = x + 1;</code> являются lvalue. Правое вхождение используется для чтения значения, левое — для записи результата в тот же объект. Положение слева или справа от <code>=</code> не меняет категорию.</p>
<p>Целочисленный литерал <code>7</code> и сумма двух целых <code>x + 1</code> — <strong>prvalue</strong>: в этом контексте они вычисляют значения. Встроенному присваиванию требуется изменяемое lvalue слева, поэтому <code>7 = 10;</code> — пример недопустимого выражения. Имя объекта <code>const int limit{10};</code> тоже является lvalue, но записывать через него новое значение нельзя.</p>
<p>Таким образом, «lvalue» не означает «можно изменить», а «rvalue» не означает «стоит справа». В C++17/20 три основные категории — lvalue, prvalue и xvalue. Пошаговый разбор чтения и записи дан в <a href="https://stepik.org/lesson/853532/step/2" rel="noopener noreferrer nofollow">следующем тексте</a>, а общая схема категорий — в <a href="https://stepik.org/lesson/853532/step/3" rel="noopener noreferrer nofollow">таблице выражений</a>.</p>

<h2>Чтение значения и изменение объекта</h2>
<p>Ниже фрагмент тела функции; все используемые переменные объявлены в нём. Числа малы и представимы типом <code>int</code>, поэтому арифметические операции здесь не переполняются.</p>
<pre><code class="language-cpp">int a{5};
a = 4 + 6;
int b = a;
b = b;
b = b + 2;
</code></pre>
<p>После первой строки объект <code>a</code> хранит 5, после второй — 10. При инициализации <code>b</code> значение <code>a</code> копируется, поэтому два разных объекта хранят 10. Присваивание <code>b = b;</code> для <code>int</code> снова записывает 10 в <code>b</code>; это не делает переменные ссылками и не объединяет их.</p>
<p>Последняя строка разбирается так:</p>
<ol><li>Правое выражение <code>b</code> — lvalue, обозначающее объект. Чтобы вычислить сумму, программа читает хранимое значение 10. Этот переход называют <em>lvalue-to-rvalue-преобразованием</em>.</li><li>Выражение <code>b + 2</code> целиком — prvalue со значением 12.</li><li>Левое выражение <code>b</code> обозначает место назначения. Присваивание записывает туда 12.</li></ol>
<p>Итог: <code>a</code> хранит 10, <code>b</code> хранит 12. Преобразование правого операнда не меняет категорию всех выражений с именем <code>b</code> и не создаёт новую переменную. Та же модель действует для элемента массива: при корректном индексе <code>values[i]</code> обозначает существующий элемент, а чтение его значения и запись нового значения — разные применения этого выражения.</p>

<h2>Три основные категории и две объединяющие</h2>
<p>В C++17/20 каждое выражение относится ровно к одной основной категории: <strong>lvalue</strong>, <strong>xvalue</strong> или <strong>prvalue</strong>. <strong>Glvalue</strong> объединяет lvalue и xvalue — выражения, определяющие идентичность объекта или функции. <strong>Rvalue</strong> объединяет prvalue и xvalue. Поэтому xvalue одновременно является glvalue и rvalue; это не четвёртая отдельная категория.</p>
<p>Для таблицы предполагаются объявления <code>int x{7}; const int n{10}; int* p = &amp;x;</code> и подключённый заголовок <code>&lt;utility&gt;</code>. Все указатели в примерах обозначают живые объекты.</p>
<table><thead><tr><th>Выражение</th><th>Категория</th><th>Что означает</th></tr></thead><tbody>
<tr><td><code>x</code>, <code>*p</code></td><td>lvalue</td><td>Обозначают существующий объект <code>x</code>; через них можно изменить его.</td></tr>
<tr><td><code>n</code></td><td>lvalue</td><td>Обозначает константный объект; присваивание через это выражение запрещено.</td></tr>
<tr><td><code>7</code>, <code>x + 2</code></td><td>prvalue</td><td>Вычисляют целочисленные значения.</td></tr>
<tr><td><code>std::move(x)</code></td><td>xvalue</td><td>Обозначает тот же <code>x</code>, но допускает выбор операции перемещения.</td></tr>
<tr><td><code>std::move(n)</code></td><td>xvalue</td><td>Обозначает тот же константный объект: <code>const</code> сохраняется.</td></tr>
<tr><td><code>"abc"</code></td><td>lvalue</td><td>Строковый литерал — массив <code>const char</code>, а не prvalue указателя.</td></tr>
</tbody></table>
<p>Xvalue не обещает, что объект сейчас уничтожится или что его ресурс уже передан. <code>std::move</code> сам не переносит данные. Для встроенного <code>int</code> последующая операция просто работает со значением; для класса может выбираться специальная функция.</p>
<p>Prvalue класса может непосредственно инициализировать результат либо привести к появлению временного объекта, когда нужен объект для привязки ссылки. Временные объекты обычно уничтожаются в конце полного выражения; отдельные правила привязки ссылок могут продлевать их жизнь. Категория выражения и время жизни — связанные, но разные понятия.</p>
<p>Фраза «rvalue нельзя менять» тоже слишком широка: для rvalue класса может быть разрешён изменяющий метод. Например, фрагмент <code>std::string{} = "abc";</code> корректен при подключённом <code>&lt;string&gt;</code>, хотя созданный временный результат сразу уничтожается. Для дальнейшей работы важнее <a href="https://stepik.org/lesson/853534/step/1" rel="noopener noreferrer nofollow">правила привязки ссылок</a>, чем расположение выражения относительно знака присваивания.</p>
