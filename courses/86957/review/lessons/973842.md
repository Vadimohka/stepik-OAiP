<p style="text-align: center;"><strong>Очереди</strong></p>

<p> </p>

<p><strong>Очередь</strong> - это абстрактная структура данных, которая представляет собой последовательность элементов, где элементы добавляются в конец очереди и удаляются из начала очереди. Такая структура данных реализуется в виде списка, массива или связного списка.</p>

<p>Очередь имеет две основные операции - добавление элемента в конец очереди (enqueue) и удаление элемента из начала очереди (dequeue). При добавлении элемента он помещается в конец очереди, а при удалении элемента - удаляется первый элемент из начала очереди. Это логический порядок элементов: физически перемещать все оставшиеся элементы не требуется. В связном списке меняют начало списка, а в кольцевом буфере — индекс начала.</p>

<p>Очередь также поддерживает операцию просмотра элемента в начале очереди без его удаления (peek), которая возвращает первый элемент очереди.</p>

<p>Очереди могут быть реализованы как с использованием массивов, так и с использованием связных списков. В кольцевом буфере индексы начала и конца переходят через границу массива по модулю его ёмкости. Удаление меняет индекс начала без сдвига остальных элементов. При заполнении буфера нужно отдельно выбрать политику: отказ во вставке, увеличение ёмкости или перезапись по условиям задачи.</p>

<p>Одним из основных применений очередей является управление ресурсами в операционных системах. Очереди используются для управления процессами, которые должны быть выполнены в определенном порядке, и для управления потоками, которые ждут доступа к общим ресурсам.</p>

<p>Также очереди широко используются в компьютерных сетях, например, для управления пакетами данных, которые передаются между компьютерами.</p>

<p>В целом, очереди являются важной структурой данных в программировании, которая позволяет эффективно управлять процессами, ресурсами и данными.</p>

<p style="text-align: center;"><strong>Типы очередей</strong></p>

<p>В языке программирования C++ существует несколько типов очередей, которые отличаются особенностями работы и применениями:</p>

<ul>
	<li>
	<p><strong>FIFO (First-In, First-Out) </strong>- это самый распространенный тип очереди, где элементы добавляются в конец очереди и удаляются из начала очереди. Такой тип очереди работает по принципу "первым пришел - первым ушел". FIFO-очереди широко используются в операционных системах для управления процессами и потоками.</p>
	</li>
	<li>
	<p><strong>LIFO (Last-In, First-Out) </strong>- это тип очереди, где элементы добавляются и удаляются из конца очереди. Такой тип очереди работает по принципу "последним пришел - первым ушел". LIFO-очереди также известны как стеки.</p>
	</li>
	<li>
	<p><strong>Приоритетные очереди</strong> - это тип очереди, в котором каждый элемент имеет свой приоритет, и элементы с более высоким приоритетом обслуживаются раньше, чем элементы с более низким приоритетом. Приоритетные очереди широко используются в операционных системах, системах управления базами данных и других приложениях, где нужно обслуживать запросы с разной важностью.</p>
	</li>
	<li>
	<p><strong>Очереди с ограниченной емкостью</strong> - это тип очереди, в которой устанавливается максимальное количество элементов, которые могут быть помещены в очередь. Когда очередь заполнена, новые элементы не могут быть добавлены, пока старые элементы не будут удалены. Очереди с ограниченной емкостью используются в системах, где нужно контролировать количество запросов или сообщений, которые могут быть обработаны за определенный период времени.</p>
	</li>
	<li>
	<p><strong>Двухсторонние очереди</strong> - это тип очереди, который позволяет добавлять и удалять элементы как в начале, так и в конце очереди. Такие очереди широко используются в многопоточных системах, где нужно обеспечивать доступ к данным из нескольких потоков одновременно.</p>
	</li>
</ul>

<p style="text-align: center;"><strong>Queue</strong></p>

<p><code>queue</code> в C++ - это стандартный адаптер контейнера, который предоставляет интерфейс очереди. Он представляет собой абстрактный тип данных, который позволяет добавлять элементы в конец очереди и извлекать элементы из начала очереди.</p>

<p><code>queue</code> поддерживает операции добавления элемента в конец очереди, удаления элемента из начала очереди, доступа к первому элементу в очереди и определения количества элементов в очереди.</p>

<p>Для работы с <code>queue</code> в C++ необходимо подключить заголовочный файл <code>queue</code>, который содержит класс <code>queue</code>. Конструктор без аргументов создаёт пустую очередь. Конструктора queue(n), принимающего размер, нет. Можно передать готовый базовый контейнер: например, <code>std::deque&lt;int&gt; values(3); std::queue&lt;int&gt; q(values);</code> создаёт очередь из трёх нулей. По умолчанию базовый контейнер — std::deque.</p>

<p>Важно отметить, что <code>queue</code> не позволяет получать доступ к элементам, кроме первого и последнего. Если необходимо работать со всеми элементами в очереди, их необходимо извлекать при помощи метода <code>pop</code>.</p>

<p><code>queue</code> в C++ может использоваться для решения широкого спектра задач, связанных с обработкой последовательности элементов. Он может быть использован для реализации алгоритмов BFS (Breadth-First-Search) и решения других задач, связанных с обходом графов и деревьев. Кроме того, <code>queue</code> может быть использован для реализации алгоритмов, требующих обработки элементов в порядке их поступления.</p>

<p>Для std::queue&lt;T&gt; с базовым std::deque&lt;T&gt; операции имеют следующие оценки. front(), back() и pop() требуют непустой очереди; pop() удаляет элемент и не возвращает его:</p>

<ul>
<li>push() — вставка в конец: O(1);</li>
<li>pop() — удаление из начала: O(1);</li>
<li>front() — доступ к первому элементу: O(1);</li>
<li>back() — доступ к последнему элементу: O(1);</li>
<li>size() — количество элементов: O(1);</li>
<li>empty() — проверка пустоты: O(1);</li>
<li>Удаление последнего элемента и произвольный поиск не входят в интерфейс std::queue.</li>
</ul>

<p style="text-align: center;"><strong>Deque</strong></p>

<p> </p>

<p>Deque (double-ended queue, двусторонняя очередь) представляет собой контейнер, который обладает всеми свойствами последовательности данных, но также может эффективно выполнять операции добавления и удаления элементов как в начале, так и в конце очереди.</p>

<p>Интерфейс deque очень похож на интерфейс vector, за исключением двух новых операций push_front и pop_front, которые позволяют добавлять и удалять элементы с начала очереди за O(1) время в худшем случае.</p>

<p>Одной из основных задач при реализации deque является обеспечение возможности добавления и удаления элементов с обоих концов очереди за O(1) время в худшем случае. Для достижения этой цели большинство реализаций deque используют блочную структуру данных, которая представляет собой массивы фиксированного размера, называемые блоками, связанные с помощью массива указателей на эти блоки, называемого картой.</p>

<p>Каждый блок представляет собой массив элементов. В показанной далее реализации порядок блоков задаётся массивом указателей — картой, а не ссылками next/prev внутри блоков. При необходимости добавляется новый блок и обновляется карта; при удалении крайних элементов ненужные блоки могут освобождаться.</p>

<p>Основные свойства deque в сравнении с другими контейнерами:</p>

<ul>
	<li>
	<p>В отличие от vector, deque не гарантирует непрерывное размещение всех элементов. Случайный доступ по индексу остаётся O(1), но передавать &amp;d[0] вместе с d.size() как адрес единого массива нельзя. Если функции нужен непрерывный массив, данные можно скопировать в std::vector;</p>
	</li>
	<li>
	<p>deque может расходовать больше памяти, чем vector, из-за необходимости хранения блоков и карты. Однако, большинство реализаций deque используют эффективные методы управления памятью, такие как выделение памяти по требованию и перераспределение блоков в случае необходимости, чтобы минимизировать издержки на память;</p>
	</li>
	<li>
	<p>Операции добавления и удаления элементов в начале и конце deque имеют константное время выполнения O(1) в худшем случае, что делает deque идеальным выбором для реализации структур данных, таких как двусторонние очереди или стеки;</p>
	</li>
	<li>
	<p>в deque также есть методы, такие как at(), front(), back(), которые позволяют получать доступ к элементам по индексу или по значению в начале и конце очереди;</p>
	</li>
	<li>
	<p>deque также поддерживает методы, такие как insert() и erase(), которые позволяют добавлять и удалять элементы в произвольных позициях очереди;</p>
	</li>
	<li>
	<p>deque может использоваться вместо vector в большинстве случаев, но vector обычно более эффективен при доступе к элементам и при выполнении операций, которые изменяют размер контейнера.</p>
	</li>
</ul>

<p>Однако, следует учитывать, что использование deque может привести к потере производительности, поскольку блочная структура данных требует большего количества операций обращения к памяти. Также, некоторые реализации могут потребовать больше памяти для хранения карты и блоков, чем для других контейнеров, таких как vector.</p>

<p>Далее рассмотрим реализацию, основанную на идее выделения «блоков» (массивов фиксированного размера) элементов, а затем использования «карты» (массива указателей на эти блоки) для отслеживания блоков.</p>

</ul>
