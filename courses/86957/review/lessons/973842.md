<h2>Очередь и её инвариант FIFO</h2>
<p>Очередь хранит последовательность элементов и обслуживает их по правилу <strong>first in, first out</strong>: раньше добавленный элемент удаляется раньше. Предварительные знания — <a href="https://stepik.org/lesson/973837/step/1" rel="noopener noreferrer nofollow">интерфейс и реализация</a>, <a href="https://stepik.org/lesson/770590/step/1" rel="noopener noreferrer nofollow">контракт функции</a>.</p>
<p>В абстрактной очереди <code>enqueue(x)</code> добавляет значение в конец, <code>front()</code> показывает первое значение, <code>dequeue()</code> удаляет его. Чтение и удаление требуют непустой очереди; конкретный интерфейс определяет, возвращает ли удаление значение. У <code>std::queue::pop()</code> результат имеет тип <code>void</code>.</p>
<table><thead><tr><th>Операция</th><th>Состояние от начала к концу</th><th>Смысл</th></tr></thead><tbody><tr><td>Начало</td><td>[]</td><td>Очередь пуста.</td></tr><tr><td>Добавить A, затем B</td><td>[A, B]</td><td>A будет обработан первым.</td></tr><tr><td>Прочитать начало</td><td>[A, B]</td><td>Получено A; очередь не изменена.</td></tr><tr><td>Удалить начало</td><td>[B]</td><td>A больше не хранится.</td></tr><tr><td>Добавить C</td><td>[B, C]</td><td>B предшествует C.</td></tr></tbody></table>
<p><strong>Инвариант</strong>: относительный порядок ещё не удалённых элементов совпадает с порядком добавления. Перемещать все элементы в памяти при каждом удалении не требуется. В связном списке меняется указатель начала, в кольцевом буфере — индекс.</p>
<p>У кольцевого буфера ёмкости <code>c &gt; 0</code> индексы обходят массив циклически. Размер нужно отличать от ёмкости: по одному совпадению индексов начала и конца нельзя определить одновременно и пустоту, и заполненность без дополнительного соглашения. При заполнении заранее выбирают политику: отказ, рост или перезапись. Перезапись меняет договор: часть старых данных теряется.</p>
<p>FIFO описывает порядок, а не безопасность параллельного доступа. Очередь сообщений между потоками требует отдельной синхронизации. В следующем шаге сравним FIFO с другими правилами выбора элемента.</p>

<h2>FIFO, стек, приоритетная и двусторонняя очередь</h2>
<p>У этих интерфейсов разный договор о том, какое значение доступно следующим. Ограниченная ёмкость — отдельное свойство хранения, а не ещё один порядок обслуживания.</p>
<table><thead><tr><th>Модель</th><th>Следующий элемент</th><th>Средство C++</th></tr></thead><tbody><tr><td>FIFO-очередь</td><td>Самый ранний из оставшихся</td><td><code>std::queue</code>: <code>front</code>, <code>push</code>, <code>pop</code></td></tr><tr><td>Стек, LIFO</td><td>Последний добавленный</td><td><code>std::stack</code>: <code>top</code>, <code>push</code>, <code>pop</code></td></tr><tr><td>Приоритетная очередь</td><td>Определяется отношением сравнения</td><td><code>std::priority_queue</code>; при обычном сравнении сверху наибольшее значение</td></tr><tr><td>Двусторонняя очередь</td><td>Можно выбирать любой край</td><td><code>std::deque</code>: операции с обоих концов и доступ по индексу</td></tr></tbody></table>
<p>После добавления чисел 4, 1, 7 FIFO выдаёт 4 первым, стек — 7, стандартная приоритетная очередь с обычным сравнением — тоже 7, но по другой причине: это наибольшее значение. Если затем добавить 2, вершиной стека станет 2, а приоритетной очереди останется 7. Для одинакового приоритета <code>std::priority_queue</code> не обещает FIFO-порядок.</p>
<p>Стек не следует смешивать с FIFO под одним названием «обычная очередь». Приоритетная очередь также не является отсортированной последовательностью с произвольным доступом: она эффективно предоставляет один приоритетный край.</p>
<p>Адаптеры <code>queue</code> и <code>stack</code> с обычным базовым контейнером не задают пользовательский предел размера. Для ограниченной очереди нужен дополнительный договор о переполнении. Ни <code>queue</code>, ни <code>deque</code> сами по себе не являются очередями для одновременной записи и чтения из разных потоков.</p>
<p>Далее рассмотрим точный интерфейс <code>std::queue</code> и свойства его стандартного базового контейнера <code>std::deque</code>.</p>

<h2>std::queue: ограниченный интерфейс последовательности</h2>
<p>Заголовок <code>&lt;queue&gt;</code> определяет адаптер <code>std::queue</code>. Для <code>std::queue&lt;T&gt;</code> базовым контейнером служит <code>std::deque&lt;T&gt;</code>. Подходящий иной контейнер должен предоставлять <code>front</code>, <code>back</code>, <code>push_back</code> и <code>pop_front</code>: например, <code>std::list</code> подходит, а <code>std::vector</code> не имеет <code>pop_front</code>.</p>
<table><thead><tr><th>Операция</th><th>Контракт</th><th>С базовым deque</th></tr></thead><tbody><tr><td><code>empty(), size()</code></td><td>Проверить пустоту, узнать количество</td><td>O(1)</td></tr><tr><td><code>front(), back()</code></td><td>Ссылка на крайний элемент; очередь непуста</td><td>O(1)</td></tr><tr><td><code>push(x), emplace(...)</code></td><td>Добавить с конца</td><td>O(1) операций с элементами</td></tr><tr><td><code>pop()</code></td><td>Удалить первый элемент; очередь непуста; ничего не возвращает</td><td>O(1)</td></tr></tbody></table>
<p>Это библиотечные оценки, а не обещание фиксированного времени по часам: выделение памяти и операции самого типа <code>T</code> тоже имеют стоимость. При замене базового контейнера оценки определяются его операциями.</p>
<h3>Разобранный пример</h3>
<p>Полная программа C++17/20 сначала копирует текущее значение в локальный объект, затем удаляет элемент из очереди. Локальная строка продолжает жить независимо от очереди.</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;queue&gt;
#include &lt;string&gt;

int main() {
    std::queue&lt;std::string&gt; pending;
    pending.push("parse");
    pending.push("save");
    while (!pending.empty()) {
        std::string current = pending.front();
        pending.pop();
        std::cout &lt;&lt; current &lt;&lt; '\n';
    }
}</code></pre>
<p>Вывод — <code>parse</code>, затем <code>save</code> на отдельных строках. Ссылка, полученная от <code>front()</code>, после <code>pop()</code> удаляемого элемента стала бы недействительной: поэтому переменная <code>current</code> хранит собственную строку.</p>
<p>Итераторов <code>begin/end</code> и индексирования у <code>queue</code> нет. Обработка с удалением соответствует её интерфейсу; если нужен обход без удаления, можно обойти копию очереди либо выбрать контейнер с итераторами. Конструктор без аргументов создаёт пустую очередь; конструктора <code>queue(n)</code> с размером нет. Готовый базовый контейнер можно передать конструктору.</p>

<h2>std::deque: гарантии и возможное устройство</h2>
<p><code>std::deque</code> из заголовка <code>&lt;deque&gt;</code> — последовательный контейнер с произвольным доступом и изменением обоих концов. В отличие от адаптера <code>queue</code>, он предоставляет итераторы и индексирование.</p>
<table><thead><tr><th>Свойство</th><th>std::vector</th><th>std::deque</th></tr></thead><tbody>
<tr><td>Хранение элементов</td><td>Непрерывное для обычного <code>vector&lt;T&gt;</code>; <code>vector&lt;bool&gt;</code> — специальный случай</td><td>Непрерывность всех элементов не гарантирована</td></tr>
<tr><td>Доступ по индексу</td><td>O(1)</td><td>O(1)</td></tr>
<tr><td>Добавление одного элемента с конца</td><td>Амортизированно O(1), отдельная реаллокация линейна</td><td>Константная сложность в модели требований контейнеров</td></tr>
<tr><td>Добавление и удаление в начале</td><td>Обычно сдвиг элементов, O(n)</td><td>Константная сложность</td></tr>
<tr><td>Вставка в середину</td><td>O(n)</td><td>O(n)</td></tr>
</tbody></table>
<p><code>operator[]</code> требует индекс меньше <code>size()</code>; <code>at()</code> проверяет индекс и при выходе за границы выбрасывает <code>std::out_of_range</code>. <code>front()</code>, <code>back()</code>, <code>pop_front()</code> и <code>pop_back()</code> требуют непустой контейнер.</p>
<h3>Указатели, ссылки и итераторы — разные гарантии</h3>
<p>Вставка на любом конце <code>deque</code> сохраняет ссылки на прежние элементы, но делает прежние итераторы недействительными. Это относится и к ранее сохранённому <code>end()</code>. Вставка в середину делает недействительными и итераторы, и ссылки. При удалении на краю ссылки на не удалённые элементы сохраняются; отдельные правила для итераторов и <code>end()</code> зависят от удаляемого края. Надёжный простой приём — заново получать итераторы после изменения контейнера.</p>
<p>Полная программа C++17/20 выводит <code>20 30</code>, затем <code>10 20 30 40</code>. Ссылка <code>first</code> по-прежнему обозначает прежний объект со значением 20, хотя его индекс изменился.</p><pre><code class="language-cpp">#include &lt;deque&gt;
#include &lt;iostream&gt;

int main() {
    std::deque&lt;int&gt; values{20, 30};
    int&amp; first = values.front();
    values.push_front(10);
    values.push_back(40);
    std::cout &lt;&lt; first &lt;&lt; ' ' &lt;&lt; values.at(2) &lt;&lt; '\n';
    // References survive insertion at the ends; old iterators do not.
    for (auto it = values.begin(); it != values.end(); ++it) {
        std::cout &lt;&lt; *it &lt;&lt; ' ';
    }
    std::cout &lt;&lt; '\n';
}</code></pre>
<h3>Как это может быть устроено</h3>
<p>Распространённая реализация хранит элементы в нескольких блоках, а адреса блоков — в отдельной таблице. Пара «номер блока, позиция внутри» позволяет вычислять адрес элемента за постоянное число операций. Размер блока, политика его выделения и устройство таблицы адресов зависят от библиотеки: стандарт не требует конкретного каркаса <code>T**</code>.</p>
<p>Такое устройство объясняет, почему из <code>&amp;d[0]</code> и <code>d.size()</code> нельзя получить единый массив всех элементов. Для API, ожидающего непрерывный диапазон, подходит отдельный <code>vector</code>. Размер служебных структур и реальное быстродействие измеряют на конкретной задаче: из таблицы сложности нельзя вывести, что один контейнер всегда быстрее другого.</p>
<p>Теперь у нас разделены логический порядок, интерфейс и размещение. Следующий урок о приведениях возвращается к <a href="https://stepik.org/lesson/877084/step/1" rel="noopener noreferrer nofollow">типам и наследованию</a>: смена вида доступа к объекту не является перестройкой контейнера.</p>
