<h3>Одномерный динамический массив</h3>

<p>Кроме отдельных динамических объектов в языке C++ мы можем использовать динамические массивы, размер которых, в отличие от фиксированного массива, не должен быть известен во время компиляции. Динамическое выделение массива в языке C++ позволяет нам устанавливать его длину во время выполнения программы.</p>

<p>Для выделения памяти под динамический массив также используется оператор <code>new[]</code>, где в квадратных скобках указывается, сколько массив будет содержать объектов:</p>

<pre><code class="language-cpp">int *numbers = new int[4];</code></pre>

<p>Причем в этом случае оператор <code>new[]</code> также возвращает указатель на объект типа <code>int</code> - первый элемент в созданном массиве.</p>

<p>Обратите внимание, поскольку память для динамических и фиксированных массивов выделяется из разных мест, то размер динамического массива может быть очень большим (пока не закончится оперативная память). Рассмотрим это на следующем примере:</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
 
int main() {
    const int veryBigConst = 1000000000;

    //int staticArray[veryBigConst]; // данная строка вызовет ошибку    
    int* dynamicArray = new int[veryBigConst]; // всё хорошо

    return 0;
}</code></pre>

<p>На моём компьютере я получил ошибку уже при выделении статического массива размером 4мб, что обусловлено переполнением стека. Стек переполняется - мы получаем ошибку <code>stack overflow</code>. Однако динамически я могу выделить массив такого размера, т.к. он выделяется не на стеке, а в каком-то абсолютно другом месте в оперативной памяти, которое нам предоставляет ОС.</p>

<h4>Инициализация динамических массивов</h4>

<p>В данном случае определяется массив из четырех элементов типа int, но каждый из них имеет неопределенное значение. Однако мы также можем инициализировать массив значениями:</p>

<pre><code class="language-cpp">int *n1 = new int[4];   // каждый элемент имеет неопределенное значение
int *n2 = new int[4](); // каждый элемент имеет значение по умолчанию - 0
int *n3 = new int[4]{ 1, 2, 3, 4 }; // массив состоит из чисел 1, 2, 3, 4</code></pre>

<p>В последнем случае при инициализации массива конкретными значениями следует учитывать, что если значений в фигурных скобках больше чем длина массива, то оператор <code>new[]</code> потерпит неудачу и не сможет создать массив. Если переданных значений, наоборот, меньше, то элементы, для которых не предоставлены значения, инициализируются значением по умолчанию. Данный способ инициализации (uniform initialization) работает только начиная со стандарта C++11.</p>

<p>В целом после создания динамического массива мы можем работать с ним точно так же, как и с фиксированным, только помня, что он всегда имеет тип указателя:</p>

<pre><code class="language-cpp">int n = 5;  // размер массива
int *p = new int[n]{ 1, 2, 3, 4, 5 };
for (int *q = p; q != p + n; q++) {
    std::cout &lt;&lt; *q &lt;&lt; "\t";
}</code></pre>

<p>Для удаления динамического массива и освобождения занятой им памяти используется оператор <code>delete[]</code>:</p>

<pre><code class="language-cpp">delete [] указатель_на_динамический_массив;</code></pre>

<p>Самая распространенная ошибка, которую совершают новички при работе с динамическим выделением памяти, является использование <code>delete</code> вместо <code>delete[]</code> для удаления динамических массивов. При использовании оператора <code>delete</code> с динамическим массивом, выделенным оператором <code>new[]</code>, мы получим неопределённое поведение (undefined behaviour), т.к. в стандарте не задокументирована данная ситуация, и каждый компилятор может себя вести по-разному.</p>

<h3>Двумерный динамический массив</h3>

<p>Рассмотрим процесс объявления двумерного динамического массива:</p>

<pre><code class="language-cpp">int nstr = 5; // количество строк
int nstb = 5; // количество столбцов
// объявление двумерного динамического массива на 25 элементов
int** a = new int*[nstr]; // пять строк в массиве
for (int i = 0; i &lt; nstr; ++i) {
    a[i] = new int[nstb]; // и пять стобцов
}
// где a  – массив указателей на выделенный участок памяти 
// под массив целых числе типа int
</code></pre>

<p>Сначала объявляется указатель второго  порядка <code>int** a</code>, который ссылается на массив указателей <strong> </strong><code>int* [nstr]</code>,<strong> </strong>где размер массива равен пяти<strong>. </strong>После чего в цикле<strong> </strong><code>for</code><strong> </strong>каждой строке массива объявленного в<strong> строке 4 </strong>выделяется память под пять элементов. В результате получается двумерный динамический массив <strong> </strong><code>a[5][5]</code>.<strong> </strong></p>

<p>Для того, чтобы лучше понимать, как устроен двумерный динамический массив, рассмотрим данную схему:</p>

<p><img alt="" height="2429" name="Frame 20.png" src="https://ucarecdn.stepik.net/5f870e84-3430-4368-b968-7476ca7100e3/-/crop/4563x2429/0,177/-/preview/" width="4563"></p>

<p>Здесь мы можем увидеть, что при обращении к элементу <code>a[i][j]</code>мы на самом деле сначала обращаемся к массиву <code>int** a</code> по индексу <code>i</code>, следовательно, получаем значение, хранящееся в ячейке под этим индексом, а это — некоторый указатель <code>int*</code>. Затем мы обращаемся уже к этому указателю по индексу <code>j</code>, а это не что иное, как значение типа <code>int</code>.</p>

<p>Рассмотрим пример высвобождения памяти отводимой под двумерный динамический массив.</p>

<pre><code class="language-cpp">// высвобождение памяти отводимой под двумерный динамический массив:
for (int i = 0; i &lt; nstr; ++i) {
    delete[] a[i]; // удаляем строку
    a[i] = nullptr; // убираем висячий указатель
}
delete[] a; // удаляем сам двумерный массив
a = nullptr; // убираем висячий указатель</code></pre>

<p>Объявление и удаление двумерного динамического массива выполняется с помощью цикла, так как показано выше, необходимо понять и запомнить то, как это делается.</p>

<p>*Ещё один важный момент. Можно заметить, что после использования оператора <code>delete[]</code> я присваиваю удалённому указателю значение <code>nullptr</code>. Это считается хорошим тоном в программировании на C++, т.к. наш указатель в действительности после удаления по-прежнему указывает на то место в памяти, где раньше находился массив, однако там уже могут лежать совершенно другие данные. Следовательно, чтобы запретить доступ к этим данным через данный указатель, следует установить его значение как нулевое. В таком случае, при обращении к нему возникнет ошибка.</p>

<h3>Работа с динамической памятью в языке С</h3>

<p>В предыдущих модулях уже обсуждалось, что локальные переменные кладутся в стек и существуют до тех пор, пока мы не вышли из функции. С одной стороны, это позволяет автоматически очищать память, с другой стороны, существует необходимость в переменных, время жизни которых мы можем контролировать самостоятельно. Кроме того, нам необходимо динамическое выделение памяти, когда размер используемого пространства заранее не известен. Для этого используется выделение памяти в куче. Недостатков у такого подхода два: во-первых, память необходимо вручную очищать, во-вторых, выделение памяти – достаточно дорогостоящая операция.</p>

<p>В C не поддерживаются такие операторы, как <em>new[]</em> и <em>delete[]</em>. Для выделения памяти в куче в С используется функция <em>malloc</em> (memory allocation) из библиотеки stdlib.h</p>

<pre><code class="language-cpp">void* malloc(size_t size);</code></pre>

<p>Функция выделяет <code>size</code> байтов памяти и возвращает указатель на неё. Если память выделить не удалось, то функция возвращает <code>NULL</code>. Так как malloc возвращает указатель типа <code>void</code>, то его необходимо явно приводить к нужному нам типу. Например, создадим указатель, после этого выделим память размером в 100 байт:</p>

<pre><code class="language-cpp">#include &lt;conio.h&gt;
#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;
 
void main() {
    int *p = NULL;
    p = (int*)malloc(100);
 
    free(p);
}</code></pre>

<p>После того, как мы поработали с памятью, необходимо освободить память функцией <code>free</code>.<br>
Используя указатель, можно работать с выделенной памятью как с массивом. Пример: пользователь вводит число – размер массива, создаём массив этого размера и заполняем его квадратами чисел по порядку. После этого выводим и удаляем массив.</p>

<pre><code class="language-cpp">#include &lt;conio.h&gt;
#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;
 
void main() {
    const int maxNumber = 100;
    int *p = NULL;
    unsigned i, size;
 
    do {
        printf("Enter number from 0 to %d: ", maxNumber);
        scanf("%d", &amp;size);
        if (size &lt; maxNumber) {
            break;
        }
    } while (1);
 
    p = (int*)malloc(size * sizeof(int));
 
    for (i = 0; i &lt; size; i++) {
        p[i] = i*i;
    }
 
    for (i = 0; i &lt; size; i++) {
        printf("%d ", p[i]);
    }

    free(p);
}</code></pre>

<p>Остановимся подробнее на <code>p = (int*)malloc(size * sizeof(int));</code></p>

<p>Здесь <code>(int*)</code> – приведение типов. Пишем такой же тип, как и у указателя.<br>
<code>size * sizeof(int)</code> – сколько байт выделить. <code>sizeof(int)</code> – размер одного элемента массива.<br>
После этого работаем с указателем точно также, как и с массивом. В конце не забываем удалять выделенную память.</p>

<p>Теперь представим на рисунке, что у нас происходило. Пусть мы ввели число 5.</p>

<p><img alt="" height="474" name="Frame 21.png" src="https://ucarecdn.stepik.net/476ae5b8-ed17-4498-b3a7-51b21b473a49/-/crop/5661x3693/0,259/-/preview/" width="727"></p>

<p> </p>

<p>Функция malloc выделила память в куче по определённому адресу, после чего вернула его. Теперь указатель <code>p</code> хранит этот адрес и может им пользоваться для работы. В принципе, он может пользоваться и любым другим адресом. Когда функция <code>malloc</code> "выделяет память", то она резервирует место на куче и возвращает адрес этого участка. У нас будет гарантия, что компьютер не отдаст нашу память кому-то ещё. Когда мы вызываем функцию <code>free</code>, то мы освобождаем память, то есть говорим компьютеру, что эта память может быть использована кем-то другим. Он может использовать нашу память, а может и нет, но теперь у нас уже нет гарантии, что эта память наша. При этом сама переменная не зануляется, она продолжает хранить адрес, которым ранее пользовалась.</p>

<p>Это очень похоже на съём номера в отеле. Мы получаем дубликат ключа от номера, живём в нём, а потом сдаём комнату обратно. Но дубликат ключа у нас остаётся. Всегда можно зайти в этот номер, но в нём уже кто-то может жить. Так что наша обязанность – удалить дубликат.</p>

<p>Иногда думают, что происходит "создание" или "удаление" памяти. На самом деле происходит только перераспределение ресурсов.</p>

<h4>Освобождение памяти с помощью free</h4>

<p>Теперь рассмотрим, как происходит освобождение памяти. Переменная указатель хранит адрес области памяти, начиная с которого она может им пользоваться. Однако, она не хранит размера этой области. Откуда тогда функция <code>free</code> знает, сколько памяти необходимо освободить?</p>

<p>Очевидно, что информация о размере выделенного участка должна где-то храниться. Есть несколько решения этой проблемы.</p>

<ul>
	<li>Можно создать карту, в которой будет храниться размер выделенного участка. Каждый раз при освобождении памяти компьютер будет обращаться к этим данным и получать нужную информацию.</li>
	<li>Второе решение более распространено. Информация о размере хранится на куче до самих данных. Таким образом, при выделении памяти резервируется места больше и туда записывается информация о выделенном участке. При освобождении памяти функция <code>free</code> "подсматривает", сколько памяти необходимо удалить.</li>
</ul>

<p>Функция <code>free</code> освобождает память, но при этом не изменяет значение указателя, о чём нужно помнить.</p>

<p>Если мы не используем эту функцию, то динамическая память все равно освободится автоматически при завершении работы программы. Однако все же хорошей практикой является вызов функции <code>free</code>, который позволяет как можно раньше освободить память и не допустить утечки памяти.</p>

<h3>Работа с массивами в языке С</h3>

<p>Динамическое создание одномерного массива мы рассмотрим на примере. Пусть длина массива неизвестна и вводится во время выполнения программы пользователем:</p>

<pre><code class="language-cpp">#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;
 
int main(void) {   
    int *block; // указатель для блока памяти
    int n;      // число элементов массива
    // ввод числа элементов
    printf("Size of array=");
    scanf("%d", &amp;n);
     
    // выделяем память для массива
    // функция malloc возвращает указатель типа void*
    // который автоматически мы явно конвертируем в int*
    block = (int*)malloc(n * sizeof(int));

    // очень важный код

    free(block); // не забываем освободить занятые ресурсы
    block = NULL;
    return 0;
}</code></pre>

<p> </p>

<p>Для динамического создания двумерного массива сначала необходимо создать массив указателей, после чего каждому из элементов этого массива присвоить адрес нового массива.<br>
Для удаления массива необходимо повторить операцию в обратном порядке - удалить сначала подмассивы, а потом и сам массив указателей.</p>

<pre><code class="language-cpp">#include &lt;conio.h&gt;
#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;
 
void main() {
    float **p = NULL;
    unsigned i;
    const int rowNum = 10, colNum = 10;
 
    p = (float**)malloc(rowNum * sizeof(float*));
    for (i = 0; i &lt; rowNum; i++) {
        p[i] = (float*)malloc(colNum * sizeof(float));
    }
 
    //Здесь какой-то важный код

    for (i = 0; i &lt; rowNum; i++) {
        free(p[i]);
        p[i] = NULL;
    }
    free(p);
    p = NULL;
}</code></pre>

<p>Сначала создаём массив указателей, а после этого каждому элементу этого массива присваиваем адрес вновь созданного массива. Это значит, что можно:</p>

<ul>
	<li>Создавать массивы "неправильной формы", то есть массив строк, каждая из которых имеет свой размер.</li>
	<li>Работать по отдельности с каждой строкой массива: освобождать память или изменять размер строки.</li>
</ul>

<h4>Функции realloc и calloc</h4>

<p>Функция <code>calloc</code> выделяет <code><span style="color: #000000;">num</span></code> объектов размером <code><span style="color: #000000;">size</span></code> и заполняет их нулями, т.е. фактически избавляет нас от необходимости каждый раз высчитывать количество байт, которое нужно выделить, используя функцию <code>malloc</code>. Обычно она используется для выделения памяти под массивы. В случае неудачного выполнения возвращает <code>NULL</code>.</p>

<pre><code class="language-cpp">void* calloc(size_t num, size_t size);</code></pre>

<p>Ещё одна важная функция – <code>realloc</code> (re-allocation). Она позволяет изменить размер ранее выделенной памяти, адрес которой хранит указатель <code>ptr</code>, и получает в качестве аргументов этот указатель и новый размер памяти в байтах. Если указатель <code>ptr</code> имеет значение <code>NULL</code>, то есть память не выделялась, то действие функции аналогично действию <code>malloc</code>:</p>

<pre><code class="language-cpp">void* realloc(void* ptr, size_t size)</code></pre>

<p>Функция realloc может как использовать ранее выделенный участок памяти, так и новый. При этом не важно, меньше или больше новый размер – менеджер памяти сам решает, где выделять память.</p>

<p>Вообще говоря, функции <code>calloc</code> и <code>realloc</code> лишь дополняют возможности функции <code>malloc</code> по выделении памяти, поэтому их можно заставить работать аналогично функции <code>malloc</code>:</p>

<pre><code class="language-cpp">block = (int*)malloc(n * sizeof(int));
block = (int*)calloc(n, sizeof(int));
block = (int*)realloc(block, n * sizeof(int));</code></pre>

<p><br>
Пример, в котором удобно использовать функцию <code>realloc</code> – пользователь вводит слова. Для начала выделяем под слова массив размером 10. Если пользователь ввёл больше слов, то изменяем его размер при помощи функции <code>realloc</code>, чтобы хватило места. Когда пользователь вводит слово end, прекращаем ввод и выводим на печать все слова.</p>

<pre><code class="language-cpp">#include &lt;conio.h&gt;
#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;
#include &lt;string.h&gt;
 
void main() {
    //Массив указателей на слова
    char **words;
    //Строка, которая используется для считывания введённого пользователем слова
    char buffer[128];
    //Счётчик слов
    unsigned wordCounter = 0;
    //Длина введённого слова
    unsigned length;
    //Размер массива слов. Для уменьшения издержек на выделение памяти 
    const int sizeIncrement = 10;
    //каждый раз будем увеличивать массив слов не на одно значение, а на
    //sizeIncrement слов
    const char* termWord = "end";
    unsigned size = sizeIncrement;
    int i;
 
    //Выделяем память под массив из size указателей
    words = (char**)malloc(size * sizeof(char*));
    do {
        printf("%d: ", wordCounter);
        scanf("%127s", buffer);
        //Функция strcmp возвращает 0, если две строки равны
        if (strcmp(termWord, buffer) == 0) {
            break;
        }
        //Определяем длину слова
        length = strlen(buffer);
        //В том случае, если введено слов больше, чем длина массива, то
        //увеличиваем массив слов
        if (wordCounter &gt;= size) {
            size += sizeIncrement;
            words = (char**)realloc(words, size * sizeof(char*));
        }
        //Выделяем память непосредственно под слово
        //на 1 байт больше, так как необходимо хранить терминальный символ
        words[wordCounter] = (char*)malloc(length + 1);
        //Копируем слово из буффера по адресу, который 
        //хранится в массиве указателей на слова
        strcpy(words[wordCounter], buffer);
        wordCounter++;
    } while(1);
 
    for (i = 0; i &lt; wordCounter; i++) {
        printf("%s\n", words[i]);
    }
    _getch();
 
    for (i = 0; i &lt; wordCounter; i++) {
        free(words[i]);
    }
    free(words);
}</code></pre>

<p>Обратите внимание, что при выделении памяти пишем <code>sizeof(char*)</code>, т.к. размер указателя на <code>char</code> не равен одному байту, как размер переменной типа <code>char</code>.</p>

### Шаг 5 — text (ID 3213210)

[Открыть на Stepik](https://stepik.org/lesson/770587/step/5?unit=773028) · [Исходник step-source](../../raw/step-sources/3213210.json) · [Объект step](../../raw/steps/3213210.json)

<h3>Ошибки при выделении памяти</h3>

<p>Сейчас будут рассмотрены ошибки при выделении памяти с большим обилием примеров. Настоятельно рекомендую скопировать код и запустить у себя в IDE.</p>

<p>1. Бывает ситуация, при которой память не может быть выделена. В этом случае функция <code>malloc</code> (и <code>calloc</code>) возвращает <code>NULL</code>. Поэтому, перед выделением памяти необходимо обнулить указатель, а после выделения проверить, не равен ли он <code>NULL</code>. Так же ведёт себя и <code>realloc</code>. Когда мы используем функцию <code>free</code> проверять на <code>NULL</code> нет необходимости, так как согласно документации <code>free(NULL)</code> не производит никаких действий. Применительно к последнему примеру:</p>

<pre><code class="language-cpp">#include &lt;conio.h&gt;
#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;
#include &lt;string.h&gt;
 
void main() {
    char **words;
    const char* termWord = "end";
    char buffer[128];
    unsigned wordCounter = 0;
    unsigned length;
    const int sizeIncrement = 10;
    unsigned size = sizeIncrement;
    int i;
 
    if (!(words = (char**)malloc(size*sizeof(char*)))) {
        printf("Error: can't allocate memory");
        _getch();
        exit(1);
    }
 
    do {
        printf("%d: ", wordCounter);
        scanf("%127s", buffer);
         
        if (strcmp(termWord, buffer) == 0) {
            break;
        }
 
        length = strlen(buffer);
 
        if (wordCounter &gt;= size) {
            size += sizeIncrement;
            if (!(words = (char**)realloc(words, size*sizeof(char*)))) {
                printf("Error: can't reallocate memory");
                _getch();
                exit(2);
            }
        }
 
        if (!(words[wordCounter] = (char*)malloc(length + 1))) {
            printf("Error: can't allocate memory");
            getch();
            exit(3);
        }
 
        strcpy(words[wordCounter], buffer);
        wordCounter++;
    } while(1);
 
    for (i = 0; i &lt; wordCounter; i++) {
        printf("%s\n", words[i]);
    }
    getch();
 
    for (i = 0; i &lt; wordCounter; i++) {
        free(words[i]);
    }
    free(words);
}</code></pre>

<p><strong><em>*</em></strong>Необходимо добавить, что ошибки выделения памяти могут случиться, и просто выходить из приложения и выкидывать ошибку плохо. Решение зависит от ситуации. Например, если не хватает памяти, то можно подождать некоторое время и после этого опять попытаться выделить память, или использовать для временного хранения файл и переместить туда часть объектов. Или выполнить очистку, сократив используемую память и удалив ненужные объекты.</p>

<p>**Также стоит добавить, что, если <code>malloc</code> не может выделить память и вернёт <code>NULL</code>, не всегда может произойти ошибка при обращении по этому адресу по следующей причине.</p>

<p>В начале адресного пространства одна или несколько страниц памяти защищены операционной системой от записи. Это позволяет выявить ошибки обращения к памяти по нулевому указателю, или указателю, значение которого близко к 0 (да <code>nullptr</code> — это указатель на начало адресного пространства процесса).</p>

<p>В разных операционных системах для этих целей резервируется разное количество памяти. При этом в некоторых ОС это значение можно настраивать. Поэтому нет смысла называть какое-то конкретное число зарезервированных байт памяти. Но чтобы как-то сориентировать читателя, скажу, что в Linux системах типовым значением является 64 Кбайт.</p>

<p>Важно, что, прибавив к нулевому указателю какое-то достаточно большое число, можно «промазать» мимо контрольных страниц памяти и случайно попасть в какие-то незащищенные от записи страницы. Таким образом можно испортить где-то какие-то данные, но операционная система этого не заметит и никакого сигнала / исключения она не сгенерирует.</p>

<p>2. Изменение указателя, который хранит адрес выделенной области памяти. Как уже упоминалось выше, в выделенной области хранятся данные об объекте — его размер. При удалении <code>free</code> получает эту информацию. Однако, если мы изменили указатель, то удаление приведёт к ошибке, например:</p>

<pre><code class="language-cpp">#include &lt;conio.h&gt;
#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;
 
void main() {
    int *p = NULL;
    if (!(p = (int*)malloc(100 * sizeof(int)))) {
        printf("Error");
        exit(1);
    }
    //Изменили указатель
    p++;
    //Теперь free не может найти метаданные об объекте
    free(p);
    //На некоторых компиляторах ошибки не будет
    getch();
}</code></pre>

<p>Таким образом, если указатель хранит адрес, то его не нужно изменять. Для работы лучше создать дополнительную переменную указатель, с которой работать дальше.</p>

<p>3. Использование освобождённой области. Эта ошибка выливается в другую – так называемые висячие указатели (dangling pointers или wild pointers). При удалении объекта забывают изменить значение указателя на NULL (в C++ настоятельно рекомендуется использовать <code>nullptr</code>, который имеет тип указателя в отличии от <code>NULL</code> — константы, которая имеет тип <code>int</code>). В итоге, он хранит адрес области памяти, которой уже нельзя воспользоваться, при этом проверить, валидная эта область или нет, у нас нет возможности.</p>

<pre><code class="language-cpp">#include &lt;conio.h&gt;
#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;
 
void main() {
    const int size = 10;
    int *p = NULL;
    int i;
 
    p = (int*)malloc(size * sizeof(int));
    for (i = 0; i &lt; size; i++) {
        p[i] = i;
    }
    free(p);
    for (i = 0; i &lt; size; i++) {
        printf("%i ", p[i]);
    }
    getch();
}</code></pre>

<p>Эта программа отработает и выведет мусор, или не мусор, или не выведет. Поведение не определено.</p>

<p>Если же мы напишем  <code>free(p); p = NULL;</code>то программа выкинет исключение. Это определённо лучше, чем неопределённое поведение. Если освобождается память и используется указатель в дальнейшем, то обязательно необходимо обнулить его.</p>

<p>4. Освобождение освобождённой памяти.</p>

<pre><code class="language-cpp">#include &lt;conio.h&gt;
#include &lt;stdio.h&gt;
 
void main() {
    int *a, *b;
    a = (int*)malloc(sizeof(int));
    free(a);
    b = (int*)malloc(sizeof(int));
    free(a);
    free(b);
    getch();
}</code></pre>

<p>Здесь дважды вызывается <code>free</code> для переменной <code>a</code>. При этом, переменная <code>a</code> продолжает хранить адрес, который может далее быть передан кому-нибудь для использования. Решение здесь такое же как и раньше - обнулить указатель явно после удаления.</p>

<p>5. Одновременная работа с двумя указателями на одну область памяти. Пусть, например, у нас два указателя <code>p1</code> и <code>p2</code>. Если под первый указатель была выделена память, то второй указатель может запросто скомпрометировать эту область:</p>

<pre><code class="language-cpp">#include &lt;conio.h&gt;
#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;
 
void main() {
    const int size = 10;
    int *p1 = NULL;
    int *p2 = NULL;
    size_t i;
 
    p1 = (int*)malloc(sizeof(int) * size);
    p2 = p1;
 
    for (i = 0; i &lt; size; i++) {
        p1[i] = i;
    }
    p2 = (int*)realloc(p1, size * 5000 * sizeof(int));
    for (i = 0; i &lt; size; i++) {
        printf("%d ", p1[i]);
    }
    printf("\n");
    for (i = 0; i &lt; size; i++) {
        printf("%d ", p2[i]);
    }
    getch();
}</code></pre>

<p>Рассмотрим код ещё раз (8 - 13):</p>

<pre><code class="language-cpp">int *p1 = NULL;
int *p2 = NULL;
size_t i;
 
p1 = (int*)malloc(sizeof(int) * SIZE);
p2 = p1;</code></pre>

<p>Теперь оба указателя хранят один адрес (19 строка): <code>p2 = (int*)realloc(p1, size * 5000 * sizeof(int))</code></p>

<p>А вот здесь происходит непредвиденное. Мы решили выделить под <code>p2</code> новый участок памяти. <code>realloc</code> гарантирует сохранение контента, но вот сам указатель <code>p1</code> может перестать быть валидным. Есть разные ситуации. Во-первых, вызов <code>malloc</code> мог выделить много памяти, часть которой не используется. После вызова ничего не поменяется и <code>p1</code> продолжит оставаться валидным. Если же потребовалось перемещение объекта, то <code>p1</code> может указывать на невалидный адрес (именно это с большой вероятностью и произойдёт в нашем случае). Тогда <code>p1</code> выведет мусор (или же произойдёт ошибка, если <code>p1</code> полезет в недоступную память), в то время как <code>p2</code> выведет старое содержимое <code>p1</code>. В этом случае поведение не определено.</p>

<p>Два указателя на одну область памяти это вообще-то не ошибка. Бывают ситуации, когда без них не обойтись. Но это очередное минное поле для программиста.</p>

<h4><strong>И самое главное</strong></h4>

<p>При вызове функции malloc, realloc и calloc с нулевым размером поведение не определено. Это значит, что может быть возвращён как NULL, так и реальный адрес. Им можно пользоваться, но к нему нельзя применять операцию разадресации. Вызов realloc(NULL, size_t) эквиваленте вызову malloc(size_t). Однако, вызов realloc(NULL, 0) не эквивалентен вызову malloc(0).</p>
