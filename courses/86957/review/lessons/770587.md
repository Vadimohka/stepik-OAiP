<h3>Одномерный динамический массив</h3>

<p>Кроме отдельных динамических объектов в языке C++ мы можем использовать динамические массивы, размер которых, в отличие от фиксированного массива, не должен быть известен во время компиляции. Динамическое выделение массива в языке C++ позволяет нам устанавливать его длину во время выполнения программы.</p>

<p>Для выделения памяти под динамический массив также используется оператор <code>new[]</code>, где в квадратных скобках указывается, сколько массив будет содержать объектов:</p>

<pre><code class="language-cpp">int *numbers = new int[4];</code></pre>

<p>Причем в этом случае оператор <code>new[]</code> также возвращает указатель на объект типа <code>int</code> - первый элемент в созданном массиве.</p>

<p>В типичных реализациях динамический массив может быть значительно больше автоматического массива на стеке. Однако успешное выделение не гарантировано: ограничения связаны с размером массива, доступным адресным пространством и ресурсами системы. Обычное new[] сообщает о неудаче исключением. Следующий пример показывает обработку такой ситуации:</p>

<pre><code class="language-cpp">#include &lt;cstddef&gt;
#include &lt;iostream&gt;
#include &lt;new&gt;

int main() {
    const std::size_t veryBigSize = 1000000000;
    // int automaticArray[veryBigSize]; // такой объект может переполнить стек
    try {
        int* dynamicArray = new int[veryBigSize];
        // Работа с массивом — только после успешного выделения.
        delete[] dynamicArray;
    } catch (const std::bad_alloc&amp;) {
        std::cerr &lt;&lt; "Cannot allocate the array\n";
        return 1;
    }
}</code></pre>

<p>На моём компьютере я получил ошибку уже при выделении автоматического массива размером 4 Мбайт, что обусловлено переполнением стека. Стек переполняется - мы получаем ошибку <code>stack overflow</code>. Однако динамически я могу выделить массив такого размера, т.к. он выделяется не на стеке, а в каком-то абсолютно другом месте в оперативной памяти, которое нам предоставляет ОС.</p>

<h4>Инициализация динамических массивов</h4>

<p>В данном случае определяется массив из четырех элементов типа int, но каждый из них имеет неопределенное значение. Однако мы также можем инициализировать массив значениями:</p>

<pre><code class="language-cpp">int *n1 = new int[4];   // каждый элемент имеет неопределенное значение
int *n2 = new int[4](); // каждый элемент имеет значение по умолчанию - 0
int *n3 = new int[4]{ 1, 2, 3, 4 }; // массив состоит из чисел 1, 2, 3, 4</code></pre>

<p>Число инициализаторов не должно превышать длину массива. Если несоответствие известно при компиляции, такой код не компилируется; при вычисляемой во время выполнения длине обычное new[] может выбросить std::bad_array_new_length. Если значений меньше, оставшиеся элементы int инициализируются нулями. Инициализация динамического массива списком в фигурных скобках доступна с C++11.</p>

<p>В целом после создания динамического массива мы можем работать с ним точно так же, как и с фиксированным, помня, что результат new[] — указатель на первый элемент, а длину массива нужно хранить отдельно:</p>

<pre><code class="language-cpp">int n = 5;  // размер массива
int *p = new int[n]{ 1, 2, 3, 4, 5 };
for (int *q = p; q != p + n; q++) {
    std::cout &lt;&lt; *q &lt;&lt; "\t";
}</code></pre>

<p>Для удаления динамического массива и освобождения занятой им памяти используется оператор <code>delete[]</code>:</p>

<pre><code class="language-cpp">delete [] указатель_на_динамический_массив;</code></pre>

<p>Самая распространенная ошибка, которую совершают новички при работе с динамическим выделением памяти, является использование <code>delete</code> вместо <code>delete[]</code> для удаления динамических массивов. При использовании оператора <code>delete</code> с динамическим массивом, выделенным оператором <code>new[]</code>, мы получим неопределённое поведение (undefined behaviour), поскольку стандарт прямо определяет несовпадение new[] и delete как неопределённое поведение.</p>

<h3>Двумерный динамический массив</h3>

<p>Рассмотрим процесс объявления двумерного динамического массива:</p>

<pre><code class="language-cpp">int nstr = 5; // количество строк
int nstb = 5; // количество столбцов
// объявление двумерного динамического массива на 25 элементов
int** a = new int*[nstr]; // пять строк в массиве
for (int i = 0; i &lt; nstr; ++i) {
    a[i] = new int[nstb]; // и пять столбцов
}
// где a  – массив указателей на выделенный участок памяти 
// под массив целых чисел типа int
</code></pre>

<p>Сначала new int*[nstr] создаёт массив из пяти указателей; его адрес сохраняется в int** a. Затем для каждого указателя a[i] выделяется отдельная строка из пяти int. Получается таблица 5 × 5 из отдельно выделенных строк; переменная a имеет тип int**, а не int[5][5].</p>

<p>Для того, чтобы лучше понимать, как устроен двумерный динамический массив, рассмотрим данную схему:</p>

<p><img alt="" height="2429" name="Frame 20.png" src="https://ucarecdn.stepik.net/5f870e84-3430-4368-b968-7476ca7100e3/-/crop/4563x2429/0,177/-/preview/" width="4563"></p>

<p>Здесь мы можем увидеть, что при обращении к элементу <code>a[i][j]</code> мы на самом деле сначала обращаемся к массиву <code>int** a</code> по индексу <code>i</code>, следовательно, получаем значение, хранящееся в ячейке под этим индексом, а это — некоторый указатель <code>int*</code>. Затем мы обращаемся уже к этому указателю по индексу <code>j</code>, а это не что иное, как значение типа <code>int</code>.</p>

<p>Рассмотрим пример высвобождения памяти, отводимой под двумерный динамический массив.</p>

<pre><code class="language-cpp">// высвобождение памяти, отводимой под двумерный динамический массив:
for (int i = 0; i &lt; nstr; ++i) {
    delete[] a[i]; // удаляем строку
    a[i] = nullptr; // убираем висячий указатель
}
delete[] a; // удаляем сам двумерный массив
a = nullptr; // убираем висячий указатель</code></pre>

<p>Объявление и удаление двумерного динамического массива выполняется с помощью цикла, так как показано выше, необходимо понять и запомнить то, как это делается.</p>

<p>После delete[] удалён массив, а не сама переменная-указатель. Присваивание nullptr отмечает отсутствие массива и позволяет проверить указатель перед использованием. Нулевой указатель нельзя разыменовывать: это неопределённое поведение, а не гарантированное исключение. Другие копии прежнего адреса от такого присваивания не изменятся.</p>

<h3>Работа с динамической памятью в языке С</h3>

<p>Автоматические локальные переменные обычно существуют до выхода из своего блока; в распространённых реализациях для них используется стек. Динамическая память нужна, когда размер становится известен во время выполнения или время хранения требуется контролировать отдельно от блока. Для функций C, рассматриваемых ниже, программист должен явно освобождать успешно выделенные блоки.</p>

<p>В C не поддерживаются такие операторы, как <em>new[]</em> и <em>delete[]</em>. Для выделения памяти в куче в С используется функция <em>malloc</em> (memory allocation) из библиотеки stdlib.h</p>

<pre><code class="language-cpp">void* malloc(size_t size);</code></pre>

<p>Функция выделяет <code>size</code> байтов памяти и возвращает указатель типа <code>void*</code>. При неудаче она возвращает <code>NULL</code>. В языке C результат <code>malloc</code> не требуется явно приводить к указателю на объект; в C++ такое преобразование требует явного приведения. Ниже приведён код C11/C17:</p>

<pre><code class="language-c">#include &lt;stdlib.h&gt;

int main(void) {
    int* p = malloc(100);
    if (p == NULL) {
        return 1;
    }
    free(p);
    return 0;
}</code></pre>

<p>После того, как мы поработали с памятью, необходимо освободить память функцией <code>free</code>.<br>
Используя указатель, можно работать с выделенной памятью как с массивом. Пример: пользователь вводит число – размер массива, создаём массив этого размера и заполняем его квадратами чисел по порядку. После этого выводим и удаляем массив.</p>

<pre><code class="language-c">#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;

int main(void) {
    const unsigned maxNumber = 100;
    unsigned size;
    printf("Enter number from 0 to %u: ", maxNumber);
    if (scanf("%u", &amp;size) != 1 || size &gt; maxNumber) {
        return 1;
    }
    if (size == 0) {
        return 0;
    }
    int* p = malloc(size * sizeof *p);
    if (p == NULL) {
        return 1;
    }
    for (unsigned i = 0; i &lt; size; ++i) {
        p[i] = (int)(i * i);
    }
    for (unsigned i = 0; i &lt; size; ++i) {
        printf("%d ", p[i]);
    }
    printf("\n");
    free(p);
    return 0;
}</code></pre>

<p>Остановимся подробнее на <code>int* p = malloc(size * sizeof *p);</code>.</p>

<p><code>sizeof *p</code> — размер одного элемента <code>int</code>; <code>size * sizeof *p</code> — требуемое число байтов. Оператор <code>sizeof</code> в этом выражении не разыменовывает <code>p</code> во время выполнения. Перед обращением к массиву мы проверяем успешность выделения. После использования освобождаем блок через <code>free(p)</code>.</p>

<p>Теперь представим на рисунке, что у нас происходило. Пусть мы ввели число 5.</p>

<p><img alt="" height="474" name="Frame 21.png" src="https://ucarecdn.stepik.net/476ae5b8-ed17-4498-b3a7-51b21b473a49/-/crop/5661x3693/0,259/-/preview/" width="727"></p>

<p> </p>

<p>При успешном вызове <code>malloc</code> указатель <code>p</code> обозначает начало выделенного блока. Обращаться можно только к допустимым объектам внутри его границ. <code>free(p)</code> освобождает этот блок, после чего обращаться к нему через прежний указатель нельзя. Сама переменная-указатель при этом не обнуляется; её можно явно установить в <code>NULL</code>, если она больше не нужна.</p>

<p>Это похоже на аренду номера в отеле: после сдачи номера старый ключ может остаться у нас, но право пользоваться комнатой уже закончилось. Так и после free сохранённый адрес не даёт права обращаться к прежнему блоку.</p>

<p>Иногда думают, что происходит "создание" или "удаление" памяти. На самом деле происходит только перераспределение ресурсов.</p>

<h4>Освобождение памяти с помощью free</h4>

<p>Теперь рассмотрим, как происходит освобождение памяти. Переменная указатель хранит адрес области памяти, начиная с которого она может им пользоваться. Однако, она не хранит размера этой области. Откуда тогда функция <code>free</code> знает, сколько памяти необходимо освободить?</p>

<p>Очевидно, что информация о размере выделенного участка должна где-то храниться. Есть несколько решений этой проблемы.</p>

<ul>
	<li>Можно создать карту, в которой будет храниться размер выделенного участка. Каждый раз при освобождении памяти компьютер будет обращаться к этим данным и получать нужную информацию.</li>
	<li>Второе решение более распространено. Информация о размере хранится в куче перед самими данными. Таким образом, при выделении памяти резервируется больше места и туда записывается информация о выделенном участке. При освобождении памяти функция <code>free</code> "подсматривает", сколько памяти необходимо удалить.</li>
</ul>

<p>Функция <code>free</code> освобождает память, но при этом не изменяет значение указателя, о чём нужно помнить.</p>

<p>Если мы не используем эту функцию, то динамическая память все равно освободится автоматически при завершении работы программы. Однако все же хорошей практикой является вызов функции <code>free</code>, который позволяет как можно раньше освободить память и не допустить утечки памяти.</p>

<h3>Работа с массивами в языке С</h3>

<p>Динамическое создание одномерного массива мы рассмотрим на примере. Пусть длина массива неизвестна и вводится во время выполнения программы пользователем:</p>

<pre><code class="language-c">#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;

int main(void) {
    unsigned n;
    printf("Size of array (1..100000)=");
    if (scanf("%u", &amp;n) != 1 || n == 0 || n &gt; 100000) {
        return 1;
    }
    int* block = malloc((size_t)n * sizeof *block);
    if (block == NULL) {
        return 1;
    }
    // Здесь можно работать с n элементами после их инициализации.
    free(block);
    block = NULL;
    return 0;
}</code></pre>

<p> </p>

<p>Для динамического создания двумерного массива сначала необходимо создать массив указателей, после чего каждому из элементов этого массива присвоить адрес нового массива.<br>
Для удаления массива необходимо повторить операцию в обратном порядке - удалить сначала подмассивы, а потом и сам массив указателей.</p>

<pre><code class="language-c">#include &lt;stdlib.h&gt;

int main(void) {
    const size_t rowNum = 10, colNum = 10;
    float** p = malloc(rowNum * sizeof *p);
    if (p == NULL) {
        return 1;
    }
    for (size_t i = 0; i &lt; rowNum; ++i) {
        p[i] = malloc(colNum * sizeof *p[i]);
        if (p[i] == NULL) {
            while (i &gt; 0) {
                free(p[--i]);
            }
            free(p);
            return 1;
        }
    }
    // Здесь можно работать с таблицей после инициализации элементов.
    for (size_t i = 0; i &lt; rowNum; ++i) {
        free(p[i]);
    }
    free(p);
    return 0;
}</code></pre>

<p>Сначала создаём массив указателей, а после этого каждому элементу этого массива присваиваем адрес вновь созданного массива. Это значит, что можно:</p>

<ul>
	<li>Создавать массивы "неправильной формы", то есть массив строк, каждая из которых имеет свой размер.</li>
	<li>Работать по отдельности с каждой строкой массива: освобождать память или изменять размер строки.</li>
</ul>

<h4>Функции realloc и calloc</h4>

<p>Функция <code>calloc</code> выделяет место для <code>num</code> элементов по <code>size</code> байт и обнуляет все байты блока. Для массива int это даёт нулевые значения; обнуление байтов не является универсальным способом получить нулевой указатель или значение любого другого типа. При неудаче возвращается NULL.</p>

<pre><code class="language-cpp">void* calloc(size_t num, size_t size);</code></pre>

<p>Ещё одна важная функция – <code>realloc</code> (re-allocation). Она позволяет изменить размер ранее выделенной памяти, адрес которой хранит указатель <code>ptr</code>, и получает в качестве аргументов этот указатель и новый размер памяти в байтах. Если указатель <code>ptr</code> имеет значение <code>NULL</code>, то есть память не выделялась, то действие функции аналогично действию <code>malloc</code>:</p>

<pre><code class="language-cpp">void* realloc(void* ptr, size_t size);</code></pre>

<p>Функция realloc может как использовать ранее выделенный участок памяти, так и новый. При этом не важно, меньше или больше новый размер – менеджер памяти сам решает, где выделять память.</p>

<p><code>calloc</code> выделяет новый обнулённый блок, а <code>realloc</code> изменяет размер ранее выделенного блока. Результат realloc сначала сохраняют во временный указатель: при неудаче с ненулевым размером старый блок остаётся действительным. Ниже n и new_n положительны, а вычисляемые размеры помещаются в size_t:</p>

<pre><code class="language-c">size_t n = 10, new_n = 20;
int* block = malloc(n * sizeof *block);

if (block == NULL || zeroed == NULL) {
    free(block);
    free(zeroed);

}
int* replacement = realloc(block, new_n * sizeof *block);
if (replacement != NULL) {
    block = replacement;
}
// При отказе realloc блок block по-прежнему принадлежит нам.
free(block);
free(zeroed);</code></pre>

Если пользователь ввёл больше слов, то изменяем его размер при помощи функции <code>realloc</code>, чтобы хватило места. Когда пользователь вводит слово end, прекращаем ввод и выводим на печать все слова.</p>

<pre><code class="language-c">#include &lt;stdint.h&gt;
#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;
#include &lt;string.h&gt;

int main(void) {

    char buffer[128];
    int failed = 0;

    }
    while (scanf("%127s", buffer) == 1 &amp;&amp; strcmp(buffer, "end") != 0) {

### Шаг 5 — text (ID 3213210)

[Открыть на Stepik](https://stepik.org/lesson/770587/step/5?unit=773028) · [Исходник step-source](../../raw/step-sources/3213210.json) · [Объект step](../../raw/steps/3213210.json)

<h3>Ошибки при выделении памяти</h3>

<p>Рассмотрим ошибки управления памятью и способы их избежать. Для функций <code>malloc</code>, <code>calloc</code>, <code>realloc</code> и <code>free</code> в этом разделе используются правила C11/C17. Недопустимые операции ниже оставлены только в комментариях; выполняемый код показывает исправленные варианты.</p>

<h4>1. Неудача выделения памяти</h4>

<p>При неудаче <code>malloc</code> и <code>calloc</code> возвращают <code>NULL</code>. Для <code>realloc</code> с ненулевым размером неудача означает, что прежний блок остаётся действительным. Поэтому результат <code>realloc</code> сначала сохраняют во временный указатель. <code>free(NULL)</code> не выполняет действий.</p>

<p>Следующий пример читает слова до <code>end</code> или конца ввода, расширяет таблицу указателей и освобождает все успешно выделенные блоки, в том числе при ошибке:</p>

<pre><code class="language-c">#include &lt;stdint.h&gt;
#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;
#include &lt;string.h&gt;

int main(void) {
    size_t capacity = 10;
    size_t count = 0;
    char** words = malloc(capacity * sizeof *words);
    char buffer[128];
    int failed = 0;
    if (words == NULL) {
        return 1;
    }
    while (scanf("%127s", buffer) == 1 &amp;&amp; strcmp(buffer, "end") != 0) {
        if (count == capacity) {
            if (capacity &gt; SIZE_MAX / sizeof *words - 10) {
                failed = 1;
                break;
            }
            size_t new_capacity = capacity + 10;
            char** replacement = realloc(words, new_capacity * sizeof *words);
            if (replacement == NULL) {
                failed = 1;
                break;
            }
            words = replacement;
            capacity = new_capacity;
        }
        words[count] = malloc(strlen(buffer) + 1);
        if (words[count] == NULL) {
            failed = 1;
            break;
        }
        strcpy(words[count], buffer);
        ++count;
    }
    for (size_t i = 0; i &lt; count; ++i) {
        puts(words[i]);
        free(words[i]);
    }
    free(words);
    if (failed) {
        fputs("Cannot allocate memory\n", stderr);
        return 1;
    }
    return 0;
}</code></pre>

<p>Как реагировать на нехватку памяти, определяет задача: можно завершить текущую операцию, освободить ненужные данные или сообщить пользователю об ошибке. Игнорировать возвращённый <code>NULL</code> нельзя. Разыменование нулевого указателя имеет неопределённое поведение и не гарантирует исключение C++ или сигнал операционной системы. <code>nullptr</code> в C++ имеет отдельный тип <code>std::nullptr_t</code>; он не обозначает доступную ячейку памяти по адресу ноль.</p>

<h4>2. Потеря начала выделенного блока</h4>

<p>В <code>free</code> передают нулевой указатель либо указатель на начало ещё не освобождённого блока, полученный от функции выделения памяти. Указатель на середину массива передавать нельзя. Для обхода удобно хранить отдельный указатель:</p>

<pre><code class="language-c">int* base = malloc(100 * sizeof *base);
if (base == NULL) {
    return 1;
}
int* current = base + 1;
*current = 42;
// free(current); // Ошибка: это не начало выделенного блока.
free(base);
base = NULL;
current = NULL;</code></pre>

<h4>3. Использование освобождённой памяти</h4>

<p>После <code>free</code> время жизни размещённых в блоке объектов заканчивается. Прежний указатель становится висячим (dangling pointer). Обнуление одной переменной не меняет другие копии указателя и не делает доступ через них допустимым.</p>

<pre><code class="language-c">int* p = malloc(sizeof *p);
if (p == NULL) {
    return 1;
}
*p = 42;
free(p);
p = NULL;
// printf("%d", *p); // Ошибка: разыменование NULL также имеет UB.
if (p != NULL) {
    printf("%d", *p);
}</code></pre>

<p>После <code>free(p); p = NULL;</code> проверка <code>p != NULL</code> позволяет пропустить запрещённый доступ. Само присваивание <code>NULL</code> не превращает последующее разыменование в определённое поведение и не обещает исключение.</p>

<h4>4. Повторное освобождение</h4>

<p>Каждый выделенный блок освобождают ровно один раз. Повторный <code>free</code> с прежним ненулевым указателем имеет неопределённое поведение. Обнуление помогает предотвратить повторное освобождение через ту же переменную:</p>

<pre><code class="language-c">int* p = malloc(sizeof *p);
if (p == NULL) {
    return 1;
}
free(p);
p = NULL;
free(p); // Допустимо: free(NULL) не выполняет действий.</code></pre>

<h4>5. Несколько указателей и realloc</h4>

<p>Несколько указателей могут обозначать один блок, но после успешного <code>realloc</code> старый объект освобождён, а действительным является возвращённый указатель на новый объект. Это правило действует даже тогда, когда числовое значение адреса не изменилось. Старые алиасы нужно обновить до дальнейшего использования. При неудаче <code>realloc</code> с ненулевым размером прежний блок и его данные сохраняются.</p>

<pre><code class="language-c">#include &lt;stdio.h&gt;
#include &lt;stdlib.h&gt;

int main(void) {
    int* p1 = malloc(10 * sizeof *p1);
    if (p1 == NULL) {
        return 1;
    }
    for (int i = 0; i &lt; 10; ++i) {
        p1[i] = i;
    }
    int* p2 = p1;
    int* replacement = realloc(p1, 20 * sizeof *p1);
    if (replacement == NULL) {
        free(p1);
        return 1;
    }
    p1 = replacement;
    p2 = p1; // Обновляем алиас после успешного realloc.
    for (int i = 0; i &lt; 10; ++i) {
        printf("%d ", p2[i]);
    }
    free(p1);
    p1 = NULL;
    p2 = NULL;
    return 0;
}</code></pre>

<h4>Нулевой размер: правила C11/C17</h4>

<p>Для <code>malloc(0)</code> и <code>calloc</code> с нулевым общим размером результат определяется реализацией: возвращается <code>NULL</code> либо особый указатель, который можно передать в <code>free</code>, но через который нельзя обращаться к объектам. Это не следует называть неопределённым поведением самого вызова. По правилам C11/C17 <code>realloc(NULL, n)</code> эквивалентен <code>malloc(n)</code>, в том числе при <code>n = 0</code>.</p>

<p>Правила <code>realloc(p, 0)</code> менялись между версиями C. Не используйте нулевой размер как переносимый способ освобождения: когда блок больше не нужен, явно вызовите <code>free(p)</code> и обнулите соответствующие указатели. Все вызовы <code>realloc</code> в исполняемых примерах выше имеют ненулевой размер.</p>

<p>Что использовать: new или malloc?</p>

<p>Краткий ответ: в C++ обычно используют контейнеры и умные указатели, а при ручном управлении объектами — new/delete. В C для динамической памяти применяют функции malloc, calloc, realloc и free.</p>

<p>Сложный ответ: досмотрите эту страницу до конца и увидите разницу между двумя подходами.</p>

<p>Это <strong>дополнительный</strong> шаг про различия между С и С++, <code>malloc</code> и <code>new</code>, <code>free</code> и <code>delete</code>.</p>

<p>Проблемы С API: </p>

<ol>
	<li>Если нам понадобится выделить память и явно указать выравнивание (число, которому должен быть кратен адрес блока), то для этого в C11(и в С++17) добавлен <code>aligned_alloc</code>, но <code>realloc</code> и <code>calloc</code> все ещё не имеют такой функции.</li>
	<li>Как уже было сказано, <code>free</code> принимает только указатель на освобождаемую память, соответственно где-то там хранятся метаданные. Также мы не имеем возможности освободить лишь часть памяти.</li>
	<li><code>malloc</code> в некоторых реализациях использует кэш недавно освобождённых блоков и старается выделить память из него. Выделяет он первый подходящий блок или наименьший подходящий, суть одна - может выделить больше памяти, чем нам необходимо, и не уведомляет об этом.</li>
	<li>realloc - пытается увеличить доступную память без копирования, но в случае неудачи производит выделение нового блока и копирование сохранённого содержимого туда. Проблема в том, что это происходит автоматически. Возникают проблемы с реализацией конструктора перемещения в c++ и self-referential pointer (пока не важно, что это за проблемы).</li>
</ol>

<p>А что же с <code>new</code> вы можете спросить? А <code>new</code> наследует большинство вышеперечисленных проблем, как минимум, потому что многие реализации <code>new</code> используют <code>malloc</code>. Но различия есть:</p>
