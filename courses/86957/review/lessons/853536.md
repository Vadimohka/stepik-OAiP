<h2>Продолжительность хранения и время жизни объекта</h2>
<p><strong>Цель:</strong> различать сам объект-владелец и управляемую им память, выбирать обычное локальное значение, когда динамическое владение не требуется.</p>
<p><strong>Storage duration</strong> — продолжительность хранения: свойство, определяющее минимальный потенциальный срок существования памяти объекта. <strong>Время жизни объекта</strong> связано с его инициализацией и уничтожением. Эти понятия не тождественны: наличие области памяти само по себе не означает, что в ней уже живёт пригодный для использования объект.</p>
<h3>Четыре вида продолжительности хранения</h3>
<ul>
<li><strong>Автоматическая.</strong> Обычные локальные переменные и параметры функций. Полностью построенный локальный объект уничтожается при выходе из своего блока, в том числе при <code>return</code> или раскрутке стека до обработчика исключения. Такое хранение часто реализовано через стек, но стандарт не требует конкретного физического размещения.</li>
<li><strong>Статическая.</strong> В частности, переменные пространства имён и локальные переменные с <code>static</code>. Их память сохраняется в течение программы. Это не означает, что вся инициализация происходит в самом начале: локальный <code>static</code> с динамической инициализацией инициализируется при первом прохождении через объявление.</li>
<li><strong>Потоковая.</strong> Переменные с <code>thread_local</code>: свой экземпляр для каждого потока, а память связана с продолжительностью его выполнения. Построенные экземпляры уничтожаются при завершении потока.</li>
<li><strong>Динамическая.</strong> Память выделяется во время работы программы; обычный <code>new</code> создаёт динамический объект, а соответствующий <code>delete</code> уничтожает его и освобождает память. В прикладном коде этими действиями обычно управляет готовый владеющий тип, например контейнер или умный указатель.</li>
</ul>
<h3>Сначала обычное значение</h3>
<p>Для отдельного значения в функции обычно достаточно <code>int count{0};</code> или <code>Record record{};</code>. Для изменяемой последовательности подходит <code>std::vector</code>. Сам локальный вектор имеет автоматическую продолжительность хранения, а память для его элементов управляется динамически. Его деструктор освобождает эту память автоматически: слово «динамическая» не означает «обязательно освобождаем вручную».</p>
<p>Полная программа возвращает владеющий контейнер по значению:</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;vector&gt;

std::vector&lt;int&gt; make_values() {
    std::vector&lt;int&gt; values{10, 20, 30};
    return values;
}

int main() {
    const std::vector&lt;int&gt; values = make_values();
    std::cout &lt;&lt; values.size() &lt;&lt; ' ' &lt;&lt; values[1] &lt;&lt; '\n';
}
</code></pre>
<p>Вывод: <code>3 20</code>. Результат возвращается как полноценное значение. При разрешённой оптимизации NRVO локальная переменная <code>make_values</code> и результат могут быть одним объектом: тогда он живёт до конца соответствующего блока <code>main</code>. Если NRVO не выполнена, вектор перемещается в результат, а локальный объект-источник уничтожается при выходе из функции. В обоих случаях результат не является ссылкой на уничтоженный локальный объект; в <code>main</code> данные принадлежат полученному вектору. Обычная запись <code>return values;</code> здесь достаточна.</p>
<h3>Учебный разбор сырого указателя</h3>
<p>Следующий фрагмент нужен только для различения времени жизни указателя и объекта. Он предполагает выполнение всех строк без раннего выхода; для владения отдельным динамическим объектом используем <a href="https://stepik.org/lesson/853536/step/3" rel="noopener noreferrer nofollow">std::unique_ptr</a>.</p>
<pre><code class="language-cpp">int* owner = nullptr;
{
    int* another_name = new int{42};
    owner = another_name;
} // Уничтожена переменная-указатель another_name, но не динамический int.

delete owner; // Уничтожен динамический int и освобождена его память.
owner = nullptr;
</code></pre>
<p>Копирование сырого указателя копирует адрес. Оно не создаёт нового объекта и не определяет, кто обязан его уничтожить. Завершение жизни переменной-указателя не вызывает <code>delete</code> для адресуемого объекта.</p>
<h3>Как соединяются хранение и владение</h3>
<p>Локальный вектор показывает, что объект с автоматической продолжительностью хранения может владеть динамической памятью. У сырого указателя такой обязанности нет: конец жизни <code>another_name</code> завершает существование только самой переменной. Неизвестный до выполнения размер последовательности поэтому обычно ведёт к <code>std::vector</code>, а не к отдельному умному указателю на контейнер.</p>
<p>При возвращении значения владение переходит вместе с результатом. При передаче ссылки или адреса доступ остаётся зависимым от существования владельца. Следующий текст объясняет <a href="https://stepik.org/lesson/853536/step/2" rel="noopener noreferrer nofollow">RAII и освобождение ресурса при выходе из блока</a>.</p>

<h2>RAII: ресурс освобождает его владелец</h2>
<p><strong>Цель:</strong> объяснять освобождение ресурсов при обычном выходе, раннем <code>return</code> и обработке исключения; выбирать между локальным объектом и динамическим владением.</p>
<p><strong>RAII</strong> (Resource Acquisition Is Initialization) связывает ресурс с временем жизни объекта-владельца. Владелец получает ресурс при создании или явной передаче владения, а его деструктор освобождает ресурс. Так работают, например, стандартные контейнеры, файловые потоки и умные указатели. Правило относится не только к памяти.</p>
<h3>Почему недостаточно поставить delete в конце функции</h3>
<p>В учебном фрагменте <code>X</code>, <code>should_stop</code> и <code>work</code> обозначают существующие тип и функции; это не готовая программа для запуска:</p>
<pre><code class="language-cpp">X* pointer = new X{};
if (should_stop()) {
    return; // Утечка: динамический X не уничтожен.
}
work();    // Если исключение уходит из функции, delete также пропускается.
delete pointer;
</code></pre>
<p>При выходе из блока уничтожается локальная переменная-указатель, но сырой указатель не вызывает <code>delete</code>. Добавлять освобождение во все ветви вручную неудобно и легко ошибиться при последующих изменениях. Объект-владелец делает освобождение частью своей работы.</p>
<h3>Сначала локальный объект, затем — динамическое владение при необходимости</h3>
<p>Если объект нужен только в текущей функции, начните с <code>X object{};</code>. Если нужно выразить исключительное владение отдельным динамическим объектом, используйте <code>std::unique_ptr</code>; создать его удобно через <code>std::make_unique</code> из <code>&lt;memory&gt;</code>. Если требуется последовательность элементов, чаще подходит контейнер. Эти варианты можно комбинировать.</p>
<p>Полная программа печатает моменты создания и уничтожения. Динамический объект здесь добавлен для сравнения двух способов хранения. Три варианта входных данных — <code>normal</code>, <code>early</code> и <code>throw</code> — дают разобранные ниже пути выполнения.</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;memory&gt;
#include &lt;stdexcept&gt;
#include &lt;string&gt;
#include &lt;utility&gt;

class Resource {
public:
    explicit Resource(std::string name) : name_{std::move(name)} {
        std::cout &lt;&lt; "create " &lt;&lt; name_ &lt;&lt; '\n';
    }

    ~Resource() {
        std::cout &lt;&lt; "destroy " &lt;&lt; name_ &lt;&lt; '\n';
    }

private:
    std::string name_;
};

void process(const std::string&amp; mode) {
    Resource local{"local"};
    auto owner = std::make_unique&lt;Resource&gt;("dynamic");

    if (mode == "early") {
        std::cout &lt;&lt; "early return\n";
        return;
    }
    if (mode == "throw") {
        throw std::runtime_error{"stop"};
    }
    std::cout &lt;&lt; "normal end\n";
}

int main() {
    std::string mode;
    if (!(std::cin &gt;&gt; mode) ||
        (mode != "normal" &amp;&amp; mode != "early" &amp;&amp; mode != "throw")) {
        return 1;
    }

    try {
        process(mode);
    } catch (const std::runtime_error&amp; error) {
        std::cout &lt;&lt; "caught " &lt;&lt; error.what() &lt;&lt; '\n';
    }
    std::cout &lt;&lt; "done\n";
}
</code></pre>
<p>При вводе <code>early</code> вывод такой:</p><pre>create local
create dynamic
early return
destroy dynamic
destroy local
done
</pre>
<p>При вводе <code>throw</code>:</p><pre>create local
create dynamic
destroy dynamic
destroy local
caught stop
done
</pre>
<p>Оба полностью построенных локальных объекта уничтожаются в обратном порядке создания: сначала <code>owner</code>, который уничтожает свой динамический <code>Resource</code>, затем <code>local</code>. При исключении это происходит во время раскрутки стека до показанного обработчика. При обычном завершении вместо <code>early return</code> печатается <code>normal end</code>; порядок освобождения тот же. Если ввод отсутствует или команда неизвестна, программа завершается с кодом 1 до создания ресурсов.</p>
<p>Разбор касается обычного выхода и раскрутки стека до найденного обработчика. Деструкторы локальных объектов не обещаны при аварийном завершении процесса или принудительном прекращении программы. Если конструктор самого владельца не завершился, его деструктор не вызывается; уже построенные подобъекты очищаются по правилам обработки исключений.</p>
<h3>Владение и доступ — разные обязанности</h3>
<p>Владелец отвечает за завершение времени жизни ресурса. Функция, которой нужно только прочитать объект, обычно принимает <code>const X&amp;</code>; чтобы изменить его — <code>X&amp;</code>. Сырой указатель подходит для невладеющего доступа, в том числе когда допустимо отсутствие объекта. Такой доступ не продлевает время жизни объекта. Умный указатель помогает выразить владение, но не делает любой сохранённый адрес автоматически безопасным.</p>
<h3>Разбор ответственности за освобождение</h3>
<p>В <code>process</code> нет ручного <code>delete</code>: освобождение выполняют деструкторы. Динамический ресурс уничтожается раньше <code>local</code>, потому что его владелец <code>owner</code> был построен позже и разрушается первым. Сам по себе вид хранения не устанавливает этот порядок; его задаёт время жизни владельцев в показанной области.</p>
<p>Функции, которая только печатает живой объект, обычно достаточно <code>const X&amp;</code>. Передача <code>unique_ptr</code> по значению выражала бы другую обязанность — получить владение. Этот выбор интерфейса разобран в <a href="https://stepik.org/lesson/853536/step/3" rel="noopener noreferrer nofollow">следующей полной программе</a>.</p>

<h2>std::unique_ptr: один владелец, несколько способов доступа</h2>
<p><strong>Цель:</strong> создавать динамический объект через <code>std::make_unique</code>, передавать владение и отличать эту передачу от временного доступа к живому объекту.</p>
<p><code>std::unique_ptr&lt;T&gt;</code> из <code>&lt;memory&gt;</code> выражает исключительное владение. Непустой владелец уничтожает управляемый объект при своём уничтожении или замене ресурса. Для обычного <code>std::unique_ptr&lt;T&gt;</code> со стандартным deleter это означает вызов <code>delete</code>. Пустой указатель не уничтожает никакого объекта.</p>
<p>Основной способ создания отдельного динамического объекта — <code>std::make_unique&lt;T&gt;(аргументы_конструктора)</code>, доступный с C++14. Эта функция создаёт объект и сразу возвращает его владельца. Для обычного локального значения умный указатель не требуется: <code>T value{};</code> остаётся хорошим выбором.</p>
<h3>Полная программа: доступ не передаёт владение</h3>
<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;memory&gt;
#include &lt;utility&gt;

struct Record {
    int score{0};
};

void print_score(const Record&amp; record) {
    std::cout &lt;&lt; record.score &lt;&lt; '\n';
}

int main() {
    Record local{10};
    print_score(local);

    auto first = std::make_unique&lt;Record&gt;();
    first-&gt;score = 42;
    Record* observer = first.get();
    print_score(*first);

    auto second = std::move(first);
    std::cout &lt;&lt; std::boolalpha &lt;&lt; static_cast&lt;bool&gt;(first) &lt;&lt; ' '
              &lt;&lt; static_cast&lt;bool&gt;(second) &lt;&lt; '\n';
    print_score(*observer);

    second.reset();
    observer = nullptr;
    std::cout &lt;&lt; static_cast&lt;bool&gt;(second) &lt;&lt; '\n';
}
</code></pre>
<p>Вывод:</p><pre>10
42
false true
42
false
</pre>
<ul>
<li><code>print_score(const Record&amp;)</code> только читает объект. Она одинаково работает с локальным значением и с объектом, которым владеет умный указатель.</li>
<li><code>first-&gt;score</code> и <code>*first</code> обращаются к объекту. В этих строках непустота известна: <code>make_unique</code> успешно завершился и владение ещё не передавалось.</li>
<li><code>first.get()</code> возвращает адрес без передачи владения. <code>observer</code> не обязан и не должен вызывать <code>delete</code>.</li>
<li><code>auto second = std::move(first);</code> передаёт владение. После такого конструктора перемещения <code>first</code> гарантированно пуст. Это конкретная гарантия <code>unique_ptr</code>, а не общее правило для всех перемещённых объектов.</li>
<li>Сам объект <code>Record</code> при передаче владения не перемещается в новую область памяти, поэтому <code>observer</code> всё ещё годится для доступа, пока объект жив.</li>
<li><code>second.reset();</code> уничтожает объект и делает владельца пустым. С этого момента прежний адрес непригоден для разыменования. Присваивание <code>observer = nullptr;</code> очищает только эту переменную; другие сохранённые адреса сами не обновятся.</li>
</ul>
<p>Константность владельца и объекта также различается: через <code>const std::unique_ptr&lt;Record&gt;</code> можно изменять живой <code>Record</code>, но нельзя заменить владение вызовом <code>reset</code>. Тип <code>std::unique_ptr&lt;const Record&gt;</code> запрещает изменение <code>Record</code> через этот доступ. Это та же граница константности, что у указателя и адресуемого им объекта.</p>
<h3>Пустое состояние и операции</h3>
<p><code>std::unique_ptr&lt;Record&gt; empty;</code> создаёт пустого владельца. Если указатель может быть пуст, сначала проверьте <code>if (empty)</code>, а затем используйте <code>*</code> или <code>-&gt;</code>. Проверка не нужна повторно в каждой строке, когда непустота уже следует из логики программы. Обычная запись <code>bool flag = empty;</code> недопустима: преобразование к <code>bool</code> явное. В условии <code>if</code> оно разрешено; для отдельного значения можно написать <code>static_cast&lt;bool&gt;(empty)</code>.</p>
<p>Копирование <code>unique_ptr</code> запрещено: два владельца не должны независимо удалять один объект. Для передачи владения используйте перемещение, для временного доступа — ссылку или невладеющий указатель. Не создавайте второй <code>unique_ptr</code> из <code>first.get()</code> и не вызывайте <code>delete first.get()</code>: это нарушает единственность владения и может привести к повторному удалению.</p>
<p>Умный указатель управляет временем жизни, но не проверяет корректность любого доступа. Разыменование пустого владельца или невладеющего указателя после уничтожения объекта недопустимо. Получая ссылку или адрес, всегда выясняйте, кто сохраняет объект живым и до какого момента.</p>
<h3>Почему передача доступа не меняет владельца</h3>
<p><code>print_score</code> принимает ссылку, потому что для печати не должна решать, когда уничтожать <code>Record</code>. Конструирование <code>second</code> перемещением меняет владельца, но сохраняет адрес и жизнь самого <code>Record</code>; поэтому невладеющий <code>observer</code> всё ещё пригоден. <code>reset</code> завершает жизнь объекта, и сохранённые адреса больше не дают права его разыменовывать.</p>
<p>Запись <code>auto second = first;</code> требовала бы запрещённого копирования <code>unique_ptr</code> и не компилировалась бы. Несколько функций могут читать один объект по ссылке, пока его удерживает единственный владелец; общий доступ сам по себе не требует <code>shared_ptr</code>. Различие с <a href="https://stepik.org/lesson/853537/step/1" rel="noopener noreferrer nofollow">совместным владением</a> состоит в ответственности за время жизни.</p>

<h2>Учебная реализация исключительного владения</h2>
<p><strong>Цель:</strong> проследить, как деструктор и операции перемещения сохраняют правило «у динамического объекта один владелец», и объяснить запрет копирования.</p>
<p>Ниже сохранён низкоуровневый разбор устройства владельца. <code>LearningOwner</code> — учебный класс для <strong>одного объекта</strong>, созданного через обычный <code>new T</code>. В рабочем коде выбирайте <code>std::unique_ptr</code> и <code>std::make_unique</code>. Учебный класс не поддерживает массивы, пользовательские deleter, преобразования между типами владельцев и полный интерфейс стандартного класса.</p>
<p>Договоримся о предусловиях: переданный ненулевой адрес принадлежит только этому владельцу; объект не удаляется извне; деструктор <code>T</code> не выбрасывает исключений; разыменование допустимо только у непустого владельца.</p>
<p>Полная программа C++17/20. Проверки <code>assert</code> являются частью авторского разбора контракта; они включены, когда не определён <code>NDEBUG</code>.</p>
<pre><code class="language-cpp">#include &lt;cassert&gt;
#include &lt;iostream&gt;
#include &lt;utility&gt;

template&lt;class T&gt;
class LearningOwner {
public:
    explicit LearningOwner(T* pointer = nullptr) noexcept : pointer_{pointer} {}

    ~LearningOwner() {
        delete pointer_;
    }

    LearningOwner(const LearningOwner&amp;) = delete;
    LearningOwner&amp; operator=(const LearningOwner&amp;) = delete;

    LearningOwner(LearningOwner&amp;&amp; other) noexcept : pointer_{other.pointer_} {
        other.pointer_ = nullptr;
    }

    LearningOwner&amp; operator=(LearningOwner&amp;&amp; other) noexcept {
        if (this != &amp;other) {
            T* incoming = other.pointer_;
            other.pointer_ = nullptr;
            delete pointer_;
            pointer_ = incoming;
        }
        return *this;
    }

    explicit operator bool() const noexcept {
        return pointer_ != nullptr;
    }

    T&amp; operator*() const {
        return *pointer_;
    }

    T* operator-&gt;() const noexcept {
        return pointer_;
    }

private:
    T* pointer_;
};

struct Item {
    inline static int alive{0};
    int value;
    LearningOwner&lt;Item&gt; child;

    explicit Item(int initial) : value{initial} {
        ++alive;
    }

    ~Item() {
        --alive;
    }
};

int main() {
    {
        LearningOwner&lt;Item&gt; first{new Item{42}};
        LearningOwner&lt;Item&gt; second{std::move(first)};
        assert(!first &amp;&amp; second);

        LearningOwner&lt;Item&gt; third{new Item{7}};
        third = std::move(second);
        assert(!second &amp;&amp; Item::alive == 1);

        LearningOwner&lt;Item&gt;&amp; same = third;
        third = std::move(same);
        assert(third &amp;&amp; Item::alive == 1);
        assert((*third).value == 42);
        std::cout &lt;&lt; third-&gt;value &lt;&lt; '\n';
    }
    assert(Item::alive == 0);
    std::cout &lt;&lt; Item::alive &lt;&lt; '\n';

    {
        LearningOwner&lt;Item&gt; root{new Item{1}};
        root-&gt;child = LearningOwner&lt;Item&gt;{new Item{2}};
        assert(Item::alive == 2);

        root = std::move(root-&gt;child);
        assert(root &amp;&amp; root-&gt;value == 2 &amp;&amp; Item::alive == 1);
        std::cout &lt;&lt; root-&gt;value &lt;&lt; '\n';
    }
    assert(Item::alive == 0);
    std::cout &lt;&lt; Item::alive &lt;&lt; '\n';
}
</code></pre>
<p>Вывод:</p><pre>42
0
2
0

<h3>Что обеспечивает единственность владения</h3>
<ol>
<li><strong>Деструктор</strong> вызывает <code>delete</code> один раз для своего адреса. Для <code>nullptr</code> такая операция безопасна.</li>
<li><strong>Копирование запрещено</strong> через <code>= delete</code>. Простое копирование адреса создало бы двух независимых владельцев одного объекта.</li>
<li><strong>Конструктор перемещения</strong> забирает адрес и обнуляет источник. Его будущий деструктор больше не удалит переданный объект.</li>
<li><strong>Присваивание перемещением</strong> сначала сохраняет входящий адрес в локальную переменную и обнуляет источник, затем освобождает прежний ресурс получателя и устанавливает сохранённый адрес. Этот порядок нужен, если источник — поле внутри удаляемого объекта, как в <code>root = std::move(root-&gt;child)</code>: после удаления родителя нельзя читать его поле. Проверка <code>this != &amp;other</code> отдельно сохраняет объект при присваивании самому себе.</li>
<li><strong>noexcept</strong> обозначает обещание не выбрасывать исключений. В этих операциях выполняются только работа с адресами и удаление объекта с указанным выше невыбрасывающим деструктором.</li>
</ol>
<p>Счётчик <code>Item::alive</code> и проверки <code>assert</code> помогают увидеть важные переходы: после замены ресурса жив только один <code>Item</code>, после выхода из блока — ни одного. Псевдоним <code>same</code> намеренно проверяет случай самоприсваивания перемещением. Второй блок проверяет передачу владения от дочернего поля родительскому владельцу: родитель удаляется, а дочерний объект остаётся жив и становится новым корнем. Эти проверки иллюстрируют контракт примера и не превращают учебный класс в полноценную замену стандартной библиотеке.</p>
<p>Здесь специальные функции написаны вручную, потому что сам класс непосредственно управляет ресурсом. Обычный прикладной класс с полями <code>std::string</code>, <code>std::vector</code> или <code>std::unique_ptr</code> обычно следует правилу нуля и поручает эту работу готовым владельцам.</p>
<h3>Границы контракта учебного владельца</h3>
<p>Обнуление источника после передачи адреса сохраняет единственность владения. Без него деструкторы двух владельцев попытались бы удалить один объект. Освобождение прежнего ресурса получателя при присваивании предотвращает утечку. <code>LearningOwner&lt;int&gt;</code> нельзя передать результат <code>new int[10]</code>: здесь реализован <code>delete</code> для одиночного объекта, а массив требует <code>delete[]</code>.</p>
<p>Шаблон <code>template&lt;class T&gt;</code> позволяет одному определению описывать владельца разных типов. Это дополнительная иллюстрация внутреннего устройства, а для использования стандартного <code>unique_ptr</code> писать такой класс не требуется. Совместное владение потребует другого инварианта, разобранного в <a href="https://stepik.org/lesson/853537/step/1" rel="noopener noreferrer nofollow">следующем уроке</a>.</p>
