<h3>Как C++ управляет памятью?</h3>

<p>Для того чтобы понять, как работает управление памятью в C++, необходимо разобраться в понятии <strong>storage duration</strong> (длительность хранения). Это свойство объекта, определяющее минимальную потенциальную продолжительность существования отведённой ему памяти. Продолжительность хранения и время жизни самого объекта связаны, но не тождественны.</p>

<p>В C++ существует четыре вида storage duration:</p>

<ul>
	<li><strong>Автоматическая storage duration</strong>. Обычный локальный объект инициализируется, когда выполнение доходит до его объявления, и уничтожается при выходе из блока, в котором он создан. Его память обычно размещается на стеке, но конкретный способ размещения стандартом не фиксируется.</li>
</ul>

<pre><code class="language-cpp">class X {
    int a;
    double b;
public:
    void func() {};
};

int main() {
    X object; // В памяти создается объект класса
    {
        X object2; // Ещё один объект размещён в памяти
        // В данный момент в памяти размещены и доступны оба объекта
    } // Здесь object2 выходит из области видимости и уничтожается
} //Здесь уничтожается object</code></pre>

<ul>
	<li><strong>Статическая</strong> связана с использованием спецификаторов static и extern. Память таких объектов сохраняется на протяжении программы. Инициализация не обязана происходить при запуске: например, локальный static обычно инициализируется при первом прохождении через его объявление.</li>
	<li><strong>Storage duration потока</strong> устанавливается спецификатором thread_local. Память такого объекта связана с соответствующим потоком; для каждого потока существует отдельный экземпляр. Инициализация может быть отложенной, а построенные объекты уничтожаются при завершении потока.</li>
	<li><strong>Динамическая storage duration</strong> связана с выделением и освобождением памяти во время выполнения программы с помощью ключевых слов new и delete. Объекты с динамической storage duration создаются во время выполнения программы и могут существовать до тех пор, пока не освободятся или до тех пор, пока не завершится выполнение программы.
	<pre><code class="language-cpp">X* ptr = nullptr; //Указатель, не указывающий ни на что
{
    X* ptr2 = new X(); // Размещение объекта класса Х в памяти
                       // (также известной как динамическая память,
                       // зачастую реализованной в виде кучи). ptr2 - указатель на этот объект
    ptr = ptr2; //ptr указывает на тот же объект

} // Указатель ptr2 выходит из области видимости и уничтожается, 
  // но объект, на который он указывает, остаётся в памяти

delete ptr; // Происходит вызов деструктора, а после этого объект, 
            // на который указывает ptr, удаляется из памяти</code></pre>
	</li>
</ul>

<p>Можно сказать, что в случае с автоматической storage duration память освобождается автоматически, а в случае с динамической – вручную. Однако почему не использовать всегда автоматическую память?</p>

<p>Размер каждого обычного локального объекта задаётся его типом. Если количество элементов определяется во время выполнения или данные должны пережить область видимости, в которой созданы, удобно использовать динамическое хранение. При этом локальный std::vector или умный указатель сам может иметь автоматическую продолжительность хранения, а управляемая им память — динамическую. Освобождение этой памяти тогда выполняет деструктор владельца.</p>

<h3>Что такое умные указатели и зачем они нужны?</h3>

<p>Используя динамическую память в C++, объекты могут выходить за пределы области видимости, где они были созданы, и иметь определяемый во время выполнения размер, но это может привести к проблемам с освобождением памяти при использовании операторов new и delete.</p>

<pre><code class="language-cpp">void func3() {
    X* ptr = new X();
    if (func()) {
        func2();
        return;
    }
    delete ptr;
}</code></pre>

<p>На первый взгляд, здесь всё хорошо, но есть нюансы:</p>

<p>·         Если <code>func()</code> выбросит исключение, то управление не дойдёт до delete и память не освободится.</p>

<p>·         Если <code>func()</code> вернёт true, то после выполнения <code>func2()</code> управление покинет функцию, но память не освободится, т.к. автор кода забыл добавить delete внутрь условия.</p>

<p>·         Если бы автор забыл и последний delete, память тоже не освободилась бы.</p>

<p>Тут встретились C++ программисты и решили, что больше не будут использовать операторы new/delete. Для владения динамическими объектами предпочитают RAII: контейнеры и умные указатели освобождают ресурс в своих деструкторах. Это связано не только с проблемами, связанными с использованием new/delete, но и с проблемой разделения указателей, которые владеют объектом (owning pointer), и указателей, которые используют объект (non owning pointer).</p>

<p>По одному типу простого указателя (raw pointer) нельзя определить, какой указатель владеет объектом и должен отвечать за вызов операторов new/delete, а какой только использует объект. Это может приводить к проблемам с утечками памяти и безопасностью. Взгляните на следующую декларацию:</p>

<p> <code>int* func();</code></p>

<p>Главная проблема здесь, что тому, кто будет вызывать функцию, совершенно неясно, должен он вызвать delete для возвращаемого указателя или за это ответственен код где-то в другой части программы. Иначе говоря, здесь не видно, является указатель владеющим или использующим.</p>

<p>Все вышеназванные проблемы изящно решаются умными указателями. Умные указатели в C++ – это не что-то магическое, встроенное в синтаксис языка, а не более чем набор классов из стандартной библиотеки. Разберёмся с ними один за одним.</p>

<p><strong><em>Благодаря умным указателям можно избежать утечек памяти и обеспечить безопасное ее использование.</em></strong></p>

<p>Умный указатель нужен, когда нужно выразить владение динамическим объектом. Для обычного локального значения зачастую достаточно самого объекта, а для невладеющего доступа подходят ссылка или сырой указатель. Поэтому сначала определите, кто отвечает за время жизни ресурса, затем выбирайте подходящий способ хранения и доступа.</p>

<h2><strong><em>std::unique</em></strong><strong><em>_</em></strong><strong><em>ptr</em></strong></h2>

<p>Первым умным указателем, который будет рассмотрен, является <code>std::unique_ptr. </code>Он указывает на объект в динамической памяти и автоматически уничтожает его при выходе из области видимости. Ниже приведен пример кода:</p>

<pre><code class="language-cpp">{
    std::unique_ptr&lt;X&gt; ptr(new X()); // Объект класса х создан в динамической памяти
} // Здесь указатель ptr покидает свою область видимости и уничтожается,
  // но перед этим удаляет из памяти объект, на который указывает</code></pre>

<p>Когда сам владеющий std::unique_ptr уничтожается, его деструктор вызывает deleter для хранимого ненулевого указателя. В показанном варианте со стандартным deleter это удаляет объект и освобождает его память.</p>

<p>Необходимо понимать, что внутри умные указатели все еще используют операторы new/delete, но они позволяют программисту избежать использования этих операторов вручную, и, следовательно, защищают от ошибок.</p>

<p>Поскольку<code> std::unique_ptr</code> разработан с учетом семантики перемещения, то семантика копирования по умолчанию отключена. Для передачи владения в другой std::unique_ptr используют перемещение. Чтобы лишь временно дать доступ к объекту, его можно передать по ссылке или указателю без передачи владения.</p>

<h4>Доступ к объекту, который хранит умный указатель</h4>

<p>Умный указатель <code>std::unique_ptr</code> имеет <strong>перегруженные операторы</strong> <code>*</code> и <code>-&gt;</code>, которые используются для доступа к хранимым объектам. Оператор <code>*</code> возвращает ссылку на управляемый ресурс, а оператор <code>-&gt;</code> возвращает указатель.</p>

<p>Однако не всегда умный указатель <code>std::unique_ptr</code>может управлять объектом: это может произойти, если объект был создан пустым (с использованием конструктора по умолчанию или при передаче в него значения <code>nullptr</code>)), либо если ресурс, которым он управлял, был перемещен в другой​​​​​​​ <code>std::unique_ptr</code>. Поэтому перед использованием какого-либо из этих операторов необходимо проверить, управляет ли <code>std::unique_ptr</code> ресурсом. К счастью, это делается легко: умный указатель​​​​​​​ <code>std::unique_ptr</code> имеет <code>explicit operator bool()</code>. Этот оператор участвует в контекстном преобразовании, например в <code>if (ptr)</code>, и возвращает true, если ​​​​​​​<code>std::unique_ptr</code>хранит ненулевой указатель. Обычная инициализация <code>bool b = ptr;</code> недопустима; для неё нужно явное <code>static_cast&lt;bool&gt;(ptr)</code>.</p>

<p>Существует два способа неправильного использования <code>std::unique_ptr,</code> которых легко избежать. Во-первых, не позволяйте нескольким классам «владеть» одним и тем же ресурсом. Например:</p>

<pre><code class="language-cpp">X* item = new X;
std::unique_ptr&lt;X&gt; item1(item);
std::unique_ptr&lt;X&gt; item2(item);</code></pre>

<p>Хотя это синтаксически допустимо, конечным результатом будет то, что и <code>item1</code>, и <code>item2 </code>попытаются удалить объект X, что приведет к неопределенному поведению/результатам.</p>

<p>Во-вторых, не удаляйте выделенный ресурс вручную из-под <code>std::unique_ptr</code>:</p>

<pre><code class="language-cpp">X* item = new X;
std::unique_ptr&lt;X&gt; item1(item);
delete item;</code></pre>

<p>Если вы это сделаете, <code>std::unique_ptr</code> попытается удалить уже удаленный ресурс, что опять приведет к неопределенному поведению/результатам.</p>

<h3>Так можно реализовать аналог класса std::unique_ptr.</h3>

<pre><code class="language-cpp">// Учебный вариант для одиночного объекта T (не для массива).
template&lt;class T&gt;
class unique_ptr {
private:
    T* m_ptr;

public:
    explicit operator bool() const {
        return m_ptr != nullptr;
    }

    explicit unique_ptr(T* ptr = nullptr) {
        m_ptr = ptr;
    }

    // Деструктор позаботится об удалении указателя
    ~unique_ptr() {
         delete m_ptr;
    }

    // Конструктор перемещения, который передает право собственности на x.m_ptr в m_ptr
    unique_ptr(unique_ptr&amp;&amp; x) {
        m_ptr = x.m_ptr;
        x.m_ptr = nullptr;
    }

    unique_ptr(const unique_ptr&amp; x) = delete;

    unique_ptr&amp; operator=(const unique_ptr&amp; a) = delete;

    // Оператор присваивания перемещением, который передает право собственности на x.m_ptr в m_ptr
    unique_ptr&amp; operator=(unique_ptr&amp;&amp; x) {
        // Проверка на самоприсваивание
        if (&amp;x == this)
            return *this;

        // Удаляем всё, что к этому моменту может хранить указатель 
        delete m_ptr;

        // Передаем право собственности на x.m_ptr в m_ptr
        m_ptr = x.m_ptr;
        x.m_ptr = nullptr; // мы поговорим об этом чуть позже

        return *this;
    }

    T&amp; operator*() const {
        return *m_ptr;
    }

    T* operator-&gt;() const {
        return m_ptr;
    }

    bool isNull() const { 
        return m_ptr == nullptr;
    }
};
</code></pre>
