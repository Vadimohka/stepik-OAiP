<h3>Как C++ управляет памятью?</h3>

<p>Для того чтобы понять, как работает управление памятью в C++, необходимо разобраться в понятии <strong>storage duration</strong> (длительность хранения). Это свойство объекта, которое описывает, когда он создается в памяти и когда ее освобождает.</p>

<p>В C++ существует четыре вида storage duration:</p>

<ul>
	<li><strong>Автоматическая storage duration</strong>. Объект размещается в автоматической памяти, обычно в виде стека, когда управление входит в область видимости объекта (scope), и удаляется из памяти, когда управление покидает эту область и вызывается деструктор объекта.</li>
</ul>

<pre><code class="language-cpp">class X {
    int a;
    double b;
public:
    void func() {};
};

int main() {
    X object; // В памяти создается объект класса
    {
        X object2; // Ещё один объект размещён в памяти
        // В данный момент в памяти размещены и доступны оба объекта
    } // Здесь object2 выходит из области видимости и уничтожается
} //Здесь уничтожается object</code></pre>

<ul>
	<li><strong>Статическая</strong> связана с использованием спецификаторов static и extern. Объекты, которые имеют статическую длительность хранения, создаются при запуске программы и удаляются при её завершении.</li>
	<li><strong>Storage duration потока</strong> устанавливается спецификатором thread_local. Имеющие эту storage duration объекты создаются при старте соответствующего потока и удаляются при его завершении.</li>
	<li><strong>Динамическая storage duration</strong> связана с выделением и освобождением памяти во время выполнения программы с помощью ключевых слов new и delete. Объекты с динамической storage duration создаются во время выполнения программы и могут существовать до тех пор, пока не освободятся или до тех пор, пока не завершится выполнение программы.
	<pre><code class="language-cpp">X* ptr nullptr; //Указатель, не указывающий ни на что
{
    X* ptr2 = new x(); // Размещение объекта класса Х в памяти
                       // (также известной как динамическая память,
                       // зачастую реализованной в виде кучи). ptr2 - указатель на этот объект
    ptr = ptr2; //ptr указывает на тот же объект

} // Указатель ptr2 выходит из области видимости и уничтожается, 
  // но объект, на который он указывает, остаётся в памяти

delete ptr; // Происходит вызов деструктора, а после этого объект, 
            // на который указывает ptr, удаляется из памяти</code></pre>
	</li>
</ul>

<p>Можно сказать, что в случае с автоматической storage duration память освобождается автоматически, а в случае с динамической – вручную. Однако, почему не использовать всегда автоматическую память.</p>

<p>Ограничением автоматической памяти является то, что необходимо заранее на этапе компиляции знать, сколько памяти понадобится, что не всегда возможно. Кроме того, иногда нужно, чтобы объект оставался в памяти и после выхода из области видимости, в которой был создан, что также невозможно при размещении объекта на стеке. Для обхода этих ограничений используется динамическая память, о которой мы и поговорим сегодня.</p>

<h3>Что такое умные указатели и зачем они нужны?</h3>

<p>Используя динамическую память в C++, объекты могут выходить за пределы области видимости, где они были созданы, и иметь определяемый во время выполнения размер, но это может привести к проблемам с освобождением памяти при использовании операторов new и delete.</p>

<pre><code class="language-cpp">void func3() {
    X* ptr = new X();
    if (func()) {
        func2();
        return;
    }
    delete ptr;
}</code></pre>

<p>На первый взгляд, здесь всё хорошо, но есть нюансы:</p>

<p>·         Если <code>func()</code> выбросит исключение, то управление не дойдёт до delete и память не освободится.</p>

<p>·         Если <code>func()</code> вернёт true, то после выполнения <code>func2()</code> управление покинет функцию, но память не освободится, т.к. автор кода забыл добавить delete внутрь условия.</p>

<p>·         Если бы автор забыл delete также в 6-й строке, память тоже не освободилась бы.</p>

<p>Тут встретились C++ программисты и решили, что больше не будут использовать операторы new/delete. Вместо этого они придумали правило: всегда использовать умные указатели. Это связано не только с проблемами, связанными с использованием new/delete, но и с проблемой разделения указателей, которые владеют объектом (owning pointer), и указателей, которые используют объект (non owning pointer).</p>

<p>При использовании простых указателей (raw pointers) невозможно определить, какой указатель владеет объектом и должен отвечать за вызов операторов new/delete, а какой только использует объект. Это может приводить к проблемам с утечками памяти и безопасностью. Взгляните на следующую декларацию:</p>

<p> <code>int* func();</code></p>

<p>Главная проблема здесь, что тому, кто будет вызывать функцию, совершенно неясно, должен он вызвать delete для возвращаемого указателя или за это ответственен код где-то в другой части программы. Иначе говоря, здесь не видно, является указатель владеющим или использующим.</p>

<p>Все вышеназванные проблемы изящно решаются умными указателями. Умные указатели в C++ – это не что-то магическое, встроенное в синтаксис языка, а не более чем набор классов из стандартной библиотеки. Разберёмся с ними один за одним.</p>

<p><strong><em>Благодаря умным указателям можно избежать утечек памяти и обеспечить безопасное ее использование.</em></strong></p>

<p><strong><em>Нет таких ситуаций в которых не нужно было бы применять умных указателей. Вопрос скорее нужно поставить так - какой тип умного указателя нужно применить в той или иной ситуации?</em></strong></p>

<h2><strong><em>std::unique</em></strong><strong><em>_</em></strong><strong><em>ptr</em></strong></h2>

<p>Первым умным указателем, который будет рассмотрен, является <code>std::unique_ptr. </code>Он указывает на объект в динамической памяти и автоматически уничтожает его при выходе из области видимости. Ниже приведен пример кода:</p>

<pre><code class="language-cpp">{
    std::unique_ptr&lt;X&gt; ptr(new X()); // Объект класса х создан в динамической памяти
} // Здесь указатель ptr покидает свою область видимости и уничтожается,
  // но перед этим удаляет из памяти объект, на который указывает</code></pre>

<p>Когда объект, управляемый<code>std::unique_ptr</code> выходит из области видимости, то утечки памяти не происходит, так как деструктор умного указателя вызывает оператор<code>delete </code>для объекта, на который он ссылается, и тем самым освобождает память.</p>

<p>Необходимо понимать, что внутри умные указатели все еще используют операторы new/delete, но они позволяют программисту избежать использования этих операторов вручную, и, следовательно, защищают от ошибок.</p>

<p>Поскольку<code> std::unique_ptr</code> разработан с учетом семантики перемещения, то семантика копирования по умолчанию отключена. Если нужно передать объект, управляемый <code>std::unique_ptr,</code> то необходимо использовать семантику перемещения.</p>

<h4>Доступ к объекту, который хранит умный указатель</h4>

<p>Умный указатель <code>std::unique_ptr</code> имеет <strong>перегруженные операторы</strong> <code>*</code> и <code>-&gt;</code>, которые используются для доступа к хранимым объектам. Оператор <code>*</code> возвращает ссылку на управляемый ресурс, а оператор <code>-&gt;</code> возвращает указатель.</p>

<p>Однако не всегда умный указатель <code>std::unique_ptr</code>может управлять объектом: это может произойти, если объект был создан пустым (с использованием конструктора по умолчанию или при передаче в него значения <code>nullptr</code>)), либо если ресурс, которым он управлял, был перемещен в другой​​​​​​​ <code>std::unique_ptr</code>. Поэтому перед использованием какого-либо из этих операторов необходимо проверить, управляет ли <code>std::unique_ptr</code> ресурсом. К счастью, это делается легко: умный указатель​​​​​​​ <code>std::unique_ptr</code> имеет неявное преобразование в тип <code>bool</code>, возвращающее true, если ​​​​​​​<code>std::unique_ptr</code>владеет ресурсом.</p>

<p>Существует два способа неправильного использования <code>std::unique_ptr,</code> оба из которых легко избежать. Во-первых, не позволяйте нескольким классам «владеть» одним и тем же ресурсом. Например:</p>

<pre><code class="language-cpp">X* item = new X;
std::unique_ptr&lt;X&gt; iteml(item);
std::unique_ptr&lt;X&gt; item2(item);</code></pre>

<p>Хотя это синтаксически допустимо, конечным результатом будет то, что и <code>item1</code>, и <code>item2 </code>попытаются удалить Item, что приведет к неопределенному поведению/результатам.</p>

<p>Во-вторых, не удаляйте выделенный ресурс вручную из-под <code>std::unique_ptr</code>:</p>

<pre><code class="language-cpp">X* item = new X;
std::unique_ptr&lt;X&gt; iteml(item);
delete item;</code></pre>

<p>Если вы это сделаете, <code>std::unique_ptr</code> попытается удалить уже удаленный ресурс, что опять приведет к неопределенному поведению/результатам.</p>

<h3>Так можно реализовать аналог класса std::unique_ptr.</h3>

<pre><code class="language-cpp">Так можно реализовать аналог класса std::unique_ptr.
template&lt;class T&gt;
class unique_ptr {
private:
    T* m_ptr;

public:
    operator bool() const {
        return m_ptr != nullptr;
    }

    unique_ptr(T* ptr = nullptr) {
        m_ptr = ptr;
    }

    // Деструктор позаботится об удалении указателя
    ~unique_ptr() {
         delete m_ptr;
    }

    // Конструктор перемещения, который передает право собственности на x.m_ptr в m_ptr
    unique_ptr(unique_ptr&amp;&amp; x) {
        m_ptr = x.m_ptr;
        x.m_ptr = nullptr;
    }

    unique_ptr(const unique_ptr&amp; x) = delete;

    unique_ptr&amp; operator=(unique_ptr&amp; a) = delete;

    // Оператор присваивания перемещением, который передает право собственности на x.m_ptr в m_ptr
    unique_ptr&amp; operator=(unique_ptr&amp;&amp; x) {
        // Проверка на самоприсваивание
        if (&amp;x == this)
            return *this;

        // Удаляем всё, что к этому моменту может хранить указатель 
        delete m_ptr;

        // Передаем право собственности на x.m_ptr в m_ptr
        m_ptr = x.m_ptr;
        x.m_ptr = nullptr; // мы поговорим об этом чуть позже

        return *this;
    }

    T&amp; operator*() const {
        return *m_ptr;
    }

    T* operator-&gt;() const {
        return m_ptr;
    }

    bool isNull() const { 
        return m_ptr == nullptr;
    }
};
</code></pre>
