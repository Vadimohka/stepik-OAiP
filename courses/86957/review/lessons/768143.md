<h3>Первый запуск: от исходного файла до результата</h3>
<p><strong>Цель шага:</strong> проследить превращение исходного файла в программу с предсказуемым выводом. В примере файл <code>main.cpp</code>:</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;

int main() {
    std::cout &lt;&lt; "Hello, C++!\n";
}</code></pre>
<p><code>#include &lt;iostream&gt;</code> подключает объявления потоков. <code>main</code> — главная функция обычной программы. <code>std::cout</code> выводит текст, а <code>\n</code> обозначает перевод строки. Достижение конца <code>main</code> эквивалентно <code>return 0;</code> — успешному завершению.</p>
<h4>GCC или Clang: Linux и macOS</h4>
<p>Команды выполняются из каталога с <code>main.cpp</code>. Если установлен GCC:</p>
<pre><code class="language-bash">g++ -std=c++20 -Wall -Wextra -Wpedantic -g main.cpp -o hello
./hello</code></pre>
<p>Для Clang замените <code>g++</code> на <code>clang++</code>. Первая команда собирает программу, вторая запускает результат. Запускайте вторую команду после успешной сборки: при ошибке на диске может остаться исполняемый файл от предыдущего запуска.</p>
<h4>MSVC: Windows</h4>
<p>В окружении установленного MSVC используется <em>Developer PowerShell for Visual Studio</em> в каталоге проекта:</p>
<pre><code class="language-powershell">cl /std:c++20 /EHsc /W4 /Zi main.cpp /Fe:hello.exe
.\hello.exe</code></pre>
<p>Если работаете в IDE, создайте консольный C++-проект, добавьте этот исходный файл, выберите C++20 и выполните сборку и запуск. На Windows с GCC можно собрать <code>hello.exe</code> командой <code>g++ -std=c++20 -Wall -Wextra -Wpedantic -g main.cpp -o hello.exe</code> и запустить <code>.\hello.exe</code> в PowerShell.</p>
<p>Ожидаемый вывод во всех вариантах:</p>
<pre><code class="language-text">Hello, C++!</code></pre>
<p>Флаги <code>-Wall -Wextra -Wpedantic</code> включают полезные диагностики GCC/Clang; <code>/W4</code> — высокий уровень предупреждений MSVC. <code>-g</code> и <code>/Zi</code> добавляют отладочную информацию. Наличие предупреждений проверяйте даже тогда, когда сборка завершилась.</p>
<h3>Разбор результата</h3><p>После успешной сборки вывод равен <code>Hello, C++!</code> и переводу строки. Редактирование приветствия меняет только исходный файл; новый текст появится после новой успешной сборки. Точка останова перед выводом показывает, что программа уже запущена, но операция вывода ещё не выполнена.</p><p>Справка: <a href="https://clang.llvm.org/docs/UsersManual.html" rel="noopener noreferrer nofollow">Clang Compiler User’s Manual</a>; <a href="https://learn.microsoft.com/en-us/cpp/build/reference/std-specify-language-standard-version" rel="noopener noreferrer nofollow">стандарт языка в MSVC</a>.</p>

<h3>Как читать первые ошибки</h3>
<p><strong>Цель шага:</strong> найти причину диагностики и проверить исправление. Следующая программа <strong>намеренно ошибочна</strong> и не должна успешно компилироваться:</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;

int main() {
    cout &lt;&lt; "Hello, C++!\n";
}</code></pre>
<p>Компилятор сообщает, что имя <code>cout</code> не объявлено или не найдено. Точная формулировка зависит от GCC, Clang или MSVC и их версии. Имя объекта потока — <code>std::cout</code>: замена <code>cout</code> на <code>std::cout</code> устраняет именно эту ошибку. Заголовок подключён, но неквалифицированное имя <code>cout</code> в этой области не находится.</p>
<table><thead><tr><th>Когда обнаружена проблема</th><th>Пример</th><th>Что проверять</th></tr></thead><tbody>
<tr><td>Компиляция</td><td>Неизвестное имя или пропущенный <code>;</code>.</td><td>Файл и строку из первой существенной диагностики, объявления и типы.</td></tr>
<tr><td>Компоновка</td><td>Функция объявлена и вызвана, но её определение не передано компоновщику.</td><td>Состав исходных файлов, библиотеки и соответствие объявлений определениям.</td></tr>
<tr><td>Выполнение</td><td>Программа падает либо выдаёт неверный ответ.</td><td>Входные данные, логику, значения в отладчике и тесты.</td></tr>
</tbody></table>
<p>Текст диагностики создаёт выбранный компилятор, а IDE помогает его показать. Разные IDE могут запускать один и тот же компилятор.</p>
<h3>Два разных дефекта</h3><p>В приведённом исходнике неизвестное имя <code>cout</code> препятствует сборке. После замены на <code>std::cout</code> программа выводит ожидаемое приветствие. Если вместо <code>Hello</code> в строковом литерале записано <code>Helo</code>, синтаксис остаётся правильным и сборка проходит, но вывод отличается от требуемого. Это ошибка результата, которую компилятор не обязан обнаружить.</p><p>При обращении за помощью приложите небольшой полный пример, точную команду сборки, версию компилятора, первую диагностику и ожидаемый результат. Скриншот без исходного кода обычно затрудняет воспроизведение.</p>

<h2>Стандартные потоки ввода и вывода</h2>
<p><code>std::cin</code> читает стандартный ввод, <code>std::cout</code> используется для обычного вывода, а <code>std::cerr</code> — для сообщений об ошибках. При запуске в терминале это часто клавиатура и экран, но потоки можно перенаправить в файл или другую программу. Поэтому «стандартный ввод» не означает обязательно ручной ввод с клавиатуры.</p>
<p>Операция <code>&gt;&gt;</code> извлекает значение из входного потока; <code>&lt;&lt;</code> передаёт значение в выходной. <code>std::cout &lt;&lt; "count: " &lt;&lt; count;</code> последовательно выводит текст и значение. Это перегруженные операции библиотеки: их точное устройство будет темой классов, сейчас используется их объявленный смысл.</p>
<p>Следующая <strong>полная программа C++17/C++20</strong> читает целое число в начале ввода и принимает его как количество от 0 до 1000 включительно. Остаток ввода она не проверяет.</p>
<pre><code class="language-cpp">#include &lt;cstdlib&gt;
#include &lt;iostream&gt;

int main() {
    int count = 0;
    if (!(std::cin &gt;&gt; count)) {
        std::cerr &lt;&lt; "input error\n";
        return EXIT_FAILURE;
    }
    if (count &lt; 0 || count &gt; 1000) {
        std::cerr &lt;&lt; "out of range\n";
        return EXIT_FAILURE;
    }
    std::cout &lt;&lt; "count: " &lt;&lt; count &lt;&lt; '\n';
}
</code></pre>
<p><code>if</code> выбирает действие по условию, как ромб в блок-схеме. Первая проверка означает «если чтение не удалось»; <code>!</code> отрицает условие. При ошибке программа выводит сообщение и завершается. <code>EXIT_FAILURE</code> из <code>&lt;cstdlib&gt;</code> обозначает неуспешное завершение. Во второй проверке <code>||</code> означает «или»: отрицательное число или число больше 1000 нарушает договор задачи.</p>
<table><thead><tr><th>Ввод</th><th>Результат разбора</th><th>Сообщение</th></tr></thead><tbody><tr><td><code>25</code></td><td>Успех, допустимое количество</td><td><code>count: 25</code></td></tr><tr><td><code>0</code> или <code>1000</code></td><td>Успех на границах</td><td><code>count: 0</code> или <code>count: 1000</code></td></tr><tr><td><code>-1</code> или <code>1001</code></td><td>Целое прочитано, но не подходит задаче</td><td><code>out of range</code></td></tr><tr><td><code>abc</code>, пустой завершённый ввод или число вне диапазона int</td><td>Не удалось извлечь подходящий int</td><td><code>input error</code></td></tr></tbody></table>
<p>Форматированное чтение обычно пропускает начальные пробельные символы. Ввод <code>12x</code> даёт число 12 и оставляет <code>x</code> в потоке: программа выведет <code>count: 12</code>. Следовательно, успешное извлечение числа не доказывает, что <em>вся строка</em> является корректной числовой записью. Такой отдельный контракт будет разобран в <a href="https://stepik.org/lesson/770589/step/1" rel="noopener noreferrer nofollow">модуле 9 о строках</a>.</p>
<p>Последовательное чтение нескольких значений можно записать фрагментом <code>std::cin &gt;&gt; a &gt;&gt; b</code>, где переменные заранее объявлены. Результат всей операции тоже проверяют до использования данных. Управляющие конструкции будут систематически введены в модуле 4, а состояние потока — в модуле 11.</p>

<h2>Перевод строки и форматирование вывода</h2>
<p>Управляющая последовательность в строковом или символьном литерале обозначает специальный символ. <code>'\n'</code> — перевод строки, <code>'\t'</code> — горизонтальная табуляция, <code>'\\'</code> — обратная косая черта. Действие табуляции на экране зависит от терминала, поэтому она не гарантирует одинаковую ширину столбца. Звуковой сигнал <code>'\a'</code> также может не воспроизводиться окружением.</p>
<p><strong>Манипуляторы</strong> меняют способ работы потока или формат вывода. Например, <code>std::hex</code> задаёт основание 16 для целых, а <code>std::dec</code> возвращает десятичную запись. <code>std::setbase(16)</code> из <code>&lt;iomanip&gt;</code> также выбирает шестнадцатеричный вывод целых. Это не изменение хранимого числа: меняется его текстовое представление.</p>
<p>Ниже <strong>полная программа C++17/C++20</strong>; сообщения и настройки выбраны так, чтобы различия были видны.</p>
<pre><code class="language-cpp">#include &lt;iomanip&gt;
#include &lt;iostream&gt;

int main() {
    std::cout &lt;&lt; std::hex &lt;&lt; 125 &lt;&lt; '\n';
    std::cout &lt;&lt; std::dec &lt;&lt; 125 &lt;&lt; '\n';
    std::cout &lt;&lt; std::fixed &lt;&lt; std::setprecision(2) &lt;&lt; 2.5 &lt;&lt; '\n';
    std::cout &lt;&lt; std::setfill('0') &lt;&lt; std::setw(4) &lt;&lt; 7 &lt;&lt; ' ' &lt;&lt; 8 &lt;&lt; '\n';
    std::cout &lt;&lt; std::scientific &lt;&lt; std::setprecision(4) &lt;&lt; 36.234 &lt;&lt; '\n';
}
</code></pre>
<p>В стандартной начальной локали вывод такой:</p>
<pre><code class="language-text">7d
125
2.50
0007 8
3.6234e+01
</code></pre>
<ul><li><code>125₁₀ = 7D₁₆</code>; по умолчанию буквы шестнадцатеричного вывода строчные.</li><li><code>std::fixed</code> с <code>std::setprecision(2)</code> задаёт два знака после десятичной точки для вещественного значения: получается <code>2.50</code>.</li><li><code>std::setw(4)</code> задаёт минимальную ширину следующего форматированного поля. Число 7 дополняется нулями до четырёх знаков. Для последующего 8 эта ширина уже не действует. Если число длиннее поля, оно не обрезается.</li><li><code>std::scientific</code> задаёт экспоненциальную запись. <code>3.6234e+01</code> обозначает <code>3.6234 × 10¹</code>. Здесь точность 4 означает четыре знака после точки.</li></ul>
<p>Основание, точность, режим вещественного вывода и символ заполнения сохраняются, пока их не изменить. Ширина у показанного форматированного вывода сбрасывается после использования. В обычном режиме без <code>fixed</code> и <code>scientific</code> точность относится к значащим цифрам, поэтому её смысл нельзя всегда формулировать как «число знаков после точки».</p>
<p><code>std::endl</code> вставляет перевод строки <em>и</em> сбрасывает буфер потока. <code>'\n'</code> вставляет перевод строки без такого обязательного действия; принудительный сброс нужен не для каждого сообщения. Накопление данных в буфере и состояние потока будут дополнены в модуле 11 о файлах.</p>

<h2>Ввод-вывод C в программе C++</h2>
<p>Заголовок <code>&lt;cstdio&gt;</code> предоставляет интерфейс ввода-вывода, унаследованный от C. Он встречается в существующем коде и при взаимодействии с библиотеками C. Для первых программ курса основной выбор — потоки C++ с проверкой результата. Следующий разбор нужен для чтения другого интерфейса, а подробности адресов будут введены в модуле 6.</p>
<p><code>std::printf</code> получает строку формата и значения. Метки в формате задают, как трактовать последующие аргументы. Следующая <strong>полная программа C++17/C++20</strong> выводит известные значения и проверяет результат операции:</p>
<pre><code class="language-cpp">#include &lt;cstdio&gt;
#include &lt;cstdlib&gt;

int main() {
    if (std::printf("%d %.1f\n", 42, 3.5) &lt; 0) {
        return EXIT_FAILURE;
    }
}
</code></pre>
<p>При успешном выводе получится <code>42 3.5</code> и перевод строки. <code>%d</code> соответствует аргументу типа <code>int</code>, а <code>%.1f</code> — значению типа <code>double</code> с одним знаком после точки. Отрицательный результат <code>printf</code> обозначает ошибку. Соответствие формата фактическим типам обязательно: ошибочная метка не является безопасным преобразованием значения.</p>
<p>У <code>std::scanf</code> другая задача: прочитать данные и записать их в объекты. Поэтому ей передают <strong>адреса</strong> подходящих объектов. Для переменной <code>int value</code> запись <code>&amp;value</code> обозначает её адрес. Следующий <strong>фрагмент</strong> показывает форму вызова только для заранее оговорённого ввода одного представимого в <code>int</code> десятичного числа:</p>
<pre><code class="language-cpp">int value = 0;
if (std::scanf("%d", &amp;value) == 1) {
    std::printf("%d\n", value);
}
</code></pre>
<p>Результат 1 означает одно успешно выполненное присваивание. Если вместо адреса передать само <code>value</code>, контракт вызова нарушается. Для <code>double</code> формат чтения — <code>%lf</code> и адрес <code>double</code>; переносить правила <code>printf</code> на <code>scanf</code> без проверки нельзя.</p>
<p>Проверка количества присваиваний не делает <code>scanf("%d", ...)</code> универсальным безопасным разбором произвольной числовой строки: если результат преобразования непредставим в объекте, стандарт C не задаёт допустимое поведение. При чтении массива символов через <code>%s</code> также требуется ограничение ширины с учётом места для завершающего нуля. Эти механизмы подробно обсуждаются вместе со строками; здесь не предлагается вводить произвольные данные в этот фрагмент.</p>
<p>Функции с суффиксом <code>_s</code> и предупреждения конкретного компилятора не являются универсальным интерфейсом стандартной библиотеки C++17/C++20. Отключение предупреждения не исправляет формат или размер буфера. Аналогично, <code>std::cin.tie(nullptr)</code> меняет связь потоков, а синхронизация с вводом-выводом C управляется отдельно; в первых примерах эти настройки оставлены стандартными.</p>
