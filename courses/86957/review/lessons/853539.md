<h2>Что такое дерево?</h2>
<p>Предпосылки: <a href="https://stepik.org/lesson/973837/step/1" rel="noopener noreferrer nofollow">структура данных и интерфейс</a>, <a href="https://stepik.org/lesson/770591/step/1" rel="noopener noreferrer nofollow">вызовы функций</a>, <a href="https://stepik.org/lesson/853536/step/1" rel="noopener noreferrer nofollow">владение</a>. В этом разделе дерево — организация узлов и связей, а множество или словарь — интерфейс, который можно на ней построить.</p>

<p>Дерево — одна из наиболее широко распространённых структур данных в информатике, эмулирующая древовидную структуру в виде набора связанных узлов. Является связным графом, не содержащим циклов.</p>

<h4>Справочник терминов</h4>

<ul>
	<li>Узел — элемент дерева, хранящий данные и связи с другими узлами;</li>
	<li>Корень — самый верхний узел дерева;</li>
	<li>Ребро — связь между двумя узлами;</li>
	<li>Лист — узел, не имеющий узлов-потомков на дереве;</li>
	<li>Высота узла — максимальное число узлов на пути от него до листа включительно; в дальнейших реализациях высота листа равна 1, пустого поддерева — 0;</li>
	<li>Глубина узла — число рёбер на пути от корня до него; глубина корня равна 0;</li>
	<li>Дочерний узел — узел, связанный с родительским узлом, находящийся на более низком уровне дерева;</li>
	<li>Степень узла — количество его дочерних узлов;</li>
	<li>Поддерево — часть дерева, состоящая из узла и всех его потомков;</li>
	<li>Обход дерева — процесс посещения каждого узла дерева ровно один раз.</li>
</ul>

<h4>Бинарные деревья</h4>

<p>Теперь рассмотрим особый тип деревьев, называемых бинарными или двоичными деревьями.</p>

<p><em>В информатике бинарным (двоичным) деревом называется иерархическая структура данных, в которой каждый узел имеет не более двух дочерних узлов. Их называют левым и правым ребёнком, а узел, с которым они непосредственно связаны сверху, — их родителем.</em></p>

<p><img alt="" height="405" name="3.png" src="https://ucarecdn.stepik.net/1540e3cc-6a54-403f-8410-9b2ef1cc025b/-/preview/" width="372"></p>

<p><strong>Способы обхода дерева</strong></p>

<p>Пусть имеем дерево, где A — корень, B и C — левое и правое поддеревья.</p>

<p><img alt="" height="129" name="image.png" src="https://ucarecdn.stepik.net/aa8089aa-355b-48e2-a98c-699e2b3d0386/" width="212"></p>

<p>Рассмотрим три основных порядка обхода дерева в глубину:</p>

<ul>
	<li>Обход дерева сверху вниз (в прямом порядке): A, B, C — префиксная форма.</li>
	<li>Обход дерева в симметричном порядке (слева направо): B, A, C — инфиксная форма.</li>
	<li>Обход дерева в обратном порядке (снизу вверх): B, C, A — постфиксная форма.</li>
</ul><h3>Порядок обхода — ещё не порядок ключей</h3><p>В записи A, B, C буквы B и C обозначают <em>полные рекурсивные обходы</em> соответствующих поддеревьев. Например, для корня 20 с левым листом 10 и правым листом 30 прямой обход даёт 20, 10, 30; симметричный — 10, 20, 30; обратный — 10, 30, 20. Отсортированным симметричный обход будет при дополнительном инварианте <a href="https://stepik.org/lesson/853539/step/2" rel="noopener noreferrer nofollow">дерева поиска</a>.</p><p>В курсе высота считается в узлах: пустое дерево имеет высоту 0, лист — 1. Глубина считается в рёбрах, поэтому у непустого дерева высота равна максимальной глубине плюс 1. В других источниках высоту часто считают в рёбрах; это другое соглашение, а не другой алгоритм.</p><p>Рекурсивный обход посещает n узлов за O(n) операций и занимает O(h) памяти стека при высоте h. Позднее балансировка ограничит h величиной O(log n); произвольное дерево такой гарантии не имеет.</p>

<h2>Бинарное дерево поиска: инвариант и владение</h2>
<p>Бинарное дерево поиска (BST) добавляет к форме дерева условие порядка. В модели с уникальными ключами для любого узла <code>x</code> <strong>все</strong> ключи левого поддерева меньше <code>x.key</code>, а все ключи правого — больше. Это требование относится ко всему поддереву, а не только к непосредственным детям.</p>
<p>Ключи в примере — <code>int</code>. Повторная вставка ключа не меняет прежнее значение и возвращает <code>false</code>; это явный договор, одинаковый у последующих BST, AVL и RB. Другой интерфейс мог бы обновлять значение, но это уже отдельная операция.</p>
<h3>Полная программа C++17/20</h3>
<p>Корень и связи к детям — владельцы <code>unique_ptr</code>. У каждого узла один владелец, общего владения нет. Функция принимает ссылку на владеющий указатель, чтобы заменить именно нужную связь, в том числе корень. Она создаёт новый узел только на пустом месте.</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;memory&gt;
#include &lt;string&gt;
#include &lt;utility&gt;

struct BstNode {
    int key;
    std::string value;
    std::unique_ptr&lt;BstNode&gt; left, right;
    BstNode(int k, std::string v) : key(k), value(std::move(v)) {}
};

bool insert_bst(std::unique_ptr&lt;BstNode&gt;&amp; root, int key, const std::string&amp; value) {
    if (!root) {
        root = std::make_unique&lt;BstNode&gt;(key, value);
        return true;
    }
    if (key &lt; root-&gt;key) return insert_bst(root-&gt;left, key, value);
    if (key &gt; root-&gt;key) return insert_bst(root-&gt;right, key, value);
    return false; // Preserve the existing value for a duplicate key.
}

int main() {
    std::unique_ptr&lt;BstNode&gt; root;
    insert_bst(root, 20, "root");
    insert_bst(root, 10, "left");
    insert_bst(root, 30, "right");
    const bool inserted = insert_bst(root, 20, "other");
    std::cout &lt;&lt; std::boolalpha &lt;&lt; inserted &lt;&lt; ' ' &lt;&lt; root-&gt;value &lt;&lt; '\n';
    std::cout &lt;&lt; root-&gt;left-&gt;key &lt;&lt; ' ' &lt;&lt; root-&gt;key &lt;&lt; ' ' &lt;&lt; root-&gt;right-&gt;key &lt;&lt; '\n';
}</code></pre>
<p>Вывод: <code>false root</code>, затем <code>10 20 30</code>. Вторая вставка 20 оставила первоначальную строку. При поиске достаточно на каждом узле выбрать одно поддерево по сравнению ключей; в отброшенном поддереве искомого ключа быть не может по инварианту.</p>
<p>Сырой указатель, временно полученный через <code>get()</code> для чтения узла, был бы наблюдателем: он не продлевает время жизни и не должен удалять узел. Здесь узлы открыты ради объяснения; в библиотечном классе их обычно скрывают, чтобы вызывающий код не мог нарушить порядок.</p>
<p>Вставка и поиск требуют O(h) сравнений при высоте h. <strong>Эта программа не поддерживает баланс.</strong> Последовательная вставка уже упорядоченных ключей может создать цепочку; рекурсивные вставка и уничтожение такой цепочки также требуют глубины стека O(h). Следующий шаг объясняет, зачем ограничивать высоту.</p>

<h2>Вырожденное дерево</h2>

<p>Поиск, вставка и удаление в дереве поиска требуют O(h) сравнений, где h — высота дерева. Это верхняя оценка: успешный поиск корня завершается сразу. Но из одного и того же набора ключей можно построить разные <strong>деревья поиска </strong>, как показано на рисунке ниже.</p>

<p><img alt="" height="1761" name="4.png" src="https://ucarecdn.stepik.net/c2a4818f-212a-46b3-945a-e5f2f199da0f/-/preview/" width="4252"><br>
<br>
Дерево , как показано на рисунке а) называется вырожденным, в котором высота равна количеству узлов, что делает дерево поиска тем же, что и односвязный список со сложностью операций O(n).</p>

<p>Дерево из рисунка а) получилось после поочередной вставки упорядоченных ключей от 1 до 6. Те же ключи использовались и при построении дерева б), но порядок вставки был другим, в итоге б) получилось более сбалансированным, чем а).</p>

<p>Чтобы о сбалансированности можно было судить не только по внешнему виду деревьев, а ещё и как-то выразить в числах, скажем, что коэффициент балансировки для вершины – это разность высот её поддеревьев.</p>

<p>Сбалансированные деревья поиска помогают избежать таких ситуаций, когда высота дерева далека от предполагаемой log<sub>2</sub>(n).</p><h3>Почему одного порядка недостаточно</h3><p>Вставка ключей 1, 2, 3, 4, 5, 6 по возрастанию создаёт цепочку высоты 6. Порядок 4, 2, 6, 1, 3, 5 даёт дерево высоты 3 с теми же ключами. В обоих случаях инвариант поиска верен. Различается число узлов на пути к ответу.</p><p>У бинарного дерева высоты h, считаемой в узлах, не более 2<sup>h</sup> − 1 узлов. Поэтому минимальная возможная высота растёт как log₂(n + 1). Само BST-условие минимальную высоту не гарантирует: для этого добавляют <em>инвариант баланса</em>.</p><p>Далее <a href="https://stepik.org/lesson/853540/step/1" rel="noopener noreferrer nofollow">AVL</a> ограничивает разность высот детей, а <a href="https://stepik.org/lesson/853541/step/2" rel="noopener noreferrer nofollow">красно-чёрное дерево</a> — цвета и чёрную высоту. Оба сохраняют порядок ключей, но получают разные правила восстановления баланса.</p>
