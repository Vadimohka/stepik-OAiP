<h3>Типы файлов</h3>

<p>Большинство компьютерных программ работают с файлами, и поэтому возникает необходимость создавать, удалять, записывать и читать, открывать файлы.</p>

<p>Принято различать:</p>

<ul>
	<li>бинарные файлы;</li>
	<li>текстовые файлы.</li>
</ul>

<p>Знакомство с вводом-выводом обычно начинается с текстовых файлов. У многих оно этим и заканчивается. Однако существует еще одна общая форма представления данных в файлах, на самом деле более многообразная – двоичный файл. Сюда относятся не только файлы с «мультимедийным» содержанием: документы, изображения, звук. Форматы двоичных файлов используются в базах данных и в самой файловой системе. Например, образ дисковой файловой системы можно рассматривать как большой двоичный файл со сложной многоуровневой структурой данных, описывающей файлы и каталоги.</p>

<h3>Модель двоичного файла и правила работы с ним</h3>

<p>Двоичный файл можно рассматривать как последовательность байтов, смысл которой задаёт формат данных. Эти байты не обязательно представляют текстовые символы. В рассматриваемой модели файл похож на растущий массив байтов с возможностью произвольного доступа; его размер ограничен файловой системой и доступным пространством.</p>

<p>Такая модель файла полностью совпадает с системой представлений, принятой в С для работы с памятью на низком (физическом) уровне.</p>

<ul>
	<li>Физическая память имеет байтную структуру – единицей адресации является байт;</li>
	<li>Любая переменная занимает фиксированное количество байтов, определяемое ее типом. Операция <strong>sizeof </strong>возвращает эту размерность;</li>
	<li>Указатель  на переменную интерпретируется как ее адрес в памяти. Преобразование типа указателя к <strong>void*</strong> позволяет интерпретировать его как «чистый» адрес, а преобразование к <strong>char*</strong> - как указатель на массив байтов (физическое представление памяти).</li>
</ul>

<p>При использовании исключительно функций <strong>fread/fwrite </strong>данные, записанные в определенной последовательности в файл, хранятся в нем и читаются в том же самом порядке. Этот неизменный порядок извлечения данных называется <strong>последовательным доступом,</strong> а файл - <strong> последовательным двоичным файлом</strong>. Естественно, что нас при этом не интересуют адреса размещения данных в файле. Однако существует и другой способ, позволяющий извлекать данные в любом произвольном порядке – <strong>прямой (или произвольный) доступ.</strong></p>

<p>Произвольный доступ базируется на понятии адреса в двоичном файле. Поскольку на физическом уровне двоичный файл представляется как «неограниченно растущий» массив байтов, то под адресом понимается порядковый номер байта, начиная с 0.</p>

<p>В рассматриваемом интерфейсе C файловые позиции и смещения представлены значениями типа <strong>long, </strong>на которые можно распространить известное понятие указатель<strong> - указатель в файле. </strong>Такая образная аналогия вполне уместна и позволяет с общих позиций рассматривать структуры данных, размещенные в файлах. Указатель в файле не является типизированным, его тип никак не связан с типом адресуемых данных и он рассматривается как «чистый» физический адрес в файле.</p>

<p>С каждым открытым файлом связывается такой параметр как <strong>текущая позиция </strong>(текущий адрес) - номер байта, начиная с которого будет выполняться очередная операция чтения-записи. При открытии файла текущая позиция устанавливается на начало файла, после чтения-записи порции данных перемещается вперед на размерность этих данных. Для дополнения файла новыми данными необходимо установить текущую позицию на конец файла и выполнить операцию записи.</p>

<p>Текущая позиция в файле является адресом размещения переменной в нем, но получить этот адрес можно <em>перед, </em>и не <em>после </em>ее чтения оттуда. Текущую позицию можно читать и устанавливать с помощью функций позиционирования, которые превращают последовательный файл в файл произвольного доступа. Функция <strong>long ftell(FILE *fp)</strong> возвращает текущую позицию в файле. Если по каким-то причинам текущая позиция не определена, функция возвращает <strong>-1.</strong> Это же самое значение будем использовать в дальнейшем для представления недействительного файлового смещения в примерах этого урока, самостоятельно определив его: <code>#define  FNULL  -1L</code>.</p>

<p>Функция <strong>int    fseek(FILE *fp, long pos, int mode)</strong> устанавливает позицию с учётом смещения <strong>pos</strong> и точки отсчёта <strong>mode</strong>. Параметр <strong>mode </strong>определяет, относительно чего отсчитывается текущая позиция в файле, и задаётся одной из констант заголовка <code>&lt;stdio.h&gt;</code> (в C++ также доступен <code>&lt;cstdio&gt;</code>). Используйте имена констант: их числовые значения зависят от реализации.</p>

<pre><code class="language-cpp">// SEEK_SET — смещение относительно начала файла.
// SEEK_CUR — смещение относительно текущей позиции.
// SEEK_END — смещение относительно конца файла.
// Не определяйте эти константы самостоятельно.</code></pre>

<p>Функция <strong>fseek</strong> возвращает значение <strong>0</strong> при успешном позиционировании и <strong>ненулевое значение</strong> при ошибке. Различные значения параметра <strong>mode </strong>определяют различные способы адресации данных в файле:</p>

<ul>
	<li>значение <strong>SEEK_</strong><strong>SET </strong>определяет <strong>абсолютную </strong>адресацию данных в файле от его начала. Заметим, что функция <strong>ftell </strong>возвращает текущую позицию в абсолютном значении;</li>
	<li>значение <strong>SEEK_</strong><strong>END </strong>за начало координат берет конец файла. Смещения к уже записанным байтам перед концом файла отрицательны; нулевое смещение соответствует самому концу. Например, если в конце файла находится целая переменная, то ее позиция при адресации от конца файла будет иметь значение <strong>0–</strong><strong>sizeof(</strong><strong>int). </strong>В этом же режиме можно определить текущую длину файла простым позиционированием:</li>
</ul>

<pre><code class="language-cpp">// fl — уже открытый двоичный файл, поддерживающий позиционирование.
long fsize = -1L;
if (fseek(fl, 0L, SEEK_END) == 0) {
    fsize = ftell(fl); // -1L означает ошибку
}</code></pre>

<ul>
	<li>значение <strong>SEEK_</strong><strong>CUR </strong>дает способ <strong>относительной </strong>адресации от текущего положения указателя в файле. Таким образом, задается <em>расстояние </em>в байтах от текущей переменной до адресуемой. Если это<em> расстояние</em> само находится в файле, то оно обычно носит название <strong>смещения.</strong></li>
</ul>

<h4><strong>​Распределение памяти в двоичном файле.</strong></h4>

<p>Модель двоичного файла использует представление внешней памяти на низком (физическом) уровне. В языке программирования распределение памяти производится транслятором (обычные переменные), либо библиотекой (динамические переменные и массивы). В двоичном файле программисту приходится самому управлять размещением данных. Поэтому задача размещения данных лежит целиком на программе. К счастью, возможность расширения файла в пределах доступного пространства путем записи данных в его конец дает программистам самый простой способ распределения памяти: для размещения переменной в файле достаточно дописать её в конец файла, запомнив ее новый адрес.</p>

<pre><code class="language-cpp">// Добавить в файл вещественную переменную
double b=5.6;
fseek (fd,0L,SEEK_END); // Позиционироваться на конец файла
long pp=ftell(fd); // Адрес переменной в файле
fwrite (&amp;b, sizeof(double),1,fd); // Записать переменную как массив байтов</code></pre>

<p>Последовательность операций записи в файл создает в нем необходимую структуру данных. Иногда эти операции записи являются фиктивными с целью «занять место» под переменные с еще не определенными значениями.</p>

<p>Если содержимое двоичного файла при каждом запуске программы переписывается от начала до конца, то он всегда будет содержать только необходимые данные. Иначе обстоит дело, если двоичный файл при очередном запуске редактируется. Тогда при <strong>удалении </strong>данных в файле остаются неиспользованные участки. То же самое происходит при изменении (<strong>обновлении, </strong>в терминологии баз данных - <strong>update) </strong>данных, если их размерность увеличивается: они переписываются в конец файла. Эти свободные участки называются <strong>«мусором» </strong>и со временем они приводят к значительному превышению объема файла относительно его полезного содержимого. Программа может придерживаться разных стратегий «утилизации мусора»:</p>

<ul>
	<li>Свободные участки объединяются в отдельную структуру данных, например, список, и повторно используются. Недостатком является сложность поддержания в файле дополнительной структуры данных;</li>
	<li>Периодически выполняется процедура «<strong>сбора мусора</strong>», обычно выполняемая в виде <strong>сжатия</strong> данных: в новом двоичном файле создается аналогичная структура данных и в нее переписываются только актуальные (достижимые) данные из исходного файла. Процедура сжатия может быть вызвана пользователем явно, либо автоматически, на основании косвенных характеристик структур данных в файле.</li>
</ul>

<h4><strong>Изменение данных в файле</strong></h4>

<p>Оно<strong> </strong>не может быть выполнено непосредственно. Необходимо создать в памяти переменную, прочитать туда значение из файла, а после изменения записать обратно (обновить).</p>

<pre><code class="language-cpp">#include &lt;cstdio&gt;
#include &lt;limits&gt;

// fd открыт в режиме "r+b"; по смещению pos ранее записан int
// той же реализацией программы. Например, pos = 0L — начало файла.
bool increment_counter(std::FILE* fd, long pos) {
    int counter{};
    if (fd == nullptr || std::fseek(fd, pos, SEEK_SET) != 0 ||
        std::fread(&amp;counter, sizeof counter, 1, fd) != 1) {
        return false;
    }
    if (counter == std::numeric_limits&lt;int&gt;::max()) {
        return false; // увеличение не должно переполнить int
    }
    ++counter;
    if (std::fseek(fd, pos, SEEK_SET) != 0) {
        return false;
    }
    return std::fwrite(&amp;counter, sizeof counter, 1, fd) == 1;
}</code></pre>

<p>В связи с этим возникают вопросы о <strong>соответствии структур данных в двоичном файле и в памяти</strong>, а также о способах поддержания соответствия между ними. Как говорится, «возможны варианты»:</p>

<ul>
	<li>Структуры данных в памяти и в файле принципиально различаются. Например, дерево (данные в вершинах и связи) можно сохранить в последовательном потоке (файле) в виде рекурсивного саморазворачивающегося формата. В этом случае используется <strong>полная загрузка/сохранение структуры данных</strong> в виде единой операции;</li>
	<li>Программа может извлекать из двоичного файла только те фрагменты, которые необходимы для выполнения текущей операции. При такой <strong>поэлементной загрузке </strong>в памяти присутствуют только несвязанные копии отдельных фрагментов данных двоичного файла, а целостная структура данных не создается;</li>
	<li>В памяти могут создаваться образы наиболее важных (часто используемых, управляющих) элементов структуры данных из двоичного файла. Например, при наличии в файле массива указателей на строки в памяти создается «образ» заголовка файла и массива указателей, а сами строки читаются «по необходимости». Такой способ создания и загрузки <strong>частичного образа структуры данных </strong>предполагает сеансовый режим работы с файлом: частичный образ создается в памяти при открытии файла. Здесь также возникает проблема соответствия образа оригиналу и обновления последнего;</li>
	<li>Возможно создание в памяти <strong>идентичного</strong> <strong>образа структуры данных </strong> из двоичного файла, и наоборот. Например, для дерева в памяти можно создать идентичную структуру данных в файле, однако вершины дерева в нем будут содержать уже не обычные указатели в памяти а указатели в файле.</li>
</ul>

<p><strong>Избыточность в двоичных файлах и защита от ошибок. </strong>При работе с файлами возникает специфический род ошибок программы - ошибки формата файла. Дело в том, что при сбое или аварийном завершении программы обычные переменные теряются. Что же касается файлов данных, то в таких ситуациях они могут остаться в промежуточном состоянии, в котором структура данных в файле окажется некорректной (например, при выполнении двух последовательных операций программа успевает выполнить только одну из них). Другая причина - программа получает файл не того формата, с которым она работает (вследствие задания неправильного имени файла). Обычно в файл вносятся избыточные данные, позволяющие  обнаружить такие ошибки. </p>

<h3>Работа с текстовыми файлами в языке С++</h3>

<p>Потоки для работы с текстовыми файлами представляют объекты, для которых <strong>не задан</strong> режим открытия <code>ios::binary</code>.</p>

<h4>Запись в файл</h4>

<p>Для записи в файл к объекту ofstream или fstream применяется оператор &lt;&lt; (как и при выводе на консоль):</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;fstream&gt;
 
int main() {
    std::ofstream out;          // поток для записи
    out.open("D:\\hello.txt"); // окрываем файл для записи
    if (out.is_open()) {
        out &lt;&lt; "Hello World!" &lt;&lt; std::endl;
    }
     
    std::cout &lt;&lt; "End of program" &lt;&lt; std::endl;
    return 0;
}</code></pre>

<p>Данный способ перезаписывает файл заново. Если надо дозаписать текст в конец файла, то для открытия файла нужно использовать режим ios::app:</p>

<pre><code class="language-cpp">std::ofstream out("D:\\hello.txt", std::ios::app);
if (out.is_open()) {
    out &lt;&lt; "Welcome to CPP" &lt;&lt; std::endl;
}
out.close();        </code></pre>

<h4>Чтение из файла</h4>

<p>Если надо считать всю строку целиком или даже все строки из файла, то лучше использовать библиотечную функцию std::getline(), которая принимает поток для чтения и переменную, в которую надо считать текст:</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;fstream&gt;
#include &lt;string&gt;
 
int main() {
    std::string line;
 
    std::ifstream in("D:\\hello.txt"); // окрываем файл для чтения
    if (in.is_open()) {
        while (getline(in, line)) {
            std::cout &lt;&lt; line &lt;&lt; std::endl;
        }
    }
    in.close();     // закрываем файл
     
    std::cout &lt;&lt; "End of program" &lt;&lt; std::endl;
    return 0;
}</code></pre>

<p>Также для чтения данных из файла для объектов ifstream и fstream может применяться оператор &gt;&gt; (также как и при чтении с консоли):</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;fstream&gt;
#include &lt;vector&gt;
 
struct Operation {
