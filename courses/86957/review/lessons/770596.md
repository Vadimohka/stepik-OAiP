<h3>Структура: свой тип и его объекты</h3>

<p>Ранее типы <code>int</code> и <code>std::string</code> позволяли хранить число и строку отдельно. Когда эти значения описывают одну сущность, удобно объединить их в пользовательский тип. <code>struct</code> определяет класс в терминах языка C++; его нестатические поля входят в каждый объект этого типа.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;string&gt;

struct Person {
    std::string name;
    int age{};
};

int main() {
    Person tom{"Tom", 34};
    Person unknown{};
    std::cout &lt;&lt; tom.name &lt;&lt; ' ' &lt;&lt; tom.age &lt;&lt; '\n';
    std::cout &lt;&lt; '"' &lt;&lt; unknown.name &lt;&lt; "\" " &lt;&lt; unknown.age &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">Tom 34
"" 0</code></pre><p>Определение <code>Person</code> завершается точкой с запятой и само по себе не создаёт человека. Объявления <code>tom</code> и <code>unknown</code> создают два разных объекта. Выражение <code>tom.age</code> обозначает поле возраста именно первого объекта; изменение этого поля не меняет возраст второго.</p><p>Здесь <code>Person</code> — агрегат: открытые поля можно инициализировать списком по порядку объявления. Поэтому в <code>{"Tom", 34}</code> сначала идёт имя, затем возраст. Пустая строка конструируется по правилам <code>std::string</code>, а <code>age{}</code> задаёт ноль. Фигурные скобки у объекта не означают, что у любого пользовательского типа они обязательно заполняют поля: у неагрегатных классов работают правила выбора конструктора. Критерии агрегата и различие C++17/20 уточняются в <a href="https://stepik.org/lesson/877083/step/5" rel="noopener noreferrer nofollow">сравнении struct и class</a>.</p><p>Поля структуры по умолчанию открыты (<code>public</code>), поэтому запись <code>tom.age = -5;</code> допустима для языка. Смысловой запрет отрицательного возраста здесь ещё не выражен. В <a href="https://stepik.org/lesson/877082/step/4" rel="noopener noreferrer nofollow">теме инвариантов класса</a> разберём, как сделать недопустимое состояние недоступным через обычный интерфейс. <code>struct</code> также допускает методы, конструкторы и закрытые поля; отличие от <code>class</code> состоит в доступе по умолчанию. Общая модель типа и объекта сохраняется.</p>

<h3>Имя типа и псевдоним</h3>

<p>Определение <code>struct Point</code> вводит новый тип. В C++ после этого достаточно имени <code>Point</code>; повторять <code>struct</code> при каждом объявлении объекта не нужно. Объявление <code>using</code> даёт существующему типу ещё одно имя, но не создаёт отдельный тип.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

struct Point {
    int x{};
    int y{};
};
using Position = Point;

int main() {
    Point p{10, 20};
    Position q = p;
    q.x = 30;
    std::cout &lt;&lt; p.x &lt;&lt; ' ' &lt;&lt; q.x &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">10 30</code></pre><p>Присваиваемое значение имеет подходящий тип, потому что <code>Point</code> и <code>Position</code> — два имени одного типа. При этом <code>p</code> и <code>q</code> — разные объекты: копирование начального значения не делает их одним объектом.</p><p>Фрагмент; определения и контекст указаны в объяснении:</p><pre><code class="language-cpp">typedef Point Position; // альтернативная запись псевдонима; вместо using, а не рядом с ним</code></pre><p>В старых материалах встречается <code>typedef</code>. В C он часто избавляет от повторения слова <code>struct</code>; в C++ такой обходной приём не нужен. Современная запись <code>using</code> обычно читается проще. Ни одна из этих записей не проверяет, что «позиция» имеет иной смысл, чем «точка»: для строгого различения понадобятся два разных типа.</p><p>Фрагмент; определения и контекст указаны в объяснении:</p><pre><code class="language-cpp">struct Node {
    int value{};
    Node* next = nullptr;
};</code></pre><p>Имя <code>Node</code> уже доступно внутри определения. Поле <code>next</code> — указатель, а не ещё один узел внутри самого узла. Поэтому размер типа конечен. Сам указатель не владеет следующим объектом и не создаёт его. Эта разница понадобится при <a href="https://stepik.org/lesson/853539/step/1" rel="noopener noreferrer nofollow">разборе узлов дерева</a>.</p>

<h3>Доступ к структуре через указатель</h3>

<p>Поля можно получить через сам объект с помощью <code>.</code> или через указатель с помощью <code>-&gt;</code>. Для обычного указателя <code>p-&gt;age</code> означает то же, что <code>(*p).age</code>. Указатель должен обозначать живой объект подходящего типа.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;array&gt;
#include &lt;iostream&gt;
#include &lt;string&gt;

struct Person {
    std::string name;
    int age{};
};

int main() {
    std::array&lt;Person, 2&gt; people{{{"Anna", 20}, {"Boris", 19}}};
    Person* selected = &amp;people[1];
    selected-&gt;age = 21;
    const Person* reader = selected;
    std::cout &lt;&lt; reader-&gt;name &lt;&lt; ' ' &lt;&lt; reader-&gt;age &lt;&lt; '\n';
    std::cout &lt;&lt; people[0].age &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">Boris 21
20</code></pre><p>Массив владеет своими двумя элементами, а каждый <code>std::string</code> сам управляет памятью своей строки. <code>selected</code> лишь даёт доступ ко второму элементу: операция <code>new</code> не выполнялась, освобождать этот указатель через <code>delete</code> нельзя. После записи через стрелку возраст второго человека равен 21, первого — по-прежнему 20.</p><p><code>const Person*</code> запрещает изменять человека через этот указатель. Это ограничение доступа не делает объект отдельной копией и не исключает изменение через другой неконстантный путь. Указатель <code>nullptr</code> не обозначает человека; обращение через него недопустимо. После завершения времени жизни <code>people</code> доступ через сохранённый указатель на его элемент тоже недопустим.</p><p>Для объяснения стрелки достаточно уже знакомых <a href="https://stepik.org/lesson/763644/step/6" rel="noopener noreferrer nofollow">массивов стандартной библиотеки</a> и строк. Ручное выделение C-строк и хранение паролей не являются частью этой модели. Передачу объекта только для чтения удобно выразить и ссылкой <code>const Person&amp;</code>, если отсутствие объекта не является допустимым вариантом.</p>

<h3>Представление структуры: размер и выравнивание</h3>

<p>Логически структура объединяет поля; её физическое представление дополнительно подчиняется требованиям выравнивания. Между полями и в конце объекта могут быть байты заполнения. Поэтому сумма размеров полей не обязана совпадать с <code>sizeof</code> всего объекта.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;cstddef&gt;
#include &lt;iostream&gt;

struct Record {
    char tag;
    int value;
};

int main() {
    std::cout &lt;&lt; "char=" &lt;&lt; sizeof(char) &lt;&lt; '\n';
    std::cout &lt;&lt; "int=" &lt;&lt; sizeof(int) &lt;&lt; '\n';
    std::cout &lt;&lt; "record=" &lt;&lt; sizeof(Record) &lt;&lt; '\n';
    std::cout &lt;&lt; "alignment=" &lt;&lt; alignof(Record) &lt;&lt; '\n';
    std::cout &lt;&lt; "value_offset=" &lt;&lt; offsetof(Record, value) &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат — измерение выбранной реализации. Например, при <code>sizeof(int) == 4</code>, выравнивании <code>int</code> по 4 байтам и обычном размещении этот тип часто занимает 8 байтов, а поле <code>value</code> начинается со смещения 4. Стандарт не предписывает именно эти числа. <code>sizeof(char)</code> всегда равен 1; число битов в таком байте задаётся <code>CHAR_BIT</code>, а не обязано равняться восьми.</p><p>В нашем простом типе все поля имеют одинаковый доступ и ненулевой размер: объявленное позже поле располагается по большему адресу. Для произвольного класса C++17/20, в частности при различном доступе полей или наследовании, нельзя автоматически переносить эту схему. <code>offsetof</code> применяют переносимо к стандартно размещаемым типам; показанный <code>Record</code> удовлетворяет этому условию.</p><p>Нестандартные директивы упаковки, например <code>#pragma pack</code>, относятся к конкретному компилятору и ABI. Они не делают память структуры переносимым файловым форматом. Для <a href="https://stepik.org/lesson/771130/step/1" rel="noopener noreferrer nofollow">сохранения данных в файл</a> нужно отдельно определить поля формата, их размеры и порядок байтов; адреса, заполнение и внутреннее устройство <code>std::string</code> сериализовать как смысловые данные нельзя.</p>

<h3>Одинаковые поля ещё не означают одинаковый тип</h3>

<p>Два независимых определения структуры создают разные типы, даже если поля имеют одинаковые размеры. Переход между ними должен выражать смысл преобразования.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

struct Point { int x; int y; };
struct Apex { int a; int b; };

int main() {
    Point point{10, 20};
    Apex apex{point.x, point.y};
    std::cout &lt;&lt; apex.a &lt;&lt; ' ' &lt;&lt; apex.b &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">10 20</code></pre><p>В результате <code>a</code> получает координату <code>x</code>, а <code>b</code> — координату <code>y</code>. Связь между полями видна в исходнике. Простое <code>Apex apex = point;</code> для этих определений не компилируется: подходящее преобразование не объявлено. Позже конструктор сможет оформить такую связь как часть интерфейса типа.</p><p>Приведение указателя к <code>Point*</code> не превращает произвольный массив <code>int</code> в созданный объект <code>Point</code>. Даже если адреса и размеры кажутся подходящими, необходимо соблюдать правила времени жизни и доступа к объекту. Чтение через неподходящий тип может иметь неопределённое поведение. Поэтому здесь копируются значения полей, а не переинтерпретируются байты.</p><p>Это продолжение различия между <a href="https://stepik.org/lesson/770596/step/2" rel="noopener noreferrer nofollow">псевдонимом типа</a> и отдельным типом. <h3>Композиция: объект содержит другие объекты</h3>

<p>Полем структуры может быть другая структура. Такое устройство называют композицией: модель автомобиля содержит сведения о марке. Поле <code>make</code> — настоящий подобъект внутри <code>Model</code>, а не указатель на отдельную марку.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;string&gt;

struct Make {
    int id{};
    std::string name;
};
struct Model {
    int id{};
    Make make;
    std::string name;
    int year{};
};

int main() {
    Model original{10, {1, "Acura"}, "CL", 2003};
    Model copy = original;
    copy.name = "TSX";
    std::cout &lt;&lt; original.make.name &lt;&lt; ' ' &lt;&lt; original.name &lt;&lt; ' '
              &lt;&lt; original.year &lt;&lt; '\n';
    std::cout &lt;&lt; copy.name &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">Acura CL 2003
TSX</code></pre><p>Вложенный список <code>{1, "Acura"}</code> инициализирует поле <code>make</code>. Запись <code>original.make.name</code> сначала выбирает марку, затем её имя. Год хранится непосредственно как число 2003; скрытого смещения от исторического года здесь нет.</p><p>Копирование <code>Model</code> копирует его поля по их собственным правилам. У копии отдельное поле <code>std::string</code>, поэтому изменение <code>copy.name</code> не меняет имя исходной модели. Для строки стандартная библиотека сама выполняет необходимые действия с ресурсом. Вручную вызывать <code>free</code> или <code>delete</code> для её памяти не нужно.</p><p>Подобъекты создаются вместе с содержащим объектом и уничтожаются при его уничтожении. Эта связь времени жизни станет основой <a href="https://stepik.org/lesson/877081/step/4" rel="noopener noreferrer nofollow">RAII и деструкторов</a>. Если многим моделям понадобится доступ к одной общей марке, потребуется иная модель: отдельно решить, кто владеет маркой и как долго допустим доступ к ней.</p>

<h3>Адрес подобъекта и время жизни</h3>

<p>Адрес можно взять не только у всей структуры, но и у её поля. В этом случае указатель обозначает подобъект: его время жизни связано с содержащим объектом.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;string&gt;

struct Make {
    int id{};
    std::string name;
};
struct Model {
    int id{};
    Make make;
    std::string name;
    int year{};
};

int main() {
    Model model{10, {1, "Acura"}, "CL", 2003};
    Make* make = &amp;model.make;
    int* id = &amp;model.id;
    *id = 11;
    std::cout &lt;&lt; make-&gt;name &lt;&lt; ' ' &lt;&lt; model.id &lt;&lt; '\n';
    const Model&amp; view = model;
    const Make* read_only = &amp;view.make;
    std::cout &lt;&lt; read_only-&gt;id &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">Acura 11
1</code></pre><p><code>id</code> указывает на поле <code>model.id</code>, поэтому присваивание <code>*id = 11</code> изменяет эту модель. <code>make</code> указывает на вложенную марку; стрелка выбирает её поле. <h3>Битовые поля и границы переносимости</h3>

<p>Битовое поле задаёт число битов для значения нестатического члена. Это полезно при компактном хранении небольших целых величин. Ширина ограничивает значение поля, но не определяет полный размер структуры или порядок битов в памяти.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

struct Flags {
    unsigned x : 5;
    unsigned y : 3;
};

int main() {
    Flags flags{2, 5};
    std::cout &lt;&lt; flags.x &lt;&lt; ' ' &lt;&lt; flags.y &lt;&lt; '\n';
    flags.x = 31;
    flags.y = 7;
    std::cout &lt;&lt; flags.x &lt;&lt; ' ' &lt;&lt; flags.y &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">2 5
31 7</code></pre><p>У поля <code>x</code> пять значащих битов, поэтому в показанном беззнаковом типе представлены значения 0–31; у <code>y</code> — 0–7. Программа записывает только представимые значения. Запись значения вне диапазона не следует использовать как способ проверки или нормализации данных.</p><p>Тип битового поля должен быть целочисленным или перечислимым, а ширина — неотрицательным целым константным выражением. Нулевая ширина допускается у безымянного поля и влияет на размещение. Ширина сверх возможностей исходного типа не расширяет диапазон: лишние биты являются заполнением. В C++17 в определении битового поля нельзя задавать инициализатор; здесь значения задаются при создании объекта, что подходит и для C++20.</p><p>Битовое поле не имеет собственного адреса: нельзя получить <code>&amp;flags.x</code> или обычную изменяемую ссылку на него. Порядок упаковки, направление распределения битов и выравнивание зависят от реализации. Даже сумма ширин 5 + 3 не обещает <code>sizeof(Flags) == 1</code>. Для переносимого файла или сетевого формата задают байты и маски явно, а не используют внутреннее представление этой структуры.</p><p>Следующий тип, <a href="https://stepik.org/lesson/770597/step/1" rel="noopener noreferrer nofollow">union</a>, тоже связан с представлением данных, но решает другую задачу: разные альтернативы используют одну область хранения.</p>
