Шаги и обязанности, которые будут описаны, обобщены таким образом, что они применимы ко многим системам. В следующих статьях дополнительно будет представлена общая теория с анализом реальных реализаций. </p>

<h3>Функция _start</h3>

<p>Для большинства программ на языках C и C++ истинной точкой входа является не main, а функция _start. Эта функция инициализирует среду выполнения программы и вызывает основную функцию программы.</p>

<p>Использование _start - это просто общее соглашение. Функция ввода может варьироваться в зависимости от системы, компилятора и стандартных библиотек. Например, в OS X есть только динамически связанные приложения; загрузчик заботится о настройке, а точкой входа в программу на самом деле является main.</p>

<p>Компоновщик управляет точкой входа в программу. Точка входа по умолчанию может быть переопределена компоновщиками clang и GCC с использованием флага -e, хотя это редко делается для большинства программ.</p>

<p>Реализация функции _start обычно предоставляется libc. Функция _start часто пишется на ассемблере. Многие реализации хранят функцию _start в файле с именем crt0.s. Компиляторы обычно поставляются с предварительно скомпилированными объектными файлами crt0.o для каждой поддерживаемой архитектуры.</p>

<p>Хотя большая часть этого кода обычно реализуется средой выполнения C, поведение кода при запуске программы не определено стандартами C и C++. Вместо этого стандарты описывают условия, которые должны быть выполнены при вызове основной функции. Однако существует много шагов, которые обычно выполняются в большинстве реализаций _start.</p>

<p>На высоком уровне функция _start обрабатывает:</p>

<ol>
	<li>Ранняя низкоуровневая инициализация, например:
	<ol>
		<li>Настройка регистров процессора</li>
		<li>Инициализация внешней памяти</li>
		<li>Включение кэшей</li>
		<li>Настройка блока управления памятью</li>
	</ol>
	</li>
	<li>Инициализация стека, убедившись, что стек правильно выровнен в соответствии с требованиями двоичного интерфейса приложений</li>
	<li>Инициализация указателя фрейма (Frame pointer)</li>
	<li>Инициализация среды выполнения C/C++</li>
	<li>Инициализация других строительных лесов (Scaffolding), требуемых системой</li>
	<li>Переход к <code>main</code></li>
	<li>Выход из программы с кодом возврата из <code>main</code> </li>
</ol>

<p>Хотя процедура _start обычно включает в себя эти действия, конкретный порядок и реализация варьируются от системы к системе. Например, ранний низкоуровневый код инициализации обычно встречается во встроенных системах с открытым исходным кодом, но редко на хост-машинах с ОС. В коде запуска вашей программы Linux или OS X будет несколько функций, которые вы не найдете во встроенном коде запуска.</p>

<p>Давайте взглянем на простую реализацию функции x86_64 _start, взятой из OS Dev wiki. Этот пример предоставляет предварительный просмотр базового скелета для запуска программы.</p>

<p>Приведенный ниже код запуска предполагает, что загрузчик программы поместил:</p>

<ul>
	<li><code>*argv</code> и <code>*envp</code> переменные в стэк</li>
	<li><code>argc</code> в регистр <code>%rdi</code></li>
	<li><code>argv</code> в регистр <code>%rsi</code></li>
	<li><code>envc</code> в регистр <code>%rdx</code></li>
	<li><code>envp</code> в регистр <code>%rcx</code></li>
</ul>

<p> Вот реализация _start (asm код):</p>

<pre><code class="language-cpp">.section .text

.global _start
_start:
    # Set up end of the stack frame linked list
    movq $0, %rbp
    pushq %rbp # rip=0
    pushq %rbp # rbp=0
    movq %rsp, %rbp

    # Save argc and argv on the stack
    # We need those in a moment when we call main
    pushq %rsi
    pushq %rdi

    # Prepare signals, memory allocation, stdio, etc.
    call initialize_standard_library

    # Run the global constructors.
    call _init

    # Restore argc and argv before calling main
    popq %rdi
    popq %rsi

    # Run main
    call main

    # Terminate the process with the exit code 
    # that was returned from main
    movl %eax, %edi
    call exit</code></pre>

<p>На следующем шаге углубимся и посмотрим, что происходит во время процесса настройки среды выполнения (initialize_standard_library).</p>

<h3>Настройка среды выполнения</h3>

<p>Настройка среды выполнения C/C++ является универсальным требованием для запуска программы. На высоком уровне наша настройка среды выполнения должна выполнять следующее:</p>

<ol>
	<li>Переместите все перемещаемые разделы (если они не обрабатываются загрузчиком или компоновщиком)</li>
	<li>Инициализация глобальной и статической памяти</li>
	<li>Подготовьте переменные argc и argv для вызова main (даже если он просто устанавливает для них значение 0/NULL)</li>
	<li>Выполните любые дополнительные шаги настройки, требуемые реализацией стандартной библиотеки C/C++.</li>
</ol>

<p>Инициализация глобальной и статической памяти разбита на два отдельных этапа, которые заслуживают дополнительной информации.</p>

<p>Во-первых, среда выполнения инициализирует подмножество неинициализированной памяти (no = в объявлении) равным 0. Это включает в себя глобальные и статические переменные, но не переменные стека. Все неинициализированные данные, которым необходимо присвоить значение 0, помещаются компоновщиком в раздел .bss скомпилированного образа программы. Местоположение раздела .bss определяется во время инициализации, а объем памяти обычно устанавливается равным 0 с помощью memset.</p>

<p>Во-вторых, глобальные объекты C++ должны быть созданы перед вызовом main. Компоновщик помещает эти конструкторы в раздел .init, .init_array или .ctors изображения. Некоторые компиляторы также позволяют помечать функции C и C++ как конструктор с использованием атрибута компилятора (например, __attribute__((constuctor))). Конструкторы хранятся компоновщиком в списке. Процесс инициализации среды выполнения выполняет итерацию по списку и вызывает каждый конструктор.</p>

<p>Эти дополнительные шаги инициализации среды выполнения выполняются для многих программ (но не для всех).:</p>

<ol>
	<li>Инициализация кучи</li>
	<li>Инициализировать stdio (т.е. stdin, stdout, stderr)</li>
	<li>Поддержка инициализации исключений (при использовании C++)</li>
	<li>Зарегистрируйте деструкторы и другие функции очистки, которые будут выполняться при выходе из программы (используя atexit и __cxa_atexit)</li>
	<li>Подготовьте переменные среды</li>
</ol>

<p>На практике грань между обязанностями _start и инициализацией среды выполнения языка C может быть нечеткой. Некоторые реализации _start обрабатывают части настройки среды выполнения напрямую, такие как установка содержимого раздела .bss равным 0 и вызов глобальных конструкторов. Другие реализации обрабатывают эти задачи как часть процедур настройки среды выполнения языка C.</p>

<p>Файлы сборки, которые обычно встречаются во время этой части процесса запуска, - это crtbegin.s, crtend.s, crti.s и crtn.s. Компиляторы часто отправляют предварительно скомпилированные объектные файлы для поддерживаемых архитектур. Эти файлы связаны с вызовом глобальных конструкторов и деструкторов. Когда файлы не используются, эквивалентная функциональность часто реализуется на языке C и и вызывается во время инициализации среды выполнения.</p>

<h3>Scaffolding</h3>

<p><strong>Скаффолдинг</strong> — это процесс инициализации проекта, включающий развёртывание файловой структуры проекта и генерацию некоторого (иногда опционального) количества кода, требуемого пользователю.</p>

<ul>

	<li>Настройки локали</li>
	<li>Обработка математических ошибок</li>
	<li>Точность математической библиотеки по умолчанию</li>
</ul>

<p>Конкретные вызываемые функции скаффолдинга различаются в зависимости от реализации стандартной библиотеки и операционной системы.</p>

<h3>Переход к main()</h3>

<p>Получив полностью инициализированную систему, мы можем безопасно перейти к main и выполнить часть приложения, предназначенную для программиста.</p>

<p>Самый важный аспект: как только программа достигает main, она должна быть в состоянии, соответствующем стандартам. В противном случае предположения программы будут признаны недействительными.</p>

<h3>Возвращение из main()</h3>

<p>Хотя в первую очередь были рассмотрен путь достижения до функции <code>main()</code>, должно быть законченно объяснение обязанностей функции _start.</p>

<p>Поскольку _start вызывает <code>main</code>, он также обрабатывает его возврат. Когда элемент управления возвращается из <code>main</code> в _start, следующая функция для запуска - exit. Функция exit вызывает все функции, зарегистрированные в atexit и __cxa_atexit во время процесса запуска. Затем exit вызывает глобальные деструкторы (те, которые размещены в разделах .fini, .fini_array или .dtors). Наконец, exit завершает работу программы с возвращаемым значением, предоставленным main.</p>

<p>Функция выхода в основном используется для размещенных программ. Программы с голым металлом редко используют функцию выхода или глобальные деструкторы.</p>

<h3>Как добраться до _start?</h3>

<p>Теперь, когда мы знаем, как наша программа попадает в main с помощью функции _start, вы можете задаться вопросом, как программа попадает в _start.</p>

<p>Есть три распространенных пути:</p>

<ul>
	<li>"Чистое железо": вектор сброса</li>
	<li>Запуск приложения через загрузчик</li>
	<li>ОС вызывает функцию exec</li>
</ul>

<h4>"Чистое железо": сброс вектора</h4>

<p>Встроенное приложение на "Чистом железе" без операционной системы представляет собой самый простой путь к _start.</p>

<p>Рассмотрим пустую платформу с двоичным файлом, хранящимся во флэш-памяти. Когда на процессор подается питание, процессор копирует программу из флэш-памяти и сохраняет ее в RAM (в некоторых системах процессор пропустит шаг копирования и запустит программу прямо из флэш-памяти). Как только программа загружается в память, процессор переходит к адресу вектора прерывания сброса.</p>

<p>Обработчик прерывания сброса встроенной программы инициализирует систему после включения питания или сброса. Обработчик сброса обычно выполняет первоначальную настройку регистров процессора и критических аппаратных компонентов (таких как внешнее ОЗУ, кэш-память или бок управления памятью). Как только эта начальная конфигурация завершена, обработчик сброса переходит к _start.</p>

<p>Некоторые системы не используют стандартную библиотеку C, и в этом случае _start не будет вызываться. Вместо этого обработчик сброса вызовет другие функции настройки или непосредственно выполнит необходимые шаги настройки программы.</p>

<h4>Запуск приложения через загрузчик</h4>

<p>Многие встроенные приложения состоят из нескольких отдельных образов, которые запускаются последовательно в процессе загрузки.</p>

<p>Во многих системах используется загрузчик или гипервизор, который запускается перед загрузкой и выполнением основного приложения. Загрузчики выполняют широкий спектр действий, включая инициализацию системного оборудования, дешифрование, распаковку, проверку правильности образа встроенного ПО перед его загрузкой, выбор образа встроенного ПО для загрузки или определение того, следует ли переходить в режим обновления встроенного ПО. Сложность загрузчика зависит от требований системы; ни одна из перечисленных задач не будет выполнена.</p>

<p>Другие системы требуют инкрементного процесса загрузки, особенно когда объем основного приложения превышает объем внутренней оперативной памяти процессора. Первый этап загрузки обычно представляет собой небольшой образ, который помещается во внутреннюю память процессора. Этот образ инициализирует внешнюю оперативную память и загрузит основное приложение из флэш-памяти во внешнюю оперативную память. Загрузка на первом этапе может выполнять дополнительные шаги, такие как переназначение вектора процессора или настройка блока управления памятью. Как только основное приложение загружено, загрузка первого этапа вызывает вектор сброса основного приложения.</p>

<p>Многоступенчатые сценарии загрузки усложняют модель запуска программы. Каждый этап загрузки технически представляет собой отдельную программу. Однако не каждый этап будет проходить через полный процесс запуска программы. Простым этапам загрузки может потребоваться только очистить раздел .bss для выполнения своих обязанностей, в то время как сложным загрузчикам требуется полностью инициализированная среда выполнения C/C++. Действия по запуску программы могут быть распределены по всему процессу загрузки, причем каждый этап выполняет определенные задачи.</p>

<h4>ОС вызывает функцию exec</h4>

<p>Самый сложный сценарий - это запуск программы на хост-машине с полноценной ОС.</p>

<p>Когда вы запускаете программу, ваша оболочка или графический интерфейс вызывают загрузчик программы. Загрузчик отвечает за копирование образа приложения с жесткого диска в память и настройку среды, в которой будет выполняться программа. В Linux или OS X загрузчик представляет собой функцию семейства exec(), обычно execve() или execvp(). Для Windows загрузчиком является функция LdrInitializeThunk в ntdll.dll.</p>

<p>Загрузчики часто выполняют следующие действия:</p>

<ol>
	<li>Проверить разрешения</li>
	<li>Выделить место для стека программы</li>
	<li>Выделить место для кучи программы</li>
	<li>Инициализировать регистры (например, указатель стека)</li>
	<li>Вставка <code>argc</code>, <code>argv</code> и <code>envp</code> в стек программы.</li>
	<li>Сопоставление виртуальных адресных пространств</li>
	<li>Динамическое связывание</li>
	<li>Релокация</li>
	<li>Вызов функций предварительной инициализации</li>
</ol>

<p>Как только загрузчик настроил программную среду, он вызывает функцию _start программы.</p>
