<h3>Union: одна активная альтернатива</h3>

<p>Структура хранит свои поля одновременно. <code>union</code>, или объединение, предоставляет общую область хранения для нескольких альтернатив. В каждый момент активен не более чем один нестатический член: именно для него началось и ещё не завершилось время жизни.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

union Number {
    int integer;
    double real;
};

int main() {
    Number number{7};
    std::cout &lt;&lt; number.integer &lt;&lt; '\n';
    number.real = 2.5;
    std::cout &lt;&lt; number.real &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">7
2.5</code></pre><p>Список <code>{7}</code> инициализирует первый член <code>integer</code>. Запись <code>number.real = 2.5</code> для этого простого скалярного члена начинает его время жизни и завершает время жизни прежнего члена. После этого читается только <code>real</code>. Старое целое число не хранится рядом и не превращается автоматически в новое вещественное значение.</p><p>Объект <code>union</code> сам не записывает, какая альтернатива выбрана. Программа должна хранить или иным способом знать этот признак. Чтение неактивного члена в общем случае имеет неопределённое поведение; общая область хранения не разрешает читать произвольную альтернативу как преобразование типа. Узкие исключения, например общая начальная последовательность подходящих структур, не превращают это в общее правило.</p><p>Присваивание начинает время жизни только при определённых правилах языка. Нельзя перенести показанный приём на неактивное поле <code>std::string</code>: такая строка сначала должна быть сконструирована, а прежний нетривиальный член при необходимости уничтожен. <code>union</code> автоматически эти действия за программиста не выполняет. В <a href="https://stepik.org/lesson/770597/step/4" rel="noopener noreferrer nofollow">последнем шаге урока</a> рассмотрим <code>std::variant</code>, который хранит признак альтернативы и управляет её временем жизни.</p>

<h3>Размер union и требования к хранению</h3>

<p>Общая область хранения должна вмещать любой член объединения и удовлетворять выравниванию. Поэтому размер <code>union</code> не меньше размера каждого поля, но может быть больше максимального размера из-за заполнения.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

union Floats {
    float f;
    double d;
};

int main() {
    std::cout &lt;&lt; "float=" &lt;&lt; sizeof(float) &lt;&lt; '\n';
    std::cout &lt;&lt; "double=" &lt;&lt; sizeof(double) &lt;&lt; '\n';
    std::cout &lt;&lt; "union=" &lt;&lt; sizeof(Floats) &lt;&lt; '\n';
    std::cout &lt;&lt; "alignment=" &lt;&lt; alignof(Floats) &lt;&lt; '\n';
    return 0;
}</code></pre><p>Программа не читает неинициализированный член: <code>sizeof</code> и <code>alignof</code> применены к типам. Для распространённой реализации с размерами <code>float</code> 4 и <code>double</code> 8 байтов часто получится размер объединения 8. Эти размеры — свойства конкретной реализации, а не гарантированные константы C++17/20.</p><p>Все нестатические члены объединения начинают своё хранение по одному адресу. Это объясняет экономию места по сравнению с одновременным хранением альтернатив, но не отменяет правило активного члена. Число байтов не сообщает ни текущее значение, ни выбранный тип альтернативы.</p><p>Для вычисления размера объекта в программе применяют <code>sizeof</code>, результат которого имеет тип <code>std::size_t</code>. Даже точный <code>sizeof</code> не задаёт переносимый формат файла: порядок байтов и представление чисел могут отличаться. Для записи смыслового значения нужно сохранять явный признак альтернативы и данные по согласованным правилам.</p>

<h3>Указатель на union не выбирает активный член</h3>

<p>Для доступа через указатель к объединению применяется знакомая стрелка. Сам тип указателя сообщает тип объединения, но не сообщает, какой его член сейчас активен.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

union Number {
    int integer;
    double real;
};

int main() {
    Number number{4};
    Number* pointer = &amp;number;
    std::cout &lt;&lt; pointer-&gt;integer &lt;&lt; '\n';
    pointer-&gt;real = 1.25;
    std::cout &lt;&lt; number.real &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">4
1.25</code></pre><p>Указатель обозначает существующий локальный объект; здесь не требуется динамическая память. После второй записи активен <code>real</code>, независимо от того, обращаемся мы через <code>pointer-&gt;real</code> или через <code>number.real</code>. Доступ к <code>integer</code> после переключения не становится допустимым от использования указателя.</p><p>Указатель не владеет объектом и не продлевает его время жизни. <code>delete pointer</code> в этом примере был бы ошибкой: объект не создан операцией <code>new</code>. Для <code>nullptr</code> и для указателя после уничтожения объекта недопустимо разыменование. Правила адреса и времени жизни те же, что у структуры; к ним добавляется правило активного члена объединения.</p>

<h3>Вложенные альтернативы и std::variant</h3>

<p>Объединение может содержать структуру или другое объединение. Тогда активность нужно отслеживать на каждом уровне. Следующий фрагмент продолжает определение <code>Number</code> из <a href="https://stepik.org/lesson/770597/step/1" rel="noopener noreferrer nofollow">начала урока</a>.</p><p>Фрагмент; определения и контекст указаны в объяснении:</p><pre><code class="language-cpp">union Payload {
    Number number;
    int code;
};

Payload payload{{5}};       // активны number и number.integer
payload.number.real = 2.5;  // активны number и number.real
payload.code = 9;           // активен code; number больше не читается</code></pre><p>Появление полей сложного типа само по себе не добавляет управление их временем жизни. Для обычной программы с альтернативами «число или строка» удобен <code>std::variant</code> из C++17. Запись типов в угловых скобках задаёт допустимые альтернативы стандартного библиотечного шаблона; собственный шаблон писать не требуется.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;string&gt;
#include &lt;variant&gt;

int main() {
    std::variant&lt;int, std::string&gt; value{7};
    std::cout &lt;&lt; std::get&lt;int&gt;(value) &lt;&lt; '\n';
    value = std::string{"ready"};
    if (const auto* text = std::get_if&lt;std::string&gt;(&amp;value)) {
        std::cout &lt;&lt; *text &lt;&lt; '\n';
    }
    std::cout &lt;&lt; std::boolalpha &lt;&lt; (std::get_if&lt;int&gt;(&amp;value) == nullptr) &lt;&lt; '\n';
    try {
        std::cout &lt;&lt; std::get&lt;int&gt;(value) &lt;&lt; '\n';
    } catch (const std::bad_variant_access&amp;) {
        std::cout &lt;&lt; "wrong alternative\n";
    }
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">7
ready
true
wrong alternative</code></pre><p><code>variant</code> хранит текущую альтернативу и отвечает за создание и уничтожение её значения. После присваивания строки числовая альтернатива уже не выбрана. <code>get_if</code> возвращает указатель на нужное значение или <code>nullptr</code>; <code>get</code> при неверной альтернативе бросает <code>std::bad_variant_access</code>. Поэтому результат объясняется без чтения неактивного члена.</p><p>Это не обещание одинакового с <code>union</code> размера: для выбранной альтернативы требуется служебное состояние. При некоторых исключениях во время смены значения <code>variant</code> может остаться без значения; это проверяют методом <code>valueless_by_exception()</code>. Показанный нормальный путь завершает каждую операцию успешно. Для типов с ресурсами такой управляемый интерфейс обычно удобнее ручного переключения <code>union</code>. Следующая тема <a href="https://stepik.org/lesson/877082/step/1" rel="noopener noreferrer nofollow">классов</a> обобщает ту же идею: представление данных сопровождается допустимыми операциями.</p>
