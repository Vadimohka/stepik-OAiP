<h2>Копирование: создать объект или изменить существующий</h2>
<p><strong>Конструктор копирования</strong> создаёт новый объект на основе другого объекта того же класса. <strong>Копирующее присваивание</strong> меняет уже существующий объект. Знак <code>=</code> встречается в обоих случаях: <code>Record copy = source;</code> — инициализация, а отдельная строка <code>copy = source;</code> — присваивание.</p>
<p>Неявные операции работают поэлементно с базами и нестатическими полями. Для поля <code>std::vector&lt;int&gt;</code> это независимая копия элементов, для обычного указателя — только копия адреса. Поэтому поэлементное копирование не равнозначно побайтовому и не всегда означает отдельную копию адресуемого ресурса.</p>
<p>Полная программа использует готовую семантику вектора:</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;vector&gt;

struct Record {
    std::vector&lt;int&gt; scores;
};

int main() {
    Record source{{4, 5}};
    Record copy = source;
    copy.scores[0] = 1;

    Record assigned{{9}};
    assigned = source;
    assigned.scores.push_back(6);

    std::cout &lt;&lt; source.scores[0] &lt;&lt; ' ' &lt;&lt; copy.scores[0] &lt;&lt; '\n';
    std::cout &lt;&lt; source.scores.size() &lt;&lt; ' ' &lt;&lt; assigned.scores.size() &lt;&lt; '\n';
}
</code></pre>
<p>Вывод:</p><pre>4 1
2 3
</pre>
<p><code>copy</code> создаётся конструктором копирования, а <code>assigned</code> уже существует и получает новое содержимое присваиванием. Изменения их векторов не затрагивают <code>source</code>. Старая последовательность <code>assigned</code> заменяется; управление её памятью выполняет сам вектор.</p>
<p>При отсутствии пользовательского объявления язык неявно объявляет копирующие операции, но они могут быть определены как удалённые: например, если поле нельзя копировать или объявлены операции перемещения. Если класс сам владеет ресурсом через сырой указатель, простое копирование адреса может создать двух владельцев, каждый из которых вызовет <code>delete</code>. Правила владения тогда нужно реализовать отдельно либо запретить копирование. Обычно проще выразить поля готовыми контейнерами или умными указателями.</p>
<p>Копирование должно сохранять инвариант типа. Если инвариант связывает несколько полей, недостаточно проверить каждое поле отдельно. <a href="https://stepik.org/lesson/853535/step/3" rel="noopener noreferrer nofollow">Правило нуля</a> помогает управлять ресурсами, но не отменяет проектирование допустимого состояния класса.</p>

<h2>Перемещение, состояние источника и создание результата</h2>
<p>Копирование создаёт независимое значение согласно контракту типа. Перемещение позволяет использовать ресурсы источника для построения или изменения получателя. Для владельца большого буфера это может быть дешевле копирования элементов, но язык не обещает для любого типа ни постоянную стоимость, ни отсутствие выделения памяти.</p>
<p>Обычные формы специальных функций класса <code>X</code> — <code>X(X&amp;&amp; other)</code> и <code>X&amp; operator=(X&amp;&amp; other)</code>. Первая создаёт объект, вторая изменяет существующий. В языке допустимы и другие cv-варианты этих сигнатур, однако для передачи изменяемого ресурса обычно нужна именно неконстантная rvalue-ссылка.</p>
<p>Подходящее rvalue допускает выбор перемещающей операции. Если такой операции нет, может выбираться копирование через <code>const X&amp;</code>; если подходящей доступной операции нет вообще, программа не компилируется. <code>std::move</code> только формирует аргумент для этого выбора. Имя объекта — обычно lvalue, поэтому для двух обычных именованных объектов <code>a = b;</code> ресурс <code>b</code> не забирается неявно.</p>
<h3>Что остаётся у источника</h3>
<p>После фактического перемещения источник обычно продолжает жить. Стандартные библиотечные типы остаются в корректном, но неуточнённом состоянии, если контракт операции не обещает большего. Такой объект можно уничтожить, присвоить ему новое значение или вызвать операцию при соблюдении её предусловий. Например, нельзя без проверки читать <code>moved_vector[0]</code>, но можно сначала присвоить новый вектор. Для <code>unique_ptr</code> конструктор перемещения даёт более сильную гарантию: источник пуст.</p>
<p>У пользовательского типа состояние источника определяется реализацией. Инвариант вида «счётчик равен длине вектора» не обязательно сохранится при поэлементном перемещении: целое поле может сохраниться, а вектор изменить состояние. Такой тип требует согласованного контракта операций, а не механического добавления <code>= default</code>.</p>
<h3>Когда отдельного перемещения вообще нет</h3>
<p>В C++17/20 инициализация отдельного объекта из prvalue того же класса может строить его напрямую. Следующая полная программа корректна, хотя копирование и перемещение <code>Ticket</code> запрещены:</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;

struct Ticket {
    int number;
    explicit Ticket(int value) : number{value} {}
    Ticket(const Ticket&amp;) = delete;
    Ticket(Ticket&amp;&amp;) = delete;
};

Ticket make_ticket() {
    return Ticket{42};
}

int main() {
    Ticket ticket = make_ticket();
    std::cout &lt;&lt; ticket.number &lt;&lt; '\n';
}
</code></pre>
<p>Вывод: <code>42</code>. <code>return Ticket{42};</code> создаёт результат непосредственно; затем этот результат непосредственно инициализирует <code>ticket</code>. В этом конкретном случае отсутствие промежуточных копий — правило C++17/20, а не надежда на настройку оптимизатора. Деструктор всё равно должен быть доступен и не удалён.</p>
<p>Другой случай — именованная локальная переменная: <code>Ticket local{42}; return local;</code>. Устранение копирования <em>NRVO</em> здесь разрешено, но не гарантировано; для такого варианта нужен допустимый путь возврата без NRVO. Пример выше намеренно использует prvalue. Для обычного перемещаемого контейнера достаточно <code>return local;</code>; писать <code>return std::move(local);</code> обычно не нужно: это мешает NRVO.</p>
<p>Компилятор неявно объявляет перемещающие операции при отсутствии пользовательских объявлений копирующих и перемещающих операций и деструктора; пригодность баз и полей затем определяет, не окажется ли функция удалённой. Даже явно записанный <code>~X() = default;</code> считается пользовательским объявлением деструктора и препятствует такому неявному объявлению перемещения. Поэлементная операция выбирает подходящие действия для каждого подобъекта, включая копирование некоторых полей. Полный прикладной пример без собственных специальных функций разобран в <a href="https://stepik.org/lesson/853535/step/3" rel="noopener noreferrer nofollow">следующем тексте</a>; передача исключительного владения — в <a href="https://stepik.org/lesson/853536/step/3" rel="noopener noreferrer nofollow">примере unique_ptr</a>.</p>

<h2>std::move, std::forward и правило нуля</h2>
<p><strong>Цель:</strong> отличать разрешение на перемещение от самого переноса ресурса, не угадывать состояние перемещённого объекта и использовать готовые типы для управления ресурсами.</p>
<h3>Что делает std::move</h3>
<p><code>std::move</code> из заголовка <code>&lt;utility&gt;</code> приводит выражение к rvalue-ссылке. Для обычного объекта результат — xvalue: выражение, из которого разрешено перемещать. Сам вызов не переносит данные, не освобождает память и не завершает время жизни объекта. Дальше разрешение перегрузки выбирает доступный конструктор, присваивание или другую функцию; возможны перемещение, копирование или ошибка компиляции.</p>
<p>В записи <code>destination = std::move(source);</code> перемещающее присваивание, если оно выбрано, выполняет работу. У именованной переменной <code>source</code> выражение без <code>std::move</code> является lvalue. Применяйте перемещение, когда прежнее содержимое источника больше не требуется. Оно не гарантирует ускорения: стоимость зависит от типа и операции. Кроме того, <code>std::move</code> не снимает <code>const</code>; из константной строки или вектора обычно получается копирование, если оно доступно.</p>
<h3>Правило нуля (Rule of Zero)</h3>
<p>Если поля класса сами корректно управляют своими ресурсами, обычно не нужно писать собственные деструктор, конструкторы копирования и перемещения или операторы присваивания. Неявные операции работают с полями согласно их типам. Например, <code>std::string</code> и <code>std::vector</code> уже умеют копировать, перемещать и освобождать свои данные.</p>
<p>Полная программа: копия изменяется независимо, а ресурс источника затем передаётся другому объекту.</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;string&gt;
#include &lt;utility&gt;
#include &lt;vector&gt;

struct Group {
    std::string name;
    std::vector&lt;int&gt; scores;
};

int main() {
    Group source{"A", {4, 5}};
    Group copy = source;
    copy.scores[0] = 1;

    Group destination = std::move(source);
    std::cout &lt;&lt; copy.scores[0] &lt;&lt; ' ' &lt;&lt; destination.scores[0] &lt;&lt; '\n';
    std::cout &lt;&lt; destination.name &lt;&lt; ' ' &lt;&lt; destination.scores.size() &lt;&lt; '\n';

    source = Group{"B", {3}};
    std::cout &lt;&lt; source.name &lt;&lt; ' ' &lt;&lt; source.scores[0] &lt;&lt; '\n';
}
</code></pre>
<p>Вывод:</p><pre>1 4
A 2
B 3
</pre>
<p>В <code>Group</code> нет собственных специальных функций. Изменение копии не меняет исходный вектор. После перемещения поля <code>source</code> — стандартные строка и вектор — остаются в корректном, но в общем случае неуточнённом состоянии. Поэтому программа не предполагает их конкретные длины и не обращается к элементам. Она сначала присваивает <code>source</code> новое значение и только затем читает его. Для пользовательского класса гарантии определяются его реализацией и инвариантами.</p>
<p>Правило нуля не означает, что любой класс копируем. Например, поле <code>std::unique_ptr</code> делает копирование содержащего его класса недоступным, если его специально не реализовать; передача владения перемещением при этом может оставаться доступной.</p>
<h3>Дополнительный разбор: std::forward в шаблоне функции</h3>
<p>Шаблон функции описывает семейство функций: в записи <code>template&lt;class T&gt;</code> имя <code>T</code> обозначает тип, который при обычном вызове может быть выведен из аргумента. Для этого дополнительного разбора достаточно двух правил вывода и свёртки ссылок, показанных ниже.  В <code>template&lt;class T&gt; void relay(T&amp;&amp; argument)</code>, где <code>T</code> выводится при вызове, параметр — перенаправляющая ссылка. Имя <code>argument</code> внутри функции само является lvalue. <code>std::forward&lt;T&gt;(argument)</code> сохраняет возможность передачи как lvalue или rvalue: lvalue передаётся как lvalue, а rvalue — как xvalue. Это не обещание сохранить различие между prvalue и xvalue и не передача владения сама по себе. <code>T</code> здесь аргумент шаблона, а <code>argument</code> — аргумент функции.</p>
<p>Если аргумент имеет тип <code>std::vector&lt;int&gt;</code> и является lvalue, выводится <code>T = std::vector&lt;int&gt;&amp;</code>, а сочетание ссылок в <code>T&amp;&amp;</code> сворачивается в <code>std::vector&lt;int&gt;&amp;</code>. Для rvalue выводится <code>T = std::vector&lt;int&gt;</code>, и параметр имеет тип <code>std::vector&lt;int&gt;&amp;&amp;</code>. Эти правила относятся к выводимому <code>T&amp;&amp;</code>: конкретный параметр <code>std::vector&lt;int&gt;&amp;&amp;</code> без вывода типа — обычная rvalue-ссылка. <code>std::move(argument)</code> в шаблоне всегда разрешал бы перемещение, включая вызовы с lvalue; поэтому здесь используется <code>std::forward&lt;T&gt;</code>.</p>
<p>Полная программа:</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;utility&gt;
#include &lt;vector&gt;

void inspect(const std::vector&lt;int&gt;&amp; values) {
    std::cout &lt;&lt; "const lvalue reference: " &lt;&lt; values.size() &lt;&lt; '\n';
}

void inspect(std::vector&lt;int&gt;&amp;&amp; values) {
    std::cout &lt;&lt; "rvalue reference: " &lt;&lt; values.size() &lt;&lt; '\n';
}

template&lt;class T&gt;
void relay(T&amp;&amp; argument) {
    inspect(std::forward&lt;T&gt;(argument));
}

int main() {
    std::vector&lt;int&gt; values{1, 2, 3};
    relay(values);
    relay(std::vector&lt;int&gt;{4, 5});
    relay(std::move(values));
    std::cout &lt;&lt; "still present: " &lt;&lt; values.size() &lt;&lt; '\n';
}
</code></pre>
<p>Вывод:</p><pre>const lvalue reference: 3
rvalue reference: 2
rvalue reference: 3
still present: 3
</pre>
<p>В последнем вызове <code>relay</code> используется <code>std::move(values)</code>, но выбранная <code>inspect</code> только читает размер. Никто не перемещает вектор в другой объект, поэтому его содержимое сохраняется. Ни <code>std::move</code>, ни <code>std::forward</code> сами по себе не обещают экономию копирования.</p>
<h3>Почему результаты различаются</h3>
<p>В первом примере вектор копии имеет собственные элементы, поэтому изменение <code>copy.scores[0]</code> не меняет значение 4, позже полученное <code>destination</code>. Сразу после перемещения исходный вектор не обязан содержать первый элемент; присваивание нового <code>Group</code> устанавливает известное состояние перед чтением. Во втором примере <code>inspect</code> лишь читает размер через ссылку, поэтому даже переданный как rvalue вектор сохраняет все три элемента.</p>
<p>Следующий шаг связывает эту модель с <a href="https://stepik.org/lesson/853536/step/1" rel="noopener noreferrer nofollow">временем жизни владельца и управляемого объекта</a>. Правило нуля — рекомендация по проектированию, а правила вывода типов и выбора перегрузок задаёт язык.</p>
