<p><strong>Конструктор копирования</strong></p>

<p>Конструктор копирования в C++ создаёт объект на основе другого объекта того же класса. Копирующее присваивание изменяет уже существующий объект. Если соответствующие функции не объявлены пользователем, компилятор при соблюдении правил языка объявляет их неявно; они могут оказаться удалёнными, например из-за некопируемого поля или объявленных операций перемещения. Неявное копирование выполняется поэлементно: поля класса копируются с помощью операций их типов. Для обычного указателя копируется только адрес, для std::string или std::vector копируется содержимое в соответствии с их семантикой. Если класс самостоятельно владеет динамической памятью через сырой указатель, нужно определить правила владения: написать подходящее копирование, запретить его или использовать готовый контейнер/умный указатель. Глубокая копия требуется не каждому классу.</p>

<h3><strong>Семантика перемещения</strong></h3>

<p> </p>

<p>В C++11 были добавлены две новые функции - конструктор перемещения и оператор присваивания перемещением - для работы с семантикой перемещения. В отличие от семантики копирования, которая заключается в создании копии объекта, целью семантики перемещения является перенос владения ресурсами из одного объекта в другой. Для владельца ресурса передача владения часто дешевле глубокого копирования. Однако перемещение не гарантирует отсутствие выделений памяти или копирования: это зависит от типа и реализации операции. Особенно полезно использовать семантику перемещения для объектов, которые управляют большими блоками памяти или ресурсами, например, файловыми дескрипторами.</p>

<p><strong>Конструктор перемещения</strong> и <strong>оператор присваивания перемещением</strong> определяются так же, как и конструктор и оператор присваивания копированием. Однако, вместо константной ссылки l-value, функции с перемещением принимают неконстантную ссылку r-value в качестве параметра.</p>

<h3>Когда вызываются конструктор перемещения и оператор присваивания перемещением?</h3>

<p>Когда аргумент — подходящее rvalue, разрешение перегрузки может выбрать конструктор перемещения или перемещающее присваивание. Если такой операции нет, иногда выбирается копирование через const-ссылку. При инициализации объекта из prvalue того же типа в C++17/20 объект часто строится напрямую: отдельного вызова копирующего или перемещающего конструктора нет.</p>

<p>Компилятор неявно объявляет операции перемещения, если класс не имеет пользовательских объявлений копирующего конструктора, конструктора перемещения, копирующего или перемещающего присваивания и деструктора. Некоторые такие операции затем могут оказаться удалёнными из-за свойств баз и полей. Неявная операция выполняет поэлементное перемещение баз и нестатических полей: для каждого подобъекта выбирается подходящая операция. Для int это перенос значения, для std::unique_ptr — передача владения; некоторые поля могут копироваться, если подходящее перемещение недоступно.</p>

<p>Обычная запись <code>a = b;</code> для двух именованных объектов обычно выбирает копирование: выражение b — lvalue, и его ресурс не следует забирать неявно. Если дальнейшее сохранение прежнего содержимого b не требуется, намерение переместить можно выразить явно: <code>a = std::move(b);</code>.</p>

<p>Rvalue не обязательно является временным объектом: <code>std::move(b)</code> может обозначать обычную переменную b. После фактического перемещения исходный объект продолжает жить. Объекты стандартной библиотеки обычно остаются в корректном, но неуточнённом состоянии, если для операции не задана более сильная гарантия. Их можно уничтожить, заново присвоить им значение и вызывать операции, для которых выполнены предусловия. Перемещение может экономить копирование ресурсов, но его стоимость зависит от типа и конкретной операции.</p>

<p>В C++11 через ссылки r-value мы можем изменять поведение функций в зависимости от того, чем является аргумент: r-value или l-value. Это позволяет нам принимать более разумные и эффективные решения о том, как должен работать наш код.</p>

<h2>std::move, std::forward и правило нуля</h2>
<p><strong>Цель:</strong> отличать разрешение на перемещение от самого переноса ресурса, не угадывать состояние перемещённого объекта и использовать готовые типы для управления ресурсами.</p>
<h3>Что делает std::move</h3>
<p><code>std::move</code> из заголовка <code>&lt;utility&gt;</code> приводит выражение к rvalue-ссылке. Для обычного объекта результат — xvalue: выражение, из которого разрешено перемещать. Сам вызов не переносит данные, не освобождает память и не завершает время жизни объекта. Дальше разрешение перегрузки выбирает доступный конструктор, присваивание или другую функцию; возможны перемещение, копирование или ошибка компиляции.</p>
<p>В записи <code>destination = std::move(source);</code> перемещающее присваивание, если оно выбрано, выполняет работу. У именованной переменной <code>source</code> выражение без <code>std::move</code> является lvalue. Применяйте перемещение, когда прежнее содержимое источника больше не требуется. Оно не гарантирует ускорения: стоимость зависит от типа и операции. Кроме того, <code>std::move</code> не снимает <code>const</code>; из константной строки или вектора обычно получается копирование, если оно доступно.</p>
<h3>Правило нуля (Rule of Zero)</h3>
<p>Если поля класса сами корректно управляют своими ресурсами, обычно не нужно писать собственные деструктор, конструкторы копирования и перемещения или операторы присваивания. Неявные операции работают с полями согласно их типам. Например, <code>std::string</code> и <code>std::vector</code> уже умеют копировать, перемещать и освобождать свои данные.</p>
<p>Полная программа: копия изменяется независимо, а ресурс источника затем передаётся другому объекту.</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;string&gt;
#include &lt;utility&gt;
#include &lt;vector&gt;

struct Group {
    std::string name;
    std::vector&lt;int&gt; scores;
};

int main() {
    Group source{"A", {4, 5}};
    Group copy = source;
    copy.scores[0] = 1;

    Group destination = std::move(source);
    std::cout &lt;&lt; copy.scores[0] &lt;&lt; ' ' &lt;&lt; destination.scores[0] &lt;&lt; '\n';
    std::cout &lt;&lt; destination.name &lt;&lt; ' ' &lt;&lt; destination.scores.size() &lt;&lt; '\n';

    source = Group{"B", {3}};
    std::cout &lt;&lt; source.name &lt;&lt; ' ' &lt;&lt; source.scores[0] &lt;&lt; '\n';
}
</code></pre>
<p>Вывод:</p><pre>1 4
A 2
B 3
</pre>
<p>В <code>Group</code> нет собственных специальных функций. Изменение копии не меняет исходный вектор. После перемещения поля <code>source</code> — стандартные строка и вектор — остаются в корректном, но в общем случае неуточнённом состоянии. Поэтому программа не предполагает их конкретные длины и не обращается к элементам. Она сначала присваивает <code>source</code> новое значение и только затем читает его. Для пользовательского класса гарантии определяются его реализацией и инвариантами.</p>
<p>Правило нуля не означает, что любой класс копируем. Например, поле <code>std::unique_ptr</code> делает копирование содержащего его класса недоступным, если его специально не реализовать; передача владения перемещением при этом может оставаться доступной.</p>
<h3>std::forward: сохранение категории аргумента</h3>
<p>Этот подраздел использует шаблоны функций. В <code>template&lt;class T&gt; void relay(T&amp;&amp; argument)</code>, где <code>T</code> выводится при вызове, параметр — перенаправляющая ссылка. Имя <code>argument</code> внутри функции само является lvalue. <code>std::forward&lt;T&gt;(argument)</code> сохраняет исходную категорию: lvalue передаётся как lvalue, rvalue — как rvalue. <code>T</code> здесь аргумент шаблона, а <code>argument</code> — аргумент функции.</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;utility&gt;
#include &lt;vector&gt;

void inspect(const std::vector&lt;int&gt;&amp; values) {
    std::cout &lt;&lt; "const lvalue reference: " &lt;&lt; values.size() &lt;&lt; '\n';
}

void inspect(std::vector&lt;int&gt;&amp;&amp; values) {
    std::cout &lt;&lt; "rvalue reference: " &lt;&lt; values.size() &lt;&lt; '\n';
}

template&lt;class T&gt;
void relay(T&amp;&amp; argument) {
    inspect(std::forward&lt;T&gt;(argument));
}

int main() {
    std::vector&lt;int&gt; values{1, 2, 3};
    relay(values);
    relay(std::vector&lt;int&gt;{4, 5});
    relay(std::move(values));
    std::cout &lt;&lt; "still present: " &lt;&lt; values.size() &lt;&lt; '\n';
}
</code></pre>
<p>Вывод:</p><pre>const lvalue reference: 3
rvalue reference: 2
rvalue reference: 3
still present: 3
</pre>
<p>В последнем вызове <code>relay</code> используется <code>std::move(values)</code>, но выбранная <code>inspect</code> только читает размер. Никто не перемещает вектор в другой объект, поэтому его содержимое сохраняется. Ни <code>std::move</code>, ни <code>std::forward</code> сами по себе не обещают экономию копирования.</p>
<h3>Самопроверка</h3>
<ol><li>Почему после изменения <code>copy.scores[0]</code> в <code>destination</code> остаётся 4?</li><li>Почему нельзя заменить присваивание нового значения источнику на безусловное чтение <code>source.scores[0]</code> сразу после перемещения?</li><li>Почему последнее значение размера во втором примере равно 3, хотя использован <code>std::move</code>?</li></ol>
<p><strong>Проверьте объяснение:</strong> вектор копируется независимо; у перемещённого вектора нельзя предполагать наличие первого элемента; связывание rvalue-ссылки и чтение размера не выполняют переноса ресурса.</p>
