<h3>Немного о создании программ</h3>

<p>Разработка программ на языке C++ ведется с помощью специальных комплексов программ, которые называются системами программирования и позволяют создавать программы на определенной реализации языка. Системы программирования даже одного производителя имеют различные версии, которые отражают развитие технологии программирования и эволюцию среды выполнения программ. Это стимулирует стремление максимально использовать стандартные средства языка для того, чтобы снизить затраты на модификацию программ при изменении среды выполнения или при переходе на другую версию языка. Вместе с тем ряд свойств зависит от реализации в пределах требований стандарта. К их числу относится машинное кодирование символов, числовых и логических значений. Стандарт не определяет порядок создания программы для определенной среды выполнения. Детали процесса построения программ описаны в документации системы программирования. Если отвлечься от синтаксических, семантических и иных особенностей, присущих каждой конкретной системе программирования, процесс создания программ включает четыре этапа:</p>

<ul>
	<li>
	<p>Написание и редактирование исходного текста программы с сохранением ее в виде исходного файла или модуля.</p>
	</li>
	<li>
	<p>Компиляция программы и получение ее на определенном промежуточном языке с сохранением в виде объектного файла или модуля.</p>
	</li>
	<li>
	<p>Построение исполняемого файла или модуля путем объединения (компоновки) полученного объектного модуля программы с другими объектными модулями стандартных и специальных библиотек.</p>
	</li>
	<li>
	<p>Отладка программы, которую можно проводить с помощью специального средства (отладчика), облегчающего обнаружение ошибок.</p>
	</li>
</ul>

<h3>Процесс компиляции и сборки</h3>

<p><strong>Компиляция</strong> — разновидность трансляции: преобразование программы с исходного языка в целевое представление. При обычной сборке C++ это часть процесса получения исполняемого файла.</p>

<ol>
<li><strong>Препроцессорная обработка.</strong> Обрабатываются директивы, например <code>#include</code> и <code>#define</code>.</li>
<li><strong>Компиляция.</strong> Компилятор анализирует обработанный исходный код и формирует код для целевой платформы. Он может сначала выдать ассемблерный текст, который затем преобразует ассемблер.</li>
<li><strong>Получение объектного файла.</strong> Объектный файл содержит скомпилированный код, данные и служебную информацию, в том числе сведения о ещё не разрешённых ссылках на имена. Это не исходный код на C++.</li>
<li><strong>Компоновка.</strong> Компоновщик связывает объектные файлы и необходимые библиотеки, разрешает внешние ссылки и формирует исполняемый файл или библиотеку.</li>
</ol>

<p>Эти этапы могут выполняться разными инструментами. Команда компилятора часто служит драйвером и автоматически вызывает препроцессор, ассемблер и компоновщик. Поэтому слово «компиляция» в разговоре иногда используют для всей сборки; в этом курсе различаем компиляцию исходника и компоновку.</p>

<p>Исходные файлы обычно имеют расширение <code>.cpp</code> и другие поддерживаемые компилятором расширения. Для объектных файлов часто применяют <code>.o</code> или <code>.obj</code>, для статических библиотек — <code>.a</code> или <code>.lib</code>. Имена и форматы зависят от платформы и инструментов. Исполняемый файл не обязан иметь расширение <code>.exe</code>.</p>

<h3><strong>Схема получения исполняемого модуля программы в интегрированной среде </strong><img alt="" height="1690" name="Frame 6.png" src="https://ucarecdn.stepik.net/3886b3de-92f5-4a8e-b04e-6b76f1d1bd83/-/crop/4666x1690/0,172/-/preview/" width="4666"></h3>

<p>На схеме показан типичный процесс сборки в среде Windows. Исходный модуль (ИМ) программы подготавливается с помощью встроенного или внешнего текстового редактора и размещается в файле с расширением .cpp. После этого ИМ обрабатывается препроцессором и, в случае необходимости, к исходному тексту программы присоединяются подключаемые файлы (ПФ). В дальнейшем модернизированный исходный модуль (ИМ*) обрабатывается компилятором. Выявленные синтаксические ошибки устраняются, и безошибочно откомпилированный объектный модуль (ОМ) помещается в файл с расширением .obj. Затем ОМ обрабатывается компоновщиком, который дополняет программу нужными библиотечными функциями из библиотечных файлов (БФ). Полученный модуль называется исполнимым модулем (ИсМ) и помещается в файл с расширением .exe, который в дальнейшем исполняется.</p>

<h3><strong>Этап препроцессорной обработки</strong></h3>

<ul>
	<li>Язык препроцессора – это специальный язык программирования, встроенный в C++</li>
	<li>Препроцессор работает с кодом на C++ как с текстом</li>
	<li>Команды языка препроцессора называют директивами, все директивы начинаются со знака #</li>
	<li>Директива #include позволяет подключать заголовочные файлы к файлам кода:
	<ul>
		<li><code>#include &lt;iostream&gt;</code> — пример подключения стандартного заголовка</li>
		<li><code>#include "bar.h"</code> — пример подключения заголовка проекта</li>
	</ul>
	</li>
	<li>Препроцессор заменяет директиву #include "bar.h" на содержимое файла bar.h.</li>
</ul>

<h3><strong>Этап компиляции</strong></h3>

<ul>
	<li>На вход компилятору поступает код на C++ после обработки препроцессором</li>
	<li>Каждый файл с кодом компилируется отдельно и независимо от других файлов с кодом</li>
	<li>Компилируются единицы трансляции: исходный файл вместе с включёнными заголовками после препроцессорной обработки. Расширение исходника не обязано быть .cpp: GCC, например, также распознаёт .cc и .cp.</li>

	<li>На выходе компилятора из каждого файла с кодом получается “объектный файл” — бинарный файл со скомпилированным кодом (с расширением .o или .obj в зависимости от платформы и инструментов сборки).</li>
</ul>

<h3><strong>Этап компоновки (линковки)</strong></h3>

<ul>
	<li>На этом этапе все объектные файлы объединяются в один исполняемый (или библиотечный) файл</li>
	<li>При этом разрешаются внешние ссылки на функции и данные; конкретные адреса могут также уточняться при загрузке и динамическом связывании</li>
	<li>Компоновщик использует таблицы символов объектных файлов: определения и ещё не разрешённые внешние ссылки</li>
	<li>Компоновщику нужно различать символы, соответствующие разным функциям</li>
	<li>В C++ может быть две функции с одним именем, но разными параметрами</li>
	<li>В обычных реализациях C++ применяется декорирование имён (name mangling): в имени символа кодируются сведения о функции, в том числе типы параметров и пространство имён. Формат зависит от реализации</li>
	<li>Аналогично функциям в линковке нуждаются глобальные переменные</li>
	<li>В обычной hosted-программе C++ должна быть функция main. При этом точкой входа исполняемого файла может быть служебная функция среды выполнения, которая подготавливает окружение и затем вызывает main:</li>
</ul>

<pre><code>int main () {
   return 0;
}
</code></pre>
