<h2>Зачем нужна система сборки</h2>
<p>Одну небольшую программу можно собрать командой компилятора. В проекте из нескольких исходников нужно помнить, какие файлы обрабатывать, с какими настройками, какие библиотеки подключать и какие результаты зависят друг от друга. <strong>Система сборки</strong> автоматизирует эти действия по описанию проекта.</p>
<p>Например, исполняемая программа зависит от объектных файлов, а объектный файл — от своего исходника и используемых заголовков. Если изменён <code>main.cpp</code>, его результат нужно обновить и заново соединить программу. Если изменён общий заголовок, обновление может понадобиться нескольким исходникам. Такие связи называются <strong>зависимостями сборки</strong>.</p>
<p>Система сборки не обязана повторять всю работу после каждого изменения. Она использует известные зависимости и сведения об актуальности файлов, чтобы выполнить нужные действия. Но неверно описанная зависимость может оставить устаревший результат. Поэтому понятное описание сборки — часть воспроизводимости программы, а не только удобная кнопка.</p>
<p><strong>CMake</strong> читает описание проекта и создаёт файлы для выбранного инструмента сборки. Затем этот инструмент вызывает компилятор, компоновщик и другие необходимые команды. CMake не заменяет компилятор C++ и не выбирает алгоритм программы.</p>
<p>Роли соседних инструментов различаются. Редактор меняет исходный текст; компилятор обрабатывает C++; Git сохраняет историю выбранных файлов; CMake помогает описать сборку. В репозитории обычно сохраняют исходники и <code>CMakeLists.txt</code>, а промежуточные результаты помещают в отдельный каталог сборки. Само наличие коммита не доказывает, что эта версия успешно собирается.</p>
<p><a href="https://stepik.org/lesson/774618/step/2" rel="noopener noreferrer nofollow">Следующий шаг объясняет генератор и две фазы работы CMake</a>, после чего <a href="https://stepik.org/lesson/774618/step/3" rel="noopener noreferrer nofollow">полностью разобранный пример</a> связывает описание проекта, команды и результат. В <a href="https://stepik.org/lesson/770592/step/1" rel="noopener noreferrer nofollow">модуле 7</a> та же модель будет использована для нескольких файлов и библиотек.</p>

<h2>CMake: описание проекта и получение программы</h2>
<p>Главное описание проекта обычно находится в <code>CMakeLists.txt</code>. В нём задают цели сборки, их исходники, зависимости и требования, например версию C++. <strong>Цель</strong> в этом контексте — именованный результат, который нужно получить: исполняемая программа или библиотека.</p>
<p>CMake сначала настраивает проект и генерирует описание для выбранного инструмента. <strong>Генератор</strong> определяет формат этого описания: например, файлы для Make, Ninja или проекта Visual Studio. Доступные генераторы и инструменты зависят от установленного окружения. Одного наличия CMake недостаточно, если нужный компилятор или инструмент сборки отсутствует.</p>
<p>Для проекта <a href="https://stepik.org/lesson/774618/step/3" rel="noopener noreferrer nofollow">следующего шага</a> команды оболочки имеют такой смысл. Они приведены как разбор интерфейса, а не как отдельное задание:</p>
<pre><code class="language-bash">cmake -S . -B build
cmake --build build
</code></pre>
<p>Первая команда берёт исходный каталог <code>.</code> и создаёт каталог результатов <code>build</code>, если его ещё нет. Она читает настройки проекта, определяет инструменты и записывает файлы сборки. Вторая команда просит CMake запустить инструмент, выбранный для этого каталога. Именно он организует компиляцию и компоновку описанных целей.</p>
<p>Раздельные каталоги помогают отличать авторские исходники от производных файлов. Для другого компилятора или независимой конфигурации удобно использовать отдельный каталог сборки. Генератор, поддерживающий несколько конфигураций, например Visual Studio, позволяет выбирать нужную при сборке: <code>cmake --build build --config Debug</code>. В генераторах с одной конфигурацией её обычно выбирают при настройке. Эти детали не изменяют синтаксис C++.</p>
<p>Файлы исходников, стандарт языка и библиотеки должны быть описаны явно. Стандартное свойство цели CMake помогает запросить C++17 или C++20, однако не исправляет отсутствие поддержки отдельной возможности в установленном компиляторе. <a href="https://stepik.org/lesson/774618/step/3" rel="noopener noreferrer nofollow">Полный пример с main.cpp и CMakeLists.txt</a> показывает конкретную цель <code>hello</code> и ожидаемый вывод; <a href="https://stepik.org/lesson/770592/step/1" rel="noopener noreferrer nofollow">многофайловый проект модуля 7</a> продолжит эту модель без новой роли для инструмента.</p>

<h3>Собираем первую программу с CMake</h3>
<p>Разберём полное описание сборки одной программы: выбранный стандарт, команды и расположение результата. Нужны три отдельных инструмента: CMake, компилятор C++ и выбранная система сборки, например Make, Ninja или MSBuild. Установка одного CMake не устанавливает автоматически все остальные компоненты.</p>
<p>Установите CMake версии 3.22 или новее по <a href="https://cmake.org/download/" rel="noopener noreferrer nofollow">официальной инструкции</a> или через пакетный менеджер своей ОС. Команда <code>cmake --version</code> показывает установленную версию.</p>
<p>В каталоге примера находятся два файла. Содержимое <code>main.cpp</code>:</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;

int main() {
    std::cout &lt;&lt; "Hello C++\n";
}
</code></pre>
<p>Содержимое <code>CMakeLists.txt</code>:</p>
<pre><code class="language-cmake">cmake_minimum_required(VERSION 3.22)
project(FirstProgram LANGUAGES CXX)

set(SOURCES main.cpp)
add_executable(hello ${SOURCES})
set_target_properties(hello PROPERTIES
    CXX_STANDARD 20
    CXX_STANDARD_REQUIRED YES
    CXX_EXTENSIONS NO
)

if(MSVC)
    target_compile_options(hello PRIVATE /W4 /permissive-)
elseif(CMAKE_CXX_COMPILER_ID MATCHES "GNU|Clang")
    target_compile_options(hello PRIVATE -Wall -Wextra -Wpedantic)
endif()
</code></pre>
<ul>
<li><code>add_executable</code> создаёт цель сборки <code>hello</code>. Здесь переменная <code>SOURCES</code> содержит имя одного исходного файла, а <code>${SOURCES}</code> подставляет её значение.</li>
<li>Свойства цели задают C++20, запрещают незаметно понижать запрошенный стандарт и отключают запрос расширенного диалекта компилятора. Поддержка отдельных возможностей языка и библиотеки всё равно зависит от установленного компилятора.</li>
<li>Предупреждения задаются для конкретной цели через <code>target_compile_options</code>. Флаги GCC/Clang и MSVC различаются; при другом компиляторе нужно посмотреть его документацию. Предупреждения помогают обнаруживать ошибки, но не доказывают правильность программы.</li>
</ul>
<p>При использовании Make или Ninja выполните из папки с <code>CMakeLists.txt</code>:</p>
<pre><code class="language-bash">cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
</code></pre>
<p>Первая команда настраивает проект и сохраняет служебные файлы в отдельную папку <code>build</code>. Вторая запускает компиляцию и компоновку. <code>Debug</code> — конфигурация, удобная для отладки. Для генератора Visual Studio конфигурацию выбирают на этапе сборки:</p>
<pre><code class="language-text">cmake -S . -B build
cmake --build build --config Debug
</code></pre>
<p>В Linux/macOS при Make или Ninja программа обычно запускается командой <code>./build/hello</code>. В PowerShell при генераторе Visual Studio — <code>.\build\Debug\hello.exe</code>. Расположение зависит от генератора и настроек. Ожидаемый вывод:</p>
<pre><code class="language-text">Hello C++
</code></pre>
<p><strong>Разбор изменения:</strong> если автор меняет приветствие в <code>main.cpp</code>, повторная сборка обновляет программу. Если удалена обязательная точка с запятой, компиляция завершается ошибкой; оставшийся старый исполняемый файл не содержит новое состояние исходника. После исправления и успешной сборки новый вывод соответствует исправленному тексту.</p>
<p>Документация: <a href="https://cmake.org/cmake/help/latest/manual/cmake.1.html" rel="noopener noreferrer nofollow">команды CMake</a>, <a href="https://cmake.org/cmake/help/latest/prop_tgt/CXX_STANDARD.html" rel="noopener noreferrer nofollow">выбор стандарта</a>, <a href="https://cmake.org/cmake/help/latest/prop_tgt/CXX_EXTENSIONS.html" rel="noopener noreferrer nofollow">расширения компилятора</a>.</p>

<h3>Один проект в терминале и в IDE</h3>
<p>IDE позволяет запускать те же инструменты сборки из своего интерфейса. IDE открывает каталог с <code>CMakeLists.txt</code> и связывает его с выбранным компилятором, конфигурацией <code>Debug</code> и целью <code>hello</code>. Названия кнопок могут отличаться; исходники и описание сборки остаются теми же.</p>
<p>Различайте три действия:</p>
<ol>
<li><strong>Настройка проекта:</strong> CMake читает описание и подготавливает файлы для выбранной системы сборки.</li>
<li><strong>Сборка:</strong> компилятор и компоновщик создают программу. Изменение <code>main.cpp</code> требует новой сборки.</li>
<li><strong>Запуск:</strong> выполняется уже собранная программа. Успешный запуск старого файла не подтверждает успешную сборку новой версии.</li>
</ol>
<p>Если проект собирается в терминале, но не в IDE, сравните путь к компилятору, версию CMake, каталог сборки и конфигурацию. Чтобы увидеть реальные команды компилятора, выполните:</p>
<pre><code class="language-text">cmake --build build --config Debug --verbose
</code></pre>
<p><code>--config Debug</code> выбирает конфигурацию у многоконфигурационного генератора. У генератора с одной конфигурацией тип сборки задают при настройке через <code>CMAKE_BUILD_TYPE</code>.</p>
<table><thead><tr><th>Симптом</th><th>Что проверить</th></tr></thead><tbody>
<tr><td>Команда <code>cmake</code> не найдена</td><td>Установлен ли CMake и доступен ли его каталог через <code>PATH</code>.</td></tr>
<tr><td>CMake не находит компилятор</td><td>Установлен ли набор инструментов C++; в Windows может требоваться терминал среды разработки.</td></tr>
<tr><td>Ошибка в строке <code>.cpp</code></td><td>Первую содержательную диагностику компилятора, имя файла и номер строки.</td></tr>
<tr><td>При запуске выводится старый текст</td><td>Завершилась ли последняя сборка успешно и тот ли исполняемый файл запущен.</td></tr>
</tbody></table>
<p>При смене компилятора или генератора создавайте новый каталог сборки, например <code>build-other</code>: существующий кеш CMake связан с прежней конфигурацией. Служебные каталоги сборки можно восстановить из исходников; обычно их не добавляют в Git.</p>
<p><strong>Разбор журнала:</strong> строка с <code>g++</code> и <code>-std=c++20</code> показывает компилятор и выбранный режим. Кнопка «Собрать» запускает эту цепочку инструментов, а «Запустить» исполняет полученный файл. Они выполняют разные операции даже при одинаковом интерфейсе IDE.</p>
<p><a href="https://cmake.org/cmake/help/latest/manual/cmake.1.html" rel="noopener noreferrer nofollow">Справка команд CMake</a>.</p>

<h3>Как описание сборки связывает темы курса</h3>
<p><code>CMakeLists.txt</code> описывает цели, исходники и требования сборки. Каталог <code>build</code> содержит производные результаты, которые можно получить заново из исходников при наличии нужных инструментов и зависимостей. CMake генерирует описание сборки и запускает выбранный инструмент; машинный код создаёт компилятор.</p>
<ul>
<li><a href="https://cmake.org/cmake/help/latest/guide/tutorial/" rel="noopener noreferrer nofollow">Официальный учебник CMake</a> — цели, библиотеки и работа с несколькими файлами.</li>
<li><a href="https://cmake.org/cmake/help/latest/manual/cmake.1.html" rel="noopener noreferrer nofollow">Справка <code>cmake</code></a> — параметры настройки и сборки.</li>
<li><a href="https://cmake.org/cmake/help/latest/manual/ctest.1.html" rel="noopener noreferrer nofollow">Справка CTest</a> — запуск автоматических тестов; к нему вернёмся в модуле тестирования.</li>
<li><a href="https://learn.microsoft.com/en-us/cpp/build/cmake-projects-in-visual-studio" rel="noopener noreferrer nofollow">CMake в Visual Studio</a> и <a href="https://www.jetbrains.com/help/clion/quick-cmake-tutorial.html" rel="noopener noreferrer nofollow">учебник CMake в CLion</a> — настройки конкретных IDE.</li>
</ul>
<p>Для того же исходного каталога можно настроить отдельный каталог <code>build-check</code>. Исходники остаются общими, а настройки и результаты сборки — отдельными. Это удобно для разных конфигураций. В модуле функций цель будет состоять из нескольких единиц трансляции, затем появится отдельная библиотека.</p>
<p>Пример локально использует C++20. Это настройка вашего проекта, а не заявление о версии проверяющей системы Stepik. В программных заданиях выбирайте язык из доступного списка и учитывайте указанные в условии требования.</p>
