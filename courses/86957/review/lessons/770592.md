<h3>Область видимости объектов</h3>

<p>Ранее мы рассматривали глобальные и локальные переменные. Теперь различим область видимости имени и продолжительность хранения объекта. Первая определяет, где имя доступно в коде, а вторая связана с тем, как долго существует память для объекта.</p>

<h4>Автоматические объекты</h4>

<p>Локальные объекты, которые существуют только во время выполнения того блока, в котором они определены, являются автоматическими.</p>

<p>Объявление автоматической переменной выполняется при каждом достижении соответствующего места кода. При выходе из её блока время жизни объекта заканчивается. Для объектов классов это включает вызов деструктора.</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
 
void print(int);
 
int main() {
    int z = 2;
    print(z);  // n=10
    //n++;     //так сделать нельзя, так как n определена в функции print
    return 0;
}
  
void print(int x) {
    int n = 5 * x;
    // z++; так сделать нельзя, так как z определена в функции main
    std::cout &lt;&lt; "n=" &lt;&lt; n &lt;&lt; std::endl;
}</code></pre>

<p>Здесь в функции print определена локальная переменная n. В функции main определена автоматическая переменная z. Вне своих функций эти переменные недоступны. Например, мы не можем использовать переменную n в функции main, так как ее область видимости ограничена функцией print. Соответственно также мы не можем использовать переменную z в функции print, так как эта переменная ограничена функцией main.</p>

<p>Параметры функции так же, как и локальные переменные, существуют, пока выполняется функция, вне функции их имена недоступны.</p>

<p>Подобным образом с помощью блока кода можно определить вложенные области видимости:</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
 
int main() {
    int n = 2;
    
    {
        int x = 5;
        std::cout &lt;&lt; "x=" &lt;&lt; x &lt;&lt; std::endl;
        n++;    // так можно, так как n определена во внешнем контексте
    }
    //x++;      // так сделать нельзя, так как x определена в блоке кода
    std::cout &lt;&lt; "n=" &lt;&lt; n &lt;&lt; std::endl;
    return 0;
}</code></pre>

<p>Во вложенной области могут быть доступны имена из внешней области, если их объявления уже видимы и имена не скрыты. Глобальная область видимости является внешней для функции, поэтому функция может использовать глобальные переменные. А функция является внешним контекстом для вложенного блока кода, поэтому блок кода может использовать переменную n, которая определена в функции вне этого блока. Однако переменные, определенные в блоке кода, вне этого блока использовать нельзя.</p>

<h3>Сокрытие объектов</h3>

<p>Локальные объекты, определенные внутри одного контекста, могут скрывать объекты с тем же именем, определенные во внешнем контексте:</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
 
int n = 5;
 
int main() {
    int n = 10;
    std::cout &lt;&lt; "n=" &lt;&lt; n &lt;&lt; std::endl;  // n=10
     
    {
        int n = 20;
        std::cout &lt;&lt; "n=" &lt;&lt; n &lt;&lt; std::endl; // n=20
    }
    return 0;
}</code></pre>

<p>Здесь определено три переменных с именем n. Переменная n, определенная на уровне функции main (<code>int n = 10;</code>) скрывает глобальную переменную n. А переменная n, определенная на уровне блока, скрывает переменную, определенную на уровне функции main.</p>

<h3>Статические объекты</h3>

<p>Локальная переменная с static имеет статическую продолжительность хранения и сохраняет значение между вызовами. Её успешная инициализация выполняется один раз. Если для неё требуется динамическая инициализация, она происходит при первом достижении объявления; постоянная и нулевая инициализация могут происходить раньше.</p>

<p>Например, пусть будет функция со стандартной автоматической переменной:</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
 
void display();
 
int main() {
    display();
    display();
    display();
     
    return 0;
}
  
void display() {
    int i = 0;
    i++;
    std::cout &lt;&lt; "i=" &lt;&lt; i &lt;&lt; std::endl;
}</code></pre>

<p>Функция display вызывается три раза, и при каждом вызове программа повторно будет выделять память для переменной i, которая определена в функции. А после завершения работы display, память для переменной i будет освобождаться. Соответственно ее значение при каждом вызове будет неизменно.</p>

<p>Если сделать переменную i статической, то при завершении работы функции display переменная не уничтожается, ее память не очищается, наоборот, она сохраняется в памяти. И соответственно результат работы программы будет иным.</p>

<h3>Разделение программы на файлы</h3>

<p>При разработке программ рекомендуется разбивать их на части, которые функционально ограничены и закончены. Например, некоторые функции можно расположить в  отдельных *.сpp файлах. Такой подход обеспечивает ряд преимуществ: </p>

<ul>
	<li>Обычно сложная программа разбивается на несколько отдельных частей (модулей), которые отлаживаются отдельно и зачастую разными людьми; поэтому в завершение остаётся лишь собрать готовые модули в единый проект; </li>
	<li>При исправлении в одном модуле не надо снова транслировать (переводить в машинные коды) все остальные (это могут быть десятки тысяч строк); </li>
	<li>При компоновке во многих системах можно подключать модули, написанные на  других языках, например, на C, при совместимости формата объектных файлов и интерфейса вызова. </li>
</ul>

<p>Например, определим файл factorial.cpp, который будет иметь следующий код:</p>

<pre><code class="language-cpp">int factorial(int n) {
    if (n &gt; 1)
        return n * factorial(n - 1);
    return 1;
}</code></pre>

<p>Это функция вычисления факториала.</p>

<p>Добавим еще один файл factorial.h, который будет содержать объявление функции factorial:</p>

<pre><code class="language-cpp">int factorial(int);</code></pre>

<p>Если ваш заголовочный файл может быть использован более одного раза, рекомендуется использовать директиву <code>#pragma once</code>. Это нестандартная, но широко распространённая препроцессорная директива, разработанная для контроля за тем, чтобы конкретный заголовочный файл включался не более одного раза в одной единице трансляции.</p>

<p>И также определим главный файл, который назовем main.cpp:</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
#include "factorial.h"
 
int main() {
    int result = factorial(5);
    std::cout &lt;&lt; "result = " &lt;&lt; result &lt;&lt; std::endl;
 
    return 0;
}</code></pre>

<p>Функция main вызывает функцию factorial для вычисления факториала числа. Но чтобы использовать функцию, определенную в другом файле, необходимо добавить ее объявление. В прошлых темах объявление функции добавлялось непосредственно в главный и единственный файл программы. Однако если функции определены в отдельных файлах, то более оптимально помещать объявления функций в специальные заголовочные файлы и потом подключать эти файлы. Именно поэтому в начале с помощью директивы include подключается файл factorial.h, который содержит объявление или заголовок функции. Файл factorial.h еще называется заголовочным файлом (header file).</p>

<p>Можно было бы и не подключать файл factorial.h и вообще не создавать его, а объявление функции поместить непосредственно в файл main.cpp. Но при изменении функции может потребоваться изменить и ее объявление. И если функция factorial используется в нескольких файлах с исходным кодом, то в каждом из этих файлов придется менять ее объявление. В данном же случае достаточно изменить объявление функции в одном файле - factorial.h.</p>

<p>В обычном проекте Visual Studio исходные .cpp-файлы компилируются в объектные файлы, а затем компоновщик объединяет необходимые части в исполняемый файл. Через g++ оба исходника можно передать одной командой: <code>g++ main.cpp factorial.cpp -o main</code>.</p>

<p>На выходе будет сгенерирован единый файл main.</p>

<h3>Внешние объекты</h3>

<p>Разные исходные файлы могут обращаться к одним переменным и константам. Для этого в использующем файле должно быть доступно объявление объекта; объявление с extern без инициализатора не создаёт отдельное определение.</p>

<p>Для объявления объектов определим файл objects.h со следующим содержимым:</p>

<pre><code class="language-cpp">extern const int x;
extern double y;</code></pre>

<p>Здесь объявляются константа x и переменная y. Так как эти объекты будут внешними по отношению к исходному коду, который будет их использовать, то они определяются с ключевым словом extern.</p>

<p>Для определения этих объектов добавим новый файл objects.cpp:</p>

<pre><code class="language-cpp">#include "objects.h"
 
const int x = 5;
double y = 3.4;</code></pre>

<p>Используем эти объекты в файле main.cpp:</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
#include "objects.h"
 
int main() {
    std::cout &lt;&lt; "x = " &lt;&lt; x &lt;&lt; std::endl;
    std::cout &lt;&lt; "y = " &lt;&lt; y &lt;&lt; std::endl;
 
    return 0;
}</code></pre>

### Шаг 6 — choice (ID 4718310)

[Открыть на Stepik](https://stepik.org/lesson/770592/step/6?unit=773033) · [Исходник step-source](../../raw/step-sources/4718310.json) · [Объект step](../../raw/steps/4718310.json)
