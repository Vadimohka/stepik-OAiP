### Шаг 1 — text (ID 3214992)

[Открыть на Stepik](https://stepik.org/lesson/770592/step/1?unit=773033) · [Исходник step-source](../../raw/step-sources/3214992.json) · [Объект step](../../raw/steps/3214992.json)

<h3>Область видимости, время жизни и static</h3>
<p><strong>Цель:</strong> различать три вопроса: где доступно имя, когда существует объект и сохраняется ли его состояние между вызовами.</p>
<p><strong>Область видимости</strong> определяет, где можно найти имя. <strong>Время жизни</strong> — период существования объекта. <strong>Длительность хранения</strong> описывает, как долго доступна память для него. Эти понятия связаны, но не заменяют друг друга: локальное имя может обозначать объект, который сохраняется между вызовами.</p>
<h4>Автоматическая и статическая локальная переменная</h4>
<pre><code class="language-cpp">#include &lt;iostream&gt;

int next_local() {
    int counter = 0;
    return ++counter;
}

// Demonstration: called twice; the counter must not overflow int.
int next_static() {
    static int counter = 0;
    return ++counter;
}

int main() {
    const int local_first = next_local();
    const int local_second = next_local();
    const int static_first = next_static();
    const int static_second = next_static();
    std::cout &lt;&lt; local_first &lt;&lt; ' ' &lt;&lt; local_second &lt;&lt; '\n';
    std::cout &lt;&lt; static_first &lt;&lt; ' ' &lt;&lt; static_second &lt;&lt; '\n';
    return 0;
}
</code></pre>
<p>Ввод не требуется. Программа выводит:</p>
<pre>1 1
1 2</pre>
<p>В <code>next_local</code> каждый вызов создаёт свой автоматический <code>counter</code> со значением 0. В <code>next_static</code> оба вызова работают с одним статическим объектом: после первого вызова значение 1 сохраняется, после второго становится 2. В примере каждая функция вызывается дважды; для произвольного счётчика нужно отдельно обеспечить отсутствие переполнения.</p>
<p>Имена обоих <code>counter</code> доступны только внутри своих функций. Ключевое слово <code>static</code> не делает локальное имя глобальным. Автоматический локальный объект уничтожается при выходе из блока; статический сохраняется между вызовами и имеет длительность хранения, охватывающую выполнение программы. Нельзя выводить из этого обязательное физическое выделение памяти «на стеке при каждом вызове»: стандарт описывает поведение объектов, а реализация может оптимизировать хранение.</p>
<h4>Когда происходит инициализация</h4>
<p>Динамическая инициализация локального статического объекта выполняется при первом достижении объявления и после успешного завершения не повторяется. Нулевая и константная инициализация могут происходить раньше; в нашем <code>static int counter = 0;</code> используется константная инициализация. Не следует учить общее правило «все static обязательно создаются ровно при первом вызове».</p>
<p>Переменные уровня пространства имён без <code>thread_local</code> также имеют статическую длительность хранения. Их имена видны в соответствии с объявлениями и правилами области видимости. Зависеть от порядка динамической инициализации обычных глобальных объектов из разных <code>.cpp</code> без специальных гарантий нельзя: порядок файлов в проекте сам по себе таких гарантий не даёт.</p>
<h4>Связывание и const — другие свойства</h4>
<p><code>const</code> ограничивает изменение объекта через соответствующее имя или ссылку; оно не означает <code>extern</code>. <code>extern</code> не делает объект константным. У обычной переменной <code>const int</code> на уровне пространства имён без <code>extern</code> и <code>inline</code> по умолчанию внутреннее связывание. В следующем шаге понадобится разделять объявления в заголовке и определения в исходном файле.</p>
<h4>Разбор зависимости от истории</h4>
<p>Третий вызов <code>next_local()</code> снова даёт 1, третий <code>next_static()</code> — 3. Поэтому результат функции со скрытым состоянием зависит от истории предыдущих вызовов. Когда счётчик относится к данным задачи, его можно хранить у вызывающего кода и передавать явно по изменяемой ссылке. Такой интерфейс позволяет видеть зависимость и выбирать исходное состояние.</p>
<p>Вызовы в примере записаны отдельными операторами. В C++17/20 нельзя в общем случае считать, что аргументы одного вызова вычисляются слева направо: неподтверждённый порядок побочных эффектов не должен определять результат.</p>

### Шаг 2 — text (ID 3212951)

[Открыть на Stepik](https://stepik.org/lesson/770592/step/2?unit=773033) · [Исходник step-source](../../raw/step-sources/3212951.json) · [Объект step](../../raw/steps/3212951.json)

<h3>От интерфейса функции к нескольким исходным файлам</h3>
<p>Предварительные знания: объявление и определение функции, контракт и время жизни. В <a href="https://stepik.org/lesson/770591/step/7" rel="noopener noreferrer nofollow">рекурсивном примере</a> факториал имел контракт <code>0 ≤ n ≤ 20</code>. Ниже тот же контракт реализован циклом и разделён между тремя файлами. Это законченный разобранный пример; никаких дополнительных функций для его понимания не требуется.</p>
<p><code>factorial.hpp</code> содержит интерфейс — объявление функции и именованную границу допустимых аргументов:</p>
<pre><code class="language-cpp">#ifndef COURSE_FACTORIAL_HPP
#define COURSE_FACTORIAL_HPP

inline constexpr unsigned int factorial_limit = 20;

// Precondition: n &lt;= factorial_limit. Returns n!, including 0! = 1.
unsigned long long factorial(unsigned int n);

#endif
</code></pre>

<p>Защита <code>#ifndef/#define/#endif</code> не даёт повторно обработать содержимое заголовка внутри одной единицы трансляции. Имя макроса выбрано специфичным для этого заголовка. <code>#pragma once</code> широко поддерживается, но не является директивой стандарта C++. <code>inline constexpr</code> у переменной доступно с C++17 и позволяет поместить согласованное определение общей константы в заголовок; подробнее о связывании — в следующем шаге.</p>
<p><code>factorial.cpp</code> содержит единственное обычное определение функции и включает собственный заголовок:</p>
<pre><code class="language-cpp">#include "factorial.hpp"

unsigned long long factorial(unsigned int n) {
    unsigned long long result = 1;
    for (unsigned int factor = 2; factor &lt;= n; ++factor) {
        result *= factor;
    }
    return result;
}
</code></pre>

<p>При <code>n == 0</code> или <code>n == 1</code> цикл пропускается, ответ равен 1. Для 5 последовательные произведения дают 2, 6, 24, 120. Для 20 ответ 2432902008176640000 помещается в <code>unsigned long long</code> при минимально гарантированном диапазоне этого типа. Собственный заголовок позволяет компилятору проверить соответствие интерфейса и определения; ручная копия объявления в каждом файле создала бы риск рассогласования.</p>
<p><code>main.cpp</code> отвечает за проверку ввода и вывод:</p>
<pre><code class="language-cpp">#include "factorial.hpp"
#include &lt;iostream&gt;

int main() {
    int n = 0;
    if (!(std::cin &gt;&gt; n) || n &lt; 0 || n &gt; static_cast&lt;int&gt;(factorial_limit)) {
        std::cerr &lt;&lt; "input error\n";
        return 1;
    }
    std::cout &lt;&lt; factorial(static_cast&lt;unsigned int&gt;(n)) &lt;&lt; '\n';
}
</code></pre>

<p>Отрицательное значение отклоняется до преобразования в беззнаковый тип. Для ввода <code>5</code> программа выводит <code>120</code>, для <code>0</code> — <code>1</code>; −1, 21 и нечисловой ввод дают сообщение <code>input error</code> и код завершения 1. Функция вычисления полагается на своё предусловие: внешний пользователь библиотеки также обязан его соблюдать.</p>
<h4>Единицы трансляции и компоновка</h4>
<p>После препроцессирования каждого <code>.cpp</code> вместе с включёнными заголовками получается отдельная единица трансляции. Директива <code>#include</code> предоставляет объявления, но не компилирует другой <code>.cpp</code> и не подключает его объектный файл. В обычной схеме каждый <code>.cpp</code> компилируется в объектный файл, а компоновщик связывает вызовы с определениями.</p>
<pre><code class="language-bash">g++ -std=c++20 -Wall -Wextra -Wpedantic -c factorial.cpp -o factorial.o
g++ -std=c++20 -Wall -Wextra -Wpedantic -c main.cpp -o main.o
g++ main.o factorial.o -o factorial_demo
</code></pre>

<p>Это запись этапов для GCC; драйвер может выполнить их одной командой <code>g++ -std=c++20 main.cpp factorial.cpp -o factorial_demo</code>. В Visual Studio используются те же роли компилятора и компоновщика, хотя имена файлов и параметры другие. Обычное определение функции не помещается в оба <code>.cpp</code>: для всей программы здесь нужно одно определение. Заголовок с <code>inline</code>-определениями подчиняется отдельным условиям правила одного определения.</p>
<p>При изменении тела <code>factorial.cpp</code> пересобирается этот исходник и затем выполняется компоновка. При изменении общего заголовка могут потребоваться все зависящие от него единицы трансляции. Это объясняет роль системы сборки: она отслеживает зависимости, а не просто количество исходных файлов.</p>
<p>Продолжение: <a href="https://stepik.org/lesson/770592/step/3" rel="noopener noreferrer nofollow">связывание и общие объекты</a>, затем <a href="https://stepik.org/lesson/770593/step/1" rel="noopener noreferrer nofollow">упаковка этой же реализации в библиотеку</a>.</p>

### Шаг 3 — text (ID 3214991)

[Открыть на Stepik](https://stepik.org/lesson/770592/step/3?unit=773033) · [Исходник step-source](../../raw/step-sources/3214991.json) · [Объект step](../../raw/steps/3214991.json)

<h3>Объявления, связывание и общие объекты</h3>
<p>Область видимости отвечает за поиск имени в тексте, а <strong>связывание</strong> — за то, обозначают ли объявления в разных единицах трансляции одну сущность. Само совпадение имён в двух файлах ещё не описывает все эти правила.</p>
<p>В предыдущем примере <code>inline constexpr unsigned int factorial_limit = 20;</code> задаёт неизменяемую границу в заголовке. Начиная с C++17 такая inline-переменная с внешним связыванием может иметь согласованные определения в нескольких единицах трансляции и обозначать одну сущность. Должны соблюдаться условия правила одного определения; произвольно разные значения в копиях заголовка недопустимы.</p>
<h4>Когда нужен extern</h4>
<p>Другой способ разделяет объявление и определение объекта. В следующем самостоятельном по составу файлов примере <code>objects.hpp</code> только объявляет два объекта:</p>
<pre><code class="language-cpp">#ifndef COURSE_OBJECTS_HPP
#define COURSE_OBJECTS_HPP

extern const int configured_limit;
extern double calibration;

#endif
</code></pre>

<p><code>extern</code> без инициализатора здесь не определяет новый объект. Файл <code>objects.cpp</code> включает объявление и задаёт единственные определения:</p>
<pre><code class="language-cpp">#include "objects.hpp"

const int configured_limit = 5;
double calibration = 3.4;
</code></pre>

<p>Из-за ранее видимого <code>extern</code>-объявления <code>configured_limit</code> имеет внешнее связывание, хотя определён как <code>const</code>. Без такого объявления обычная не-inline переменная <code>const</code> уровня пространства имён по умолчанию имела бы внутреннее связывание. <code>extern</code> и <code>const</code> описывают разные свойства.</p>
<p>Файл <code>main.cpp</code> использует объявления:</p>
<pre><code class="language-cpp">#include "objects.hpp"
#include &lt;iostream&gt;

int main() {
    std::cout &lt;&lt; configured_limit &lt;&lt; ' ' &lt;&lt; calibration &lt;&lt; '\n';
}
</code></pre>

<p>При сборке <code>g++ -std=c++20 main.cpp objects.cpp -o objects_demo</code> программа печатает <code>5 3.4</code>. Если не включить <code>objects.cpp</code> в сборку, объявления останутся видны, но определения для компоновки не найдутся. Если обычное определение <code>double calibration = 3.4;</code> поместить в заголовок нескольких исходников, получится нарушение правила одного определения.</p>
<h4>Общее состояние — решение интерфейса</h4>
<p>Изменяемая <code>calibration</code> показана для объяснения языка, а не как обязательный способ передачи данных. Глобальное состояние создаёт зависимость от истории вызовов и усложняет изоляцию проверок. Значение или ссылку на конфигурацию часто понятнее передать явно. Далее инвариант класса позволит описывать допустимое состояние группы данных, а владение — того, кто отвечает за его время жизни.</p>
