<h3>Перегрузка сохраняет привычный смысл операции</h3>

<p>Для встроенных чисел <code>+</code> вычисляет сумму, а для <code>std::string</code> соединяет строки. Собственный тип тоже может определить подходящую операцию. Для длины запись <code>first + second</code> естественно означает новую длину, а <code>first += second</code> — изменение первой длины.</p><p>Перегрузка объявляет обычную функцию со специальным именем, например <code>operator+</code>. Она участвует в выборе операции по типам операндов. Это не возможность изменить синтаксис всего языка: нельзя придумать новый знак, поменять приоритет существующего знака, его число операндов или переопределить сложение двух встроенных <code>int</code>.</p><p>Фрагмент; определения и контекст указаны в объяснении:</p><pre><code class="language-cpp">Distance operator+(const Distance&amp; other) const;
Distance&amp; operator+=(const Distance&amp; other);
bool operator&lt;(const Distance&amp; other) const;</code></pre><p>Это объявления возможных членов ранее изученного <code>Distance</code>, не самостоятельная программа. У первого метода результат — новое значение; конечное <code>const</code> относится к левому операнду. Второй метод изменяет текущий объект и возвращает ссылку на него. Третий даёт логический ответ о сравнении.</p><p>Обычный смысл оператора — соглашение интерфейса, а не автоматически доказанное свойство языка. Компилятор разрешит многие неожиданные реализации, но читатель ожидает, что <code>+</code> не испортит операнды, сравнение не изменит состояние, а <code>+=</code> даст тот же смысловой результат, что сложение с последующим присваиванием. Если операция не имеет такого понятного смысла, именованный метод яснее.</p><p>При проектировании остаются прежние обязанности: сохранить инвариант, определить границы результата и сообщить об отказе. В <a href="https://stepik.org/lesson/897987/step/2" rel="noopener noreferrer nofollow">следующем шаге</a> разберём префиксный <code>++</code> с проверкой максимума, а в <a href="https://stepik.org/lesson/897987/step/7" rel="noopener noreferrer nofollow">бинарных операциях</a> продолжим проверяемый <code>Distance</code>.</p>

<h3>Префиксный инкремент: изменить и вернуть тот же объект</h3>

<p>Унарная операция имеет один операнд. Для счётчика <code>++counter</code> увеличивает значение на единицу. По обычному соглашению префиксная форма возвращает ссылку на уже изменённый объект, как встроенный префиксный инкремент числа.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;limits&gt;
#include &lt;stdexcept&gt;

class Counter {
    unsigned count_{};
public:
    Counter() = default;
    explicit Counter(unsigned initial) : count_(initial) {}
    unsigned value() const { return count_; }

    Counter&amp; operator++() {
        if (count_ == std::numeric_limits&lt;unsigned&gt;::max()) {
            throw std::overflow_error("counter");
        }
        ++count_;
        return *this;
    }
};

int main() {
    Counter first, second;
    ++first;
    ++second;
    ++second;
    std::cout &lt;&lt; first.value() &lt;&lt; ' ' &lt;&lt; second.value() &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">1 2</code></pre><p>Текущий объект передаётся методу неявно, поэтому у <code>operator++()</code> нет обычного параметра-операнда. <code>*this</code> обозначает сам объект, а возвращаемый тип <code>Counter&amp;</code> сохраняет связь с ним. Возвращать отдельную копию для префикса здесь нет необходимости.</p><p>Беззнаковая арифметика языка допускает переход максимума к нулю, но для данного счётчика выбран другой контракт: превышение максимума считается ошибкой. Проверка выполняется <em>до</em> изменения. <code>std::numeric_limits&lt;unsigned&gt;::max()</code> даёт максимум типа в используемой реализации; заранее фиксировать число битов не нужно.</p><p>Это авторская политика конкретного типа. Язык не требует, чтобы каждая пользовательская перегрузка <code>++</code> проверяла переполнение или возвращала именно ссылку. Мы выбираем привычный интерфейс и объясняем его предел. Статус <code>const</code> у <code>value()</code> позволяет читать счётчик, а увеличивающий метод закономерно неконстантен.</p>

<h3>Как читается объявление operator</h3>

<p>Имя функции перегрузки состоит из слова <code>operator</code> и знака операции. Остальная запись подчиняется правилам объявления функции: возвращаемый тип, параметры и квалификаторы метода.</p><p>Фрагмент; определения и контекст указаны в объяснении:</p><pre><code class="language-cpp">Counter&amp; operator++();
Counter operator++(int);
Distance operator+(const Distance&amp; other) const;</code></pre><p>Это отдельные объявления членов подходящих классов, а не полный класс. В первой строке <code>Counter&amp;</code> — возвращаемая ссылка, <code>operator++</code> — имя функции, пустые скобки — отсутствие явных параметров. Она соответствует <code>++value</code>. Во второй строке параметр <code>int</code> различает постфиксную форму <code>value++</code>; его разбор будет в <a href="https://stepik.org/lesson/897987/step/6" rel="noopener noreferrer nofollow">шаге о постфиксе</a>.</p><p>У бинарного оператора-члена левый операнд является текущим объектом, а правый передаётся обычным параметром. Поэтому в <code>left + right</code> для показанной перегрузки выбирается вызов, соответствующий <code>left.operator+(right)</code>. Конечное <code>const</code> обещает константный доступ к левому объекту.</p><p>Оператор можно определить и свободной функцией. Тогда оба операнда бинарной операции становятся явными параметрами, например <code>Distance operator+(const Distance&amp;, const Distance&amp;);</code>. Для доступа только к публичному интерфейсу <code>friend</code> не нужен. В конкретном интерфейсе выбирают согласованный набор перегрузок; одновременное добавление конкурирующих форм может сделать вызов неоднозначным.</p><p>Выбор перегрузки зависит от типов, квалификаторов и допустимых преобразований; один лишь ожидаемый возвращаемый тип обычно не различает перегрузки. В C++17/20 <code>operator[]</code> — нестатический член с одним параметром индекса; формы из более новых стандартов в этих примерах не используются.</p>

<h3>Ссылка на результат операции и независимая копия</h3>

<p>Возвращаемая ссылка позволяет продолжить работу с тем же объектом. Возвращаемое значение может стать самостоятельной копией. Эти случаи видно по объявлению переменной-получателя.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;limits&gt;
#include &lt;stdexcept&gt;

class Counter {
    unsigned count_{};
public:
    Counter() = default;
    explicit Counter(unsigned initial) : count_(initial) {}
    unsigned value() const { return count_; }

    Counter&amp; operator++() {
        if (count_ == std::numeric_limits&lt;unsigned&gt;::max()) {
            throw std::overflow_error("counter");
        }
        ++count_;
        return *this;
    }
};

int main() {
    Counter counter;
    Counter&amp; alias = ++counter;
    Counter copy = ++counter;
    ++alias;
    std::cout &lt;&lt; counter.value() &lt;&lt; ' ' &lt;&lt; alias.value() &lt;&lt; ' ' &lt;&lt; copy.value() &lt;&lt; '\n';
    std::cout &lt;&lt; std::boolalpha &lt;&lt; (&amp;alias == &amp;counter) &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">3 3 2
true</code></pre><p>Первый инкремент изменил <code>counter</code> с 0 до 1 и вернул ссылку на него. Переменная-ссылка <code>alias</code> обозначает тот же объект. Второй инкремент дал 2; объявление <code>Counter copy</code> создало отдельный объект с этим значением. Увеличение через <code>alias</code> изменило исходный объект до 3, но не копию.</p><p>В <code>return *this;</code> не создаётся новая ссылка-владелец или новый счётчик. Выражение обозначает существующий объект, время жизни которого должно продолжаться у вызывающего кода. Возвращаемая ссылка не продлевает его жизнь.</p><p>Ссылка на локальную временную переменную метода была бы ошибочным интерфейсом: после выхода такая переменная уничтожается. Поэтому нельзя заменить <code>return *this;</code> на возврат ссылки на локальную копию. Когда требуется новое независимое значение, функция должна возвращать его по значению; именно так будет устроен постфиксный инкремент.</p>

<h3>Временный результат и возврат по значению</h3>

<p>Новая величина может быть создана выражением без отдельного локального имени. Это удобно для результата операции, который должен быть независим от исходного объекта. Для префиксного <code>++</code> мы возвращаем ссылку; для создания нового счётчика выберем обычную функцию, возвращающую значение.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

class Counter {
    unsigned count_;
public:
    explicit Counter(unsigned initial) : count_(initial) {}
    unsigned value() const { return count_; }
};

Counter make_counter(unsigned initial) {
    return Counter{initial};
}

int main() {
    Counter first = make_counter(3);
    const Counter&amp; temporary = Counter{7};
    std::cout &lt;&lt; first.value() &lt;&lt; ' ' &lt;&lt; temporary.value() &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">3 7</code></pre><p><code>Counter{initial}</code> использует конструктор с числом, а не конструктор копирования. В C++17/20 возвращаемый объект того же типа создаётся непосредственно как результат этого выражения. Отдельная промежуточная копия не требуется. Это отличается от необязательного NRVO при <code>return local_name;</code>.</p><p>При непосредственной привязке локальной <code>const Counter&amp;</code> к <code>Counter{7}</code> время жизни временного объекта продлевается до конца времени жизни этой ссылки. Такое продление не следует переносить на любой возврат ссылки из функции: ссылка на локальный объект не становится допустимой от возвращения вызывающему коду.</p><p><code>explicit</code> у конструктора требует явно выразить создание счётчика из числа; показанная запись в фигурных скобках его допускает. Нам не нужно неявно превращать любое число в счётчик при выборе перегрузки. Подробности временных объектов и категорий выражений рассматриваются в <a href="https://stepik.org/lesson/853532/step/1" rel="noopener noreferrer nofollow">модуле 14</a>.</p>

<h3>Постфиксный инкремент возвращает прежнее значение</h3>

<p>Обычный смысл <code>counter++</code>: увеличить исходный счётчик и вернуть отдельное значение, которое было до изменения. Вычисление не откладывается до произвольного будущего момента; разница с префиксом состоит в результате выражения.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;limits&gt;
#include &lt;stdexcept&gt;

class Counter {
    unsigned count_{};
public:
    Counter() = default;
    explicit Counter(unsigned initial) : count_(initial) {}
    unsigned value() const { return count_; }

    Counter&amp; operator++() {
        if (count_ == std::numeric_limits&lt;unsigned&gt;::max()) {
            throw std::overflow_error("counter");
        }
        ++count_;
        return *this;
    }

    Counter operator++(int) {
        Counter old = *this;
        ++(*this);
        return old;
    }
};

int main() {
    Counter counter;
    Counter first = ++counter;
    Counter old = counter++;
    std::cout &lt;&lt; first.value() &lt;&lt; ' ' &lt;&lt; old.value() &lt;&lt; ' ' &lt;&lt; counter.value() &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">1 1 2</code></pre><p>Префикс увеличил счётчик до 1; <code>first</code> получил копию этого значения. Затем постфикс сохранил старую единицу, вызвал уже проверенный префиксный метод и вернул старую копию. Поэтому <code>old</code> равен 1, а исходный <code>counter</code> — 2.</p><p>Дополнительный параметр <code>int</code> — часть формы постфиксной перегрузки. При записи <code>counter++</code> в него передаётся ноль; имя параметра здесь опущено, потому что значение не используется. Он не означает величину приращения. Возвращаемый <code>Counter</code> — значение, тогда как префикс возвращает <code>Counter&amp;</code>.</p><p>Если счётчик уже максимален, префиксная операция внутри постфикса бросает исключение до изменения состояния. Вызов не возвращает старое значение как успешный результат. Проверка границы сосредоточена в одном месте. Возвращаемая локальная копия безопасна именно потому, что возвращается по значению, а не по ссылке.</p><p>Такой смысл согласован со встроенными операциями и удобен для чтения программы. Язык позволяет и другие возвращаемые типы, но они должны быть мотивированы контрактом; привычная запись сама по себе не доказывает корректность реализации.</p>

<h3>Сложение двух значений Distance</h3>

<p>Бинарный оператор-член получает левый объект через <code>this</code>, правый — через явный параметр. Реализация <code>+</code> может опереться на уже разобранный метод <code>add_dist</code>, сохранив его проверку результата.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;stdexcept&gt;

class Distance {
    long long feet_{};
    long long inches_{};
public:
    static constexpr long long max_feet = 1'000'000;

    Distance() = default;
    Distance(long long feet, long long inches)
        : feet_(feet), inches_(inches) {
        if (feet &lt; 0 || feet &gt; max_feet || inches &lt; 0 || inches &gt;= 12) {
            throw std::invalid_argument("distance");
        }
    }

    long long feet() const { return feet_; }
    long long inches() const { return inches_; }
    long long total_inches() const { return feet_ * 12 + inches_; }
    Distance add_dist(const Distance&amp; other) const {
        const long long total = total_inches() + other.total_inches();
        if (total &gt; max_feet * 12 + 11) {
            throw std::overflow_error("distance sum");
        }
        return Distance{total / 12, total % 12};
    }

    Distance operator+(const Distance&amp; other) const {
        return add_dist(other);
    }
};

int main() {
    const Distance first{3, 5};
    const Distance second{11, 7};
    Distance sum = first + second;
    Distance extended = first + second + Distance{0, 6};
    std::cout &lt;&lt; sum.feet() &lt;&lt; ' ' &lt;&lt; sum.inches() &lt;&lt; '\n';

<h3>Сравнение значений и порядок</h3>

<p>Для длины сравниваются смысловые значения. Все объекты <code>Distance</code> уже нормализованы, поэтому сначала достаточно сравнить футы, а при их равенстве — оставшиеся дюймы. Перевод в <code>float</code> не нужен и не должен терять точность.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;stdexcept&gt;

class Distance {
    long long feet_{};
    long long inches_{};
public:
    static constexpr long long max_feet = 1'000'000;

    Distance() = default;
    Distance(long long feet, long long inches)
        : feet_(feet), inches_(inches) {
        if (feet &lt; 0 || feet &gt; max_feet || inches &lt; 0 || inches &gt;= 12) {
            throw std::invalid_argument("distance");
        }
    }

    long long feet() const { return feet_; }
    long long inches() const { return inches_; }
    long long total_inches() const { return feet_ * 12 + inches_; }
    bool operator&lt;(const Distance&amp; other) const {
        return feet_ &lt; other.feet_ ||
               (feet_ == other.feet_ &amp;&amp; inches_ &lt; other.inches_);
    }
    bool operator==(const Distance&amp; other) const {
        return feet_ == other.feet_ &amp;&amp; inches_ == other.inches_;
    }
    bool operator!=(const Distance&amp; other) const {
        return !(*this == other);
    }
};

int main() {
    const Distance first{5, 11};
    const Distance second{6, 0};
    const Distance equal{5, 11};
    std::cout &lt;&lt; std::boolalpha &lt;&lt; (first &lt; second) &lt;&lt; ' '
              &lt;&lt; (second &lt; first) &lt;&lt; '\n';
    std::cout &lt;&lt; (first == equal) &lt;&lt; ' ' &lt;&lt; (first != equal) &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">true false
true false</code></pre><p>Пять футов одиннадцать дюймов меньше шести футов. Равенство проверяет оба нормализованных поля, поэтому <code>first</code> и <code>equal</code> равны по значению, хотя существуют как разные объекты. Все операции возвращают <code>bool</code> и не меняют состояние.</p><p>Инвариант существенен: если бы <code>{5, 12}</code> и <code>{6, 0}</code> были двумя допустимыми представлениями одной длины, простое сравнение полей на равенство давало бы неверный смысловой результат. Выбранный конструктор запрещает первое представление. Поэтому соглашение о представлении и операции нельзя проектировать независимо.</p><p>Для использования в упорядоченных контейнерах сравнение должно задавать <strong>строгий слабый порядок</strong>. Объект не меньше самого себя; из <code>a &lt; b</code> и <code>b &lt; c</code> следует <code>a &lt; c</code>. Если ни <code>a &lt; b</code>, ни <code>b &lt; a</code> не выполняется, эти значения эквивалентны по сравнению; такая эквивалентность тоже должна быть транзитивной. У нашего <code>Distance</code> сравниваются нормализованные пары целых чисел, и эквивалентность совпадает с <code>==</code>. Для другого типа это совпадение не обязательно: <code>set</code> и <code>map</code> различают ключи по своему сравнению, а не отдельным вызовом <code>==</code>. Подробная связь с <a href="https://stepik.org/lesson/973825/step/1" rel="noopener noreferrer nofollow">set и map</a> будет после деревьев.</p><p>Здесь <code>!=</code> явно выражен через <code>==</code>, поэтому пример работает одинаково в C++17 и C++20. Специальные правила C++20 и оператор <code>&lt;=&gt;</code> не требуются для этой модели.</p>

<h3>Составное присваивание возвращает ссылку на левый объект</h3>

<p><code>left += right</code> изменяет левую длину. Обычный интерфейс возвращает <code>Distance&amp;</code>, то есть ссылку на уже изменённый объект. Это согласует операцию с привычным присваиванием и не создаёт лишнюю отдельную копию результата.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;stdexcept&gt;

class Distance {
    long long feet_{};
    long long inches_{};
public:
    static constexpr long long max_feet = 1'000'000;

    Distance() = default;
    Distance(long long feet, long long inches)
        : feet_(feet), inches_(inches) {
        if (feet &lt; 0 || feet &gt; max_feet || inches &lt; 0 || inches &gt;= 12) {
            throw std::invalid_argument("distance");
        }
    }

    long long feet() const { return feet_; }
    long long inches() const { return inches_; }
    long long total_inches() const { return feet_ * 12 + inches_; }
    Distance add_dist(const Distance&amp; other) const {
        const long long total = total_inches() + other.total_inches();
        if (total &gt; max_feet * 12 + 11) {
            throw std::overflow_error("distance sum");
        }
        return Distance{total / 12, total % 12};
    }

    Distance operator+(const Distance&amp; other) const {
        return add_dist(other);
    }
    Distance&amp; operator+=(const Distance&amp; other) {
        *this = add_dist(other);
        return *this;
    }
    bool operator&lt;(const Distance&amp; other) const {
        return feet_ &lt; other.feet_ ||
               (feet_ == other.feet_ &amp;&amp; inches_ &lt; other.inches_);
    }
    bool operator==(const Distance&amp; other) const {
        return feet_ == other.feet_ &amp;&amp; inches_ == other.inches_;
    }
    bool operator!=(const Distance&amp; other) const {
        return !(*this == other);
    }
};

int main() {
    Distance length{3, 5};
    const Distance added{11, 7};
    Distance&amp; result = (length += added);
    std::cout &lt;&lt; length.feet() &lt;&lt; ' ' &lt;&lt; length.inches() &lt;&lt; '\n';
    std::cout &lt;&lt; std::boolalpha &lt;&lt; (&amp;result == &amp;length) &lt;&lt; '\n';
    length += length;
    std::cout &lt;&lt; length.feet() &lt;&lt; ' ' &lt;&lt; length.inches() &lt;&lt; '\n';
    Distance limit{Distance::max_feet, 11};
    try {
        limit += Distance{0, 1};
    } catch (const std::overflow_error&amp;) {
        std::cout &lt;&lt; "unchanged " &lt;&lt; limit.feet() &lt;&lt; ' ' &lt;&lt; limit.inches() &lt;&lt; '\n';
    }
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">15 0
true
30 0
unchanged 1000000 11</code></pre><p>Метод сначала вычисляет проверенную новую длину <code>add_dist(other)</code>. Если она недопустима, исключение возникает до присваивания, и левый объект сохраняет прежнее состояние. Если вычисление завершилось, сформированное компилятором присваивание двух числовых полей заменяет значение, а <code>return *this</code> возвращает текущий объект.</p><p>Случай <code>length += length</code> тоже корректен: оба чтения происходят в вычислении суммы до изменения полей. После 15 футов результат равен 30 футам. Пограничная длина 1 000 000 футов 11 дюймов не может увеличиться ещё на дюйм; последняя строка вывода показывает, что значение не испорчено.</p><p>Возврат <code>void</code> технически возможен, но не поддерживает обычное использование результата присваивания. Возврат <code>Distance</code> создавал бы отдельное значение. Для выбранного интерфейса подходит именно ссылка на левый объект. Правила языка не заставляют <code>+</code> и <code>+=</code> совпадать по смыслу; здесь это обеспечено общей реализацией <code>add_dist</code>.</p>

<h3>Индексация: ссылка, const и проверка границы</h3>

<p>Перегруженный <code>operator[]</code> описывает доступ к элементу пользовательского типа. Для изменяемого целого элемента удобно возвращать <code>int&amp;</code>: присваивание результату меняет сам элемент. Для константного объекта возвращается <code>const int&amp;</code>.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;array&gt;
#include &lt;cstddef&gt;
#include &lt;iostream&gt;
#include &lt;stdexcept&gt;

class CheckedArray {
    std::array&lt;int, 4&gt; data_{};
public:
    int&amp; operator[](std::size_t index) {
        return data_.at(index);
    }
    const int&amp; operator[](std::size_t index) const {
        return data_.at(index);
    }
};

int main() {
    CheckedArray values;
    values[0] = 10;
    values[3] = 30;
    const CheckedArray&amp; view = values;
    std::cout &lt;&lt; view[0] &lt;&lt; ' ' &lt;&lt; view[1] &lt;&lt; ' ' &lt;&lt; view[3] &lt;&lt; '\n';
    try {
        values[4] = 99;
    } catch (const std::out_of_range&amp;) {
        std::cout &lt;&lt; "index error\n";
    }
    std::cout &lt;&lt; view[3] &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">10 0 30
index error
30</code></pre><p>Все четыре элемента изначально равны нулю. Допустимые индексы — 0, 1, 2 и 3. Внутри выбран метод стандартного массива <code>at</code>, который проверяет границу и при неверном индексе бросает <code>std::out_of_range</code>. Поэтому попытка записи по индексу 4 не меняет ни один элемент.</p><p>Это контракт <em>нашего</em> <code>CheckedArray</code>. У встроенного массива, <code>std::array::operator[]</code> и <code>std::vector::operator[]</code> в C++17/20 такой проверки не обещано; там индекс должен быть допустим заранее. Перегрузка не делает все операции <code>[]</code> языка проверяемыми. Например, число <code>-1</code> при преобразовании к <code>std::size_t</code> становится максимальным значением этого беззнакового типа; для массива из четырёх элементов <code>at</code> его отклоняет. Это не общее правило для любого отрицательного числа и любых исходных разрядностей: преобразование выполняется по модулю числа значений целевого беззнакового типа (его максимальное значение плюс один). Поэтому отрицательный ввод нужно отклонить до преобразования в <code>std::size_t</code>, затем проверить верхнюю границу индекса.</p><p>Через <code>view</code> выбирается константная версия. Запись <code>view[0] = 7;</code> не компилируется, зато изменение через исходный неконстантный <code>values</code> возможно. Возвращённые ссылки обозначают элементы внутри объекта и не должны использоваться после его уничтожения. Если интерфейс контейнера допускает действия, делающие ссылки недействительными, их условия также должны быть частью контракта.</p>
