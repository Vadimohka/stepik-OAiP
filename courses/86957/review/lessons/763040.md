<h2>Понятие алгоритма и алгоритмизации</h2>
<p><strong>Алгоритм</strong> описывает понятные исполнителю действия, которые приводят к требуемому результату для оговорённых исходных данных. Исполнителем может быть человек или вычислительная система. Алгоритм нужен, чтобы способ решения можно было повторить и проверить, не догадываясь о намерениях автора.</p>
<p>Например, задача «выбрать большее из двух чисел» ещё не описывает действий. Для входных чисел <code>a</code> и <code>b</code> достаточно сравнить их: если <code>a ≥ b</code>, взять <code>a</code>, иначе взять <code>b</code>. При равенстве подходит любое из двух значений. Для 7 и 4 результат равен 7; для 2 и 9 — 9. Здесь заранее определено, какие данные допустимы и что считается результатом.</p>
<p><strong>Алгоритмизация</strong> — разработка такого способа решения. Сначала уточняют задачу: что дано, что нужно получить, какие случаи возможны. Затем выбирают действия и порядок их выполнения, проверяют их на понятных примерах и объясняют, почему результат соответствует задаче. Запись на языке программирования — следующий этап: она добавляет правила конкретного языка и ограничения представления данных в компьютере.</p>
<p>Один алгоритм можно описать словами, псевдокодом или блок-схемой. Псевдокод — условная запись действий для читателя, не готовая программа для запуска. Программа на C++ имеет строгий синтаксис: даже понятное человеку действие нужно записать в разрешённой форме. И наоборот, синтаксически верная программа может решать другую задачу, если автор выбрал неверный алгоритм.</p>
<p>Дальше <a href="https://stepik.org/lesson/763040/step/2" rel="noopener noreferrer nofollow">уточним свойства алгоритма и границы задачи</a>, а затем <a href="https://stepik.org/lesson/763040/step/3" rel="noopener noreferrer nofollow">сопоставим разные записи одного решения</a>. Эти границы останутся важны и при выборе типов в C++: математические числа и значения машинного типа не всегда имеют одинаковый диапазон.</p>

<h2>Свойства алгоритма и границы задачи</h2>
<p>В этом курсе сначала рассматриваются <strong>детерминированные алгоритмы</strong>: при одинаковых входных данных они выполняют одинаковые действия и получают одинаковый результат. Существуют и рандомизированные алгоритмы; наличие случайного выбора не делает описание неточным, если правила этого выбора заданы.</p>
<p>Для рассматриваемого алгоритма необходимо указать допустимые входные данные, смысл результата и последовательность выполнимых действий. Это первые элементы <strong>контракта</strong> — соглашения о том, что требуется на входе и что обещано на выходе.</p>
<ul><li><strong>Дискретность:</strong> решение описано отдельными действиями и правилами перехода между ними. Здесь используются последовательность, выбор и повторение; параллельные вычисления пока не рассматриваются.</li>
<li><strong>Определённость:</strong> исполнитель понимает каждое действие и правило выбора следующего шага без догадок.</li>
<li><strong>Завершение:</strong> алгоритм решения конечной задачи должен закончиться на каждом допустимом входе. Постоянно работающая программа, например сервер, может содержать такие алгоритмы, продолжая ждать новые запросы.</li>
<li><strong>Корректность результата:</strong> завершение само по себе недостаточно — результат должен соответствовать задаче.</li>
<li><strong>Область применимости:</strong> описание обычно подходит классу входных данных, например любой паре целых чисел в заданном диапазоне.</li></ul>
<p>Для деления дробей ненулевой знаменатель каждой дроби и ненулевой делитель — условия допустимого входа. Для поиска в пустой последовательности допустимым результатом может быть «не найдено». Отсутствие решения тоже может быть корректным результатом, если так определена задача.</p>
<p>Позже эти условия станут контрактами функций, а в модуле алгоритмов к корректности добавится оценка затрат.</p>

<h2>Один алгоритм — разные способы записи</h2>
<p>Алгоритм можно описать словами, формулами, псевдокодом, блок-схемой или программой. Форма записи меняется, но допустимые входные данные и смысл результата должны сохраняться.</p>
<p><strong>Разобранный пример:</strong> максимум двух чисел <code>a</code> и <code>b</code>. Если <code>a ≥ b</code>, результат равен <code>a</code>; иначе результат равен <code>b</code>. При равенстве подходит любое из них: значения совпадают.</p>
<pre><code class="language-text">вход: числа a и b
если a &gt;= b:
    результат = a
иначе:
    результат = b
выход: результат</code></pre>
<p>Это <strong>псевдокод</strong>, а не готовый исходник C++: в нём важна логика, а не правила объявления переменных и расстановки скобок. Блок-схема выражает тот же выбор ромбом с двумя выходами. В программе C++ выбор будет записан конструкцией <code>if</code>; типы определят, какие числа можно передать.</p>
<p>Словесное описание удобно для объяснения смысла, псевдокод — для обсуждения шагов, схема — для просмотра ветвлений. Конкретный язык программирования нужен для исполнения. Подробность выбирается по читателю: фраза «отсортировать» может быть одним шагом внешнего алгоритма, хотя внутри неё много операций.</p>
<p>Далее блок-схемы показывают порядок действий, а функции позволяют дать такой последовательности имя и использовать её как одну операцию.</p>

<h2>Алгоритмические языки и псевдокод</h2>
<p>Алгоритму нужна запись, в которой читатель видит порядок действий. В языках программирования для этого существуют последовательность команд, выбор по условию и повторение. В учебном объяснении удобно сначала использовать те же идеи без синтаксических деталей C++.</p>
<p>Ниже <strong>псевдокод</strong> поиска большего из двух уже заданных чисел. Стрелка <code>←</code> означает «сохранить значение справа под именем слева», а отступ показывает, какая строка относится к условию.</p>
<pre><code class="language-text">если a ≥ b:
    результат ← a
иначе:
    результат ← b
сообщить результат
</code></pre>
<p>При <code>a = 7</code>, <code>b = 4</code> условие истинно: выполняется строка <code>результат ← a</code>, строка другой ветви пропускается, затем сообщается 7. При <code>a = b = 5</code> первая ветвь также даёт правильный результат 5. Последняя строка выполняется после любой из ветвей.</p>
<p>Единого обязательного синтаксиса псевдокода нет, поэтому его условные обозначения нужно объяснять. Такая запись не компилируется как C++: в ней не выбраны типы чисел, не записаны операции ввода и вывода, отсутствует функция <code>main</code>. При переводе алгоритма в программу эти решения принимают явно.</p>
<p>Термин «алгоритмический язык» иногда используют для языка описания алгоритмов, иногда — для языка программирования. В курсе будем различать назначение конкретной записи: <strong>псевдокод объясняет действия, полный пример C++ показывает исполнимую программу, фрагмент C++ показывает только указанную часть программы</strong>. На следующем уроке тот же порядок действий будет выражен <a href="https://stepik.org/lesson/763041/step/1" rel="noopener noreferrer nofollow">блок-схемой</a>.</p>
