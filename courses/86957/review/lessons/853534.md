<h2>Как категория выражения влияет на привязку ссылки</h2>
<p>Ссылка даёт другое имя уже существующему объекту либо привязывается к временному объекту по правилам языка. Она не становится самостоятельным владельцем ресурса и не может быть затем «перенаправлена» присваиванием: <code>reference = value;</code> изменяет обозначаемый объект.</p>
<p><code>T&amp;</code> называют lvalue-ссылкой, <code>T&amp;&amp;</code> — rvalue-ссылкой. Для обычных объектов одного типа неконстантная <code>T&amp;</code> привязывается к неконстантному lvalue; <code>const T&amp;</code> допускает также константные объекты и rvalue; неконстантная <code>T&amp;&amp;</code> привязывается к подходящему неконстантному rvalue.</p>
<p>Точная таблица ниже относится к <code>int x{7}; const int cx{9};</code>, без пользовательских преобразований и наследования. Для <code>std::move</code> подключён <code>&lt;utility&gt;</code>. «Да» означает, что соответствующее объявление ссылки с этим инициализатором корректно.</p>
<table><thead><tr><th>Инициализатор</th><th><code>int&amp;</code></th><th><code>const int&amp;</code></th><th><code>int&amp;&amp;</code></th></tr></thead><tbody>
<tr><td><code>x</code></td><td>да</td><td>да</td><td>нет</td></tr>
<tr><td><code>cx</code></td><td>нет</td><td>да</td><td>нет</td></tr>
<tr><td><code>7</code></td><td>нет</td><td>да</td><td>да</td></tr>
<tr><td><code>std::move(x)</code></td><td>нет</td><td>да</td><td>да</td></tr>
<tr><td><code>std::move(cx)</code></td><td>нет</td><td>да</td><td>нет</td></tr>
</tbody></table>
<p>Например, фрагмент <code>int&amp; a = x; a = 8;</code> оставляет <code>x</code> равным 8. Фрагмент <code>const int&amp; b = 2;</code> создаёт временный <code>int</code> и при такой прямой привязке локальной ссылки продлевает его жизнь до конца жизни <code>b</code>. Аналогично действует <code>int&amp;&amp; c = 3;</code>. Ссылка, возвращённая из функции, или новый псевдоним существующей ссылки не продлевает жизнь объекта повторно.</p>
<p>Сохранение ссылки требует отдельного ответа на вопрос о времени жизни. Временный объект, переданный ссылочному параметру, живёт до конца полного выражения с вызовом; хранить адрес такого объекта для последующего использования опасно. В <a href="https://stepik.org/lesson/853534/step/2" rel="noopener noreferrer nofollow">следующем примере</a> ссылка используется только во время вызова, поэтому эта опасность не возникает.</p>

<h2>Именованная rvalue-ссылка и выбор перегрузки</h2>
<p>Объявленный тип ссылки и категория выражения с её именем — разные свойства. В <code>int&amp;&amp; named = 8;</code> переменная объявлена как rvalue-ссылка, но выражение <code>named</code> является lvalue. Имя позволяет снова обращаться к одному объекту, поэтому передавать его ресурс следующей операции без явного указания не следует.</p>
<p>Полная программа показывает выбор между двумя перегрузками. Обе функции только печатают число: привязка к <code>int&amp;&amp;</code> сама по себе ничего не перемещает.</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;utility&gt;

void inspect(const int&amp; value) {
    std::cout &lt;&lt; "const lvalue reference: " &lt;&lt; value &lt;&lt; '\n';
}

void inspect(int&amp;&amp; value) {
    std::cout &lt;&lt; "rvalue reference: " &lt;&lt; value &lt;&lt; '\n';
}

int main() {
    int x{7};
    const int cx{9};
    int&amp;&amp; named = 8;
    inspect(x);
    inspect(7);
    inspect(named);
    inspect(std::move(named));
    inspect(std::move(cx));
    std::cout &lt;&lt; x &lt;&lt; ' ' &lt;&lt; named &lt;&lt; ' ' &lt;&lt; cx &lt;&lt; '\n';
}
</code></pre>
<p>Вывод:</p><pre>const lvalue reference: 7
rvalue reference: 7
const lvalue reference: 8
rvalue reference: 8
const lvalue reference: 9
7 8 9
</pre>
<p>Для <code>x</code> и <code>named</code> подходит <code>const int&amp;</code>. Для литерала и <code>std::move(named)</code> обе перегрузки допустимы, но при этих аргументах предпочтительна <code>int&amp;&amp;</code>. У <code>std::move(cx)</code> сохраняется <code>const</code>, поэтому неконстантная rvalue-ссылка не подходит и выбирается <code>const int&amp;</code>.</p>
<p>В последней строке все значения прежние: выбранные функции не меняли объекты. Временный <code>int</code>, обозначаемый <code>named</code>, живёт до конца жизни этой локальной ссылки. Временный аргумент <code>inspect(7)</code> живёт до конца полного выражения с вызовом; <code>inspect</code> не сохраняет ссылку.</p>
<p>Чтобы действительно передать ресурс, выбранная операция должна выполнить передачу. Именно это реализуют <a href="https://stepik.org/lesson/853535/step/2" rel="noopener noreferrer nofollow">конструктор перемещения и перемещающее присваивание</a>.</p>
