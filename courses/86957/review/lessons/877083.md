<h3>Static: состояние типа и состояние экземпляра</h3>

<p>Обычное нестатическое поле входит в каждый объект. Статический член данных обозначает один отдельный объект, связанный с классом, и не входит в каждый экземпляр. Обычный статический член без <code>thread_local</code> имеет статическую продолжительность хранения.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

struct Sample {
    int value{};
    inline static int limit = 10;

    bool exceeds_limit() const { return value &gt; limit; }
    static void set_limit(int next) { limit = next; }
};

int main() {
    Sample first{12}, second{8};
    std::cout &lt;&lt; std::boolalpha &lt;&lt; first.exceeds_limit() &lt;&lt; ' '
              &lt;&lt; second.exceeds_limit() &lt;&lt; '\n';
    Sample::set_limit(7);
    std::cout &lt;&lt; first.exceeds_limit() &lt;&lt; ' ' &lt;&lt; second.exceeds_limit() &lt;&lt; '\n';
    std::cout &lt;&lt; first.value &lt;&lt; ' ' &lt;&lt; second.value &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">true false
true true
12 8</code></pre><p>Сначала общий предел равен 10: его превышает только первое значение 12. После изменения предела на 7 оба значения превышают его, хотя поля объектов остались 12 и 8. Это один общий <code>Sample::limit</code>, а не две автоматически синхронизируемые копии.</p><p>Функция <code>set_limit</code> статическая: у неё нет <code>this</code>, и её можно вызвать как <code>Sample::set_limit(7)</code> без экземпляра. Она не может обратиться к нестатическому <code>value</code> без отдельно полученного объекта. Методы <code>exceeds_limit() const</code> не меняют текущие объекты, но их результат зависит от общего изменяемого предела; <code>const</code> не делает внешнее состояние неизменным.</p><p>Запись <code>inline static</code> определяет переменную в классе начиная с C++17 и подходит для обычного заголовка при соблюдении правил одинаковых определений. Альтернативный прежний способ — объявить <code>static int limit;</code> внутри класса и дать одно определение <code>int Sample::limit = 10;</code> в <code>.cpp</code>. Оба варианта задают один объект; смешивать их в этом примере не нужно.</p><p>Счётчик живых объектов потребовал бы учитывать все способы создания, копирование, перемещение и уничтожение. Простое увеличение в одном конструкторе ещё не даёт такого счётчика. Статическое поле выбирают, когда состояние действительно общее по смыслу; для независимых значений оно не нужно.</p>

<h3>Const относится к пути доступа</h3>

<p>Метод с <code>const</code> после списка параметров получает текущий объект как константный. Через этот путь он не может менять обычные нестатические поля или вызывать для текущего объекта неконстантные методы. Поэтому операции наблюдения и вычисления нового значения объявляют <code>const</code>.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;stdexcept&gt;

class Distance {
    long long feet_{};
    long long inches_{};
public:
    static constexpr long long max_feet = 1'000'000;

    Distance() = default;
    Distance(long long feet, long long inches)
        : feet_(feet), inches_(inches) {
        if (feet &lt; 0 || feet &gt; max_feet || inches &lt; 0 || inches &gt;= 12) {
            throw std::invalid_argument("distance");
        }
    }

    long long feet() const { return feet_; }
    long long inches() const { return inches_; }
    long long total_inches() const { return feet_ * 12 + inches_; }
    Distance add_dist(const Distance&amp; other) const {
        const long long total = total_inches() + other.total_inches();
        if (total &gt; max_feet * 12 + 11) {
            throw std::overflow_error("distance sum");
        }
        return Distance{total / 12, total % 12};
    }
};

int main() {
    const Distance first{1, 6};
    const Distance second{0, 8};
    Distance sum = first.add_dist(second);
    std::cout &lt;&lt; sum.feet() &lt;&lt; ' ' &lt;&lt; sum.inches() &lt;&lt; '\n';
    std::cout &lt;&lt; first.total_inches() &lt;&lt; ' ' &lt;&lt; second.total_inches() &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">2 2
18 8</code></pre><p>Сумма равна 2 футам 2 дюймам; исходные 18 и 8 дюймов сохранены. В <code>add_dist(const Distance&amp; other) const</code> две разные договорённости: параметр <code>other</code> доступен только для чтения через ссылку, и текущий объект доступен только для чтения через <code>this</code>. Новый возвращаемый объект изменяется независимо.</p><p>Если объявление и определение разделены, конечное <code>const</code> указывается в обоих местах. Оно участвует в типе нестатического метода, поэтому можно определить константную и неконстантную версии одной операции; такой приём будет использован в <a href="https://stepik.org/lesson/897987/step/10" rel="noopener noreferrer nofollow">операторе индексации</a>.</p><p>У <code>const</code> есть точные границы. Поля с <code>mutable</code> допускают изменение даже через константный текущий объект. Статические поля не являются его частью. Если поле хранит <code>int*</code>, константность объекта запрещает менять этот указатель через него, но сама по себе не превращает указанное число в <code>const int</code>. Поэтому <code>const</code> не означает автоматически «никаких побочных эффектов» или потокобезопасность.</p><p>У действительно объявленного константным объекта обычные поля нельзя менять и через снятие квалификатора: такое изменение имеет неопределённое поведение. В показанном интерфейсе для этого нет необходимости: чтение доступно напрямую, а арифметика возвращает отдельное значение.</p>

<h3>Доступ и дружба одной функции-члена</h3>

<p>Закрытое состояние позволяет проверять инвариант в ограниченном наборе операций. <code>private</code> — правило проверки программы компилятором, а не шифрование памяти и не защита от человека, который управляет процессом. Предоставляя <code>friend</code>, автор включает ещё одну функцию в набор кода, которому доверено представление.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

class Storage;

class Display {
public:
    void show(const Storage&amp; storage) const;
};

class Storage {
    int integer_;
    double real_;
public:
    Storage(int integer, double real) : integer_(integer), real_(real) {}
    friend void Display::show(const Storage&amp; storage) const;
};

void Display::show(const Storage&amp; storage) const {
    std::cout &lt;&lt; storage.integer_ &lt;&lt; ' ' &lt;&lt; storage.real_ &lt;&lt; '\n';
}

int main() {
    const Storage storage{5, 6.5};
    const Display display;
    display.show(storage);
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">5 6.5</code></pre><p>Порядок объявлений отвечает зависимостям. Сначала сообщается имя <code>Storage</code>; этого достаточно для ссылочного параметра. Затем определяется <code>Display</code> с объявлением <code>show</code>. Поэтому при объявлении дружбы компилятор уже знает, какая именно функция-член указана. Тело <code>show</code> расположено после полного определения <code>Storage</code>, когда известны его поля.</p><p><code>this</code> внутри <code>Display::show</code> обозначает <code>Display</code>, а не <code>Storage</code>. Второй объект получен через параметр <code>storage</code>. Дружба разрешает доступ по имени, но не предоставляет объект автоматически. Ровно эта функция-член стала другом; другие функции <code>Display</code> такого права из этой записи не получают.</p><p>Если вместо неё написать <code>friend class Display;</code>, доступ будет дан всем членам указанного класса. Дружба не становится взаимной, транзитивной или наследуемой. Если вывод можно реализовать через уже существующие методы чтения, дружба вообще не требуется. Это позволяет уменьшить число мест, которые зависят от закрытого представления.</p>

<h3>Создание копии и присваивание существующему объекту</h3>

<p>Инициализация создаёт объект; присваивание меняет уже существующий. Одинаковый знак <code>=</code> в исходнике не делает эти действия одинаковыми. Для класса без ручного управления ресурсом подходящие специальные операции часто может сформировать компилятор.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;stdexcept&gt;

class Distance {
    long long feet_{};
    long long inches_{};
public:
    static constexpr long long max_feet = 1'000'000;

    Distance() = default;
    Distance(long long feet, long long inches)
        : feet_(feet), inches_(inches) {
        if (feet &lt; 0 || feet &gt; max_feet || inches &lt; 0 || inches &gt;= 12) {
            throw std::invalid_argument("distance");
        }
    }

    long long feet() const { return feet_; }
    long long inches() const { return inches_; }
    long long total_inches() const { return feet_ * 12 + inches_; }
};

int main() {
    Distance original{1, 6};
    Distance copy = original;
    Distance assigned;
    assigned = original;
    original = Distance{2, 0};
    std::cout &lt;&lt; original.total_inches() &lt;&lt; ' ' &lt;&lt; copy.total_inches() &lt;&lt; ' '
              &lt;&lt; assigned.total_inches() &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">24 18 18</code></pre><p><code>Distance copy = original;</code> инициализирует новый объект копирующим конструктором. В <code>assigned = original;</code> объект уже существует, поэтому используется копирующее присваивание. Обе операции доступны для показанного типа и копируют его два числовых поля. После изменения <code>original</code> остальные значения остаются по 18 дюймов.</p><p>Формирование копирования не означает простое копирование произвольных байтов. Базы и поля копируются по своим правилам: <code>std::string</code> копирует строковое значение, а обычный указатель — только адрес. Автоматически получить независимую копию объекта за указателем таким образом нельзя. Если поле некопируемо, как <code>std::unique_ptr</code>, соответствующая неявная операция класса обычно тоже удалена.</p><p>Обычная форма копирующего конструктора — <code>Distance(const Distance&amp;)</code>. Передача источника по значению для такого конструктора потребовала бы ещё одной копии при самом вызове и не является допустимой заменой. Для наших числовых полей ручное определение не нужно.</p><p>Возврат по значению безопасно передаёт готовое значение без ссылки на уничтоженный локальный объект. В C++17/20 <code>return Distance{1, 6};</code> создаёт результат непосредственно из этого prvalue; отдельная копия или перемещение в таком случае не требуются. Для возврата именованного локального <code>result</code> действует необязательная оптимизация NRVO. Подробная связь с категориями выражений и перемещением находится в <a href="https://stepik.org/lesson/853535/step/1" rel="noopener noreferrer nofollow">модуле 14</a>.</p>

<h3>Struct и class: язык и соглашение о стиле</h3>

<p>В C++ структура может иметь методы, конструкторы, деструктор, закрытые поля и базовые классы. Обычный <code>class</code> может хранить открытые поля. Разделение «структура — только данные, класс — данные с функциями» не является правилом языка.</p><p>Фрагмент; определения и контекст указаны в объяснении:</p><pre><code class="language-cpp">struct First {
private:
    int value_{};
public:
    int value() const { return value_; }
};

class Second {
    int value_{}; // private по умолчанию
public:
    int value() const { return value_; }
};</code></pre><p>Фрагмент задаёт два разных типа с одинаковой организацией доступа. У первого закрытый доступ указан явно, у второго он установлен по умолчанию. Это не делает <code>First</code> и <code>Second</code> одним типом. При замене ключевого слова в одном определении и сохранении явных секций возможности класса сохраняются.</p><p>Второе различие по умолчанию относится к наследованию: в <code>struct Derived : Base</code> база открытая, в <code>class Derived : Base</code> — закрытая. В учебном коде модификатор базы будем писать явно, чтобы читатель видел выбранный контракт.</p><p>Полезное соглашение о стиле: <code>struct</code> для простого набора независимо доступных данных, <code>class</code> для типа, у которого операции поддерживают инвариант закрытого состояния. Это рекомендация, а не запрет методов в структуре. Выбор должен объяснять смысл типа, а не усложнять его.</p><p>Агрегатность тоже не определяется одним ключевым словом. Наш простой <code>Person</code> допускает агрегатную инициализацию, а <code>Distance</code> с закрытыми полями и пользовательским конструктором — нет. Точные условия агрегата различаются между версиями стандарта: например, явно записанный <code>S() = default;</code> внутри класса сам по себе ещё может быть совместим с агрегатом C++17, но пользовательское объявление конструктора исключает агрегатность C++20. Поэтому примеры курса не выводят агрегатность только из наличия или отсутствия тела конструктора.</p>

<h3>Разобранный пример: значение карты и перестановка объектов</h3>

<p>Соберём конструктор, инвариант, константные методы и копирование в одной программе. Карта хранит достоинство 2–14 и одну из четырёх мастей. Перестановки заранее определены: программа выводит готовый результат, не предлагает угадывать карту и не моделирует случайное перемешивание.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;array&gt;
#include &lt;iostream&gt;
#include &lt;stdexcept&gt;
#include &lt;utility&gt;

enum class Suit { clubs, diamonds, hearts, spades };

class Card {
    int rank_;
    Suit suit_;
public:
    Card(int rank, Suit suit) : rank_(rank), suit_(suit) {
        if (rank &lt; 2 || rank &gt; 14) throw std::invalid_argument("rank");
        switch (suit) {
        case Suit::clubs: case Suit::diamonds:
        case Suit::hearts: case Suit::spades: break;
        default: throw std::invalid_argument("suit");
        }
    }
    bool same_as(const Card&amp; other) const {
        return rank_ == other.rank_ &amp;&amp; suit_ == other.suit_;
    }
    void print() const {
        const char* name = "";
        switch (suit_) {
        case Suit::clubs: name = "clubs"; break;
        case Suit::diamonds: name = "diamonds"; break;
        case Suit::hearts: name = "hearts"; break;
        case Suit::spades: name = "spades"; break;
        }
        std::cout &lt;&lt; rank_ &lt;&lt; ' ' &lt;&lt; name &lt;&lt; '\n';
    }
};

int main() {
    std::array&lt;Card, 3&gt; cards{{{7, Suit::clubs}, {11, Suit::hearts}, {14, Suit::spades}}};
    const Card selected = cards[2];
    std::swap(cards[0], cards[2]);
    std::swap(cards[1], cards[2]);
    std::swap(cards[0], cards[1]);
    for (const Card&amp; card : cards) card.print();
    std::cout &lt;&lt; std::boolalpha &lt;&lt; cards[1].same_as(selected) &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">7 clubs
14 spades
