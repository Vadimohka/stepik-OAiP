<h3>Сортировка: результат, гарантии и цена</h3>
<p>Сортировка переставляет элементы в выбранном порядке. Для чисел по неубыванию каждое следующее число не меньше предыдущего. <strong>Повторы сохраняются.</strong> Пустая последовательность и последовательность из одного элемента уже отсортированы.</p>
<p>После урока вы сможете проследить основные сортировки, объяснить их время и дополнительную память, а в прикладной задаче воспользоваться стандартным алгоритмом. Собственные реализации нужны для понимания инвариантов и анализа; стандартная функция полезна как готовое решение и эталон в проверках.</p>
<h4>Начните со стандартного алгоритма</h4>
<p><code>std::sort</code> объявлен в <code>&lt;algorithm&gt;</code>. Пара <code>begin(), end()</code> задаёт полуинтервал: начало включено, конец находится за последним элементом. Вектор не копируется: меняется порядок его элементов.</p>
<p>Полная программа C++17/20. Ввод: целое <code>0 ≤ n ≤ 1000</code> и затем <code>n</code> целых значений, представимых типом <code>int</code>. Вывод: те же значения по неубыванию, разделённые пробелами; при <code>n = 0</code> — пустая строка. Ошибка ввода даёт код завершения 1. Чтение и печать находятся вне сортирующей функции, поэтому их стоимость анализируется отдельно.</p><pre><code class="language-cpp">#include &lt;cstddef&gt;
#include &lt;iostream&gt;
#include &lt;vector&gt;
#include &lt;algorithm&gt;



int main() {
    int n{};
    if (!(std::cin &gt;&gt; n) || n &lt; 0 || n &gt; 1000) {
        return 1;
    }
    std::vector&lt;int&gt; values(static_cast&lt;std::size_t&gt;(n));
    for (int&amp; value : values) {
        if (!(std::cin &gt;&gt; value)) {
            return 1;
        }
    }
    std::sort(values.begin(), values.end());
    for (std::size_t i = 0; i &lt; values.size(); ++i) {
        if (i != 0) {
            std::cout &lt;&lt; ' ';
        }
        std::cout &lt;&lt; values[i];
    }
    std::cout &lt;&lt; '\n';
}</code></pre>
<p>Например, для <code>6 3 1 3 -2 1 0</code> результат — <code>-2 0 1 1 3 3</code>. Стандарт гарантирует для <code>std::sort</code> <code>O(n log n)</code> сравнений, но не предписывает именно quicksort. Эта оценка относится к числу сравнений; сравнивать длинные строки дороже, чем машинные целые.</p>
<h4>Что такое устойчивость?</h4>
<p>Если записи с одинаковым ключом сохраняют взаимный порядок, сортировка <strong>устойчивая</strong>. Например, до сортировки по баллу записи идут <code>(Аня, 5), (Борис, 3), (Вера, 5)</code>. Устойчивая сортировка оставит Аню перед Верой. <code>std::sort</code> этого не гарантирует; для такой задачи предназначен <code>std::stable_sort</code>. Он сохраняет порядок эквивалентных по сравнению элементов, но имеет собственные требования к ресурсам.</p>
<table><thead><tr><th>Учебный вариант</th><th>Худшее время</th><th>Дополнительная память</th><th>Устойчивость</th></tr></thead><tbody>
<tr><td>Пузырёк с ранней остановкой</td><td>Θ(n²)</td><td>O(1)</td><td>Да, при обмене только строго неупорядоченных соседей</td></tr>

<tr><td>Вставки со сдвигом больших элементов</td><td>Θ(n²)</td><td>O(1)</td><td>Да</td></tr>
<tr><td>Классическое слияние с буфером</td><td>Θ(n log n)</td><td>O(n), включая буфер и стек</td><td>Да, если при равенстве берём из левой части</td></tr>

<p>Таблица относится к указанным вариантам. Сортировка Шелла зависит от последовательности промежутков; её разберём отдельно. При сравнении алгоритмов всегда уточняйте вариант, случай входа и учитываемую память.</p>
<p><strong>Мини-задача:</strong> нужно найти только наименьшее число в несортированном массиве. Обязательно ли сортировать весь массив?</p>
<details><summary>Разбор</summary><p>Достаточно одного прохода, то есть <code>O(n)</code> сравнений и <code>O(1)</code> дополнительной памяти. Для пустого массива результата нет. Если исходный порядок нужен дальше, сортировка дополнительно его разрушит.</p></details>

<h3>Пузырьковая сортировка: максимум уходит вправо</h3>
<p>Сравниваем соседние элементы. Если правый меньше левого, меняем их местами. После полного прохода наибольшее значение рассматриваемой части оказывается на её правом конце. Следующий проход может не трогать этот элемент.</p>
<p><strong>Трассировка:</strong> <code>[3, 1, 2]</code> → после первого сравнения <code>[1, 3, 2]</code> → после второго <code>[1, 2, 3]</code>. Следующий проход не делает обменов: сортировку можно закончить.</p>
<p>Полная программа C++17/20. Ввод: целое <code>0 ≤ n ≤ 1000</code> и затем <code>n</code> целых значений, представимых типом <code>int</code>. Вывод: те же значения по неубыванию, разделённые пробелами; при <code>n = 0</code> — пустая строка. Ошибка ввода даёт код завершения 1. Чтение и печать находятся вне сортирующей функции, поэтому их стоимость анализируется отдельно.</p><pre><code class="language-cpp">#include &lt;cstddef&gt;
#include &lt;iostream&gt;
#include &lt;vector&gt;
#include &lt;utility&gt;

void bubble_sort(std::vector&lt;int&gt;&amp; values) {
    for (std::size_t end = values.size(); end &gt; 1; --end) {
        bool swapped = false;
        for (std::size_t i = 1; i &lt; end; ++i) {
            if (values[i] &lt; values[i - 1]) {
                std::swap(values[i], values[i - 1]);
                swapped = true;
            }
        }
        if (!swapped) {
            return;
        }
    }
}

int main() {
    int n{};
    if (!(std::cin &gt;&gt; n) || n &lt; 0 || n &gt; 1000) {
        return 1;
    }
    std::vector&lt;int&gt; values(static_cast&lt;std::size_t&gt;(n));
    for (int&amp; value : values) {
        if (!(std::cin &gt;&gt; value)) {
            return 1;
        }
    }
    bubble_sort(values);
    for (std::size_t i = 0; i &lt; values.size(); ++i) {
        if (i != 0) {
            std::cout &lt;&lt; ' ';
        }
        std::cout &lt;&lt; values[i];
    }
    std::cout &lt;&lt; '\n';
}</code></pre>
<p><strong>Инвариант:</strong> перед очередным внешним проходом суффикс с индексов <code>end</code> до конца уже содержит наибольшие элементы в окончательном порядке. Каждый внутренний проход переносит следующий максимум на позицию <code>end−1</code>. Если обменов не было, вся оставшаяся часть уже упорядочена.</p>
<p>На уже отсортированном непустом массиве достаточно одного прохода: лучший случай <code>Θ(n)</code>. В худшем случае число сравнений порядка <code>(n−1)+(n−2)+…+1</code>, то есть <code>Θ(n²)</code>. Дополнительная память — <code>O(1)</code>. Сравнение строгое: равные значения не обмениваются, поэтому такой вариант устойчив.</p>
<p>Граница <code>end &gt; 1</code> корректно обрабатывает пустой вход. Она также позволяет избежать опасного выражения <code>values.size() - 1</code> при нулевом беззнаковом размере.</p>
<h4>Самостоятельно</h4>
<p>Удалите ранний <code>return</code> при отсутствии обменов. Будет ли результат верным? Что станет с лучшим временем?</p>
<details><summary>Разбор</summary><p>Результат останется верным, но программа выполнит все проходы даже на отсортированном входе. Лучшее время станет <code>Θ(n²)</code>.</p></details>

<h3>Сортировка вставками: расширяем упорядоченный префикс</h3>
<p>Перед итерацией с индексом <code>i</code> часть <code>[0, i)</code> уже отсортирована. Сохраняем следующий элемент, сдвигаем вправо большие значения и вставляем сохранённое значение на освободившееся место.</p>
<p>Для <code>[3, 1, 2]</code> сначала вставляем 1 перед 3 и получаем <code>[1, 3, 2]</code>. Затем для числа 2 сдвигаем только 3: <code>[1, 2, 3]</code>.</p>
<p>Полная программа C++17/20. Ввод: целое <code>0 ≤ n ≤ 1000</code> и затем <code>n</code> целых значений, представимых типом <code>int</code>. Вывод: те же значения по неубыванию, разделённые пробелами; при <code>n = 0</code> — пустая строка. Ошибка ввода даёт код завершения 1. Чтение и печать находятся вне сортирующей функции, поэтому их стоимость анализируется отдельно.</p><pre><code class="language-cpp">#include &lt;cstddef&gt;
#include &lt;iostream&gt;
#include &lt;vector&gt;

void insertion_sort(std::vector&lt;int&gt;&amp; values) {
    for (std::size_t i = 1; i &lt; values.size(); ++i) {
        const int value = values[i];
        std::size_t position = i;
        while (position &gt; 0 &amp;&amp; value &lt; values[position - 1]) {
            values[position] = values[position - 1];
            --position;
        }
        values[position] = value;
    }
}

int main() {
    int n{};
    if (!(std::cin &gt;&gt; n) || n &lt; 0 || n &gt; 1000) {
        return 1;
    }
    std::vector&lt;int&gt; values(static_cast&lt;std::size_t&gt;(n));
    for (int&amp; value : values) {
        if (!(std::cin &gt;&gt; value)) {
            return 1;
        }
    }
    insertion_sort(values);
    for (std::size_t i = 0; i &lt; values.size(); ++i) {
        if (i != 0) {
            std::cout &lt;&lt; ' ';
        }
        std::cout &lt;&lt; values[i];
    }
    std::cout &lt;&lt; '\n';
}</code></pre>
<p>В условии <code>position &gt; 0 &amp;&amp; ...</code> правая часть не вычисляется, если левая ложна. Поэтому обращения по индексу <code>position−1</code> при нулевой позиции не происходит. Сохранённая копия <code>value</code> нужна, потому что сдвиги перезаписывают исходную ячейку.</p>
<p>Лучший случай — уже упорядоченные данные: <code>Θ(n)</code>. В худшем случае приходится сдвигать растущий префикс на каждой итерации: <code>Θ(n²)</code>. Дополнительная память — <code>O(1)</code>. Равные элементы не сдвигаются друг через друга, поэтому реализация устойчива. Такой метод удобен для небольших или почти отсортированных последовательностей и может вставлять новые элементы по мере поступления.</p>
<h4>Самостоятельно</h4>

<details><summary>Разбор</summary><p>Сдвинутся 6 и 4; число 2 займёт индекс 1. Во втором случае не понадобится ни одного сдвига. Для уже упорядоченного входа внешний цикл сохраняется, но каждый внутренний сразу заканчивается.</p></details>

<h3>Быстрая сортировка: разбиение относительно опорного</h3>
<p><em>Quicksort</em> выбирает опорное значение и перераспределяет элементы вокруг него. Затем части сортируются рекурсивно. Отдельное слияние двух упорядоченных частей, как в merge sort, не требуется.</p>
<p>Удобная схема для понимания — три группы: меньше опорного, равны ему, больше него. Для <code>[4, 2, 4, 1, 5, 4]</code> и опорного 4 это группы <code>[2, 1]</code>, <code>[4, 4, 4]</code> и <code>[5]</code>. Рекурсивно обрабатываются только первая и третья. Здесь показана логическая группировка; реализация может переставлять элементы внутри исходного массива, не создавая три новых контейнера.</p>
<h4>От чего зависит время?</h4>
<ul><li>Если разбиения сбалансированы, получается порядка <code>log n</code> уровней по <code>O(n)</code> работы: <code>O(n log n)</code>.</li><li>Если на массиве различных значений каждый раз отделяется лишь один элемент, размеры задач равны <code>n−1, n−2, …</code>. Суммарная работа становится <code>Θ(n²)</code>.</li><li>При равномерном случайном выборе опорного на каждом шаге для различных ключей ожидаемое время — <code>O(n log n)</code>. Это не гарантия для каждого запуска.</li></ul>
<p>Выбор первого элемента как опорного может быть особенно неудачен на уже отсортированном входе. Много одинаковых ключей — отдельный важный тест: трёхчастное разбиение обрабатывает равные элементы вместе, а не повторяет над ними ту же работу.</p>
<h4>Какие свойства нужно проверять в реализации?</h4>
<ol><li>Разбиение сохраняет все элементы и формирует заявленные группы.</li><li>Рекурсивные поддиапазоны строго уменьшаются. Для размера 0 или 1 рекурсия останавливается.</li><li>Равные опорному значения не приводят к зацикливанию индексов.</li><li>Учитывается стек: у обычной рекурсии он имеет <code>O(log n)</code> ожидаемой глубины при указанной случайной модели, но может вырасти до <code>O(n)</code> в худшем случае.</li></ol>
<p>Обычный quicksort с обменами неустойчив: элементы с равными ключами могут поменять взаимный порядок. Название «быстрая» не означает «самая быстрая для любых данных». <code>std::sort</code> даёт собственную гарантию <code>O(n log n)</code> сравнений и не обязан использовать только обычный quicksort.</p>
<h4>Самостоятельно</h4>
<p>При разбиении массива из 8 различных элементов каждый раз получается пустая часть и часть на один элемент меньше. Какова максимальная длина цепочки рекурсивных задач? Что получится при делении примерно пополам?</p>
<details><summary>Разбор</summary><p>В первом случае размеры идут <code>8, 7, 6, …, 1</code>: глубина линейная по <code>n</code>. При делении пополам размеры вдоль одной ветви примерно <code>8, 4, 2, 1</code>: глубина логарифмическая. Глубина стека и суммарное число операций — разные характеристики.</p></details>

<h3>Сортировка слиянием: сначала половины, затем общий порядок</h3>
<p>Делим диапазон пополам, отдельно сортируем обе половины и объединяем их. Диапазон из 0 или 1 элемента уже готов. Для слияния поддерживаем два индекса: они указывают на первые ещё не перенесённые элементы левой и правой половин.</p>
<p>Слияние <code>[1, 4]</code> и <code>[2, 3]</code> выбирает по порядку 1, 2, 3, а затем копирует оставшуюся 4. Каждый элемент попадает в результат один раз: работа слияния линейна по суммарному размеру половин.</p>
<p>Полная программа C++17/20. Ввод: целое <code>0 ≤ n ≤ 1000</code> и затем <code>n</code> целых значений, представимых типом <code>int</code>. Вывод: те же значения по неубыванию, разделённые пробелами; при <code>n = 0</code> — пустая строка. Ошибка ввода даёт код завершения 1. Чтение и печать находятся вне сортирующей функции, поэтому их стоимость анализируется отдельно.</p><pre><code class="language-cpp">#include &lt;cstddef&gt;
#include &lt;iostream&gt;
#include &lt;vector&gt;

void merge_range(std::vector&lt;int&gt;&amp; values, std::vector&lt;int&gt;&amp; buffer,
                 std::size_t first, std::size_t last) {
    if (last - first &lt; 2) {
        return;
    }
    const std::size_t middle = first + (last - first) / 2;
    merge_range(values, buffer, first, middle);
    merge_range(values, buffer, middle, last);

    std::size_t left = first;
    std::size_t right = middle;
    std::size_t destination = first;
    while (left &lt; middle &amp;&amp; right &lt; last) {
        if (values[right] &lt; values[left]) {
            buffer[destination++] = values[right++];
        } else {
            buffer[destination++] = values[left++];
        }
    }
    while (left &lt; middle) {
        buffer[destination++] = values[left++];
    }
    while (right &lt; last) {
        buffer[destination++] = values[right++];
    }
    for (std::size_t i = first; i &lt; last; ++i) {
        values[i] = buffer[i];
    }
}

void merge_sort(std::vector&lt;int&gt;&amp; values) {
    std::vector&lt;int&gt; buffer(values.size());
    merge_range(values, buffer, 0, values.size());
}

int main() {
    int n{};
    if (!(std::cin &gt;&gt; n) || n &lt; 0 || n &gt; 1000) {
        return 1;
    }
    std::vector&lt;int&gt; values(static_cast&lt;std::size_t&gt;(n));
    for (int&amp; value : values) {
        if (!(std::cin &gt;&gt; value)) {
            return 1;
        }
    }
    merge_sort(values);
    for (std::size_t i = 0; i &lt; values.size(); ++i) {
        if (i != 0) {
            std::cout &lt;&lt; ' ';
        }
        std::cout &lt;&lt; values[i];
    }
    std::cout &lt;&lt; '\n';
}</code></pre>
<p><strong>Границы:</strong> <code>[first, last)</code> включает начало, но не конец. Две части <code>[first, middle)</code> и <code>[middle, last)</code> не пересекаются и вместе покрывают исходный диапазон. Размер равен <code>last−first</code>, поэтому одинаковая проверка обслуживает и пустой, и одноэлементный вход.</p>
<p><strong>Инвариант слияния:</strong> уже заполненная часть буфера упорядочена и содержит наименьшие из обработанных элементов двух половин. После окончания одной половины оставшиеся элементы другой уже идут в нужном порядке. При равных значениях выбирается левая половина: это сохраняет устойчивость.</p>
<p>Для данной реализации с делением пополам время — <code>Θ(n log n)</code> при растущем <code>n</code>. На каждом уровне суммарно обрабатывается <code>Θ(n)</code> элементов, уровней <code>Θ(log n)</code>. <p>Сортировка Шелла выполняет сортировку вставками по подпоследовательностям элементов на расстоянии <code>gap</code>. <h3>Сортировка кучей: максимум в корне</h3>
<p>Двоичная <em>max-heap</em> — почти полное бинарное дерево: все уровни, кроме последнего, заполнены, последний заполняется слева направо. Ключ родителя не меньше ключей его детей; равные значения разрешены. Поэтому максимум находится в корне.</p>
<p>Дерево удобно представить внутри того же массива. При нумерации с нуля дети индекса <code>i</code> находятся по индексам <code>2i+1</code> и <code>2i+2</code>, если эти индексы меньше текущего размера кучи. Это логическая структура данных; слово «куча» здесь не обозначает область динамической памяти.</p>
<ol><li>Строим max-heap снизу вверх, начиная с последнего внутреннего узла.</li><li>Меняем корень с последним элементом ещё активной кучи: максимум занимает окончательное место.</li><li>Уменьшаем активную часть и восстанавливаем свойство кучи просеиванием корня вниз.</li><li>Повторяем, пока остаётся больше одного элемента.</li></ol>
<p>Полная программа C++17/20. Ввод: целое <code>0 ≤ n ≤ 1000</code> и затем <code>n</code> целых значений, представимых типом <code>int</code>. Вывод: те же значения по неубыванию, разделённые пробелами; при <code>n = 0</code> — пустая строка. Ошибка ввода даёт код завершения 1. Чтение и печать находятся вне сортирующей функции, поэтому их стоимость анализируется отдельно.</p><pre><code class="language-cpp">#include &lt;cstddef&gt;
#include &lt;iostream&gt;
#include &lt;vector&gt;
#include &lt;utility&gt;

void sift_down(std::vector&lt;int&gt;&amp; values, std::size_t root, std::size_t count) {
    while (root &lt; count / 2) {
        std::size_t child = 2 * root + 1;
        if (child + 1 &lt; count &amp;&amp; values[child] &lt; values[child + 1]) {
            ++child;
        }
        if (!(values[root] &lt; values[child])) {
            return;
        }
        std::swap(values[root], values[child]);
        root = child;
    }
}

void heap_sort(std::vector&lt;int&gt;&amp; values) {
    for (std::size_t start = values.size() / 2; start &gt; 0; --start) {
        sift_down(values, start - 1, values.size());
    }
    for (std::size_t count = values.size(); count &gt; 1; --count) {
        std::swap(values[0], values[count - 1]);
        sift_down(values, 0, count - 1);
    }
}

int main() {
    int n{};
    if (!(std::cin &gt;&gt; n) || n &lt; 0 || n &gt; 1000) {
        return 1;
    }
    std::vector&lt;int&gt; values(static_cast&lt;std::size_t&gt;(n));
    for (int&amp; value : values) {
        if (!(std::cin &gt;&gt; value)) {
            return 1;
        }
    }
    heap_sort(values);
    for (std::size_t i = 0; i &lt; values.size(); ++i) {
        if (i != 0) {
            std::cout &lt;&lt; ' ';
        }
        std::cout &lt;&lt; values[i];
    }
    std::cout &lt;&lt; '\n';
}</code></pre>
<p>В <code>sift_down</code> сначала выбирается больший из существующих детей. Если родитель уже не меньше него, свойство кучи восстановлено. Иначе меняем элементы и продолжаем ниже. Проверка <code>root &lt; count / 2</code> означает, что у узла есть левый ребёнок; индексы детей вычисляются только после неё.</p>
<p><strong>Инвариант основного цикла:</strong> первые <code>count</code> элементов образуют max-heap, а оставшийся суффикс уже отсортирован и содержит извлечённые максимумы. Просеивание не трогает готовый суффикс.</p>
<p>Построение снизу вверх занимает <code>O(n)</code>: большинство узлов находятся низко и просеиваются совсем недалеко. Затем выполняется до <code>n−1</code> извлечений по <code>O(log n)</code>, поэтому худшее время ограничено <code>O(n log n)</code>. Показанная итеративная реализация использует <code>O(1)</code> дополнительной памяти и неустойчива. У рекурсивной версии просеивания дополнительно учитывался бы стек.</p>
<h4>Самостоятельно</h4>
<p>Можно ли искать произвольное значение в куче, каждый раз отбрасывая половину массива, как при бинарном поиске?</p>
<details><summary>Разбор</summary><p>Нет. Упорядочены только отношения родителя и детей; левое поддерево не обязано целиком быть меньше правого. Получение максимума из непустой max-heap требует <code>O(1)</code>, а поиск произвольного ключа в худшем случае — <code>O(n)</code>.</p></details>

<h2>Очередь заявок: сортировка с сохранением порядка</h2>
<p>Заявка состоит из двух целых чисел: <code>priority</code> (приоритет) и <code>label</code> (метка). Метка помогает различать заявки, но сама по себе не определяет их порядок и может повторяться.</p>
<p>Отсортируйте заявки по <strong>возрастанию приоритета</strong>. Заявки с одинаковым приоритетом должны идти в том же относительном порядке, в котором поступили во входных данных. Сохраните каждую заявку: даже полностью одинаковые строки нельзя удалять.</p>
<h3>Входные данные</h3>
<p>Первое число — <code>n</code>, количество заявок, <code>0 ≤ n ≤ 100000</code>. Затем идут <code>n</code> пар <code>priority label</code>. Оба числа в каждой паре находятся в диапазоне от <code>−1000000000</code> до <code>1000000000</code> включительно. Числа разделены пробельными символами.</p>
<h3>Выходные данные</h3>
<p>Выведите все <code>n</code> пар <code>priority label</code> в требуемом порядке; удобно печатать каждую пару на новой строке. Между числами допустимы любые пробельные символы. Если <code>n = 0</code>, вывод не должен содержать чисел.</p>
<h3>Как хранить два значения вместе</h3>
<p>Структуры подробно рассматриваются позже. Для этой задачи достаточно следующей заготовки: <code>Record</code> объединяет два поля, а обращение <code>record.priority</code> читает приоритет конкретной записи.</p>
<pre><code class="language-cpp">struct Record {
    int priority;
    int label;
};

bool by_priority(const Record&amp; left, const Record&amp; right) {
    return left.priority &lt; right.priority;
}</code></pre>
<p><code>const Record&amp;</code> передаёт запись в функцию без копирования и запрещает менять её через этот параметр. Функция отвечает, должен ли левый приоритет стоять раньше правого; при равных приоритетах она возвращает <code>false</code>.</p>
<p>Записи можно хранить в <code>std::vector&lt;Record&gt;</code> из <code>&lt;vector&gt;</code>. В <code>&lt;algorithm&gt;</code> есть <code>std::stable_sort</code>, сохраняющий порядок равных ключей. Другой подход — запомнить исходный номер каждой записи и применять <code>std::sort</code> с двумя критериями: сначала приоритет, затем исходный номер. Сортировка по метке как второму критерию условию не соответствует.</p>
<h3>Разбор образца</h3>
<p>У приоритета <code>1</code> метки поступили в порядке <code>9, 4</code>, и этот порядок сохраняется. У приоритета <code>2</code> остаётся последовательность <code>30, 10, 30</code>: повторная заявка не исчезает.</p>
