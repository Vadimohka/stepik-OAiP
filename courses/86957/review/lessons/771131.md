<h3>Файловые потоки</h3>

<p>Потоки для работы с файлами работают по очень схожему принципу, как и стандартные потоки ввода-вывода.</p>

<p>Для работы с файловыми потоками обычно не нужно вручную учитывать устройство файловой системы: библиотека берёт эти «подкапотные» детали на себя. При этом открытие, чтение и запись могут завершиться ошибкой, поэтому состояние потока всё равно нужно проверять.</p>

<p>Для работы с файлами в стандартной библиотеке определен заголовочный файл fstream, который определяет базовые типы для чтения и записи файлов. В частности, это:</p>

<ul>
	<li>
	<p>ifstream: для чтения из файла</p>
	</li>
	<li>
	<p>ofstream: для записи в файл</p>
	</li>
	<li>
	<p>fstream: совмещает запись и чтение</p>
	</li>
</ul>

<p>Для работы с данными типа wchar_t для этих потоков определены двойники:</p>

<ul>
	<li>
	<p>wifstream</p>
	</li>
	<li>
	<p>wofstream</p>
	</li>
	<li>
	<p>wfstream</p>
	</li>
</ul>

<h3>Открытие файла</h3>

<p>При операциях с файлом вначале необходимо открыть файл с помощью функции open(). Рассмотрим два способа вызова этой функции:</p>

<ul>
	<li>
	<p><code>open(путь)</code></p>
	</li>
	<li>
	<p><code>open(путь, режим)</code></p>
	</li>
</ul>

<p>Для открытия файла в функцию необходимо передать путь к файлу в виде строки. И также можно указать режим открытия. Список доступных режимов открытия файла:</p>

<ul>
	<li>
	<p>ios::in: разрешает чтение из файла. Поток ifstream автоматически добавляет этот флаг к переданному режиму.</p>
	</li>
	<li>
	<p>ios::out: разрешает запись в файл. Поток ofstream автоматически добавляет этот флаг. Режим out без in и app открывает файл с усечением; in | out сохраняет существующее содержимое, а out | app дописывает данные.</p>
	</li>
	<li>
	<p>ios::app: перед каждой записью выполняется переход в конец файла. Старые данные не удаляются.</p>
	</li>
	<li>
	<p>ios::ate: после открытия файла перемещает указатель в конец файла</p>
	</li>
	<li>
	<p>ios::trunc: файл усекается при открытии. Может быть установлен, если также установлен режим <code>out</code></p>
	</li>
	<li>
	<p>ios::binary: файл открывается в бинарном режиме</p>
	</li>
</ul>

<p>Если при открытии режим не указан, то по умолчанию для объектов ofstream применяется режим <code>ios::out</code>, а для объектов ifstream - режим <code>ios::in</code>. Для объектов fstream по умолчанию совмещаются режимы <code>ios::out</code> и <code>ios::in</code>: существующий файл сохраняется, отсутствующий файл не создаётся. Чтобы создать файл для чтения и записи с удалением прежнего содержимого, задают <code>in | out | trunc</code>.</p>

<pre><code class="language-cpp">std::ofstream out;          // поток для записи
out.open("D:\\hello1.txt"); // окрываем файл для записи
     
std::ofstream out2;
out2.open("D:\\hello2.txt", std::ios::app); // окрываем файл для дозаписи
 
std::ofstream out3;
out3.open("D:\\hello3.txt", std::ios::out | std::ios::trunc); // установка нескольких режимов
 
std::ifstream in;       // поток для чтения
in.open("D:\\hello4.txt"); // окрываем файл для чтения
 
std::fstream fs;        // поток для чтения-записи
fs.open("D:\\hello5.txt"); // окрываем файл для чтения-записи</code></pre>

<p>Однако в принципе необязательно использовать функцию open для открытия файла. В качестве альтернативы можно также использовать конструктор объектов-потоков и передавать в них путь к файлу и режим открытия. При вызове конструктора, в который передан путь к файлу, будет предпринята попытка открыть файл:</p>

<pre><code class="language-cpp">std::ofstream out("D:\\hello.txt");
std::ifstream in("D:\\hello.txt");
std::fstream fs("D:\\hello.txt", std::ios::app);</code></pre>

<p>Использование конструкторов для открытия потока является более предпочтительным, так как определение переменной, представляющей файловой поток, уже предполагает, что этот поток будет открыт для чтения или записи. А использование конструктора избавит от ситуации, когда мы забудем открыть поток, но при этом начнем его использовать.</p>

<p>В процессе работы мы можем проверить, открыт ли файл с помощью функции is_open(). Если файл открыт, то она возвращает true.</p>

<h3>Закрытие файла</h3>

<p>После завершения работы с файлом его следует закрыть с помощью функции close(). При выходе объекта потока из области видимости его деструктор закрывает связанный файл.</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;fstream&gt;
 
int main()
{
    std::ofstream out;          // поток для записи
    out.open("D:\\hello.txt"); // окрываем файл для записи
    out.close();            // закрываем файл
 
    std::ifstream in;       // поток для чтения
    in.open("D:\\hello.txt"); // окрываем файл для чтения
    in.close();             // закрываем файл
 
    std::fstream fs;        // поток для чтения-записи
    fs.open("D:\\hello.txt"); // окрываем файл для чтения-записи
    fs.close();             // закрываем файл
     
    return 0;
}</code></pre>

<p>Для работы с файловыми потоками не нужны специальные флаги линковки. Например, программу для C++20 можно собрать так:</p>

<pre><code>g++ -std=c++20 app.cpp -o app</code></pre>

<h3>Работа с файлами в языке С</h3>

<p>В C++ можно использовать и файловый интерфейс языка C из заголовка <code>&lt;stdio.h&gt;</code> (или <code>&lt;cstdio&gt;</code>). В этом интерфейсе открытый поток представлен указателем типа FILE*.</p>

<p>Этот интерфейс требует явно закрывать файл и проверять результаты операций. Однако не упомянуть о нём я считаю неправильным.</p>

<p>Работа с файлами через потоки по стандарту С++ выглядит следующим образом:</p>

<pre><code class="language-cpp">fstream file("ttt.txt", ios::out);
file &lt;&lt; "Hello, world!";</code></pre>

<p> Работа с файлом "напрямую" через стандарты С выглядит так:</p>

<pre><code class="language-cpp">#include &lt;stdio.h&gt;

int main(void) {
    FILE* file = fopen("ttt.txt", "wb");
    if (file == NULL) {
        return 1;
    }
    const char message[] = "Hello, world!";
    size_t written = fwrite(message, 1, sizeof message - 1, file);
    int close_result = fclose(file);
    return written == sizeof message - 1 &amp;&amp; close_result == 0 ? 0 : 1;
}</code></pre>

<p>Почему «напрямую» взято в кавычки? Оба интерфейса являются абстракциями над файловым вводом-выводом. В C используется поток, представленный FILE*, а в C++ — объект файлового потока; ни один из этих способов не означает прямой доступ к диску.</p>

<p>Обращение к файлу через интерфейс языка C производится через указатель на файл, который необходимо предварительно описать следующим образом:</p>

<pre><code>FILE *handler;</code></pre>

<p>После этого к файлу можно применять специальные функции:</p>

<ol>
	<li>
	<p>fscanf/fprintf используются для форматированного ввода/вывода при работе с текстовыми файлами. Описаны эти функции в заголовке stdio.h (cstdio) и являются аналогами функций scanf и printf, которые, в свою очередь используются для ввода с клавиатуры и вывода на экран;</p>
	</li>
	<li>
	<p>fread/fwrite для чтения/записи бинарных файлов</p>
	</li>
</ol>

<p>Что значит работа с бинарным файлом? Функциям, которые работают с двоичными файлами, неизвестна структура данных в той области памяти, в которую осуществляется ввод-вывод (указатель <strong>void* buf).</strong> Функция <strong>fread </strong>читает, а функция <strong>fwrite</strong> пишет в файл, начиная с текущей позиции, массив из <strong>n</strong> элементов размерностью <strong>size</strong> байтов каждый, возвращая количество успешно прочитанных (записанных) элементов.</p>

<p>Вот мы плавно перешли к чтению из файла и записи в него. </p>

<p>И пояснительная бригада из <a href="https://stackoverflow.com/questions/18040810/what-is-the-purpose-of-using-stdios-basetrunc-flag-with-stdios-baseout" rel="noopener noreferrer nofollow">stackoverflow</a>:</p>

<p><br>
Yes, <code>std::ios_base::out</code> is equivalent to <code>"w"</code> in <code>fopen</code>.</p>

<p>The point of <code>std::ios_base::trunc</code> is when <code>std::ios_base::in</code> and <code>std::ios_base::out</code> are used the same time.</p>

<ul>
	<li><code>in | out</code> is equivalent to <code>"r+"</code></li>
	<li><code>in | out | trunc</code> is equivalent to <code>"w+"</code></li>
	<li><code>binary | in | out</code> is equivalent to <code>"rb+"</code></li>
	<li><code>binary | in | out | trunc</code> is equivalent to <code>"wb+"</code></li>
</ul>
