<h3>Файловые потоки</h3>

<p>Потоки для работы с файлами работают по очень схожему принципу, как и стандартные потоки ввода-вывода.</p>

<p>При работе с файлами ранее необходимо было учитывать тип файловой системы, однако современны стандарты языка С++ берут данные "под капотные" движения на себя и программисту можно не переживать о том, что его программа на разных форматах дискового пространства случайно вылетит.</p>

<p>Для работы с файлами в стандартной библиотеке определен заголовочный файл fstream, который определяет базовые типы для чтения и записи файлов. В частности, это:</p>

<ul>
	<li>
	<p>ifstream: для чтения с файла</p>
	</li>
	<li>
	<p>ofstream: для записи в файл</p>
	</li>
	<li>
	<p>fstream: совмещает запись и чтение</p>
	</li>
</ul>

<p>Для работы с данными типа wchar_t для этих потоков определены двойники:</p>

<ul>
	<li>
	<p>wifstream</p>
	</li>
	<li>
	<p>wofstream</p>
	</li>
	<li>
	<p>wfstream</p>
	</li>
</ul>

<h3>Открытие файла</h3>

<p>При операциях с файлом вначале необходимо открыть файл с помощью функции open(). Данная функция имеет две версии:</p>

<ul>
	<li>
	<p><code>open(путь)</code></p>
	</li>
	<li>
	<p><code>open(путь, режим)</code></p>
	</li>
</ul>

<p>Для открытия файла в функцию необходимо передать путь к файлу в виде строки. И также можно указать режим открытия. Список доступных режимов открытия файла:</p>

<ul>
	<li>
	<p>ios::in: файл открывается для ввода (чтения). Может быть установлен только для объекта ifstream или fstream</p>
	</li>
	<li>
	<p>ios::out: файл открывается для вывода (записи). При этом старые данные удаляются. Может быть установлен только для объекта ofstream или fstream</p>
	</li>
	<li>
	<p>ios::app: файл открывается для дозаписи. Старые данные не удаляются.</p>
	</li>
	<li>
	<p>ios::ate: после открытия файла перемещает указатель в конец файла</p>
	</li>
	<li>
	<p>ios::trunc: файл усекается при открытии. Может быть установлен, если также установлен режим <code>out</code></p>
	</li>
	<li>
	<p>ios::binary: файл открывается в бинарном режиме</p>
	</li>
</ul>

<p>Если при открытии режим не указан, то по умолчанию для объектов ofstream применяется режим <code>ios::out</code>, а для объектов ifstream - режим <code>ios::in</code>. Для объектов fstream совмещаются режимы <code>ios::out</code> и <code>ios::in</code>.</p>

<pre><code class="language-cpp">std::ofstream out;          // поток для записи
out.open("D:\\hello1.txt"); // окрываем файл для записи
     
std::ofstream out2;
out2.open("D:\\hello2.txt", std::ios::app); // окрываем файл для дозаписи
 
std::ofstream out3;
out2.open("D:\\hello3.txt", std::ios::out | std::ios::trunc); // установка нескольких режимов
 
std::ifstream in;       // поток для чтения
in.open("D:\\hello4.txt"); // окрываем файл для чтения
 
std::fstream fs;        // поток для чтения-записи
fs.open("D:\\hello5.txt"); // окрываем файл для чтения-записи</code></pre>

<p>Однако в принципе необязательно использовать функцию open для открытия файла. В качестве альтернативы можно также использовать конструктор объектов-потоков и передавать в них путь к файлу и режим открытия. При вызове конструктора, в который передан путь к файлу, данный файл будет автоматически открываться:</p>

<pre><code class="language-cpp">std::ofstream out("D:\\hello.txt");
std::ifstream in("D:\\hello.txt");
std::fstream fs("D:\\hello.txt", std::ios::app);</code></pre>

<p>Использование конструкторов для открытия потока является более предпочтительным, так как определение переменной, представляющей файловой поток, уже предполагает, что этот поток будет открыт для чтения или записи. А использование конструктора избавит от ситуации, когда мы забудем открыть поток, но при этом начнем его использовать.</p>

<p>В процессе работы мы можем проверить, открыт ли файл с помощью функции is_open(). Если файл открыт, то она возвращает true.</p>

<h3>Закрытие файла</h3>

<p>После завершения работы с файлом его следует закрыть с помощью функции close(). Также стоит отметить, то при выходе объекта потока из области видимости, он удаляется, и у него автоматически вызывается функция close.</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;fstream&gt;
 
int main()
{
    std::ofstream out;          // поток для записи
    out.open("D:\\hello.txt"); // окрываем файл для записи
    out.close();            // закрываем файл
 
    std::ifstream in;       // поток для чтения
    in.open("D:\\hello.txt"); // окрываем файл для чтения
    in.close();             // закрываем файл
 
    std::fstream fs;        // поток для чтения-записи
    fs.open("D:\\hello.txt"); // окрываем файл для чтения-записи
    fs.close();             // закрываем файл
     
    return 0;
}</code></pre>

<p>Стоит отметить, что при компиляции через g++ следует использовать флаг -static, если программа работает со файлами и использует типы из заголовочного файла fstream:</p>

<pre><code>g++ app.cpp -o app -static</code></pre>

<h3>Работа с файлами в языке С</h3>

<p>Существует работа с файлом через указатель на файл, этот подход остался со времён языка С и его библиотеку <code>&lt;stdio.h&gt;</code>.</p>

<p>Он не безопасен и следует учитывать множество параметров, однако не упомянуть о нём я считаю неправильным.</p>

<p>Работа с файлами через потоки по стандарту С++ выглядит следующим образом:</p>

<pre><code class="language-cpp">fstream file("ttt.txt", ios::out);
file &lt;&lt; "Hello, world!";</code></pre>

<p> Работа с файлом "напрямую" через стандарты С выглядит так:</p>

<pre><code class="language-cpp">FILE *file("ttt.txt");
fwrite("Hello, world!",sizeof(char),sizeof(char)*13,file);//посчитал буквы(13)
</code></pre>

<p>Почему "напрямую"? Потому что оба средства являются некоторой абстракцией (привет ООП), которую в одном случае назвали <strong>файл</strong>, а в другом <strong>поток</strong>.</p>

<p>Обращение к файлу в старом стандарте производится через указатель на файл, который необходимо предварительно описать следующим образом:</p>

<pre><code>FILE *handler;</code></pre>

<p>После этого к файлу можно применять специальные функции:</p>

<ol>
	<li>
	<p>fscanf/fprintf используются для форматированного ввода/вывода при работе с текстовыми файлами. Описаны эти функции с библиотеке stdio.h (cstdio) и являются аналогами функций scanf и printf, которые, в свою очередь используются для ввода с клавиатуры и вывода на экран;</p>
	</li>
	<li>
	<p>fread/fwrite для чтения/записи бинарных файлов</p>
	</li>
</ol>

<p>Что значит работа с бинарным файлом? Функциям которые работают с бинарным файлы безразличен (неизвестен) характер структуры данных в той области памяти, в которую осуществляется ввод-вывод (указатель <strong>void* buf).</strong> Функция <strong>fread </strong>читает, а функция <strong>fwrite</strong> пишет в файл, начиная с текущей позиции, массив из <strong>n</strong> элементов размерностью <strong>size</strong> байтов каждый, возвращая количество успешно прочитанных (записанных) элементов.</p>

<p>Вот мы плавно перешли к чтению и записью в файл. </p>

<p>И пояснительная бригада из <a href="https://stackoverflow.com/questions/18040810/what-is-the-purpose-of-using-stdios-basetrunc-flag-with-stdios-baseout" rel="noopener noreferrer nofollow">stackoverflow</a>:</p>

<p><br>
Yes, <code>std::ios_base::out</code> is equivalent to <code>"w"</code> in <code>fopen</code>.</p>

<p>The point of <code>std::ios_base::trunc</code> is when <code>std::ios_base::in</code> and <code>std::ios_base::out</code> are used the same time.</p>

<ul>
	<li><code>in | out</code> is equivalent to <code>"r+"</code></li>
	<li><code>in | out | trunc</code> is equivalent to <code>"w+"</code></li>
	<li><code>binary | in | out</code> is equivalent to <code>"rb+"</code></li>
	<li><code>binary | in | out | trunc</code> is equivalent to <code>"wb+"</code></li>
</ul>

<p>Maybe a table would be more obvious:</p>

<pre><code>binary  in  out  trunc | stdio equivalent
-----------------------+-----------------
         +   +         |      "r+"
         +   +     +   |      "w+"
  +      +   +         |      "r+b"
  +      +   +     +   |      "w+b"</code></pre>
