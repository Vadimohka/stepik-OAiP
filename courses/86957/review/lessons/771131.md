<h3>Файл как источник данных: сначала операция, затем проверка</h3>
<p><strong>Цель:</strong> выбрать поток для чтения или записи и прочитать текстовый файл целиком, сохранив пробелы и пустые строки.</p>
<p>Поток связывает программу с источником или получателем данных. Оператор <code>&gt;&gt;</code>, оператор <code>&lt;&lt;</code> и функция <code>std::getline</code> работают по знакомому принципу и с консолью, и с файлами. Заголовок <code>&lt;fstream&gt;</code> предоставляет:</p>
<table><thead><tr><th>Тип</th><th>Назначение</th></tr></thead><tbody>
<tr><td><code>std::ifstream</code></td><td>Читать файл.</td></tr>
<tr><td><code>std::ofstream</code></td><td>Записывать файл.</td></tr>
<tr><td><code>std::fstream</code></td><td>Читать и записывать один файл; режим нужно выбирать осознанно.</td></tr></tbody></table>
<p>Начнём с <code>names.txt</code> в рабочем каталоге программы. В файле две строки: <code>Ada Lovelace</code> и <code>Alan Turing</code>. Программа выведет их с номерами:</p>
<pre><code>1: Ada Lovelace
2: Alan Turing</code></pre>
<p>Полная программа <code>read_lines.cpp</code>, C++17 и C++20:</p>
<pre><code class="language-cpp">#include &lt;cstddef&gt;
#include &lt;fstream&gt;
#include &lt;iostream&gt;
#include &lt;string&gt;

int main() {
    std::ifstream in{"names.txt"};
    if (!in) {
        std::cerr &lt;&lt; "Cannot open names.txt\n";
        return 1;
    }

    std::string line;
    std::size_t number = 0;
    while (std::getline(in, line)) {
        std::cout &lt;&lt; ++number &lt;&lt; ": " &lt;&lt; line &lt;&lt; '\n';
    }
    if (in.bad() || !in.eof()) {
        std::cerr &lt;&lt; "Cannot read names.txt\n";
        return 2;
    }
}</code></pre>
<p><code>std::ifstream in{"names.txt"}</code> сразу пытается открыть файл. Проверка <code>if (!in)</code> обнаруживает неудачу. Если файла нет, программа выводит сообщение в <code>std::cerr</code> и завершается с ненулевым кодом; она не выдаёт пустой файл за успешный результат.</p>
<p><code>std::getline(in, line)</code> читает до перевода строки, удаляет разделитель из потока и сохраняет остальные символы в <code>line</code>. Поэтому имя с пробелом не разрывается на два слова. Пустая строка тоже является строкой и получает номер. Последняя непустая строка читается и без завершающего перевода строки.</p>
<h4>Почему условием цикла служит чтение</h4>
<p><code>while (std::getline(in, line))</code> допускает тело цикла только после успешного извлечения строки. <code>eof()</code> сообщает о конце ввода, уже обнаруженном операцией. Это не предсказание следующего чтения. Условие <code>while (!in.eof())</code> может допустить обработку после неудачного чтения, а при другой ошибке — вовсе не остановить цикл.</p>
<p>После цикла проверяем, чем он закончился: <code>bad()</code> означает серьёзную ошибку потока; отсутствие <code>eof()</code> означает, что цикл остановился не из-за обычного конца файла. Для <code>getline</code> пустой файл — нормальный случай: ни одной строки и никакого вывода. Разбор чисел имеет дополнительные ошибки формата; они разобраны в <a href="https://stepik.org/lesson/771130/step/3" rel="noopener noreferrer nofollow">шаге о числовом файле</a>.</p>
<h4>Кто закрывает файл</h4>
<p>Объект файлового потока владеет открытым файлом и закрывает его при уничтожении. Это пример <strong>RAII</strong>: время жизни ресурса связано со временем жизни объекта. Закрытие происходит при обычном выходе из области видимости, при <code>return</code> и при раскрутке стека до найденного обработчика исключения. Аварийное завершение процесса не даёт тех же гарантий. Здесь достаточно готового владельца <code>ifstream</code>; устройство владельца и порядок уничтожения разобраны в <a href="https://stepik.org/lesson/853536/step/2" rel="noopener noreferrer nofollow">шаге о RAII</a>. Проверка ошибок сохранения разобрана в <a href="https://stepik.org/lesson/771131/step/2" rel="noopener noreferrer nofollow">следующем шаге</a>: автоматическое закрытие не делает запись безошибочной.</p>
<p>Все полные программы этого урока можно собирать так, заменяя имя файла:</p>
<pre><code>g++ -std=c++20 -Wall -Wextra -Wpedantic read_lines.cpp -o read_lines</code></pre>
<p>Для C++17 замените <code>c++20</code> на <code>c++17</code>. В Linux/macOS запуск — <code>./read_lines</code>; в Windows имя исполняемого файла и команда запуска зависят от оболочки.</p>
<h4>Разбор пустой и последней строки</h4><p>Если файл содержит <code>Ada</code>, пустую строку и <code>Alan</code> без завершающего перевода строки, вывод состоит из <code>1: Ada</code>, <code>2: </code> и <code>3: Alan</code>. Пустая строка успешно извлечена, а последняя непустая строка не теряется при достижении EOF. У полностью пустого файла успешных извлечений нет и программа не печатает строк. Наличие пустой строки и отсутствие строк — разные данные.</p>
<p>Справочные источники: <a href="https://timsong-cpp.github.io/cppwp/n4861/string.io" rel="noopener noreferrer nofollow">string.io</a>; <a href="https://timsong-cpp.github.io/cppwp/n4861/iostate.flags" rel="noopener noreferrer nofollow">iostate.flags</a>; <a href="https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rr-raii" rel="noopener noreferrer nofollow">CppCoreGuidelines#Rr-raii</a>.</p>

<h3>Открытие, пути и проверка сохранения</h3>
<p><strong>Цель:</strong> выбрать режим открытия, найти файл относительно рабочего каталога и отличить успешное открытие от успешного завершения записи.</p>
<p>Имя <code>"report.txt"</code> задаёт <strong>относительный путь</strong>. Он отсчитывается от текущего рабочего каталога процесса, который может отличаться от каталога исходника и исполняемого файла. При запуске из терминала это обычно каталог, из которого вы запустили программу; IDE задаёт его в настройках запуска. Если файл «пропал», сначала проверьте рабочий каталог. Использование конкретного диска вроде <code>D:\</code> делает пример зависимым от компьютера.</p>
<table><thead><tr><th>Открытие</th><th>Если файл есть</th><th>Если файла нет</th></tr></thead><tbody>
<tr><td><code>std::ifstream in{"data.txt"};</code></td><td>Чтение с начала.</td><td>Открытие не удаётся.</td></tr>
<tr><td><code>std::ofstream out{"data.txt"};</code></td><td>Прежнее содержимое удаляется.</td><td>Предпринимается создание.</td></tr>
<tr><td><code>std::ofstream out{"data.txt", std::ios::app};</code></td><td>Каждая запись добавляет данные в конец.</td><td>Предпринимается создание.</td></tr>
<tr><td><code>std::fstream file{"data.txt"};</code></td><td>Чтение и запись с начала, без усечения.</td><td>Открытие не удаётся.</td></tr></tbody></table>
<p>Создание может не удаться, например, из-за неверного пути или отсутствия прав. Режим <code>std::ios::trunc</code> явно выражает намерение удалить старое содержимое при открытии для записи. Флаги соединяют побитовым <code>|</code>: например, <code>std::ios::in | std::ios::out | std::ios::trunc</code>. Не используйте для их объединения <code>&amp;</code>.</p>
<h4>Пример: отчёт готов только после проверки</h4>
<p>Программа создаёт или перезаписывает <code>report.txt</code>. В примере используется отдельный каталог с демонстрационными данными. Ожидаемое содержимое файла — две строки <code>count 3</code> и <code>sum 42</code>; сообщение <code>saved</code> появляется только после проверки закрытия.</p>
<p>Полная программа <code>write_report.cpp</code>, C++17 и C++20:</p>
<pre><code class="language-cpp">#include &lt;fstream&gt;
#include &lt;iostream&gt;

int main() {
    std::ofstream out{"report.txt"};
    if (!out) {
        std::cerr &lt;&lt; "Cannot open report.txt\n";
        return 1;
    }

    out &lt;&lt; "count 3\n" &lt;&lt; "sum 42\n";
    out.close();
    if (!out) {
        std::cerr &lt;&lt; "Cannot finish report.txt\n";
        return 2;
    }
    std::cout &lt;&lt; "saved\n";
}</code></pre>
<p>Первая проверка обнаруживает ошибку открытия. Вторая выполняется <em>после</em> <code>close()</code>: часть ошибок вывода может обнаружиться только при передаче накопленных данных или закрытии файла. Успешное открытие через <code>is_open()</code> ещё не доказывает успех всех дальнейших операций.</p>
<p>Мы явно вызываем <code>close()</code>, чтобы проверить результат завершения записи до сообщения об успехе. Для простого чтения обычно достаточно автоматического закрытия. Эти способы дополняют друг друга: RAII освобождает ресурс, а проверки позволяют сообщить пользователю об ошибке.</p>
<h4>Буфер, flush и состояние потока</h4>
<p>Файловый поток работает через потоковый буфер; конкретное накопление и момент передачи данных зависят от реализации и настроек. <code>out.flush()</code> запрашивает синхронизацию буфера, после чего нужно проверить <code>out</code>. <code>std::endl</code> добавляет перевод строки и вызывает <code>flush()</code>; если немедленная синхронизация не нужна, достаточно <code>'\n'</code>. Ни <code>flush()</code>, ни успешный <code>close()</code> сами по себе не обещают сохранность при отключении питания.</p>
<p>Оператор вывода возвращает ссылку на тот же поток: результат <code>out &lt;&lt; 42</code> имеет тип <code>std::ostream&amp;</code>. Благодаря этому можно записать цепочку <code>out &lt;&lt; count &lt;&lt; ' ' &lt;&lt; sum</code>.</p>
<h4>Разбор усечения и успешного закрытия</h4><p>Если в <code>report.txt</code> были 100 строк, обычное открытие через <code>ofstream</code> удаляет прежнее содержимое; в примере остаётся новый отчёт. После <code>close()</code> связь с открытым файлом отсутствует, поэтому <code>is_open()</code> возвращает <code>false</code> и при успешной записи. Об успехе операции судят по состоянию потока после закрытия. RAII отвечает за освобождение ресурса, а проверка состояния — за корректное сообщение о результате.</p>
<p>Справочные источники: <a href="https://timsong-cpp.github.io/cppwp/n4861/filebuf.members" rel="noopener noreferrer nofollow">filebuf.members</a>; <a href="https://timsong-cpp.github.io/cppwp/n4861/ofstream.members" rel="noopener noreferrer nofollow">ofstream.members</a>; <a href="https://timsong-cpp.github.io/cppwp/n4861/ostream.unformatted" rel="noopener noreferrer nofollow">ostream.unformatted</a>.</p>

<h3>Интерфейс C: распознаём и проверяем ручное владение</h3>
<p><strong>Цель:</strong> читать код с <code>std::FILE*</code>, правильно проверять результаты и объяснять отличие от объекта <code>std::ofstream</code>. Основной способ для новых учебных программ — стандартные потоки C++.</p>
<p>В существующих библиотеках встречается интерфейс C из <code>&lt;cstdio&gt;</code>. <code>std::fopen</code> возвращает <code>std::FILE*</code> при успешном открытии и <code>nullptr</code> при ошибке. Сам вызов не выводит диагностическое сообщение за программу. Указатель обозначает библиотечный поток; это не прямой адрес файла на диске.</p>
<p>Полная программа записывает <code>Hello, files!</code> и перевод строки в <code>message.txt</code>. Режим <code>"wb"</code> создаёт файл для двоичной записи либо удаляет прежнее содержимое.</p>
<p>Полная программа <code>c_write.cpp</code>, C++17 и C++20:</p>
<pre><code class="language-cpp">#include &lt;cstdio&gt;

int main() {
    std::FILE* file = std::fopen("message.txt", "wb");
    if (file == nullptr) {
        std::fputs("Cannot open message.txt\n", stderr);
        return 1;
    }

    const char message[] = "Hello, files!\n";
    const std::size_t size = sizeof message - 1;
    const std::size_t written = std::fwrite(message, 1, size, file);
    const int closed = std::fclose(file);
    if (written != size || closed != 0) {
        std::fputs("Cannot finish message.txt\n", stderr);
        return 2;
    }
}</code></pre>
<p><code>std::fwrite(buffer, size, count, file)</code> возвращает количество полностью записанных элементов размером <code>size</code>, а не логическое «успех/ошибка». В примере размер элемента равен 1, поэтому результат одновременно равен числу записанных байтов. <code>std::fread</code> работает аналогично для чтения. Если <code>size</code> равен 8 и возвращено 3, полностью обработаны три восьмибайтовых элемента.</p>
<p>Последний нулевой символ массива <code>message</code> нужен для C-строки в памяти; в файл его здесь не записываем. Поэтому число записываемых элементов равно <code>sizeof message - 1</code>.</p>
<p><code>std::fclose</code> выполняется даже при неполной записи. Только после него проверяются оба результата. Не объединяйте запись и закрытие так, чтобы короткое замыкание <code>&amp;&amp;</code> или <code>||</code> пропускало <code>fclose</code>. Успешное закрытие возвращает 0; ненулевой результат означает ошибку.</p>
<p>Указатель <code>std::FILE*</code> сам по себе не закрывает файл при выходе из области видимости. Здесь ответственность лежит на программе. После <code>fclose</code> этот поток больше нельзя использовать или закрывать повторно. В более сложном коде ручное владение легко нарушить на раннем <code>return</code> или при исключении; именно эту обязанность берут на себя владельцы ресурсов, в том числе файловые потоки C++.</p>
<p><code>std::fprintf</code>/<code>std::fscanf</code> выполняют форматированный вывод/ввод; <code>std::fwrite</code>/<code>std::fread</code> передают блоки данных заданного размера. Выбор функции и режим открытия — разные решения.</p>
<h4>Разбор неполной записи</h4><p>Если <code>std::fwrite(buffer, 4, 5, file)</code> вернул 3, полностью записаны только три из пяти четырёхбайтовых элементов. Это не подтверждает запись всех 20 запрошенных байтов. Закрытие всё равно выполняется, а его результат проверяется отдельно. Ненулевой результат <code>fwrite</code> не является логическим признаком полного успеха. Форма API определяет контракт возвращаемого значения.</p>

### Шаг 4 — text (ID 3580923)

[Открыть на Stepik](https://stepik.org/lesson/771131/step/4?unit=773576) · [Исходник step-source](../../raw/step-sources/3580923.json) · [Объект step](../../raw/steps/3580923.json)

<h3>Дописать, перезаписать или сдвинуть позицию?</h3>
<p><strong>Цель:</strong> предсказать изменение файла по режиму открытия. Это полезнее, чем запоминать названия флагов отдельно от результата.</p>
<table><thead><tr><th>Режим C++</th><th>Аналог fopen</th><th>Поведение</th></tr></thead><tbody>
<tr><td><code>in</code></td><td><code>"r"</code></td><td>Чтение; файл должен существовать.</td></tr>
<tr><td><code>out</code> или <code>out | trunc</code></td><td><code>"w"</code></td><td>Запись с усечением; отсутствующий файл создаётся, если это разрешено.</td></tr>
<tr><td><code>out | app</code></td><td><code>"a"</code></td><td>Каждая запись в конец; существующие данные сохраняются.</td></tr>
<tr><td><code>in | out</code></td><td><code>"r+"</code></td><td>Чтение и запись без усечения; файл должен существовать.</td></tr>
<tr><td><code>in | out | trunc</code></td><td><code>"w+"</code></td><td>Чтение и запись с усечением/созданием.</td></tr>
<tr><td><code>in | out | app</code></td><td><code>"a+"</code></td><td>Чтение и добавление; каждая запись в конец.</td></tr></tbody></table>
<p><code>std::ifstream</code> сам добавляет <code>in</code>, а <code>std::ofstream</code> — <code>out</code>. Поэтому для дописывания через <code>ofstream</code> достаточно явно передать <code>app</code>. В C режим — одна строка: например, <code>"r+b"</code>. Выражение <code>"r" | "w"</code> не является способом задать режим.</p>
<h4>Два разных «конца файла»</h4>
<p><code>app</code> направляет <strong>каждую запись</strong> в конец файла. <code>ate</code> перемещает позицию в конец <strong>один раз, после открытия</strong>; затем можно позиционироваться иначе. <code>ate</code> не отменяет усечение, которое следует из остальных флагов. В режиме <code>app</code> попытка предварительно изменить позицию записи не превращает дописывание в перезапись середины.</p>
<h4>Пример 1: журнал</h4>
<p>Если <code>journal.txt</code> содержит строку <code>5</code> с завершающим переводом строки, после запуска он содержит строки <code>5</code> и <code>7</code>. Повторный запуск добавит ещё одну строку <code>7</code>. Если последнего перевода строки в исходном файле не было, программа сама его перед записью не добавит: к <code>5</code> присоединится <code>7</code>.</p>
<p>Полная программа <code>append_line.cpp</code>, C++17 и C++20:</p>
<pre><code class="language-cpp">#include &lt;fstream&gt;
#include &lt;iostream&gt;

int main() {
    std::ofstream out{"journal.txt", std::ios::app};
    if (!out) {
        std::cerr &lt;&lt; "Cannot open journal.txt\n";
        return 1;
    }

    out &lt;&lt; "7\n";
    out.close();
    if (!out) {
        std::cerr &lt;&lt; "Cannot finish journal.txt\n";
        return 2;
    }
}</code></pre>
<h4>Пример 2: запись поверх начала</h4>
<p>Исходный <code>text.txt</code> содержит ровно пять символов <code>ABOBA</code>. Следующая программа получает <code>LUCIA</code>: четыре новых символа заменяют первые четыре старых, а последний <code>A</code> остаётся. Это не вставка и не усечение. Если файла нет, открытие не удаётся.</p>
<p>Полная программа <code>overwrite_prefix.cpp</code>, C++17 и C++20:</p>
<pre><code class="language-cpp">#include &lt;fstream&gt;
#include &lt;iostream&gt;

int main() {
    std::fstream file{"text.txt"};
    if (!file) {
        std::cerr &lt;&lt; "Cannot open text.txt\n";
        return 1;
    }

    file &lt;&lt; "LUCI";
    file.close();
    if (!file) {
        std::cerr &lt;&lt; "Cannot finish text.txt\n";
        return 2;
    }
}</code></pre>
<p>Место чтения меняют через <code>seekg</code>, записи — через <code>seekp</code>; результат перехода нужно проверять. Эти операции и ограничения текстового режима разобраны в <a href="https://stepik.org/lesson/771130/step/2" rel="noopener noreferrer nofollow">шаге о позиционировании</a>. У файлового потока чтение и запись используют общую файловую позицию: буквы <code>g</code> и <code>p</code> не означают два независимых курсора в файле.</p>
<p>При чередовании направлений после записи перед чтением выполняют <code>flush()</code> либо позиционирование. После чтения перед записью выполняют позиционирование, кроме случая, когда чтение встретило конец файла. Перед продолжением проверяют состояние потока и причину остановки. Для намеренной записи после нормального EOF вызывают <code>clear()</code>: нужно сбросить и <code>eofbit</code>, даже если последнее извлечение значения завершилось успешно и <code>failbit</code> не установлен. Уже установленный <code>failbit</code> одним позиционированием не устраняется. После восстановления допустимого состояния выполняют нужный переход или запись. Сам <code>clear()</code> не меняет позицию и не исправляет повреждённый файл. Для примеров с одним направлением достаточно отдельных <code>ifstream</code> и <code>ofstream</code>.</p>
<h4>Разбор выбора режима</h4><p>Для существующего файла <code>in | out</code> сохраняет данные и разрешает оба направления. Добавление <code>trunc</code> меняет договор: файл создаётся заново с удалением прежних данных. Для журнала с записью только в конец достаточно <code>ofstream</code> с <code>app</code>. Это три разных операции; выбор зависит от требуемого изменения файла, а не от сходства названий флагов.</p>
