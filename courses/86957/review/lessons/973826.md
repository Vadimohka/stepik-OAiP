<p style="text-align: center;"><strong>Алгоритмическая сложность</strong></p>

<p>Для грамотного выбора структуры данных необходимо понимать несколько важных вещей. Первое —  сет и мап являются надстройкой и могут иметь в своей основе разные структуры данных. Второе — в зависимости от выбранной основы будет меняться сложность операций, проводимых над ними. </p>

<p>Как правило, классификация алгоритмов имеет вид О(f(n)), где f(n) наиболее часто является такой функцией от n, как n, n^3 или 2^n.</p>

<p>Предположим, например, что существует алгоритм, наихудшая производительность которого никогда не превышает прямую пропорциональность размеру входного экземпляра задачи по достижении некоторого «достаточно большого» размера. Точнее говоря, существует некоторая константа с &gt; 0, такая, что t(n) ≤ c·n для всех n &gt; n0, где n0 является той точкой, в которой экземпляр задачи становится «достаточно большим». В этом случае классификацией будет функция f(n) = n и мы будем использовать запись О(n). </p>

<p>Для этого же алгоритма предположим, что производительность в наилучшем случае никогда не меньше, чем прямая пропорциональность размеру экземпляра входной задачи. В этом случае существует другая постоянная с и другой порог размера задачи n0 и t(n) ≥ c·n для всех n &gt; n0. В этом случае классификация вновь имеет вид f(n) = n, но в этот раз она записывается как Ω(n).<br>
Таким образом, фактическая формальная запись будет выглядеть следующим образом:</p>

<ul>
	<li>Нижняя граница времени работы классифицируется как Ω(f(n)) и соответствует сценарию наилучшего случая;</li>
	<li>Верхняя граница времени работы алгоритма классифицируется как О(f(n)) и соответствует сценарию наихудшего случая.</li>
</ul>

<p>Кроме этого всего существует ещё запись Θ(f(n)), которая сочетает в себе обе концепции для определения точной границы, то есть когда нижняя граница Ω(f(n)) и верхняя граница О(f(n)) используют для классификации одну и ту же функцию f(n). </p>

<p>Однако наиболее часто используют оценку верхней границы, поэтому и здесь производительность операций будет происходить через нее же. </p>

<p><em><strong>Иногда для успешного решения задачи, нужно всего лишь прочитать условие, а затем написать решение - Тренер Belarusian SUIR #1: So Stuffy.</strong></em></p>

<p>Максим Витальевич решил изучить новый язык программирования. Один его знакомый порекомендовал изучить язык Rust, так как он самый перспективный. Да, язык действительно воодушевляет, но заставляет столкнуться с суровой реальностью - великим и могучим borrow checker.</p>

<p>Сказать, что Максим Витальевич был в некоторой растерянности, это ничего не сказать. Чтобы выйти из данной ситуации и разобраться с borrow checker, Максим Витальевич решил упростить язык.</p>

<p>Новый язык поддерживает только заранее определенный набор функций. Всего в языке доступно $n$ функций, описание каждой имеет следующий синтаксис:</p>

<pre><code class="language-rust">&lt;char&gt; := "a" | "b" | ... | "z"
&lt;name&gt; := &lt;char&gt; | &lt;char&gt; &lt;name&gt;
&lt;nameOrRefName&gt; := &lt;name&gt; | "&amp;" &lt;name&gt;
&lt;argument&gt; := &lt;nameOrRefName&gt;
&lt;arguments&gt; := &lt;argument&gt; | &lt;argument&gt; ", " &lt;arguments&gt;
&lt;functionName&gt; := &lt;nameOrRefName&gt;
&lt;functionArguments&gt; := "" | &lt;arguments&gt;
&lt;function&gt; := "fn " &lt;functionName&gt; "(" &lt;functionArguments&gt; ")"</code></pre>

<p>Таким образом, &lt;function&gt; является описанием функции. Можно заметить, что имя функции может быть как «name», так и «&amp;name». В первом случае, функция возвращает значение, во втором случае — ссылку. Примеры корректных функций:</p>

<pre><code class="language-rust">fn input()        // Функция input, возвращает значение и не содержит аргументов.
fn sum(a, b)      // Функция sum, возвращает значение и принимает два аргумента по значению.
fn add(&amp;a, &amp;b)    // Функция add, возвращает значение и принимает аргументы по ссылке.
fn &amp;ref(a)        // Функция ref, возвращает ссылку и принимает аргумент по значению.
fn assign(a, &amp;b)  // Функция assign, возвращает значение и принимает первый аргумент
                  // по значению, а второй по ссылке. </code></pre>

<p>Приведем также некорректные примеры (такие примеры не могут встречаться во входных данных):</p>

<pre><code class="language-rust">&amp;fn funcd()      // Неверный порядок символов.
fn funcb(a, b&amp;)  // Неверный порядок символов.
fn funcc(&amp;&amp;a)    // Нельзя получить ссылку на ссылку.
fn &amp;&amp;funca()     // Нельзя вернуть ссылку на ссылку.
fn fn()          // Используется fn в качестве имени.
fn funce(fn)     // Используется fn в качестве имени.
fn funcf(a, a)   // Одинаковые имена аргументов.
fn funcg(a, &amp;a)  // Одинаковые имена аргументов.</code></pre>

<p>Чтобы реализовать некоторую программу, в языке доступна конструкция «&lt;declare&gt;» — объявление новой переменной (или ссылки). Можно описать синтаксис следующим образом:</p>

<pre><code class="language-rust">&lt;callArguments&gt; := &lt;expression&gt; | &lt;expression&gt; ", " &lt;callArguments&gt;
&lt;functionCallArguments&gt; := "" | &lt;callArguments&gt;
&lt;functionCall&gt; := &lt;name&gt; "(" &lt;functionCallArguments&gt; ")"
&lt;expression&gt; := &lt;nameOrRefName&gt; | &lt;functionCall&gt;
&lt;declare&gt; := &lt;name&gt; " := " &lt;expression&gt;</code></pre>

<p>Приведем корректные примеры использования конструкции:</p>

<pre><code class="language-rust">a := input()      // Определяем переменную со значением результата input().
b := input()
c := a            // Приcваиваем новой переменной старое значение.
d := add(&amp;b, &amp;c)  // Вызываем функцию с передачей аргументов по ссылке.
e := add(ref(b), ref(c))
f := &amp;e</code></pre>

<p>Приведем некорректные примеры использования конструкции (такие примеры не могут встречаться во входных данных):</p>

<pre><code class="language-rust">a := &amp;input()  // Нельзя получить ссылку на результат функции.
fn := a        // Нельзя использовать fn в качестве имени.
&amp;b := c        // Нельзя объявлять имя-ссылку.</code></pre>

<p>Максим Витальевич считает, что такой синтаксис довольно простой, поэтому <strong>синтаксических ошибок при использовании языка он допустить не может</strong>.</p>

<p>Однако Максим Витальевич может допустить следующие ошибки:</p>

<ul>
	<li>
	<p>Использовать ранее не объявленную с помощью «:=» переменную.</p>
	</li>
	<li>
	<p>Использовать несуществующую функцию.</p>
	</li>
	<li>
	<p>Вызывать функцию с неверным числом аргументов (число аргументов должно совпадать с определением).</p>
	</li>
	<li>
	<p>В аргумент функции принимающий значение передавать ссылку (либо наоборот).</p>
	</li>
	<li>
	<p><strong>Использовать в выражении ранее перемещенное значение переменной (либо ссылку на такую переменную)</strong>.</p>
	</li>
</ul>

<p>Последний пункт рассмотрим поподробнее. В языке Максима Витальевича предусмотрен собственный механизм borrow checker. Суть заключается в том, что все переменные, которые <strong>используются по значению, перемещаются</strong> и перестают быть доступными. Рассмотрим следующий пример:</p>

<pre><code class="language-rust">a := input()    // a является значением.
b := sum(a, a)  // Ошибка!</code></pre>

<p>В этом случае переменная «a» передается по значению 2 раза, однако после первого же использования она перестает быть доступна, таким образом возникает ошибка. В то же время:</p>

<pre><code class="language-rust">a := input()      // a является значением.
b := sum(&amp;a, &amp;a)  // Корректно, если sum принимает ссылки. Переменная a
                  // остается доступной, так как не была использована по значению.</code></pre>

<p>После объявления переменной с тем же именем (:=), старая переменная (если она является значением) <strong>считается перемещенной</strong> и перестает быть доступной <strong>начиная со следующей строки</strong>.</p>

<p>Для ссылок действуют следующие правила:</p>

<ul>
	<li>
	<p>Нельзя получать ссылку для перемещенной переменной.</p>
	</li>
	<li>
	<p>Нельзя получать ссылку для переменной-ссылки.</p>
	</li>
	<li>
	<p>Нельзя использовать ссылку на перемещенную переменную.</p>
	</li>
	<li>
	<p><strong>Нельзя одновременно передавать переменную-значение и ссылку на эту переменную в той же строке.</strong></p>
	</li>
</ul>

<p>Рассмотрим следующие примеры:</p>

<pre><code class="language-rust">a := input()
b := a
c := &amp;a  // Ошибка, переменная a была перемещена.

a := input()
b := &amp;a
c := move(a) // Аналогично c := a. В любом случае переменная a перемещается.
d := b       // Ошибка, переменная b является ссылкой на значение a, которое было перемещено.

a := input()
b := &amp;a
c := call(a, b) // Ошибка. Переменная a была перемещена, поэтому ссылку использовать нельзя.

a := input()
b := &amp;a
a := a         // Старое значение переменной a перемещено.
c := clone(b)  // Ошибка, переменная b ссылается на старую переменную a, которая
               // была перемещена в предыдущей строке.</code></pre>

<p>Так как Максим Витальевич придумал язык и хочет его использовать, он просит вас реализовать программу, которая будет проверять код Максима Витальевича на наличие ошибок.</p>

<p>В первой строке задано число $n$ - количество функций.</p>

<p>В следующих $n$ строках заданы описания функций в соответствии с описанным синтаксисом. Гарантируется, что все имена функций уникальны, и все имена аргументов у каждой функции так же уникальны.</p>

<p>В следующей строке задано число $m$ - количество строк в коде Максима Витальевича.</p>

<p>В следующих $m$ строках заданы конструкции объявления новой переменной в соответствии с описанием синтаксиса.</p>

<p>Гарантируется, что суммарная длина строк не превышает $100\,000$. Во входных данных не содержится лишних пробелов, а также не может быть пробелов меньше, чем описано в синтаксисе языка.</p>

<p>$$ 1 \le n \le 20 $$<br>
$$ 1 \le m \le 100 $$</p>

<p>В единственной строке выведите "Valid" (без кавычек), если программа является корректной.</p>

<p>В противном случае выведите "Error in line N" (без кавычек), где N - номер первой строки с ошибкой в коде Максима Витальевича.</p>

<p>Нумерация строк начинается с $1$.</p>
