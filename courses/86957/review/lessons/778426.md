<p><img alt="" height="284" name="image.png" src="https://ucarecdn.stepik.net/f4cb398f-2c9c-4269-8c12-f4c81e8f808a/" width="923"></p>

<p>Казалось бы: ну что может пойти не так? Достаточно просто написать функцию, которая вычисляет сумму цифр в числе, и просто в цикле перебрать весь интервал.</p>

<p>Реализация этих двух функций выглядит примерно так:</p>

<pre><code>int SumOfDigits(int num) {
    int result = 0;

    for (int i = 0; pow(10, i) &lt; num; i++) {
        result += (int)(num / pow(10, i)) % 10;
    }

    return result;
}

int CountInterestingInInterval(int intervalEnd) {
    int result = 0;

    for (int i = 1; i &lt;= intervalEnd; i++) {
        if (SumOfDigits(i) &gt; SumOfDigits(i + 1)) {
            result++;
        }
    }

    return result;
}</code></pre>

<p>Но этот код является типичным примером неправильной реализации алгоритма, так как при больших значениях конца интервала скорость выполнения станет невероятно малой (при пограничном случае 10^9 программа будет отрабатывать в районе 20 минут).</p>

### Шаг 4 — text (ID 3253429)

[Открыть на Stepik](https://stepik.org/lesson/778426/step/4?unit=780910) · [Исходник step-source](../../raw/step-sources/3253429.json) · [Объект step](../../raw/steps/3253429.json)

<p><strong>Исправление алгоритма</strong></p>

<p>В такой ситуации нужно искать другой выход. И он есть. Ведь интересными являются только числа, оканчивающиеся девяткой. Из-за того, что следующее число в лучшем случае имеет в разряде десятков цифру, большую на единицу, а в разряде единиц ноль,  сумма цифр уменьшается минимум на 8, что и является признаком интересного числа. В других случаях это не происходит. Сократим код:</p>

<pre><code>int CountInterestingInInterval(int intervalEnd) {
    int result = 0;

    for (int i = 1; i &lt;= intervalEnd; i++) {
        if (i % 10 == 9) {
            result++;
        }
    }
    

    return result;
}</code></pre>

<p>Так как подсчёт суммы цифр числа был очень затратной операцией, такое упрощение алгоритма позволило уменьшить время выполнения до двух секунд. И этого достаточно для данной задачи. Однако можно ещё больше сократить алгоритм! Достаточно понять, что каждое интересное число повторяется через 10. Это значит, что код функции можно сократить до одной строки, а время выполнения станет моментальным.</p>

<pre><code>int CountInterestingInInterval(int intervalEnd) {
    return (intervalEnd + 1) / 10;
}</code></pre>

<p>Такой процесс модификации программы для улучшения её эффективности называется <strong>оптимизацией</strong>.</p>

<p>Ещё существует процесс повышения читабельности кода -<strong> рефакторинг</strong>.</p>

<p>Итоговый код программы выглядит примерно так:</p>

<pre><code>#include &lt;iostream&gt;

<p><strong>Собственно Google Test</strong></p>

<p>Все эти проверки и замеры проводились вручную, что не всегда позволяет удобно и точно устранять баги. Поэтому воспользуемся специальными тестами. Для того, чтобы добавить к заданию тесты, нужно кликнуть ПКМ по названию решения, затем “Добавить” =&gt; “Cоздать проект…”.</p>

<p style="text-align: center;"><img alt="" height="817" name="image.png" src="https://ucarecdn.stepik.net/c46e90e2-39f1-4c25-98bf-b3d4b3d6d0b8/" width="983"></p>

<p><img alt="" height="991" name="image.png" src="https://ucarecdn.stepik.net/e5573656-a84f-458e-9d0e-16a54d2c8e50/" width="1887"></p>

<p>По умолчанию новый тестовый cpp файл будет содержать такой код:</p>

<pre><code>#include "pch.h"

TEST(TestCaseName, TestName) 
{
    EXPECT_EQ(1, 1);
    EXPECT_TRUE(true);
}</code></pre>

<p>Для удобного тестирования нужно вставить прототип функции, которую нужно тестировать в этот файл, а под тестом добавить её тело. Если вы получаете ответ задачи не в отдельной функции, a в функции main(что не очень хорошо, ибо функции упрощают понимание кода), то придётся каждый раз копировать этот код. Так что лучше сделать отдельную функцию для этого.</p>

<pre><code>#include "pch.h"


int CountInterestingInInterval(int interval_end);

TEST(TestCaseName, TestName) 
{
    EXPECT_EQ(1, 1);
    EXPECT_TRUE(true);
}

int CountInterestingInInterval(int interval_end)
{
    return  (interval_end + 1) / 10;
}</code></pre>

<p>Затем нужно создать несколько тестов, не забыв сделать для каждого уникальное название (желательно осмысленное).</p>

<pre><code>#include "pch.h"

int CountInterestingInInterval(int end_of_interval);

TEST(test_ordinary_1)
{
    ASSERT_EQ(CountInterestingInInterval(3), 0);
}
TEST(test_ordinary_2)
{
    ASSERT_EQ(CountInterestingInInterval(9), 1);
}
TEST(test_ordinary_3)
{
    ASSERT_EQ(CountInterestingInInterval(10), 1);
}
TEST(test_ordinary_4)
{
    ASSERT_EQ(CountInterestingInInterval(34), 3);
}
TEST(test_ordinary_5)
{
    ASSERT_EQ(CountInterestingInInterval(880'055'535), 88'005'553);
}
TEST(test_min)
{
    ASSERT_EQ(CountInterestingInInterval(1), 0);
}
TEST(test_max)
{
    ASSERT_EQ(CountInterestingInInterval(1'000'000'000), 100'000'000);
}


int CountInterestingInInterval(int end_of_interval)
{
    return  (end_of_interval + 1) / 10;
}</code></pre>

<p>Конструкция ASSERT_EQ проверяет на равенство два числа. Если они отличаются, то тест считается проваленным.</p>

### Шаг 7 — text (ID 3253553)

[Открыть на Stepik](https://stepik.org/lesson/778426/step/7?unit=780910) · [Исходник step-source](../../raw/step-sources/3253553.json) · [Объект step](../../raw/steps/3253553.json)

<p><strong>Фичи</strong></p>

<p>Стоит отметить, что ASSERT_EQ может работать не только с переменными типа int, но и с переменными любых других типов (он будет проверять их на равенство). Также для отдельных ситуаций можно использовать и более лаконичные варианты:</p>

<p style="text-align: center;"><img alt="" height="556" name="image.png" src="https://ucarecdn.stepik.net/9ec46997-58f7-4d88-84ad-f0335f993d83/" width="772"></p>

<p>Соответственно, три нижеописанные конструкции проверяют одно и тоже</p>

<pre><code>TEST(test_of_assert_eq)
{
    ASSERT_EQ(CountInterestingInInterval(1), 0);
}
TEST(test_of_assert_true)
{
    ASSERT_TRUE(CountInterestingInInterval(1) == 0);
}
TEST(test_of_fail)
{
    if (CountInterestingInInterval(1) != 0)
        FAIL();
}</code></pre>

<p>Нужно упомянуть о <strong>EXPECT</strong>.<br>
При тестировании может быть три исхода:</p>

<ol>
	<li>success - все работает корректно, выполнения теста продолжается</li>
	<li>non-fatal failure - работает некорректно, выполнение теста продолжается - сработал EXPECT</li>
	<li>fatal failure - работает некорректно, выполнение теста завершено - сработал ASSERT</li>
</ol>

<p>Для EXPECT действительны окончания, что и для ASSERT: EQ, GT, TRUE и т.д.</p>

<p>Можно добавить свой собственный <strong>комментарий</strong> к ASSERT, EXPECT: </p>

<pre><code class="language-cpp">ASSERT_EQ(some_variable, 0) &lt;&lt; "The comment you would like to see in the terminal if the assertion failed";</code></pre>

<p>Тесты могут использовать схожие условия для проверки. Чтобы избежать дублирования кода, не думать о инициализации и очищении ресурсов за собой при написании тестового блока, можно воспользоваться фиксацией. Для её использования необходимо использовать классы, потому <strong><a href="https://habr.com/ru/post/667880/#:~:text=%D0%94%D0%BE%D0%BF%D1%83%D1%81%D1%82%D0%B8%D0%BC%20%D1%83%20%D0%BD%D0%B0%D1%81%20%D0%B5%D1%81%D1%82%D1%8C%20%D1%82%D0%B0%D0%BA%D0%BE%D0%B9%20%D0%BA%D0%BB%D0%B0%D1%81%D1%81" rel="noopener noreferrer nofollow">читать не обязательно</a>.</strong></p>
