<p>Казалось бы: ну что может пойти не так? Достаточно просто написать функцию, которая вычисляет сумму цифр в числе, и просто в цикле перебрать весь интервал.</p>

<p>Реализация этих двух функций выглядит примерно так:</p>

<pre><code class="language-cpp">int SumOfDigits(int num) {
    // Предусловие: num &gt;= 0.
    int result = 0;
    do {
        result += num % 10;
        num /= 10;
    } while (num != 0);
    return result;
}

int CountInterestingInInterval(int intervalEnd) {
    int result = 0;
    for (int i = 1; i &lt;= intervalEnd; ++i) {
        if (SumOfDigits(i) &gt; SumOfDigits(i + 1)) {
            ++result;
        }
    }
    return result;
}</code></pre>

<p>Эта реализация корректно вычисляет сумму цифр, но перебирает весь интервал и повторяет деление на 10 для каждого числа. При границе 10<sup>9</sup> число операций слишком велико. Точное время зависит от реализации и оборудования; измерения нужны, чтобы оценить, укладывается ли программа в ограничение задачи. Далее найдём более быстрый алгоритм.</p>

### Шаг 4 — text (ID 3253429)

[Открыть на Stepik](https://stepik.org/lesson/778426/step/4?unit=780910) · [Исходник step-source](../../raw/step-sources/3253429.json) · [Объект step](../../raw/steps/3253429.json)

<p><strong>Исправление алгоритма</strong></p>

<p>В такой ситуации нужно искать другой выход. И он есть. Ведь интересными являются только числа, оканчивающиеся девяткой. Из-за того, что следующее число в лучшем случае имеет в разряде десятков цифру, большую на единицу, а в разряде единиц ноль,  сумма цифр уменьшается минимум на 8, что и является признаком интересного числа. В других случаях это не происходит. Сократим код:</p>

<pre><code>int CountInterestingInInterval(int intervalEnd) {
    int result = 0;

    for (int i = 1; i &lt;= intervalEnd; i++) {
        if (i % 10 == 9) {
            result++;
        }
    }
    

    return result;
}</code></pre>

<p>Так как подсчёт суммы цифр числа был очень затратной операцией, в показанном авторском замере такое упрощение уменьшило время выполнения до двух секунд. И этого достаточно для данной задачи. Однако можно ещё больше сократить алгоритм! Достаточно понять, что интересные числа идут с шагом 10. Это значит, что код функции можно сократить до одной строки, и выполнить подсчёт за постоянное число арифметических операций.</p>

<pre><code>int CountInterestingInInterval(int intervalEnd) {
    return (intervalEnd + 1) / 10;
}</code></pre>

<p>Такой процесс модификации программы для улучшения её эффективности называется <strong>оптимизацией</strong>.</p>

<p>Рефакторинг — изменение внутренней структуры кода без изменения его наблюдаемого поведения; одной из целей может быть улучшение читаемости.</p>

<p>Итоговый код программы выглядит примерно так:</p>

<pre><code class="language-cpp">#include &lt;climits&gt;
#include &lt;iostream&gt;
#include &lt;limits&gt;

void WriteEmptyLine(int n = 1);

int main() {

        for (int i = 0; i &lt; t; ++i) {

            std::cout &lt;&lt; "  Answer : " &lt;&lt; CountInterestingInInterval(n) &lt;&lt; "\n\n";
        }
    } catch (const std::exception&amp; error) {
        std::cerr &lt;&lt; error.what() &lt;&lt; '\n';

    }
}

int GetNumber(int intervalBegin = INT_MIN, int intervalEnd = INT_MAX, std::string purpose = "number") {
    while (true) {
        int value;
        std::cout &lt;&lt; "  Enter " &lt;&lt; purpose &lt;&lt; " : ";
        if (std::cin &gt;&gt; value) {
            if (value &gt;= intervalBegin &amp;&amp; value &lt;= intervalEnd) {

            }
        } else if (std::cin.eof() || std::cin.bad()) {

        }

        std::cout &lt;&lt; "  Input Error. Please repeat\n\n";
    }
}

int CountInterestingInInterval(int intervalEnd) {
    return (intervalEnd + 1) / 10;
}

void WriteEmptyLine(int n) {
    for (int i = 0; i &lt; n; ++i) {
        std::cout &lt;&lt; '\n';
    }
}</code></pre>

В проекте обычно подключают заголовок функции и связывают тесты с её исходной реализацией, чтобы не поддерживать отдельную копию алгоритма. Если вычисления пока находятся в main, сначала выделите их в отдельную функцию.</p>

<pre><code>#include "pch.h"


int CountInterestingInInterval(int interval_end);

TEST(TestCaseName, TestName) 
{
    EXPECT_EQ(1, 1);
    EXPECT_TRUE(true);
}

int CountInterestingInInterval(int interval_end)
{
    return  (interval_end + 1) / 10;
}</code></pre>

<p>Затем создайте несколько тестов. Макрос <code>TEST</code> принимает два аргумента: имя набора и имя теста, например <code>TEST(InterestingNumbers, OrdinaryCase)</code>. Оба должны быть допустимыми непустыми идентификаторами C++; имя теста должно быть уникальным внутри набора.</p>

<pre><code>#include "pch.h"

int CountInterestingInInterval(int end_of_interval);

TEST(InterestingNumbers, test_ordinary_1)
{
    ASSERT_EQ(CountInterestingInInterval(3), 0);
}
TEST(InterestingNumbers, test_ordinary_2)
{
    ASSERT_EQ(CountInterestingInInterval(9), 1);
}
TEST(InterestingNumbers, test_ordinary_3)
{
    ASSERT_EQ(CountInterestingInInterval(10), 1);
}
TEST(InterestingNumbers, test_ordinary_4)
{
    ASSERT_EQ(CountInterestingInInterval(34), 3);
}
TEST(InterestingNumbers, test_ordinary_5)
{
    ASSERT_EQ(CountInterestingInInterval(880'055'535), 88'005'553);
}
TEST(InterestingNumbers, test_min)
{
    ASSERT_EQ(CountInterestingInInterval(1), 0);
}
TEST(InterestingNumbers, test_max)
{
    ASSERT_EQ(CountInterestingInInterval(1'000'000'000), 100'000'000);
}


int CountInterestingInInterval(int end_of_interval)
{
    return  (end_of_interval + 1) / 10;
}</code></pre>

<p>Конструкция ASSERT_EQ проверяет на равенство два числа. Если они отличаются, то тест считается проваленным.</p>

### Шаг 7 — text (ID 3253553)

[Открыть на Stepik](https://stepik.org/lesson/778426/step/7?unit=780910) · [Исходник step-source](../../raw/step-sources/3253553.json) · [Объект step](../../raw/steps/3253553.json)

<p><strong>Фичи</strong></p>

<p>ASSERT_EQ подходит не только для int, но и для других типов, допускающих соответствующее сравнение. Для C-строк ASSERT_EQ сравнивает указатели; для сравнения содержимого используют ASSERT_STREQ. Для отдельных проверок доступны и другие макросы:</p>

<p style="text-align: center;"><img alt="" height="556" name="image.png" src="https://ucarecdn.stepik.net/9ec46997-58f7-4d88-84ad-f0335f993d83/" width="772"></p>

<p>Соответственно, три нижеописанные конструкции проверяют одно и то же</p>

<pre><code>TEST(InterestingNumbers, test_of_assert_eq)
{
    ASSERT_EQ(CountInterestingInInterval(1), 0);
}
TEST(InterestingNumbers, test_of_assert_true)
{
    ASSERT_TRUE(CountInterestingInInterval(1) == 0);
}
TEST(InterestingNumbers, test_of_fail)
{
    if (CountInterestingInInterval(1) != 0)
        FAIL();
}</code></pre>

<p>Нужно упомянуть о <strong>EXPECT</strong>.<br>
При тестировании может быть три исхода:</p>

<ol>
	<li>success — проверка успешна, выполнение продолжается</li>
	<li>non-fatal failure — проверка EXPECT не прошла, но текущая функция продолжает выполняться</li>
	<li>fatal failure — проверка ASSERT не прошла и завершила текущую функцию. Если это тело теста, оставшаяся часть его тела не выполняется</li>
</ol>

<p>Для EXPECT доступны те же окончания, что и для ASSERT: EQ, GT, TRUE и т.д.</p>

<p>Можно добавить свой собственный <strong>комментарий</strong> к ASSERT, EXPECT: </p>

<pre><code class="language-cpp">ASSERT_EQ(some_variable, 0) &lt;&lt; "The comment you would like to see in the terminal if the assertion failed";</code></pre>

<p>Для общей подготовки и освобождения ресурсов нескольких тестов можно использовать тестовую фикстуру (test fixture). Это помогает избежать повторения кода инициализации и очистки. Фикстуры Google Test основаны на классах; этот дополнительный материал можно изучить после знакомства с ними.</p>
