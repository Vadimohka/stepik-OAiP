<h2>Функция как именованная операция</h2>
<p>Функция объединяет действия под одним именем. <strong>Определение</strong> описывает эти действия, а <strong>вызов</strong> запускает их для конкретных аргументов. Функция может вычислять результат, выполнять действие вроде вывода или сочетать оба варианта.</p>
<p>Например, операция «перевести метры в сантиметры» получает длину в метрах и возвращает длину в сантиметрах. Внутри выполняется умножение на 100. Вызывающий код может пользоваться этой операцией, зная единицы измерения и допустимые значения, без повторения формулы.</p>
<p>Имя помогает читать программу, но само по себе не гарантирует корректность. У функции есть контракт: смысл аргументов, ограничения, результат и возможные побочные эффекты. Для числовых типов C++ дополнительно важны диапазон и точность.</p>
<p>Сейчас функция служит способом разложить алгоритм на понятные действия. Синтаксис, параметры и время жизни данных будут подробно разобраны в <a href="https://stepik.org/lesson/770590/step/1" rel="noopener noreferrer nofollow">модуле 7 «Функции»</a>. Он находится перед тестированием и пользовательскими типами, поэтому эта идея будет продолжаться на протяжении курса.</p>

<h2>Зачем выделять функции</h2>
<p>Функция даёт части алгоритма смысловую границу. Вычисление стоимости заказа можно отделить от чтения данных и вывода чека: у этих действий разные обязанности и причины изменения.</p>
<p>Если одна формула используется в нескольких местах, её определение в одной функции уменьшает риск исправить только одну копию. Но повторение — не обязательное условие: отдельная функция полезна и для единственного сложного действия, если её имя и контракт упрощают чтение.</p>
<p><strong>Разбор:</strong> функция расчёта получает цену и количество, возвращает стоимость и ничего не печатает. Функция вывода получает готовую стоимость. Изменение оформления чека тогда не меняет арифметику. Если функция расчёта начнёт неожиданно записывать файл, изменится и её контракт — это следует явно отразить в интерфейсе.</p>
<p>Такое разделение помогает независимо рассуждать о частях программы и проверять их. Функции не делают программу автоматически быстрой, переносимой или безошибочной: эти свойства зависят от выбранных операций, контрактов и реализации.</p>

<h2>Вызов функции: вход, работа, результат</h2>
<p>Знание веб-разработки здесь не требуется. Рассмотрим знакомый расчёт: длина 2,5 метра выражается как 250 сантиметров.</p>
<table><thead><tr><th>Часть операции</th><th>Смысл</th></tr></thead><tbody><tr><td>Имя</td><td><code>meters_to_centimeters</code> — перевод единиц.</td></tr><tr><td>Аргумент</td><td><code>2.5</code>, длина в метрах.</td></tr><tr><td>Действие</td><td>Умножение аргумента на <code>100.0</code>.</td></tr><tr><td>Результат</td><td><code>250.0</code>, длина в сантиметрах.</td></tr></tbody></table>
<p>В записи <code>meters_to_centimeters(2.5)</code> круглые скобки с аргументом обозначают вызов. Другой вызов с аргументом <code>0.8</code> использует то же определение, но даёт <code>80.0</code>. Для этих значений результат представим точно; произвольные вычисления с вещественными числами могут округляться.</p>
<p>Функция не обязана знать, откуда появилась длина: из ввода, файла или другого вычисления. Поэтому её проще использовать повторно. Позже такие функции будут объединены в заголовки и библиотеки; пока достаточно отделять смысл операции от способа получения исходных данных.</p>

<h2>Полный пример с функцией</h2>
<p>Следующая программа не требует ввода. Она продолжает разобранный перевод единиц и выводит <code>250</code>.</p><pre><code class="language-cpp">#include &lt;iostream&gt;

double meters_to_centimeters(double meters) {
    return meters * 100.0;
}

int main() {
    const double length_m = 2.5;
    const double length_cm = meters_to_centimeters(length_m);
    std::cout &lt;&lt; length_cm &lt;&lt; '\n';
}</code></pre>
<p><code>double</code> обозначает тип с плавающей точкой; <code>const</code> запрещает изменение значения через это имя. При вызове значение <code>length_m</code> передаётся параметру <code>meters</code>. Выражение после <code>return</code> вычисляется и становится результатом вызова. Затем <code>std::cout</code> выводит этот результат и перевод строки.</p>
<p><code>main</code> — главная функция обычной программы C++. <code>std::cout</code> — объект стандартного потока вывода, а <code>&lt;&lt;</code> здесь обозначает вставку данных в поток. Это разные сущности, хотя все они участвуют в одном выражении.</p>
<p>Сейчас достаточно проследить путь <strong>исходное значение → вызов → возвращённое значение → вывод</strong>. Подробные правила типов появятся в модуле 4, а параметры, возвращаемые значения и контракты — в модуле 7.</p>

<h2>Вызов функции на блок-схеме</h2>
<p>Если подробности действия описаны отдельно, основной алгоритм можно показать короче: использовать блок предопределённого процесса с именем операции, её входными данными и результатом. Для функции важно различать <strong>место вызова</strong> и <strong>описание её работы</strong>.</p>
<p>В <a href="https://stepik.org/lesson/768145/step/4" rel="noopener noreferrer nofollow">полной программе предыдущего шага</a> функция <code>meters_to_centimeters</code> переводит длину из метров в сантиметры. Её отдельная схема имеет такой смысл: получить аргумент <code>meters</code>, вычислить <code>meters × 100</code>, вернуть полученное значение. «Вернуть» здесь означает передать результат вызвавшей части программы, а не обязательно показать его на экране.</p>
<table><thead><tr><th>Место выполнения</th><th>Действие</th><th>Данные</th></tr></thead><tbody><tr><td>Основной алгоритм</td><td>Подготовить исходную длину</td><td><code>length_m = 2.5</code></td></tr><tr><td>Блок вызова</td><td>Передать значение в функцию</td><td><code>meters = 2.5</code></td></tr><tr><td>Функция</td><td>Вычислить и вернуть результат</td><td><code>2.5 × 100 = 250</code></td></tr><tr><td>Продолжение основного алгоритма</td><td>Сохранить результат и вывести его</td><td><code>length_cm = 250</code></td></tr></tbody></table>
<p>Стрелка после блока вызова означает продолжение <em>после возвращения</em> из функции. Внутренние шаги функции не нужно копировать в каждое место вызова: её имя обозначает один и тот же описанный способ обработки данных. Другой аргумент, например 0,8 метра, даст 80 сантиметров.</p>
<p>Эта схема объясняет обычный последовательный вызов. Она не изображает процессорные инструкции, стек или все возможные способы завершения функции. Такие детали понадобятся в <a href="https://stepik.org/lesson/770590/step/1" rel="noopener noreferrer nofollow">модуле 7 о собственных функциях</a>. Сейчас существенна связь: задача разбивается на понятные операции, алгоритм задаёт их порядок, программа записывает его по правилам выбранного языка.</p>
