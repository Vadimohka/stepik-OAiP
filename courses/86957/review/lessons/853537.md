<h2>shared_ptr и weak_ptr: общее владение и наблюдение</h2>
<p>Несколько частей программы могут пользоваться одним объектом, пока его удерживает один владелец: для этого достаточно ссылок или невладеющих указателей. <code>std::shared_ptr</code> нужен, когда несколько владельцев должны независимо продлевать жизнь одного динамического объекта и заранее нельзя выразить единственного владельца. Решение зависит от ответственности за время жизни, а не от числа читателей.</p>
<p>Объекты <code>shared_ptr</code>, полученные копированием или через <code>weak_ptr::lock()</code> из одной группы владения, совместно управляют ресурсом. Копия добавляет владельца; уничтожение или <code>reset()</code> освобождает соответствующую долю владения. В обычном случае <code>make_shared&lt;T&gt;</code> объект <code>T</code> уничтожается после исчезновения последнего сильного владельца.</p>
<p>Удобная модель реализации — блок управления с учётом сильных и слабых ссылок. <code>weak_ptr</code> не удерживает сам объект живым, но позволяет проверить существование группы владения. Информация для слабых ссылок должна пережить объект; конкретное размещение и устройство счётчиков — деталь реализации. Если <code>make_shared</code> использовал общую область для объекта и служебных данных, память этой области может освобождаться позже вызова деструктора <code>T</code>.</p>
<h3>Полная программа: локальный владелец, полученный из наблюдателя</h3>
<pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;memory&gt;

int main() {
    auto owner = std::make_shared&lt;int&gt;(42);
    std::weak_ptr&lt;int&gt; observer = owner;
    {
        auto second = owner;
        std::cout &lt;&lt; owner.use_count() &lt;&lt; '\n';
    }
    std::cout &lt;&lt; owner.use_count() &lt;&lt; '\n';

    auto held = observer.lock();
    if (held) {
        std::cout &lt;&lt; *held &lt;&lt; '\n';
    }
    owner.reset();
    std::cout &lt;&lt; std::boolalpha &lt;&lt; observer.expired() &lt;&lt; ' '
              &lt;&lt; static_cast&lt;bool&gt;(held) &lt;&lt; '\n';
    held.reset();
    auto result = observer.lock();
    std::cout &lt;&lt; observer.expired() &lt;&lt; ' '
              &lt;&lt; static_cast&lt;bool&gt;(result) &lt;&lt; '\n';
}
</code></pre>
<p>Вывод:</p><pre>2
1
42
false true
true false
</pre>
<p>После выхода из внутреннего блока владелец <code>second</code> исчезает и остаётся <code>owner</code>. Затем <code>lock()</code> создаёт локального сильного владельца <code>held</code>. Поэтому <code>owner.reset()</code> ещё не уничтожает <code>int</code>. После <code>held.reset()</code> сильных владельцев нет: <code>expired()</code> даёт <code>true</code>, а повторный <code>lock()</code> — пустой результат. Слабая ссылка не может воскресить уничтоженный объект.</p>
<p><code>lock()</code> атомарно выполняет проверку и получение сильного владения. Отдельная проверка <code>expired()</code> перед использованием адреса не заменяет <code>lock()</code>, если другой поток может освободить последнего владельца. При этом умный указатель не синхронизирует произвольные чтения и изменения самого <code>T</code>. Вывод <code>use_count()</code> в примере служит объяснению последовательного выполнения, а не способу определить безопасность изменения объекта в многопоточной программе.</p>
<h3>Цикл владения и цикл доступа</h3>
<p>Если A сильно владеет B, а B сильно владеет A, исчезновение внешних владельцев не обнулит счётчики: объекты продолжают удерживать друг друга. Одну из связей, которая нужна для доступа, но не должна продлевать жизнь, можно представить <code>weak_ptr</code>. Например, родитель хранит дочерние объекты через <code>shared_ptr</code>, а ребёнок наблюдает за родителем через <code>weak_ptr</code> и перед доступом вызывает <code>lock()</code>. Это решение должно соответствовать требуемым временам жизни, а не применяться к произвольной связи автоматически.</p>
<p>Нельзя создать два независимых <code>shared_ptr</code> из одного сырого адреса: у них могут оказаться разные группы владения и повторное удаление. Для общего владения копируют существующий <code>shared_ptr</code>. В <a href="https://stepik.org/lesson/853537/step/2" rel="noopener noreferrer nofollow">дополнительном разборе реализации</a> показано, почему объект и блок управления имеют разные времена жизни.</p>

<h2>Дополнительный разбор: два времени жизни в общем владении</h2>
<p>Для использования <code>std::shared_ptr</code> достаточно контракта из предыдущего текста. Этот дополнительный разбор показывает одну реализацию инварианта: объект существует при наличии сильных владельцев, а служебная информация — пока она нужна сильным или слабым ссылкам. Шаблон <code>template&lt;class T&gt;</code> позволяет использовать один алгоритм с разными типами объекта; <code>friend</code> даёт паре классов доступ к общему служебному состоянию.</p>

<p>Объект T и блок управления имеют разные времена жизни. Ниже используется простая <strong>однопоточная</strong> схема с двумя счётчиками: strong — число shared_ptr; weak — число weak_ptr плюс одна служебная слабая ссылка, пока сохраняется сильное владение или выполняется уничтожение T. Поэтому новый блок получает счётчики strong = 1, weak = 1. При переходе strong к нулю сначала уничтожается T, затем освобождается служебная слабая ссылка. Блок удаляется только при переходе weak к нулю. Эта служебная ссылка нужна, в частности, если у T есть weak_ptr на самого себя: уничтожение этого поля не должно удалить блок посреди деструктора T. В стандартной библиотеке внутреннее представление может отличаться, но слабые ссылки также должны безопасно переживать объект.</p>

<p><code>std::exchange(value, replacement)</code> из <code>&lt;utility&gt;</code> возвращает прежнее значение <code>value</code> и записывает в него <code>replacement</code>. В коде этот приём передаёт адрес и сразу обнуляет источник. Метод <code>swap</code> меняет адреса блоков управления местами, не создавая нового объекта <code>T</code>.</p>
<p>При копировании shared_ptr увеличивается strong, при копировании weak_ptr — weak. Перемещение передаёт ссылку на блок, не меняя счётчик. Присваивание сначала получает новое владение, затем освобождает прежнее; в примере это обеспечивается передачей параметра по значению и swap. Уничтожение weak_ptr не удаляет T, но может удалить уже ненужный блок управления.</p>

<p>lock() при strong == 0 возвращает пустой shared_ptr. Пока strong больше нуля, он увеличивает счётчик и возвращает нового владельца. В однопоточной версии между этими действиями нет другого потока. Для настоящей многопоточной реализации нужна атомарная операция получения сильной ссылки; простая замена двух счётчиков на atomic сама по себе не делает весь алгоритм правильным. В прикладном коде используйте std::shared_ptr и std::weak_ptr.</p>

<p>Первый фрагмент — определения классов. Он компилируется вместе со вторым фрагментом, содержащим <code>main</code>; в указанном порядке они образуют полную программу C++17/20.</p>
<pre><code class="language-cpp">#include &lt;cstddef&gt;
#include &lt;utility&gt;

namespace teaching {

template&lt;class T&gt;
struct control_block {
    T* value;
    std::size_t strong;
    std::size_t weak;
};

template&lt;class T&gt; class weak_ptr;

template&lt;class T&gt;
class shared_ptr {
    control_block&lt;T&gt;* control_ = nullptr;
    struct counted_t {};
    shared_ptr(control_block&lt;T&gt;* p, counted_t) noexcept : control_(p) {}
    friend class weak_ptr&lt;T&gt;;

    void release() noexcept {
        if (control_ &amp;&amp; --control_-&gt;strong == 0) {
            T* value = std::exchange(control_-&gt;value, nullptr);
            delete value; // служебная слабая ссылка удерживает блок
            if (--control_-&gt;weak == 0) delete control_;
        }
        control_ = nullptr;
    }

public:
    shared_ptr() noexcept = default;

    explicit shared_ptr(T* p) {
        if (!p) return;
        try {
            control_ = new control_block&lt;T&gt;{p, 1, 1};
        } catch (...) {
            delete p;
            throw;
        }
    }

    shared_ptr(const shared_ptr&amp; other) noexcept : control_(other.control_) {
        if (control_) ++control_-&gt;strong;
    }
    shared_ptr(shared_ptr&amp;&amp; other) noexcept
        : control_(std::exchange(other.control_, nullptr)) {}
    shared_ptr&amp; operator=(shared_ptr other) noexcept {
        swap(other);
        return *this;
    }
    ~shared_ptr() { release(); }

    void swap(shared_ptr&amp; other) noexcept { std::swap(control_, other.control_); }
    void reset() noexcept { shared_ptr{}.swap(*this); }
    std::size_t use_count() const noexcept { return control_ ? control_-&gt;strong : 0; }
    T* get() const noexcept { return control_ ? control_-&gt;value : nullptr; }
    explicit operator bool() const noexcept { return get() != nullptr; }
    T&amp; operator*() const { return *get(); } // только для непустого указателя
    T* operator-&gt;() const noexcept { return get(); }
};

template&lt;class T&gt;
class weak_ptr {
    control_block&lt;T&gt;* control_ = nullptr;

    void release() noexcept {
        if (control_ &amp;&amp; --control_-&gt;weak == 0) {
            delete control_;
        }
        control_ = nullptr;
    }

public:
    weak_ptr() noexcept = default;
    weak_ptr(const shared_ptr&lt;T&gt;&amp; owner) noexcept : control_(owner.control_) {
        if (control_) ++control_-&gt;weak;
    }
    weak_ptr(const weak_ptr&amp; other) noexcept : control_(other.control_) {
        if (control_) ++control_-&gt;weak;
    }
    weak_ptr(weak_ptr&amp;&amp; other) noexcept
        : control_(std::exchange(other.control_, nullptr)) {}
    weak_ptr&amp; operator=(weak_ptr other) noexcept {
        swap(other);
        return *this;
    }
    ~weak_ptr() { release(); }

    void swap(weak_ptr&amp; other) noexcept { std::swap(control_, other.control_); }
    void reset() noexcept { weak_ptr{}.swap(*this); }
    std::size_t use_count() const noexcept { return control_ ? control_-&gt;strong : 0; }
    bool expired() const noexcept { return use_count() == 0; }

    shared_ptr&lt;T&gt; lock() const noexcept {
        if (!control_ || control_-&gt;strong == 0) return {};
        ++control_-&gt;strong;
        return shared_ptr&lt;T&gt;(control_, typename shared_ptr&lt;T&gt;::counted_t{});
    }

    bool same_owner(const weak_ptr&amp; other) const noexcept {
        return control_ == other.control_;
    }
};

} // namespace teaching</code></pre>

<p>Это учебный вариант для одиночного объекта, переданного из <code>new T</code>. Его деструктор должен быть доступен и не выбрасывать исключений; счётчики предполагаются представимыми в <code>std::size_t</code>. В нём нет пользовательских deleter, массивов, aliasing-конструкторов и межтиповых преобразований стандартной библиотеки. Один сырой указатель нельзя передавать в два независимых shared_ptr. Функция same_owner сравнивает принадлежность к блоку управления; сравнение адресов объектов и сравнение владения — разные операции.</p>

<p>Пример после определений классов выше:</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;

int main() {
    teaching::weak_ptr&lt;int&gt; observer;
    {
        teaching::shared_ptr&lt;int&gt; owner(new int(42));
        observer = owner;
        auto second_owner = observer.lock();
        std::cout &lt;&lt; owner.use_count() &lt;&lt; '\n'; // 2
    } // int уничтожен; observer ещё удерживает блок управления
    auto result = observer.lock();
    std::cout &lt;&lt; std::boolalpha &lt;&lt; observer.expired() &lt;&lt; '\n'; // true
    std::cout &lt;&lt; static_cast&lt;bool&gt;(result) &lt;&lt; '\n'; // false
} // последний weak_ptr освобождает блок управления</code></pre>
<p>Ожидаемый вывод объединённой программы:</p><pre>2
true
false
</pre>
<p>Внутри блока существуют <code>owner</code> и <code>second_owner</code>. При выходе оба уничтожаются; переход <code>strong</code> к нулю уничтожает <code>int</code>. <code>observer</code> ещё удерживает служебные данные, поэтому вызов <code>lock()</code> безопасно обнаруживает истечение. После уничтожения последней слабой ссылки удаляется и блок управления.</p>
<p>Если выделение блока управления при создании владельца не удалось, конструктор удаляет уже переданный объект и повторно выбрасывает исключение. Это часть защиты от утечки в показанной модели. Учебные классы не являются реализацией всех гарантий стандартных умных указателей; их однопоточный <code>lock()</code> нельзя переносить в конкурентный код.</p>
<p>Следующее применение явного владения — <a href="https://stepik.org/lesson/973837/step/1" rel="noopener noreferrer nofollow">структуры данных и их интерфейсы</a>: внутренние связи структуры должны сохранять время жизни узлов и её инвариант.</p>
