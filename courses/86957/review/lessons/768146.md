<h2>Стандартная библиотека C++</h2>
<p><strong>Стандартная библиотека</strong> предоставляет согласованный набор типов, функций и других средств: ввод и вывод, строки, контейнеры, алгоритмы, управление ресурсами. Их назначение и требования описаны вместе с языком. Библиотека позволяет использовать уже определённые операции, сохраняя внимание к задаче программы.</p>
<p>Например, в знакомой программе <code>std::cout</code> обозначает стандартный поток вывода. Заголовок <code>&lt;iostream&gt;</code> предоставляет необходимые объявления. Объявление сообщает компилятору, как обращаться к средству; исполняемая реализация и её подключение относятся также к библиотеке и инструментам сборки. Поэтому библиотека — более широкое понятие, чем список заголовочных файлов.</p>
<p>У каждого средства есть <strong>контракт</strong>: допустимые аргументы, результат, ограничения и поведение при ошибке. Включение заголовка не доказывает, что вызов с любыми данными правильный. Например, операция чтения целого числа может завершиться неудачно, а программе потребуется проверить состояние потока.</p>
<p>Большинство имён стандартной библиотеки находится в пространстве имён <code>std</code>. Запись <code>std::cout</code> явно указывает, где искать имя. Некоторые средства представлены макросами и имеют другие правила; поэтому «вся библиотека без исключения находится в std» было бы неточно.</p>
<p>Не нужно заучивать весь состав библиотеки заранее. В первых программах достаточно вывода и проверяемого ввода; строки появятся в модуле 9, файлы — в модуле 11, владельцы ресурсов — в модуле 15. <a href="https://stepik.org/lesson/768146/step/2" rel="noopener noreferrer nofollow">Сначала разберём пространство имён</a>, а затем <a href="https://stepik.org/lesson/768146/step/4" rel="noopener noreferrer nofollow">свяжем нужные средства с заголовками</a>.</p>

<h2>Пространство имён и запись std::</h2>
<p>Разные части программы могут выбирать одинаковые короткие имена. <strong>Пространство имён</strong> помогает объединять связанные объявления и различать такие имена. Оператор разрешения области <code>::</code> уточняет, где искать имя.</p>
<p>Ниже <strong>полная программа C++17/C++20</strong>. В ней две независимые величины названы <code>value</code>, но находятся в разных пространствах имён.</p>
<pre><code class="language-cpp">#include &lt;iostream&gt;

namespace first {
    const int value = 10;
}

namespace second {
    const int value = 20;
}

int main() {
    std::cout &lt;&lt; first::value &lt;&lt; ' ' &lt;&lt; second::value &lt;&lt; '\n';
}
</code></pre>
<p>Вывод:</p>
<pre><code class="language-text">10 20
</code></pre>
<p>В записи <code>first::value</code> используется значение 10, а в <code>second::value</code> — 20. Точно так же <code>std::cout</code> указывает на имя стандартной библиотеки. Пространство имён не запускает код, не создаёт отдельную программу и не является папкой файловой системы.</p>
<p>Можно ввести выбранное имя в текущую область с помощью <code>using std::cout;</code>, а затем писать <code>cout</code>. Это <strong>объявление using</strong>. Директива <code>using namespace std;</code> влияет на поиск сразу множества имён и имеет более широкий эффект. Ни одна из этих записей не переносит определение <code>main</code> в <code>std</code> и не подключает заголовки.</p>
<p>В небольших примерах курса будем предпочитать явные записи <code>std::...</code>: по ним видно происхождение библиотечного имени. <a href="https://stepik.org/lesson/768146/step/5" rel="noopener noreferrer nofollow">Отдельный шаг разбирает конфликт имён и границы using</a>. Позже пространство имён также поможет организовать собственную многофайловую библиотеку в модуле 7.</p>

<h2>Средства библиотеки C в C++</h2>
<p>Часть стандартной библиотеки C++ основана на библиотеке C. Для неё предусмотрены заголовки вида <code>&lt;cstdlib&gt;</code>, <code>&lt;cstdio&gt;</code>, <code>&lt;ctime&gt;</code>. Есть и совместимые заголовки с окончаниями <code>.h</code>, например <code>&lt;stdlib.h&gt;</code>. Это разные предусмотренные формы доступа, а не библиотеки, между которыми компилятор выбирает «более приоритетную».</p>
<p>Для программы C++ удобно использовать заголовок вида <code>&lt;c...&gt;</code> и нужное имя из <code>std</code>. Например, следующая <strong>полная программа C++17/C++20</strong> получает модуль целого числа:</p>
<pre><code class="language-cpp">#include &lt;cstdlib&gt;
#include &lt;iostream&gt;

int main() {
    const int value = -7;
    std::cout &lt;&lt; std::abs(value) &lt;&lt; '\n';
}
</code></pre>
<p>Вывод равен <code>7</code> с переводом строки. Заголовок <code>&lt;cstdlib&gt;</code> нужен для целочисленной перегрузки <code>std::abs</code>, а <code>&lt;iostream&gt;</code> — для <code>std::cout</code>. Это две используемые возможности, поэтому включение обоих заголовков естественно.</p>
<p>Контракт операции по-прежнему важен. Результат модуля должен быть представим в соответствующем целочисленном типе. Для −7 это выполнено; для самого малого значения знакового типа это может быть неверно. Пример не объявляет <code>std::abs</code> безопасным способом обработки любого возможного входа без проверки диапазона.</p>
<p>Аналогично, <code>std::clock</code> объявлена в <code>&lt;ctime&gt;</code>, а средства <code>std::printf</code> и <code>std::scanf</code> — в <code>&lt;cstdio&gt;</code>. Использование конкретной функции определяется её именем, доступными объявлениями и правилами вызова. Подсказка IDE о неиспользуемом заголовке означает отсутствие нужды в нём в данном исходнике по анализу инструмента; она не свидетельствует об «отклонении библиотеки».</p>
<p><a href="https://stepik.org/lesson/768143/step/5" rel="noopener noreferrer nofollow">Ввод-вывод C будет разобран как отдельный интерфейс совместимости</a>; для первых программ основным средством останутся потоки C++.</p>

<h2>Почему using namespace требует внимания</h2>
<p><code>using namespace</code> — допустимое средство C++, которое влияет на поиск имён. Оно не копирует все сущности в текущую область. Трудность возникает, когда несколько доступных пространств предлагают подходящее одинаковое имя.</p>
<p>В <a href="https://stepik.org/lesson/768146/step/2" rel="noopener noreferrer nofollow">полной программе с пространствами first и second</a> уже существуют <code>first::value</code> и <code>second::value</code>. Если заменить тело <code>main</code> следующим <strong>намеренно ошибочным фрагментом</strong>, неуточнённое имя <code>value</code> станет неоднозначным:</p>
<pre><code class="language-cpp">using namespace first;
using namespace second;
std::cout &lt;&lt; value &lt;&lt; '\n'; // какое value?
</code></pre>
<p>Обе директивы действуют в этой области. Компилятор не выбирает «первое» или «более важное» пространство имён: такой поиск не даёт единственного подходящего имени, поэтому фрагмент не компилируется.</p>
<p>Законченный разбор исправления: запись <code>std::cout &lt;&lt; first::value &lt;&lt; '\n';</code> явно выбирает 10; запись с <code>second::value</code> выбирает 20. В исходной полной программе использованы обе квалифицированные записи, поэтому её вывод остаётся <code>10 20</code>.</p>
<p><code>using std::cout;</code> вводит выбранное имя, а не все имена пространства. Локальное применение внутри небольшой функции ограничивает область влияния. Директива <code>using namespace std;</code> в общем заголовке влияет и на код, который включит этот заголовок, поэтому для учебных библиотек будем избегать её в таком месте. Это рекомендация по понятности и устойчивости к изменениям, а не синтаксический запрет языка.</p>
<p>Отсутствие конфликта в сегодняшней маленькой программе не гарантирует его отсутствия после добавления новых объявлений. Явный префикс <code>std::</code> показывает происхождение библиотечного средства, а именование собственных операций по назначению уменьшает случайные столкновения.</p>
