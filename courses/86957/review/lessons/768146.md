<h3>Стандартная библиотека языка C++</h3>

<p>В языке программирования C++ термин <strong>Стандартная Библиотека</strong> означает коллекцию <a href="https://ru.wikipedia.org/wiki/%D0%9A%D0%BB%D0%B0%D1%81%D1%81_(%D0%BF%D1%80%D0%BE%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5)" rel="noopener noreferrer nofollow" title="Класс (программирование)">классов</a> и <a href="https://ru.wikipedia.org/wiki/%D0%A4%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D1%8F_(%D0%BF%D1%80%D0%BE%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5)" rel="noopener noreferrer nofollow" title="Функция (программирование)">функций</a>. Стандартная Библиотека поддерживает несколько основных контейнеров, функций для работы с этими контейнерами, объектов-функции, основных типов строк и потоков (включая интерактивный и файловый ввод-вывод), поддержку некоторых языковых особенностей, и часто используемые функции для выполнения таких задач, как, например, нахождение квадратного корня числа. Стандартная Библиотека языка C++ также включает в себя спецификации стандартной библиотеки языка Си. Функциональные особенности Стандартной Библиотеки объявляются внутри пространства имен <em>std</em>.</p>

<p>Стандартная библиотека C++ содержит последние расширения C++ стандарта ANSI (включая библиотеку стандартных шаблонов и новую библиотеку iostream). Она представляет собой набор файлов заголовков. В новых файлах заголовков отсутствует расширение H.</p>

<h3>Пространства имён</h3>

<p>Пространство имен — это декларативная область, в рамках которой определяются различные идентификаторы (имена типов, функций, переменных, и т. д.). Пространства имен используются для организации кода в виде логических групп и с целью избежания конфликтов имен, которые могут возникнуть, особенно в таких случаях, когда база кода включает несколько библиотек. Все идентификаторы в пределах пространства имен доступны друг другу без уточнения. Идентификаторы за пределами пространства имен могут получить доступ к членам с помощью полного имени для каждого идентификатора, например <code>std::vector&lt;std::string&gt; vec;</code>, с помощью <a href="https://docs.microsoft.com/ru-ru/cpp/cpp/using-declaration?view=msvc-160" rel="noopener noreferrer nofollow">объявления</a> для одного идентификатора (<code>using std::string</code>) или <a href="https://docs.microsoft.com/ru-ru/cpp/cpp/namespaces-cpp?view=msvc-160#using_directives" rel="noopener noreferrer nofollow">директивы using</a> для всех идентификаторов в пространстве имен (<code>using namespace std;</code>). Код в файлах заголовков всегда должен содержать полное имя в пространстве имен.</p>

<p>Пример кода в котором перед функцией main было объявление, что весь код находится в пространстве имён <em>std</em>.</p>

<pre><code class="language-cpp">....
using namespace std;
....
int main()
{
....
vector&lt;string&gt; vec;
....
}</code></pre>

<h3>Почему 'using namespace std;' - плохая практика в программировании на С++?</h3>

<p>Всё, что объявлено внутри пространства имен, принадлежит только этому пространству имен (а не глобальному). Используя using мы вытаскиваем сущности какого-либо пространства имен в глобальный контекст.</p>

<p>Допустим, мы используем две библиотеки под названием Foo и Bar и написали в начале файла что-то типа:</p>

<pre><code class="language-cpp">using namespace foo;
using namespace bar;</code></pre>

<p>Все работает нормально, и мы можем без проблем вызвать Fee() из Foo и Bee() из Bar. Но однажды при обновлении библиотеки Foo до новой версии Foo 2.0, которая теперь еще имеет в себе функцию Bee() у нас возникает конфликт: и Foo 2.0, и Bar импортируют Bee() в наше глобальное пространство имен. В лучшем случае это вызовет ошибку на этапе компиляции, и исправление этого потребует усилий и времени.</p>

<h4>Но это лучшее, что могло возникнуть, что же с худшим вариантом?</h4>

<p>В библиотеку Foo 2.0 могла быть добавлена функция foo::Bee(), про которую компилятор по ряду причин посчитает, что она однозначно лучше подходит для некоторых ваших вызовов Bee(), чем bar::Bee(), вызывавшаяся в нашем коде на протяжении многих лет. Тогда наш код всё равно скомпилируется, но будет вызывать неправильную функцию, что почти всегда приводит к непредвиденным последствиям.</p>

<p>Когда мы говорим про Стандартную библиотеку С++ нужно учитывать, что пространство имен std:: имеет множество идентификаторов, многие из которых являются очень распространенными (list, sort, string, iterator, swap), которые, скорее всего, могут появиться и в другом коде, либо наоборот, в следующей версии стандарта C++ в std добавят что-то, что совпадет с каким-то из идентификаторов в вашем существующем коде.</p>

<p><strong>Решение данной проблемы простое</strong>: необходимо указывать в коде метод с его пространством имен, а именно, foo::Fee() и bar::Bee(), при таких действиях добавление foo:Bee() не будет проблемой проблемой.</p>
