<h3>Композиция и открытое наследование</h3>

<p>Композиция выражает связь «содержит»: автомобиль содержит двигатель. Открытое наследование выражает отношение подтипа: объект производного класса можно использовать через доступный и однозначный базовый интерфейс. Для хорошего проекта это должно сохранять смысл и контракты операций базы.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;string&gt;

class Device {
    std::string name_;
public:
    explicit Device(const std::string&amp; name) : name_(name) {}
    const std::string&amp; name() const { return name_; }
};

class Printer : public Device {
    int pages_per_minute_;
public:
    Printer(const std::string&amp; name, int speed)
        : Device(name), pages_per_minute_(speed) {}
    int speed() const { return pages_per_minute_; }
};

void print_name(const Device&amp; device) {
    std::cout &lt;&lt; device.name() &lt;&lt; '\n';
}

int main() {
    const Printer printer{"Office", 20};
    print_name(printer);
    std::cout &lt;&lt; printer.speed() &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">Office
20</code></pre><p>У <code>Printer</code> есть подобъект <code>Device</code> и собственное поле скорости. Публичное наследование позволяет передать принтер в функцию с параметром <code>const Device&amp;</code>. Ссылка даёт доступ к базовой части без копирования всего объекта. Закрытое <code>name_</code> не становится доступным производному классу по имени; он пользуется открытым методом <code>name()</code>.</p><p>Для скорости здесь допустим любой <code>int</code>: пример показывает отношение типов, а не полный физический контракт устройства. Если предметная область требует положительное значение, это ограничение должен установить конструктор и сохранять операции. Полезность наследования определяется такой договорённостью, а не возможностью механически не переписывать поля.</p><p>При <code>public</code>-наследовании открытые члены базы остаются открытым интерфейсом, защищённые доступны с правилами <code>protected</code>, закрытые остаются закрытыми для производного класса. <code>private</code>- и <code>protected</code>-наследование меняют доступ к базовому интерфейсу; это иные проектные решения. Модификатор относится к каждой базе отдельно, поэтому его удобно писать явно.</p><p>Объекты программы локальны и уничтожаются как <code>Printer</code>; удаления через <code>Device*</code> здесь нет. Стандартные контейнеры не образуют общую иерархию наследования только из-за сходства некоторых операций.</p>

<h3>Виртуальная база в ромбовидной иерархии</h3>

<p>Если две промежуточные базы сами наследуют один тип, в конечном объекте без специальных указаний будет два его подобъекта. При виртуальном наследовании соответствующие пути могут пользоваться одним общим подобъектом виртуальной базы.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

struct Identity {
    int id;
    explicit Identity(int value) : id(value) {}
};

struct Scanner : virtual public Identity {
    Scanner() : Identity(1) {}
};

struct Printer : virtual public Identity {
    Printer() : Identity(2) {}
};

struct Combined : public Scanner, public Printer {
    explicit Combined(int value) : Identity(value), Scanner(), Printer() {}
};

int main() {
    Combined device{42};
    Scanner&amp; scanner = device;
    Printer&amp; printer = device;
    Identity* first = &amp;scanner;
    Identity* second = &amp;printer;
    std::cout &lt;&lt; device.id &lt;&lt; '\n';
    std::cout &lt;&lt; std::boolalpha &lt;&lt; (first == second) &lt;&lt; '\n';
    Scanner standalone;
    std::cout &lt;&lt; standalone.id &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">42
true
1</code></pre><p>Оба указателя получены через разные ветви одного <code>Combined</code>, но обозначают общий <code>Identity</code>, поэтому сравнение даёт <code>true</code>. Этот подобъект инициализирует конструктор наиболее производного объекта: здесь <code>Combined</code> передаёт 42. Записи <code>Identity(1)</code> и <code>Identity(2)</code> у промежуточных баз при создании <code>Combined</code> не выбирают два разных значения.</p><p>Для самостоятельного объекта <code>Scanner</code> наиболее производный тип — сам <code>Scanner</code>, поэтому его база получает 1. Если удалить <code>virtual</code> в обеих ветвях, у конечного объекта будут два <code>Identity</code>; без выбора ветви обращение <code>device.id</code> станет неоднозначным, а конструктор <code>Combined</code> уже не сможет инициализировать косвенную невиртуальную базу напрямую.</p><p>Виртуальная база и виртуальная функция — разные механизмы. Первый регулирует число и устройство базовых подобъектов, второй — выбор переопределённой функции. Конкретные скрытые указатели, таблицы и смещения относятся к ABI; стандарт не требует определённого способа реализации.</p><p>Ромбовидное наследование нужно только когда общий подобъект соответствует модели. Само желание повторно использовать несколько полей ещё не оправдывает такую иерархию: композиция часто даёт более прямое отношение времени жизни и владения.</p>

<h3>Порядок создания и уничтожения частей объекта</h3>

<p>Производный объект строится из баз и полей. Порядок задаёт язык: сначала виртуальные базы по установленному обходу иерархии, затем непосредственные невиртуальные базы в порядке списка наследования, затем поля в порядке объявления и, наконец, тело конструктора. Перестановка записей после двоеточия этот порядок не меняет.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;stdexcept&gt;

struct BaseA {
    BaseA() { std::cout &lt;&lt; "BaseA\n"; }
    ~BaseA() { std::cout &lt;&lt; "~BaseA\n"; }
};
struct BaseB {
    BaseB() { std::cout &lt;&lt; "BaseB\n"; }
    ~BaseB() { std::cout &lt;&lt; "~BaseB\n"; }
};
struct Member {
    Member() { std::cout &lt;&lt; "Member\n"; }
    ~Member() { std::cout &lt;&lt; "~Member\n"; }

class Derived : public BaseA, public BaseB {
    Member member_;

int main() {

    try {
        Derived incomplete{true};
    } catch (const std::runtime_error&amp;) {
        std::cout &lt;&lt; "caught\n";
    }
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">BaseA

При выходе сначала выполняется тело деструктора <code>Derived</code>, затем уничтожается <code>member_</code>, потом базы <code>BaseB</code> и <code>BaseA</code>. <h3>Базовая ссылка, динамический тип и срезка</h3>

<p>Ссылка или указатель на базу может обозначать базовую часть производного объекта. Это не создаёт копию и не меняет полный тип объекта. Для доступной однозначной базы преобразование вверх выполняется неявно.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

class Base {
public:
    virtual const char* kind() const { return "Base"; }
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    const char* kind() const override { return "Derived"; }
};

int main() {
    Derived object;
    const Base&amp; view = object;
    Base copy = object;
    std::cout &lt;&lt; view.kind() &lt;&lt; ' ' &lt;&lt; copy.kind() &lt;&lt; '\n';
    Base* pointer = &amp;object;
    std::cout &lt;&lt; std::boolalpha &lt;&lt; (dynamic_cast&lt;Derived*&gt;(pointer) == &amp;object) &lt;&lt; '\n';
    Base plain;
    Base* plain_pointer = &amp;plain;
    std::cout &lt;&lt; (dynamic_cast&lt;Derived*&gt;(plain_pointer) == nullptr) &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">Derived Base
true
true</code></pre><p>У выражения <code>view</code> базовый статический тип, но ссылка обозначает часть исходного <code>Derived</code>. Виртуальный вызов выбирает его переопределение и выводит <code>Derived</code>. Объявление <code>Base copy = object</code> создаёт самостоятельный объект только базового типа: производная часть не копируется. Это называют срезкой; <code>copy.kind()</code> выводит <code>Base</code>.</p><p>Обратное преобразование требует знания реального типа. У полиморфной базы, то есть имеющей хотя бы одну виртуальную функцию, <code>dynamic_cast</code> проверяет подходящий тип во время выполнения. В показанном случае он возвращает адрес исходного <code>Derived</code>, а для самостоятельного <code>Base</code> — <code>nullptr</code>. Вариант с ссылкой при неудаче бросает <code>std::bad_cast</code>.</p><p><code>static_cast</code> не является такой проверкой. Обратное приведение к подходящему производному типу допустимо только при выполнении его условий; слепое приведение не создаёт отсутствующую производную часть. Подробные границы разобраны в <a href="https://stepik.org/lesson/977027/step/3" rel="noopener noreferrer nofollow">отдельной теме dynamic_cast</a>.</p><p>Адрес базового подобъекта может отличаться от адреса всего объекта: необходимое изменение адреса выполняет преобразование языка. Нельзя обходить массив производных объектов арифметикой <code>Base*</code> как массив баз. Все указатели здесь невладеющие и указывают на локальные объекты; их не удаляют. Виртуальный деструктор задаёт корректный интерфейс на случай обычного удаления через <code>Base*</code>.</p>

<h3>Абстрактный интерфейс и виртуальное уничтожение</h3>

<p>Абстрактный класс задаёт интерфейс, для которого не все операции имеют конкретную реализацию. Чисто виртуальная функция объявляется с <code>= 0</code>. Самостоятельный объект абстрактного типа создать нельзя, но базовый подобъект может входить в конкретный производный объект.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;array&gt;
#include &lt;iostream&gt;
#include &lt;stdexcept&gt;

class Shape {
public:
    virtual long long area() const = 0;
    virtual ~Shape() = default;
};

class Rectangle : public Shape {
    long long width_;
    long long height_;
public:
    Rectangle(long long width, long long height) : width_(width), height_(height) {
        if (width &lt; 0 || width &gt; 1'000'000 || height &lt; 0 || height &gt; 1'000'000) {
            throw std::invalid_argument("rectangle");
        }
    }
    long long area() const override { return width_ * height_; }
};

class UnitSquare : public Shape {
public:
    long long area() const override { return 1; }
};

int main() {
    const Rectangle rectangle{3, 4};
    const UnitSquare square;
    std::array&lt;const Shape*, 2&gt; shapes{{&amp;rectangle, &amp;square}};
    for (const Shape* shape : shapes) {
        std::cout &lt;&lt; shape-&gt;area() &lt;&lt; '\n';
    }
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">12
1</code></pre><p>Один цикл работает через <code>const Shape*</code>, а виртуальный вызов выбирает <code>Rectangle::area</code> или <code>UnitSquare::area</code>. <code>override</code> требует, чтобы метод действительно переопределял виртуальную функцию базы: ошибка в параметрах или конечном <code>const</code> будет обнаружена компилятором. Стороны прямоугольника ограничены конструктором, поэтому площадь неотрицательна и помещается в <code>long long</code>.</p><p>Чтобы класс стал конкретным, для каждой чисто виртуальной функции требуется окончательное переопределение, которое больше не является чистым. При этом тело подходящей функции вполне может быть пустым, если это соответствует её контракту. Промежуточный производный класс сам может оставаться абстрактным.</p><p>Если объект будет обычно удаляться через указатель на базу, у такой базы должен быть доступный виртуальный деструктор. Чисто виртуальная <code>area</code> сама по себе не делает деструктор виртуальным, поэтому он записан отдельно. В программе объекты локальные, а массив хранит только доступ к ним; владение здесь не передаётся. В <a href="https://stepik.org/lesson/853536/step/1" rel="noopener noreferrer nofollow">модуле умных указателей</a> появится владелец динамического объекта с тем же правилом для базового интерфейса.</p><p>Абстрактный интерфейс полезен, когда разные реализации должны выполнять один контракт. Он не обязателен для каждой структуры данных: стандартные <code>vector</code>, <code>deque</code>, <code>set</code> и <code>map</code> не обязаны наследовать общий класс контейнера. Связь абстрактной операции и конкретной реализации продолжит <a href="https://stepik.org/lesson/973837/step/1" rel="noopener noreferrer nofollow">модуль структур данных</a>.</p>
