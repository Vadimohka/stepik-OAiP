<h2>C-строка: массив символов с признаком конца</h2>
<p><strong>C-строка</strong> — последовательность символов, завершённая нулевым символом <code>'\0'</code>. Такой способ представления пришёл из C и используется также в интерфейсах C++. Сам тип <code>char*</code> не сообщает ни длину, ни размер буфера, ни наличие терминатора: эти условия должен обеспечивать код, передающий указатель.</p>
<p>Терминатор <code>'\0'</code> имеет числовое значение ноль. Он отличается от символа цифры <code>'0'</code>. Время жизни и границы массива продолжают действовать: поиск конца должен встретить ноль раньше выхода за доступную память.</p>
<p><strong>Полная программа C++17/C++20.</strong></p>
<pre><code class="language-cpp">#include &lt;cstring&gt;
#include &lt;iostream&gt;

int main() {
    char word[8] = "cat";
    const char data[] = {'A', '\0', 'B', '\0'};
    std::cout &lt;&lt; std::strlen(word) &lt;&lt; ' ' &lt;&lt; sizeof word &lt;&lt; '\n';
    std::cout &lt;&lt; std::strlen(data) &lt;&lt; ' ' &lt;&lt; sizeof data &lt;&lt; '\n';
}
</code></pre>
<p>Первая строка вывода — <code>3 8</code>: длина текста равна трём, а массив содержит восемь элементов <code>char</code>. После букв при инициализации помещается терминатор; остальные элементы тоже становятся нулевыми. <code>std::strlen</code> считает символы до первого нуля, не включая его. <code>sizeof word</code> здесь даёт размер всего массива в байтах C++, а <code>sizeof(char)</code> всегда равен 1.</p>
<p>Вторая строка — <code>1 4</code>. Массив <code>data</code> содержит четыре элемента, но для C-строковой функции текст заканчивается сразу после <code>A</code>. Наличие последующей буквы <code>B</code> не меняет результат <code>strlen</code>.</p>
<table><thead><tr><th>Запись</th><th>Смысл</th></tr></thead><tbody><tr><td><code>char text[] = "cat";</code></td><td>Изменяемый массив из четырёх элементов: три буквы и терминатор.</td></tr><tr><td><code>const char* text = "cat";</code></td><td>Указатель на строковый литерал. Литерал нельзя изменять; указатель не является отдельной копией букв.</td></tr><tr><td><code>char text[3] = {'c', 'a', 't'};</code></td><td>Массив из трёх символов без нулевого терминатора. Это не C-строка; передавать его в strlen или строковый вывод нельзя.</td></tr><tr><td><code>char text[1] = {'\0'};</code></td><td>Корректная пустая C-строка. Для терминатора всё равно нужен один элемент.</td></tr></tbody></table>
<p>В C++ определение <code>char text[3] = "cat";</code> некорректно: массив слишком мал для литерала вместе с завершающим нулём. У языка C в этом частном случае есть другое правило; переносить его в C++ нельзя.</p>
<p>Для C-строки длины <code>n</code> требуется как минимум <code>n + 1</code> доступных элементов. Перед записью нового текста проверяется именно ёмкость буфера, включая место для нуля. <a href="https://stepik.org/lesson/770588/step/2" rel="noopener noreferrer nofollow">Следующий шаг</a> разбирает контракты библиотечных функций, а <a href="https://stepik.org/lesson/770589/step/1" rel="noopener noreferrer nofollow"><code>std::string</code></a> хранит размер и управляет памятью внутри своего объекта.</p>

<h2>Операции с C-строками: контракт важнее имени функции</h2>
<p>Заголовок C++ <code>&lt;cstring&gt;</code> предоставляет функции семейства C-строк в пространстве имён <code>std</code>. В программе C используют <code>&lt;string.h&gt;</code> и имена без <code>std::</code>. Ни одна из этих форм не передаёт размер буфера автоматически.</p>
<table><thead><tr><th>Операция C++</th><th>Что обязательно обеспечить</th></tr></thead><tbody><tr><td><code>std::strlen(text)</code></td><td>Доступная C-строка с терминатором. Результат не включает ноль. Указатель без терминатора не задаёт корректного аргумента.</td></tr><tr><td><code>std::strcpy(dst, src)</code></td><td>Корректная исходная C-строка, неперекрывающиеся области, доступное место под все символы и ноль. Копирование не знает ёмкости dst.</td></tr><tr><td><code>std::strcat(dst, src)</code></td><td>Обе области изначально задают C-строки; назначения хватает для прежней длины, добавленного текста и терминатора; области не перекрываются.</td></tr><tr><td><code>std::strcmp(a, b)</code></td><td>Обе строки корректны. Результат меньше нуля, равен нулю или больше нуля; обещания вернуть ровно −1 или 1 нет.</td></tr><tr><td><code>std::strchr(text, ch)</code></td><td>Корректная строка. Возвращается указатель на первое совпадение либо нулевой указатель; до разыменования нужен разбор этого исхода.</td></tr></tbody></table>
<h3>Параметр количества не всегда означает ёмкость</h3>
<p><code>std::strncpy(dst, src, n)</code> записывает ровно <code>n</code> элементов: копирует до первого нуля, затем при необходимости дополняет нулями. Если в первых <code>n</code> символах источника нуля нет, результат <strong>не получает терминатор</strong>. Для назначения всё равно нужны <code>n</code> доступных элементов; исходная область должна быть доступна до нуля либо до границы копирования. Области не должны перекрываться.</p>
<p>В <code>std::strncat(dst, src, n)</code> число <code>n</code> ограничивает добавляемые символы источника, а не полный размер назначения. Функция добавляет ещё и завершающий ноль. Например, строка <code>"ab"</code> длины 2 и три добавляемых символа требуют как минимум 6 элементов назначения. Поэтому ни <code>strncpy</code>, ни <code>strncat</code> не являются автоматической защитой от неверных размеров.</p>
<p><strong>Фрагмент внутри функции C++; требуется &lt;cstring&gt;. Все размеры здесь известны.</strong></p>
<pre><code class="language-cpp">char text[8] = "ab";
std::strcat(text, "cd"); // теперь "abcd", занято 5 элементов вместе с нулём
const int order = std::strcmp("ab", "abc"); // order &lt; 0
</code></pre>
<p>Оба обращения корректны: <code>abcd</code> вместе с нулём помещается в восемь элементов, а при сравнении первая строка является собственным префиксом второй. Сравнение выполняется по элементам, а не по правилам словаря естественного языка.</p>
<h3>Символ и число — разные преобразования</h3>
<p>Функции <code>std::isdigit</code>, <code>std::isspace</code>, <code>std::isalpha</code>, <code>std::tolower</code> находятся в <code>&lt;cctype&gt;</code>. Их аргумент должен быть значением <code>unsigned char</code>, преобразованным в <code>int</code>, либо специальным значением <code>EOF</code>. Обычный <code>char</code> может быть отрицательным, поэтому для символа из строки используют приведение:</p>
<p><strong>Фрагмент внутри функции C++; требуется &lt;cctype&gt;.</strong></p>
<pre><code class="language-cpp">char ch = '7';
const bool digit = std::isdigit(static_cast&lt;unsigned char&gt;(ch)) != 0;
// digit == true; точное ненулевое значение, возвращённое isdigit, не требуется.
</code></pre>
<p>Классификация некоторых символов зависит от текущей локали. Побайтовый вызов этих функций не разбирает автоматически многобайтовый UTF-8. Возвращённый библиотекой <code>EOF</code> нужно хранить в подходящем <code>int</code> и отличать от символа до сужения типа.</p>
<p><code>atoi</code> из семейства <code>&lt;cstdlib&gt;</code> не подходит для строгой проверки пользовательского числа: интерфейс не сообщает позицию остановки, не даёт полноценного сигнала ошибки формата и не обеспечивает безопасной диагностики переполнения результата. Варианты <code>strtol</code>/<code>strtoll</code> позволяют проверить конец разобранного текста и <code>errno == ERANGE</code>, но требуют аккуратно обработать весь этот контракт, в том числе очистить <code>errno</code> перед вызовом.</p>
<p>В C++17/C++20 <a href="https://stepik.org/lesson/770589/step/5" rel="noopener noreferrer nofollow">полный разбор со <code>std::from_chars</code></a> ниже показывает явную проверку ошибки, диапазона типа и отсутствия лишнего хвоста. Строковый ввод, число и набор символов нельзя считать взаимозаменяемыми без такого преобразования.</p>

<h3>Указатель на символы строки: char* и const char*</h3>
<p>Ниже приведены независимые фрагменты внутри функции, а не одна программа. Там, где показана ошибка, строка предназначена для объяснения отказа компиляции.</p>

<p><code>char s[] = "text";</code> объявляет массив s типа char[5] и инициализирует его строковым литералом. Он содержит элементы t, e, x, t и завершающий нулевой символ.</p>

<p>Элементы массива можно изменять: </p>

<pre><code class="language-cpp">s[0] = 'n'; /* s: "next" */</code></pre>

<p>Но не можете переприсвоить сам массив <code>s</code> (это же массив):</p>

<pre><code class="language-cpp">char s[] = "text";  /* OK */
s = "another text"; /* Это ошибка. */</code></pre>

<p> Если вы используете указатель:</p>

<pre><code class="language-cpp">// До C++11 допускалось устаревшее объявление:
// char* s = "text";
// В современном C++:
const char* s = "text";</code></pre>

<p>Здесь s — указатель типа const char* на первый элемент строкового литерала. Изменять сам литерал нельзя. Даже если принудительно получить неконстантный указатель и записать через него символ, поведение будет неопределённым.</p>

<p>И уже сам указатель переприсваивать можно:</p>

<pre><code class="language-cpp">const char *p = "text"; /* OK */
p = "another text"; /* OK */</code></pre>

<p>В таком объявлении обычный строковый литерал преобразуется в const char*. Неявно получить char* из литерала в современном C++ нельзя. Указатель на константный char не следует путать с константным указателем.</p>

<p>Для обычной работы со строковыми значениями удобно использовать std::string. Массивы char и C-строки остаются полезны, например, при взаимодействии с C API. Продолжение — <a href="https://stepik.org/lesson/770589/step/1" rel="noopener noreferrer nofollow">введение <code>std::string</code>, владения строкой и чтения текста</a>.</p>
