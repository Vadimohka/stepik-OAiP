<h3>Из каких инструментов состоит рабочее место C++</h3>
<p><strong>Цель шага:</strong> объяснить, кто превращает исходный текст в программу и где искать сообщение об ошибке.</p>
<p><strong>IDE</strong> (Integrated Development Environment, интегрированная среда разработки) объединяет редактор, навигацию по коду и управление сборкой, запуском и отладкой. Нажатие кнопки «Собрать» запускает отдельные инструменты. Они могут поставляться вместе с IDE или устанавливаться отдельно.</p>
<table><thead><tr><th>Инструмент</th><th>Что делает</th><th>Пример результата</th></tr></thead><tbody>
<tr><td>Редактор</td><td>Помогает написать и сохранить исходный текст.</td><td>Файл <code>main.cpp</code>.</td></tr>
<tr><td>Компилятор C++</td><td>Проверяет программу по правилам выбранного стандарта и переводит единицы трансляции в объектный код.</td><td>Объектный файл или диагностика ошибки.</td></tr>
<tr><td>Компоновщик</td><td>Соединяет объектные файлы и нужные библиотеки.</td><td>Исполняемый файл.</td></tr>
<tr><td>Система сборки</td><td>Запускает необходимые команды с учётом зависимостей и параметров.</td><td>Собранный проект; неизменённые части часто не нужно пересобирать.</td></tr>
<tr><td>Отладчик</td><td>Позволяет остановить программу на строке, выполнять её по шагам и смотреть значения.</td><td>Наблюдение за выполнением программы.</td></tr>
</tbody></table>
<p>GCC, Clang и MSVC — семейства компиляторов; Visual Studio, CLion, Qt Creator и Xcode — IDE. Visual Studio Code — редактор, возможности которого расширяются дополнениями. Расширение C++ само по себе не устанавливает компилятор.</p>
<p>Исходный файл и исполняемый файл — разные объекты. Расширение <code>.exe</code> обычно используется в Windows; в Linux и macOS оно не требуется.</p>
<h3>Разобранная ситуация</h3>
<p>Подсветка C++ и автодополнение могут работать, даже если сборка сообщает, что компилятор не найден. Оформление редактора эту проблему не исправляет: компилятор должен быть установлен и выбран в настройках среды.</p>
<p>Подробнее: <a href="https://code.visualstudio.com/docs/languages/cpp" rel="noopener noreferrer nofollow">официальная инструкция C++ для VS Code</a>.</p>

<h3>Как выбрать среду и стандарт C++</h3>
<p><strong>Цель шага:</strong> получить набор инструментов, которым можно собрать и отладить учебную программу. Для начала достаточно одной удобной среды.</p>
<p>Рабочее окружение состоит из компилятора, средств сборки и IDE либо редактора. Его конфигурация должна однозначно задавать эти инструменты и параметры. Полный пример команды будет показан далее.</p>
<p>Для локальных разобранных примеров курса используем <strong>C++20</strong> явно: у GCC и Clang это <code>-std=c++20</code>, у MSVC — <code>/std:c++20</code>. IDE и компилятор имеют разные номера версий. Даже при выборе одного стандарта доступность отдельных библиотечных возможностей зависит от установленной реализации.</p>
<p>Большинство базовых примеров использует средства, доступные и в C++17. Если в примере нужна более новая возможность, её стандарт указан отдельно. Дополнения C++23 можно изучать после основы; переключать вводный проект на экспериментальный режим языка для прохождения уроков не требуется.</p>
<p><strong>Задания Stepik:</strong> список языков и конфигурацию проверяющей системы смотрите в самом задании. Локальный флаг <code>-std=c++20</code> не изменяет настройки Stepik и не подтверждает, что её компилятор поддерживает все возможности C++20. В решении используйте возможности выбранной проверяющей системы.</p>
<p>Для учебной работы полезны: переход к диагностике компилятора, понятный вывод программы, точки останова, просмотр переменных, форматирование и навигация по коду. Инструменты генерации сложных классов и другие расширенные функции можно освоить позднее.</p>
<h3>Разобранная ситуация</h3>
<p>Если в настройках интерфейса указан C++20, а фактическая команда содержит <code>-std=c++14</code>, эта команда использует C++14. Причиной может быть другая активная конфигурация. Режим языка проверяют по команде сборки, а не по названию IDE.</p>
<p>Справка: <a href="https://gcc.gnu.org/projects/cxx-status.html" rel="noopener noreferrer nofollow">поддержка стандартов в GCC</a>; <a href="https://learn.microsoft.com/en-us/cpp/build/reference/std-specify-language-standard-version" rel="noopener noreferrer nofollow">выбор стандарта в MSVC</a>.</p>

<h2>Рабочий цикл и три разных результата</h2>
<p>В разработке различаются редактирование исходника, сборка и выполнение. Успех одного этапа не заменяет следующий.</p>
<table><thead><tr><th>Этап</th><th>Результат</th><th>Что из него не следует</th></tr></thead><tbody><tr><td>Редактирование</td><td>Сохранён новый текст <code>main.cpp</code>.</td><td>Существующий исполняемый файл ещё не изменился.</td></tr><tr><td>Сборка</td><td>Компилятор и компоновщик создали программу.</td><td>Логика и ожидаемый вывод ещё не доказаны.</td></tr><tr><td>Запуск</td><td>Получено конкретное поведение на конкретном входе.</td><td>Один удачный запуск не подтверждает все допустимые случаи.</td></tr></tbody></table>
<p><strong>Разобранная ситуация:</strong> в исходнике приветствие изменено, но новая сборка завершилась ошибкой. Старый исполняемый файл может остаться на диске и вывести прежнее приветствие. Значит, сначала нужна успешная сборка, затем запуск именно её результата.</p>
<p>Отладчик позволяет остановить выполнение и посмотреть состояние программы; режим Debug обычно добавляет полезную для этого информацию. Git сохраняет выбранные версии исходников, а описание сборки помогает воспроизвести их. Эти инструменты продолжают одну цепочку, а не заменяют друг друга.</p>
<p>Следующий урок разбирает полный исходный файл, команду сборки и ожидаемый результат. Теория не требует установки всех IDE из предыдущих шагов.</p>
