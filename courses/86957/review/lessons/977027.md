<h2>Преобразования: значение, тип выражения и объект</h2>
<p>Этот урок продолжает темы <a href="https://stepik.org/lesson/763639/step/1" rel="noopener noreferrer nofollow">выражений</a>, <a href="https://stepik.org/lesson/770585/step/1" rel="noopener noreferrer nofollow">указателей</a> и <a href="https://stepik.org/lesson/877084/step/1" rel="noopener noreferrer nofollow">наследования</a>. Он расположен после контейнеров, но приведения не являются особой операцией очереди. Они нужны там, где интерфейсы встречаются с разными типами.</p>
<p><strong>Преобразование</strong> получает значение или выражение другого типа по правилам языка. Например, преобразование <code>int</code> в <code>double</code> создаёт значение <code>double</code>; исходный объект <code>int</code> не меняет свой тип. Приведение указателя обычно меняет вид доступа к существующему объекту, а не создаёт объект другого класса.</p>
<p>Неявное преобразование выбирается по контексту: арифметическая операция, инициализация, присваивание, передача аргумента. Оно может исполняться во время работы программы или при вычислении константного выражения. Допустимость преобразования не обещает отсутствия потери точности.</p>
<table><thead><tr><th>Запись</th><th>Намерение</th><th>Чего не обещает</th></tr></thead><tbody><tr><td><code>static_cast</code></td><td>Явное допустимое преобразование, например числовое</td><td>Сохранения диапазона и проверки фактического производного типа</td></tr><tr><td><code>dynamic_cast</code></td><td>Проверяемый доступ в полиморфной иерархии</td><td>Работы с уничтоженным объектом</td></tr><tr><td><code>const_cast</code></td><td>Изменение cv-квалификации доступа</td><td>Права менять изначально константный объект</td></tr><tr><td><code>reinterpret_cast</code></td><td>Разрешённое низкоуровневое преобразование</td><td>Создания нового объекта или произвольного доступа к его байтам как к другому типу</td></tr></tbody></table>
<p>Правильный вопрос перед приведением: какое условие делает операцию корректной? Часто достаточно подходящего типа параметра, неявного преобразования вверх по иерархии или работы через общий виртуальный интерфейс. Далее каждый оператор будет связан со своим условием.</p>

<h2>static_cast: преобразование с известными предпосылками</h2>
<p><code>static_cast&lt;T&gt;(expression)</code> явно выбирает разрешённую языком категорию преобразования. Компилятор проверяет допустимость формы, но не все условия, зависящие от значения и фактического объекта.</p>
<h3>Числовое значение и возвращение исходного указателя</h3>
<p>В полной программе C++17/20 целое 7 преобразуется до деления, поэтому результат равен 3,5. Обратное приведение из <code>void*</code> корректно, поскольку там сохранён адрес того же живого объекта <code>int</code>.</p><pre><code class="language-cpp">#include &lt;iostream&gt;

int main() {
    const int total = 7;
    const int count = 2;
    const double average = static_cast&lt;double&gt;(total) / count;
    int value = 42;
    void* storage = &amp;value;
    int* same_object = static_cast&lt;int*&gt;(storage);
    std::cout &lt;&lt; average &lt;&lt; ' ' &lt;&lt; *same_object &lt;&lt; '\n';
}</code></pre>
<p>Вывод: <code>3.5 42</code>. Запись <code>static_cast&lt;double&gt;(total / count)</code> дала бы 3,0: целочисленное деление уже отбросило дробную часть. При преобразовании плавающего значения в целое дробная часть отбрасывается; если усечённое значение не представимо целевым типом, поведение не определено. Явная запись не заменяет проверку диапазона.</p>
<h3>Вниз по иерархии</h3>
<p>Из <code>Derived*</code> в доступную однозначную базу <code>Base*</code> обычно можно перейти неявно. Обратный <code>static_cast&lt;Derived*&gt;</code> не проверяет динамический тип: исходный указатель должен обозначать подходящую базовую часть объекта <code>Derived</code> либо быть нулевым. Для ссылки нулевого случая нет. Несоответствие объекта этому условию ведёт к неопределённому поведению, а не к возвращению <code>nullptr</code>.</p>
<p>Когда фактический тип требуется проверить, подходит следующий <code>dynamic_cast</code> для полиморфной базы. Если цель — вызвать общую операцию, проще оставить базовую ссылку и виртуальную функцию. Приведение не передаёт владение: объект по-прежнему принадлежит прежнему владельцу.</p>

<h2>dynamic_cast: проверка фактического типа</h2>
<p>Нужны понятия <a href="https://stepik.org/lesson/877084/step/1" rel="noopener noreferrer nofollow">наследования и виртуальной функции</a>. Для проверяемого приведения вниз или поперёк иерархии исходный тип должен быть <strong>полиморфным</strong>: иметь виртуальную функцию. Преобразование вверх к доступной однозначной базе возможно и без полиморфизма.</p>
<p><code>dynamic_cast&lt;Derived*&gt;(base_pointer)</code> возвращает подходящий указатель или <code>nullptr</code>, если проверка не удалась. Нулевой исходный указатель даёт нулевой результат. Приведение к ссылке не имеет нулевого результата: при неудаче оно выбрасывает <code>std::bad_cast</code> из <code>&lt;typeinfo&gt;</code>.</p>
<h3>Разобранная полная программа C++17/20</h3>
<p>Локальные объекты живут до конца <code>main</code>; указатели в массиве ими не владеют. Виртуальный деструктор делает базу полиморфной и обеспечивает корректное уничтожение через базовый указатель в тех программах, где оно требуется.</p><pre><code class="language-cpp">#include &lt;iostream&gt;
#include &lt;typeinfo&gt;

struct Shape {
    virtual ~Shape() = default;
};
struct Circle : Shape {
    int radius = 3;
};

int main() {
    Circle circle;
    Shape other;
    Shape* shapes[]{&amp;circle, &amp;other, nullptr};
    for (Shape* shape : shapes) {
        if (const auto* found = dynamic_cast&lt;const Circle*&gt;(shape)) {
            std::cout &lt;&lt; found-&gt;radius &lt;&lt; '\n';
        } else {
            std::cout &lt;&lt; "not a circle\n";
        }
    }
    try {
        (void)dynamic_cast&lt;Circle&amp;&gt;(other);
    } catch (const std::bad_cast&amp;) {
        std::cout &lt;&lt; "reference cast failed\n";
    }
}</code></pre>
<p>Вывод: <code>3</code>, два раза <code>not a circle</code>, затем <code>reference cast failed</code>, каждое сообщение на новой строке. Здесь один и тот же оператор отличает объект <code>Circle</code>, обычный <code>Shape</code> и отсутствие объекта.</p>
<p>Проверка не делает безопасным висячий указатель: время жизни исходного объекта должно продолжаться. Также <code>dynamic_cast</code> не снимает <code>const</code>. Если ветвление по конкретным типам повторяется в каждом вызывающем коде, стоит рассмотреть виртуальную операцию в общем интерфейсе; выбор зависит от модели задачи.</p>

<h2>const_cast: квалификация доступа и константность объекта</h2>
<p><code>const</code> у ссылки или указателя ограничивает действия через этот путь доступа. Это не всегда означает, что исходный объект был создан константным. <code>const_cast</code> меняет допустимую квалификацию выражения, но не меняет происхождение и свойства объекта.</p>
<p>Полная программа C++17/20 показывает два разных случая. В первом исходный <code>int</code> изменяемый. Во втором исходный объект — <code>const int</code>; после приведения его разрешено читать, но попытка записи имела бы неопределённое поведение.</p><pre><code class="language-cpp">#include &lt;iostream&gt;

int main() {
    int value = 10;
    const int&amp; read_only_view = value;
    int&amp; writable_view = const_cast&lt;int&amp;&gt;(read_only_view);
    writable_view = 12; // The original object is not const.
    std::cout &lt;&lt; value &lt;&lt; '\n';
    const int immutable = 7;
    const int* pointer = &amp;immutable;
    int* stripped = const_cast&lt;int*&gt;(pointer);
    std::cout &lt;&lt; *stripped &lt;&lt; '\n'; // Reading is allowed; writing is not.
}</code></pre>
<p>Вывод: <code>12</code>, затем <code>7</code>. Само получение <code>stripped</code> не является ошибкой; недопустима последующая запись в <code>immutable</code>. Поэтому проверка только наличия <code>const_cast</code> не заменяет анализ времени жизни и реального объекта.</p>
<p>Для обычной читающей функции правильный интерфейс — <code>const T&amp;</code> или <code>const T*</code>. Добавление <code>const</code> обычно выполняется неявно. Строковый литерал нельзя делать изменяемым снятием <code>const</code>; для изменяемого текста подходит отдельный <code>std::string</code> или массив.</p>
<p>В новом коде <code>const_cast</code> должен иметь явное обоснование совместимостью интерфейсов. Для представления байтов и числовых преобразований он не предназначен.</p>

<h2>reinterpret_cast и представление объекта</h2>
<p><code>reinterpret_cast</code> разрешает только перечисленные стандартом низкоуровневые преобразования, например некоторые преобразования указателей. Он не является числовым преобразованием <code>double</code> в <code>unsigned long long</code> и не создаёт объект нового типа в прежней памяти.</p>
<p>Важны три независимых условия: допустимость самого приведения, выравнивание адреса и допустимость доступа к живому объекту через результирующий тип. Успешная компиляция приведения не доказывает остальные условия. Преобразование <code>int*</code> в <code>double*</code> не разрешает разыменовать его как <code>double</code>.</p>
<h3>Разобранный пример чтения представления</h3>
<p>Для просмотра байтов не требуется создавать фиктивный объект другого типа. Полная программа C++17/20 копирует представление <code>unsigned int</code> в массив байтов.</p><pre><code class="language-cpp">#include &lt;array&gt;
#include &lt;cstring&gt;
#include &lt;iostream&gt;

int main() {
    const unsigned int value = 1;
    std::array&lt;unsigned char, sizeof(value)&gt; bytes{};
    std::memcpy(bytes.data(), &amp;value, sizeof(value));
    std::cout &lt;&lt; bytes.size() &lt;&lt; '\n';
    for (unsigned char byte : bytes) {
        std::cout &lt;&lt; static_cast&lt;unsigned int&gt;(byte) &lt;&lt; ' ';
    }
    std::cout &lt;&lt; '\n';
}</code></pre>
<p>Первая строка — размер <code>unsigned int</code> в байтах данной реализации. Следующие числа показывают значения байтов. Конкретный размер, порядок байтов и детали представления не заданы этим примером; ожидать всегда «4» и один конкретный порядок нельзя. <code>sizeof</code> измеряет байты C++, а их число бит определяется <code>CHAR_BIT</code>.</p>
<p>В C++20 <code>std::bit_cast</code> из <code>&lt;bit&gt;</code> позволяет получить представление в другом тривиально копируемом типе того же размера с условиями допустимости результата. Это отдельная операция, не числовое преобразование. Для записи переносимого файла недостаточно выгрузить байты объекта: нужен явно определённый формат — связь с разделом <a href="https://stepik.org/lesson/771130/step/1" rel="noopener noreferrer nofollow">бинарных файлов</a>.</p>

<h2>C-style cast и выбор явного намерения</h2>
<p>Унаследованная запись <code>(T)expression</code> в C++ проверяется как определённая последовательность возможностей: <code>const_cast</code>, <code>static_cast</code>, их разрешённые сочетания, <code>reinterpret_cast</code> и его разрешённое сочетание с <code>const_cast</code>. Она не включает проверку фактического типа, которую выполняет <code>dynamic_cast</code>.</p>
<p>Это не разрешение преобразовать любые два типа: если подходящего разрешённого преобразования нет, программа не компилируется. Однако по короткой записи хуже видно, снимается ли <code>const</code>, преобразуется ли число или меняется низкоуровневый вид указателя.</p>
<table><thead><tr><th>Намерение</th><th>Ясная запись</th><th>Предпосылка</th></tr></thead><tbody><tr><td>Перейти к вещественному делению</td><td><code>static_cast&lt;double&gt;(sum) / count</code></td><td><code>count != 0</code>; учтена точность результата</td></tr><tr><td>Проверить производный тип</td><td><code>dynamic_cast&lt;Derived*&gt;(base)</code></td><td>Живой объект полиморфной базы; результат проверен</td></tr><tr><td>Снять квалификацию доступа</td><td><code>const_cast&lt;T*&gt;(pointer)</code></td><td>Для записи исходный объект должен быть изменяемым</td></tr><tr><td>Низкоуровневое представление адреса</td><td><code>reinterpret_cast</code> подходящего вида</td><td>Выполнены отдельные правила приведения и доступа</td></tr></tbody></table>
<p>Именованный оператор ограничивает и поясняет намерение, но не доказывает правильность значений. Наиболее простой код часто вообще обходится без приведения: интерфейс принимает нужный тип, а владелец объекта остаётся видимым.</p>
<p>Далее <a href="https://stepik.org/lesson/853539/step/1" rel="noopener noreferrer nofollow">деревья поиска</a> соединят наши темы: класс хранит объекты и связи, инвариант задаёт порядок, а высота определяет стоимость операций. Приведения не заменяют эти инварианты.</p>
