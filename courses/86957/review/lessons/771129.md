<h3>Поиск начинается с контракта</h3>
<p>Перед выбором алгоритма ответьте на четыре вопроса: что ищем, упорядочены ли данные, сколько будет запросов и какой результат нужен при повторениях или отсутствии элемента.</p>
<p>В этом уроке ищем целое значение <code>key</code> в последовательности. Индексы отсчитываем с нуля. Линейная функция будет возвращать индекс <strong>первого</strong> совпадения, а при отсутствии — <code>values.size()</code>. Это значение находится за допустимыми индексами; разыменовывать его нельзя. В бинарном поиске сначала найдём позицию вставки через <code>lower_bound</code>, а затем отдельно проверим совпадение. Обе программы выводят первый индекс или «не найдено»; пустой диапазон всегда даёт «не найдено».</p>
<table><thead><tr><th>Задача</th><th>Подходящий стандартный алгоритм</th><th>Результат</th></tr></thead><tbody>
<tr><td>Первое совпадение в любом диапазоне</td><td><code>std::find</code></td><td>Итератор на первое совпадение или <code>end()</code></td></tr>
<tr><td>Проверить наличие в упорядоченном диапазоне</td><td><code>std::binary_search</code></td><td><code>true</code> или <code>false</code></td></tr>
<tr><td>Найти первый элемент не меньше ключа</td><td><code>std::lower_bound</code></td><td>Итератор на границу или <code>end()</code>; равенство ключу проверяется отдельно</td></tr>
</tbody></table>
<p>Все три функции объявлены в <code>&lt;algorithm&gt;</code>. Итератор указывает место в диапазоне; <code>end()</code> — позиция за последним элементом. Для вектора разность итератора и <code>begin()</code> даёт индекс. Сначала проверьте, что результат не равен <code>end()</code>, затем обращайтесь к элементу.</p>
<h4>Цена подготовки тоже входит в решение задачи</h4>
<p>Один запрос к несортированному массиву можно выполнить линейным поиском за <code>O(n)</code>. Для <code>q</code> запросов независимый линейный поиск даёт верхнюю оценку <code>O(qn)</code>. Сортировка один раз и затем бинарный поиск дают <code>O(n log n + q log n)</code> сравнений. Выигрыш зависит от числа запросов, стоимости сравнений и возможности менять порядок.</p>
<p>Сортировка меняет индексы: найденная позиция относится к отсортированной последовательности. Если нужен исходный индекс, сохраните его вместе со значением или используйте поиск, не переставляющий вход. Повторная сортировка перед каждым запросом обычно уничтожает смысл такой подготовки.</p>
<p>Для вектора и встроенного массива бинарный поиск делает <code>O(log n)</code> шагов при сравнении за <code>O(1)</code>. В диапазонах без произвольного доступа число сравнений остаётся логарифмическим, но продвижений итераторов может быть <code>O(n)</code>.</p>
<h4>Мини-задача</h4>
<p>В исходном массиве <code>[8, 2, 8, 5]</code> требуется первый индекс числа 8. Что вернёт линейный поиск? Что изменится после сортировки?</p>
<details><summary>Разбор</summary><p>До сортировки первый индекс — 0. После сортировки массив равен <code>[2, 5, 8, 8]</code>, первый индекс — 2. Наличие числа сохранилось, а смысл индекса изменился.</p></details>
<p>Поиск подпоследовательности — другая задача: обычный <code>std::search</code> для диапазонов длины <code>n</code> и <code>m</code> имеет верхнюю оценку <code>O(nm)</code> сравнений. Не переносите гарантию бинарного поиска на функцию только потому, что в её названии есть слово «search».</p>

<h3>Линейный поиск: проверяем по одному</h3>
<p>Просматриваем элементы слева направо и возвращаем индекс при первом совпадении. Сортировка не нужна, исходный порядок сохраняется. Если совпадений нет, возвращаем размер последовательности — индекс за её концом.</p>
<p>Полная программа C++17/20. Ввод: <code>0 ≤ n ≤ 1000</code>, затем <code>n</code> целых значений типа <code>int</code> и искомый ключ того же типа. Вывод: первый индекс или строка <code>not found</code>. Ошибочный ввод даёт код завершения 1.</p>
<pre><code class="language-cpp">#include &lt;cstddef&gt;
#include &lt;iostream&gt;
#include &lt;vector&gt;

std::size_t first_index(const std::vector&lt;int&gt;&amp; values, int key) {
    for (std::size_t i = 0; i &lt; values.size(); ++i) {
        if (values[i] == key) {
            return i;
        }
    }
    return values.size();
}

int main() {
    int n{};
    if (!(std::cin &gt;&gt; n) || n &lt; 0 || n &gt; 1000) {
        return 1;
    }
    std::vector&lt;int&gt; values(static_cast&lt;std::size_t&gt;(n));
    for (int&amp; value : values) {
        if (!(std::cin &gt;&gt; value)) {
            return 1;
        }
    }
    int key{};
    if (!(std::cin &gt;&gt; key)) {
        return 1;
    }
    const std::size_t position = first_index(values, key);
    if (position == values.size() || values[position] != key) {
        std::cout &lt;&lt; "not found\n";
    } else {
        std::cout &lt;&lt; position &lt;&lt; '\n';
    }
}</code></pre>
<p>Для <code>4 8 2 8 5 8</code> программа выводит <code>0</code>. Возвращается первое из двух совпадений. Для пустого массива цикл сразу пропускается, функция возвращает 0, равный размеру.</p>
<p><strong>Инвариант:</strong> перед проверкой индекса <code>i</code> ни один элемент на индексах <code>[0, i)</code> не равен ключу. Поэтому найденное совпадение действительно первое. Если цикл завершился, проверены все элементы.</p>
<p>Лучший случай на непустом массиве — одно сравнение, худший — <code>n</code>. При равновероятной позиции заведомо присутствующего ключа среднее равно <code>(n+1)/2</code>. Дополнительная память функции — <code>O(1)</code>; память самого входного вектора в эту величину не включена.</p>
<p>В прикладной программе ту же задачу решает <code>std::find(values.begin(), values.end(), key)</code>. Он возвращает итератор на первое совпадение или <code>values.end()</code> и выполняет не более <code>n</code> проверок равенства. Собственная функция показывает, как устроен этот простой поиск.</p>
<h4>Самостоятельно</h4>
<p>Измените функцию так, чтобы она возвращала индекс <em>последнего</em> совпадения. Сохраните договорённость о результате при отсутствии и не меняйте вход. Проверьте пустой массив, одно значение и повторения.</p>
<details><summary>Подсказка и проверка</summary><p>Можно хранить последний найденный индекс, первоначально равный размеру, и обновлять его при каждом совпадении. Для <code>[8, 2, 8, 5]</code> и ключа 8 получится 2. Ранний выход после первого совпадения больше не подходит.</p></details>

<h3>Бинарный поиск и первая подходящая позиция</h3>
<p>Для этого урока входной массив должен быть отсортирован по неубыванию. Найдём границу: первый индекс, на котором значение <em>не меньше</em> ключа. Если на этой позиции находится сам ключ, это его первое вхождение. Иначе ключ отсутствует.</p>
<p>Работаем с полуинтервалом <code>[left, right)</code>. Начальные границы — 0 и размер массива, поэтому пустой вход не требует отдельного случая. Индекс <code>middle = left + (right−left)/2</code> избегает переполнения суммы границ.</p>
<p>Полная программа C++17/20. Ввод: <code>0 ≤ n ≤ 1000</code>, затем <code>n</code> значений типа <code>int</code> по неубыванию и искомый ключ. Вывод: первый индекс или <code>not found</code>. В учебной оболочке некорректный ввод и нарушение сортировки дают код завершения 1.</p>
<pre><code class="language-cpp">#include &lt;cstddef&gt;
#include &lt;iostream&gt;
#include &lt;vector&gt;
#include &lt;algorithm&gt;

std::size_t lower_bound_index(const std::vector&lt;int&gt;&amp; values, int key) {
    std::size_t left = 0;
    std::size_t right = values.size();
    while (left &lt; right) {
        const std::size_t middle = left + (right - left) / 2;
        if (values[middle] &lt; key) {
            left = middle + 1;
        } else {
            right = middle;
        }
    }
    return left;
}

int main() {
    int n{};
    if (!(std::cin &gt;&gt; n) || n &lt; 0 || n &gt; 1000) {
        return 1;
    }
    std::vector&lt;int&gt; values(static_cast&lt;std::size_t&gt;(n));
    for (int&amp; value : values) {
        if (!(std::cin &gt;&gt; value)) {
            return 1;
        }
    }
    int key{};
    if (!(std::cin &gt;&gt; key)) {
        return 1;
    }
    if (!std::is_sorted(values.begin(), values.end())) {
        return 1;
    }
    const std::size_t position = lower_bound_index(values, key);
    if (position == values.size() || values[position] != key) {
        std::cout &lt;&lt; "not found\n";
    } else {
        std::cout &lt;&lt; position &lt;&lt; '\n';
    }
}</code></pre>
<h4>Трассировка для повторяющихся значений</h4>
<p>В массиве <code>[1, 2, 2, 2, 5, 9]</code> ищем 2.</p>
<table><thead><tr><th>left</th><th>right</th><th>middle</th><th>Значение</th><th>Следующий диапазон</th></tr></thead><tbody>
<tr><td>0</td><td>6</td><td>3</td><td>2</td><td>[0, 3)</td></tr>
<tr><td>0</td><td>3</td><td>1</td><td>2</td><td>[0, 1)</td></tr>
<tr><td>0</td><td>1</td><td>0</td><td>1</td><td>[1, 1)</td></tr>
</tbody></table>
<p>Возвращаем 1. При равенстве поиск продолжался влево, поэтому найдено первое вхождение, а не произвольное совпадение.</p>
<p><strong>Инвариант:</strong> все индексы меньше <code>left</code> содержат значения меньше ключа; все индексы начиная с <code>right</code> — значения не меньше ключа. Неопределённая часть находится между границами. На каждой итерации она строго уменьшается. При <code>left == right</code> граница найдена.</p>
<p>Сама функция требует <code>O(log n)</code> сравнений и <code>O(1)</code> дополнительной памяти. Проверка <code>std::is_sorted</code> в <code>main</code> занимает <code>O(n)</code>: она включена для наглядной диагностики предусловия. В серии запросов к неизменному массиву порядок проверяют или обеспечивают один раз, а не перед каждым поиском. Чтение всего ввода тоже линейное.</p>
<p>Стандартная функция <code>std::lower_bound</code> возвращает такую же границу итератором. Её результат может указывать на большее значение, поэтому «итератор не равен <code>end()</code>» ещё не означает наличие ключа. Для проверки только наличия предназначен <code>std::binary_search</code>.</p>
<h4>Самостоятельно</h4>
<p>Что вернёт <code>lower_bound_index</code> для ключей 0, 4 и 10 на массиве выше? Какие ответы напечатает программа?</p>
<details><summary>Разбор</summary><p>Границы: 0, 4 и 6. Ни одна не указывает на значение, равное ключу, поэтому во всех трёх случаях выводится <code>not found</code>. Индекс 6 равен размеру, и обращение <code>values[6]</code> недопустимо; условие в <code>main</code> проверяет границу раньше доступа.</p></details>

<h3>Интерполяционный поиск</h3>
<p>Интерполяционный поиск работает с массивом числовых ключей, отсортированным по возрастанию. Он оценивает позицию искомого x по его положению между значениями на границах текущего диапазона.</p>
<p>Пусть l и r — индексы границ. Если <code>a[l] &lt; a[r]</code> и <code>a[l] ≤ x ≤ a[r]</code>, пробный индекс вычисляют так:</p>
<p><code>pos = l + floor((x − a[l]) · (r − l) / (a[r] − a[l]))</code>.</p>
<p>Например, при l=0, r=99, a[l]=5, a[r]=200 и x=20 получаем <code>pos = floor(15 · 99 / 195) = 7</code>. Это оценка позиции, а не гарантия, что именно там находится x.</p>
<p>Сравните a[pos] с x. При совпадении поиск окончен; если a[pos] меньше, продолжайте с l=pos+1, иначе — с r=pos−1. Для пустого диапазона или x вне значений его границ поиск заканчивается неудачей. Если a[l]=a[r], деление выполнять нельзя: достаточно сравнить x с этим общим значением.</p>
<p>В реализации следите за переполнением произведения и порядком целочисленного деления: выражение (x−a[l])/(a[r]−a[l]) может преждевременно дать ноль. Выбирайте промежуточный тип по ограничениям задачи.</p>
<p>В худшем случае требуется O(n) проверок. Ожидаемая оценка O(log log n) относится к модели равномерно распределённых ключей и не следует из одной отсортированности массива. Попробуйте реализовать поиск самостоятельно, проверив пустой диапазон, одинаковые элементы и ключи на границах.</p>

<p>Брюс недавно получил работу в NEERC (Numeric Expression Engineering &amp; Research Center), где изучают и строят много различных любопытных чисел. Его первым заданием  стало исследование двудесятичных чисел. Натуральное число называется <strong>двудесятичным</strong>, если его десятичное представление  является суффиксом его двоичного представления; и двоичное, и десятичное представление рассматривается без ведущих нулей. Например, 10<sub>10</sub> = 1010<sub>2</sub>, так что <strong>10 </strong>двудесятичное число. Числа 1010<sub>10</sub> = 1111110010<sub>2</sub> и 42<sub>10</sub> = 101010<sub>2</sub> не являются  двудесятичными. Сначала Брюс хочет создать список двудесятичных чисел. Помогите ему найти <strong>n</strong>-ое наименьшее двудесятичное число.</p>

<p><strong>Выходные данные </strong></p>
