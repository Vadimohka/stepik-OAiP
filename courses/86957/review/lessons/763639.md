<h2>Выражение: что вычисляется и что меняется</h2>
<p>Операнды — значения или объекты, над которыми записана операция. В <code>a + b</code> два операнда, в <code>-a</code> один. Выражение может вычислять значение и менять состояние программы: например, <code>a + 1</code> не меняет <code>a</code>, а <code>a += 1</code> меняет.</p>
<table><thead><tr><th>Операции</th><th>Смысл</th></tr></thead><tbody><tr><td><code>+ - * / %</code></td><td>Арифметика; <code>%</code> — остаток целочисленного деления, не процент.</td></tr><tr><td><code>=</code>, <code>+= -= *= /= %=</code></td><td>Присваивание и составные присваивания. <code>=</code> меняет значение, <code>==</code> сравнивает.</td></tr><tr><td><code>== != &lt; &lt;= &gt; &gt;=</code></td><td>Сравнения; результат имеет тип <code>bool</code>.</td></tr><tr><td><code>! &amp;&amp; ||</code></td><td>Логические НЕ, И, ИЛИ.</td></tr><tr><td><code>++ --</code></td><td>Увеличение или уменьшение на единицу; у префиксной и постфиксной форм разные результаты выражения.</td></tr></tbody></table>
<h3>Тип операции выбирается до присваивания</h3>
<p><strong>Фрагмент внутри функции; это не отдельная программа.</strong></p>
<pre><code class="language-cpp">double first = 7 / 2;                    // 3.0: сначала int / int
double second = 7.0 / 2;                 // 3.5: деление double
double third = static_cast&lt;double&gt;(7) / 2; // 3.5
</code></pre>
<p>Для целых частное усекается к нулю: <code>-7 / 2</code> равно −3, <code>-7 % 2</code> равно −1. При ненулевом делителе и представимом частном выполняется равенство <code>(a / b) * b + a % b == a</code>. Нулевой правый операнд запрещён и для <code>/</code>, и для <code>%</code>. Если частное не помещается в тип результата, неопределённое поведение имеют обе операции, даже когда математический остаток равен нулю. Поэтому при представлении знаковых чисел дополнительным кодом нельзя вычислять ни минимальное значение, делённое на <code>-1</code>, ни его остаток от деления на <code>-1</code>. Ненулевого делителя самого по себе недостаточно.</p>
<p><strong>Полная программа C++17/C++20.</strong></p>
<pre><code class="language-cpp">#include &lt;iostream&gt;
int main() {
    int a{}, b{};
    if (!(std::cin &gt;&gt; a &gt;&gt; b) || a &lt; -100 || a &gt; 100
                            || b &lt; -100 || b &gt; 100 || b == 0) {
        std::cout &lt;&lt; "INVALID\n";
        return 1;
    }
    std::cout &lt;&lt; a / b &lt;&lt; ' ' &lt;&lt; a % b &lt;&lt; '\n';
}
</code></pre>
<p>Контракт примера: два успешно прочитанных целых от −100 до 100 и ненулевой делитель. В этом диапазоне частное представимо даже в минимально допустимом <code>int</code>. Для <code>-7 2</code> программа печатает <code>-3 -1</code>. Неверный ввод даёт <code>INVALID</code> и код завершения 1. Остаток входного потока после двух чисел программа не использует.</p>
<h3>Условия и побочные эффекты</h3>
<p>Встроенные <code>&amp;&amp;</code> и <code>||</code> вычисляют правую часть только при необходимости. Поэтому <code>b != 0 &amp;&amp; a / b &gt; 2</code> сначала проверяет делитель. Это не снимает других ограничений, включая представимость частного. Побитовые <code>&amp;</code> и <code>|</code> такого пропуска не обеспечивают.</p>
<p><strong>Фрагмент внутри функции; это не отдельная программа.</strong></p>
<pre><code class="language-cpp">int n{3};
int old = n++; // old = 3, n = 4
int now = ++n; // n = 5, now = 5
</code></pre>
<p>Одна инструкция с одним очевидным изменением проще для разбора. Приоритет операции задаёт группировку выражения, а не общий порядок побочных эффектов. Не следует строить вычисление на нескольких несогласованных изменениях одной переменной. <a href="https://stepik.org/lesson/763639/step/2" rel="noopener noreferrer nofollow">Далее</a> уточняются преобразования, выполняемые перед операциями.</p>

<h2>Преобразование типа: что сохраняется</h2>
<p>Преобразование получает значение другого типа. Оно не меняет тип исходной переменной. Преобразование бывает неявным — например, при инициализации <code>double d = 5;</code>, — и явным: <code>static_cast&lt;double&gt;(5)</code>. Для обычных числовых преобразований используем именованную C++-форму <code>static_cast</code>; запись <code>(double)5</code> встречается в коде C и старом C++, но хуже показывает намерение.</p>
<p>Явная запись не проверяет диапазон. Сначала нужно обосновать, что результат представим и подходит задаче. Размер в байтах сам по себе не доказывает сохранения значения: целое может помещаться в диапазон <code>double</code>, но округляться из-за недостатка точности.</p>
<table><thead><tr><th>Переход</th><th>Правило</th></tr></thead><tbody><tr><td>Целое → другой целый</td><td>Представимое значение сохраняется. При переходе к беззнаковому типу действует приведение по модулю степени двойки; отрицательное число не отклоняется.</td></tr><tr><td><code>double</code> → целое</td><td>Дробная часть отбрасывается к нулю. Результат после усечения должен помещаться в целевой тип; иначе поведение не определено.</td></tr><tr><td>Целое → <code>double</code></td><td>Точное представление получается, если возможно; большие целые могут округляться. Для наших малых примеров это преобразование точно.</td></tr><tr><td><code>float</code> → <code>double</code> → <code>long double</code></td><td>Для конечных значений расширение сохраняет значение; обратный путь может терять точность или выходить за диапазон.</td></tr><tr><td>Число → <code>bool</code></td><td>Ноль даёт <code>false</code>, ненулевое значение — <code>true</code>.</td></tr></tbody></table>
<p>Версии C++ различаются для непредставимого значения при преобразовании в знаковый целый тип: в C++17 результат определяется реализацией; в C++20 действует установленное модульное правило. Это не разрешение знакового <em>арифметического</em> переполнения: оно остаётся неопределённым поведением. Начальный код лучше строить на значениях, представимых до и после преобразования.</p>
<h3>Преобразования внутри выражения</h3>
<p>Малые целочисленные типы сначала проходят продвижение: обычно <code>char</code> и <code>short</code> становятся <code>int</code>; если он не вмещает все значения исходного типа, используется <code>unsigned int</code>. Затем для двух арифметических операндов определяется общий тип. В частности, при сравнении <code>int</code> с <code>unsigned int</code> знаковый операнд преобразуется к беззнаковому. Поэтому выражение <code>-1 &lt; 1U</code> ложно, хотя математически −1 меньше 1.</p>
<p>Инициализация списком запрещает сужающие преобразования, например <code>int n{3.5};</code> не компилируется. Она полезна для обнаружения ошибки, но не заменяет контракт вычисления или проверку внешнего ввода.</p>
<p><strong>Полная программа C++17/C++20.</strong></p>
<pre><code class="language-cpp">#include &lt;cmath&gt;
#include &lt;iostream&gt;
int main() {
    double value{};
    if (!(std::cin &gt;&gt; value) || !std::isfinite(value)
                            || value &lt; 0.0 || value &gt; 100.0) {
        std::cout &lt;&lt; "INVALID\n";
        return 1;
    }
    const int whole = static_cast&lt;int&gt;(value);
    std::cout &lt;&lt; whole &lt;&lt; '\n';
}
</code></pre>
<p>Контракт программы намеренно узкий: конечное значение от 0 до 100 включительно. <code>std::isfinite</code> проверяет отсутствие бесконечности и NaN. После проверки усечённое значение помещается в любой стандартный <code>int</code>. Ввод <code>12.9</code> даёт 12; <code>-0.5</code> отклоняется по контракту, хотя само его усечение было бы представимо. Значение не округляется до ближайшего целого: это отдельная операция.</p>

<h3>Побитовые операции в языке С++</h3>

<p>Побитовые операции выполняются над отдельными разрядами или битами чисел. Данные операции производятся только над целыми числами.</p>

<h3>Операции сдвига</h3>

<p>Каждое целое число в памяти представлено в виде определенного количества разрядов. И операции сдвига позволяют сдвинуть битовое представление числа на несколько разрядов вправо или влево. Операции сдвига применяются только к целочисленным операндам. Есть две операции:</p>

<ul>
	<li>
	<p>&lt;&lt;</p>

	<p>Сдвигает битовое представление числа, представленного первым операндом, влево на определенное количество разрядов, которое задается вторым операндом.</p>
	</li>
	<li>
	<p>&gt;&gt;</p>

	<p>Сдвигает битовое представление числа вправо на определенное количество разрядов.</p>
	</li>
</ul>

<p>Число позиций сдвига должно быть неотрицательным и меньше ширины типа левого операнда <em>после целочисленного продвижения</em>. Нарушение этого условия приводит к неопределённому поведению. Как и в <a href="https://stepik.org/lesson/763639/step/2" rel="noopener noreferrer nofollow">разборе преобразований</a>, сначала определяется тип выполняемой операции; тип переменной, в которую затем записывают результат, этого правила не меняет.</p>

<p><strong>Фрагмент внутри функции, не отдельная программа; совместим с C++17/C++20.</strong></p>

<pre><code class="language-cpp">int a = 2 &lt;&lt; 2;           // 10  на два разряда влево = 1000 - 8

int b = 16 &gt;&gt; 3;          // 10000 на три разряда вправо = 10 - 2</code></pre>

<p> </p>

<p>Число 2 в двоичном представлении 10. Если сдвинуть число 10 на два разряда влево, то получится 1000, что в десятичной системе равно числу 8.</p>

<p> </p>

<p>Число 16 в двоичном представлении 10000. Если сдвинуть двоичное число 10000 на три разряда вправо (три последних разряда отбрасываются), то получится 10, что в десятичной системе представляет число 2.</p>

<p>В этих двух примерах исходные числа неотрицательны, количество позиций допустимо, результаты 8 и 2 помещаются в <code>int</code>. Переносить их разбор на любые знаковые значения нельзя. В C++17 сдвиг отрицательного значения влево имеет неопределённое поведение, а результат сдвига отрицательного значения вправо определяется реализацией; для неотрицательного сдвига влево также есть ограничение представимости. В C++20 левый сдвиг задан модульным правилом, а правый соответствует делению на степень двойки с округлением вниз. Ограничение количества позиций сохраняется в обеих версиях. Для битовых флагов удобно использовать беззнаковый тип и отдельно проверять число позиций.</p>
<h3>Поразрядные операции</h3>

<p>Поразрядные операции также проводятся только над соответствующими разрядами целочисленных операндов:</p>

<ul>
	<li>
	<p>&amp;: поразрядная конъюнкция (операция И или поразрядное умножение). Возвращает 1, если оба из соответствующих разрядов обоих чисел равны 1</p>
	</li>
	<li>
	<p>|: поразрядная дизъюнкция (операция ИЛИ или поразрядное сложение). Возвращает 1, если хотя бы один из соответствующих разрядов обоих чисел равен 1</p>
	</li>
	<li>
	<p>^: поразрядное исключающее ИЛИ. Возвращает 1, если только один из соответствующих разрядов обоих чисел равен 1</p>
	</li>
	<li>
	<p>~: поразрядное отрицание или инверсия. Инвертирует все разряды операнда. Если разряд равен 1, то он становится равен 0, а если он равен 0, то он получает значение 1.</p>
	</li>
</ul>

<p>Следующие независимые фрагменты внутри функции рассматриваются в C++20, где знаковые целые используют дополнительный код. В частности, ~9 равно -10:</p>

<pre><code class="language-cpp">int a = 5 | 2;          // 101 | 010 = 111  - 7

int b = 6 &amp; 2;          // 110 &amp; 010 = 10  - 2

int c = 5 ^ 2;          // 101 ^ 010 = 111 - 7

int d = ~9;             // -10</code></pre>

<p> </p>

<p>Например, выражение <code>5 | 2</code> равно 7. Число 5 в двоичной записи равно 101, а число 2 - 10 или 010. Сложим соответствующие разряды обоих чисел. При сложении если хотя бы один разряд равен 1, то сумма обоих разрядов равна 1. Поэтому получаем:</p>

<p> </p>

<table>
	<tbody>
		<tr>
			<td>1</td>
			<td>0</td>
			<td>1</td>
		</tr>
		<tr>
			<td>0</td>
			<td>1</td>
			<td>0</td>
		</tr>
		<tr>
			<td>1</td>
			<td>1</td>
			<td>1</td>
		</tr>
	</tbody>
</table>

<p>В итоге получаем число 111, что в десятичной записи представляет число 7.</p>

<p>Возьмем другое выражение <code>6 &amp; 2</code>. Число 6 в двоичной записи равно 110, а число 2 - 10 или 010. Умножим соответствующие разряды обоих чисел. Произведение обоих разрядов равно 1, если оба этих разряда равны 1. Иначе произведение равно 0. Поэтому получаем:</p>

<table>
	<tbody>
		<tr>
			<td>1</td>
			<td>1</td>
			<td>0</td>
		</tr>
		<tr>
			<td>0</td>
			<td>1</td>
			<td>0</td>
		</tr>
		<tr>
			<td>0</td>
			<td>1</td>
			<td>0</td>
		</tr>
	</tbody>
</table>

<p>Получаем число 010, что в десятичной системе равно 2.</p>

Указатели вводятся в <a href="https://stepik.org/lesson/770585/step/1" rel="noopener noreferrer nofollow">модуле 6</a>, а операции пользовательских типов — в <a href="https://stepik.org/lesson/877082/step/1" rel="noopener noreferrer nofollow">модуле 13</a>. <p>Меньший номер означает более высокий приоритет. Приоритет и ассоциативность определяют группировку выражения; они сами по себе не задают порядок вычисления всех его операндов.</p>
