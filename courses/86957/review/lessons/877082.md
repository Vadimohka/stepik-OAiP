<h3>Класс продолжает модель пользовательского типа</h3>

<p>В <a href="https://stepik.org/lesson/770596/step/1" rel="noopener noreferrer nofollow">теме структур</a> мы объединили связанные значения в собственный тип. В C++ <code>struct</code> и <code>class</code> описывают одну модель класса: у типа могут быть поля, функции-члены, конструкторы, деструктор и правила доступа. Различаются значения доступа по умолчанию: у <code>struct</code> члены и базы открытые, у <code>class</code> — закрытые.</p><p>Главная новая задача этого модуля — не заменить слово <code>struct</code>, а связать представление с допустимыми операциями. Например, уровень громкости может принимать значения от 0 до 100. Если хранить его в открытом поле <code>int</code>, любая часть программы может записать 150. Закрытое поле и проверяемая операция изменения позволяют поддерживать требуемое правило.</p><p>Правило, которое выполняется для каждого полностью созданного объекта до и после его публичных операций, называют <strong>инвариантом</strong>. Для нашего примера это <code>0 &lt;= value &amp;&amp; value &lt;= 100</code>. Конструктор устанавливает допустимое состояние, а изменяющие операции сохраняют его. Внутри реализации могут быть промежуточные состояния; они не должны становиться результатом завершившейся публичной операции.</p><p>Интерфейс — доступные пользователю типа операции и их контракты. Представление — поля и вспомогательные действия, которыми этот интерфейс реализован. Компилятор проверяет доступ и типы, но не доказывает смысловой инвариант автоматически: правильные проверки и реализацию пишет автор класса.</p><p>Класс может моделировать предмет, число, поток, контейнер или иной программный объект. C++ позволяет сочетать свободные функции, обычные структуры, обобщённый код и объектно-ориентированные интерфейсы. Для хорошей программы не требуется превращать каждую функцию в метод или каждую связь — в наследование. В <a href="https://stepik.org/lesson/877082/step/2" rel="noopener noreferrer nofollow">следующем шаге</a> покажем небольшой полный тип с ограниченным состоянием.</p>

<h3>Открытый интерфейс и закрытое состояние</h3>

<p><code>public</code> обозначает доступный снаружи интерфейс, <code>private</code> — члены, к которым по имени обращаются члены класса и его друзья. Секция доступа действует до следующей секции или конца класса. В <code>class</code> доступ <code>private</code> установлен по умолчанию.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

class Level {
    int value_{};
public:
    int value() const { return value_; }
    bool set(int next) {
        if (next &lt; 0 || next &gt; 100) return false;
        value_ = next;
        return true;
    }
};

int main() {
    Level level;
    std::cout &lt;&lt; level.value() &lt;&lt; '\n';
    std::cout &lt;&lt; std::boolalpha &lt;&lt; level.set(70) &lt;&lt; ' ' &lt;&lt; level.value() &lt;&lt; '\n';
    std::cout &lt;&lt; level.set(150) &lt;&lt; ' ' &lt;&lt; level.value() &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">0
true 70
false 70</code></pre><p>Поле <code>value_{}</code> получает ноль при создании, поэтому новый объект сразу допустим. <code>set(70)</code> возвращает <code>true</code> и изменяет состояние. <code>set(150)</code> возвращает <code>false</code> и оставляет прежнее значение 70. Проверка выполнена до присваивания: отказ не разрушает инвариант.</p><p>Запись <code>level.value_ = 150;</code> вне класса не компилируется, потому что поле закрыто. Метод <code>value() const</code> разрешает читать уровень, не меняя обычные поля через текущий объект; подробности <code>const</code> будут в <a href="https://stepik.org/lesson/877083/step/2" rel="noopener noreferrer nofollow">отдельном шаге</a>. Имена <code>value_</code> и <code>value()</code> различны: первое — поле, второе — операция чтения.</p><p>Третий вид доступа, <code>protected</code>, допускает использование из производных классов с дополнительными правилами; он нужен в <a href="https://stepik.org/lesson/877084/step/1" rel="noopener noreferrer nofollow">уроке о наследовании</a>. Пока у типа нет такой задачи, его внутреннее состояние оставляют <code>private</code>. Наличие метода <code>set</code> не обязательно: интерфейс выбирают по смыслу, а не создают автоматически отдельный setter для каждого поля.</p>

<h3>Члены класса, обычные функции и предварительное объявление</h3>

<p>Нестатическая функция-член, или метод, вызывается для конкретного объекта. Она имеет доступ к закрытым членам своего класса. Обычная свободная функция получает объекты через параметры и пользуется их открытым интерфейсом. При необходимости класс отдельно предоставляет функции или другому классу права доступа с помощью <code>friend</code>. Такая дружба не превращает свободную функцию в метод.</p><p>Фрагмент; определения и контекст указаны в объяснении:</p><pre><code class="language-cpp">void print_level(const Level&amp; level) {
    std::cout &lt;&lt; level.value() &lt;&lt; '\n';
}</code></pre><p>Фрагмент продолжает <a href="https://stepik.org/lesson/877082/step/2" rel="noopener noreferrer nofollow">полную программу с Level</a> и требует заголовка <code>&lt;iostream&gt;</code>. У функции нет <code>this</code>; объект приходит как параметр. <code>friend</code> здесь не нужен, потому что публичного метода <code>value()</code> достаточно. Поэтому представление <code>Level</code> можно менять, не переписывая эту функцию, пока сохраняется интерфейс.</p><p>Иногда имя типа нужно упомянуть до полного определения. Для указателя, ссылки или объявления функции достаточно предварительного объявления:</p><p>Фрагмент; определения и контекст указаны в объяснении:</p><pre><code class="language-cpp">class Item;
void print_item(const Item&amp; item);
struct Link {
    Item* next = nullptr;
};</code></pre><p>Компилятор уже знает, что <code>Item</code> — тип класса, но ещё не знает его поля и размер. Поэтому здесь можно объявить ссылочный параметр и указатель. Создать самостоятельный объект <code>Item</code> или обращаться к его членам можно после полного определения. Это именно предварительное объявление типа, а не «прототип с перечнем полей».</p><p>Конструктор и деструктор относятся к специальным функциям-членам, связанным с созданием и уничтожением объекта. Их рассмотрим в <a href="https://stepik.org/lesson/877081/step/3" rel="noopener noreferrer nofollow">уроке о конструкторах</a>. Разделение объявления и определения продолжает <a href="https://stepik.org/lesson/770592/step/2" rel="noopener noreferrer nofollow">многофайловое устройство программы</a>: имя типа и доступные объявления должны быть видимы в месте использования.</p>

<h3>Зачем типу нужен инвариант</h3>

<p>Функции и структуры уже позволяют хорошо разложить программу на части. Процедурная программа не обязана использовать глобальное состояние, а класс не гарантирует хороший проект сам по себе. Польза класса особенно заметна, когда несколько значений должны всегда согласовываться.</p><p>Фрагмент; определения и контекст указаны в объяснении:</p><pre><code class="language-cpp">struct Range {
    int low;
    int high;
};
Range range{10, 3}; // допустимо для языка, но не для интервала low &lt;= high</code></pre><p>Оба поля имеют тип <code>int</code>, поэтому проверка типов не обнаруживает смысловую ошибку. Если такой интервал используется поиском, сортировкой и выводом, всем функциям пришлось бы отдельно помнить правило <code>low &lt;= high</code>. При закрытом представлении конструктор проверяет правило один раз при создании, а операции изменения не позволяют нарушить его.</p><p>В <a href="https://stepik.org/lesson/877082/step/2" rel="noopener noreferrer nofollow">примере Level</a> это уже сделано: допустимы только значения 0–100, а неудачная попытка изменения сохраняет прежний уровень. Контракт метода отвечает на вопросы, какие входы он принимает, что возвращает при отказе и как меняет объект. Инвариант отвечает на другой вопрос: что всегда можно предполагать о корректно созданном объекте между вызовами.</p><p>Не всем данным нужен закрытый интерфейс. Для пары координат, чьи значения независимы и для которых допустима любая пара чисел, открытый <code>struct</code> может быть самым ясным решением. Для неотрицательной длины в футах и дюймах полезно потребовать нормализованный остаток дюймов; для открытого файла — связать доступ с владельцем ресурса.</p><p>В <a href="https://stepik.org/lesson/877081/step/2" rel="noopener noreferrer nofollow">примере Distance</a> последовательно построим такой тип: сначала зададим допустимое состояние, затем обеспечим его конструктором и сохраним при сложении. Существующие <a href="https://stepik.org/lesson/770590/step/1" rel="noopener noreferrer nofollow">контракты функций</a> продолжатся контрактами методов, а не будут заменены другой несвязанной моделью.</p>

<h3>Два объекта одного класса</h3>

<p>Определение класса задаёт тип. Объявление объекта создаёт конкретное состояние этого типа. Одна и та же функция-член может применяться к разным объектам.</p><p>Полная программа, C++17 и C++20:</p><pre><code class="language-cpp">#include &lt;iostream&gt;

class SomeClass {
    int data_{};
public:
    void setdata(int data) { data_ = data; }
    int data() const { return data_; }
};

int main() {
    SomeClass first, second;
    std::cout &lt;&lt; first.data() &lt;&lt; ' ' &lt;&lt; second.data() &lt;&lt; '\n';
    first.setdata(1066);
    second.setdata(1776);
    std::cout &lt;&lt; first.data() &lt;&lt; ' ' &lt;&lt; second.data() &lt;&lt; '\n';
    return 0;
}</code></pre><p>Результат:</p><pre><code class="language-no-highlight">0 0
1066 1776</code></pre><p>При создании поля обоих объектов получают ноль благодаря <code>int data_{}</code>. Поэтому метод чтения допустим сразу, без обязательного предварительного вызова <code>setdata</code>. У <code>first</code> и <code>second</code> отдельные поля; установка 1066 у первого не меняет второго.</p><p>Вызов <code>first.setdata(1066)</code> означает применение функции-члена к объекту <code>first</code>. Точка выбирает член, а круглые скобки выполняют вызов. При доступе через действительный указатель можно написать <code>pointer-&gt;setdata(1066)</code>. Закрытый доступ не мешает самим методам читать и изменять поле.</p><p>У этого учебного типа нет дополнительного ограничения значения: допустим любой <code>int</code>. Если добавить ограничение, метод изменения должен будет проверять его, как в <code>Level</code>. В следующем <a href="https://stepik.org/lesson/877081/step/1" rel="noopener noreferrer nofollow">уроке о методах</a> разберём, откуда метод знает текущий объект.</p>

<h3>Что относится к объекту, а что — к типу</h3>

<p>Каждый объект содержит свои нестатические поля. Код функции-члена не копируется внутрь каждого объекта как отдельный набор команд. Определения методов описывают операции типа; при вызове операция получает доступ к конкретному объекту.</p><p>В <a href="https://stepik.org/lesson/877082/step/5" rel="noopener noreferrer nofollow">полной программе с SomeClass</a> существуют два отдельных поля <code>data_</code>: одно у <code>first</code>, другое у <code>second</code>. Из этого не следует, что <code>sizeof(SomeClass)</code> обязательно равен <code>sizeof(int)</code>: представление объекта, заполнение и служебные данные зависят от его устройства и реализации.</p><p>Раздельные поля не всегда означают раздельные внешние данные. Если поле содержит указатель или ссылку, два объекта могут получать доступ к одному внешнему объекту:</p><p>Фрагмент; определения и контекст указаны в объяснении:</p><pre><code class="language-cpp">struct View { int* value; };
int number = 5;
View first{&amp;number};
View second{&amp;number};
*first.value = 8; // *second.value теперь тоже равно 8</code></pre><p>У <code>first</code> и <code>second</code> разные поля-указатели, но они обозначают один <code>number</code>. Копирование указателя не создаёт копию числа и не передаёт владение им. Доступ действителен только пока число существует. Это частный случай различия между состоянием объекта и ресурсами, к которым оно даёт доступ.</p><p>Оптимизация и встраивание вызовов относятся к реализации. Они не меняют правила наблюдаемого поведения и времени жизни. Сам факт общего кода методов также ничего не доказывает о безопасности параллельных обращений к общему состоянию. Модель совместного доступа и владения будет развита в <a href="https://stepik.org/lesson/853537/step/1" rel="noopener noreferrer nofollow">теме shared_ptr и weak_ptr</a>.</p>
