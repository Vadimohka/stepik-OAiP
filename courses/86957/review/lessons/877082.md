<h2>Что такое Класс в языках программирования?</h2>

<p>Термин «класс» в языке С++ употребляется для обозначения типов объектов, определяемых пользователем с ориентацией на технологию объектно ориентированного программирования. В отличие от определяемых в стиле языка С производных структурированных типов, таких как структуры или объединения, объявление класса позволяет наряду с описанием данных представления объектов указать и аспекты использования таких данных:</p>

<ol>
	<li>список функций доступа к объектам; </li>
	<li>правила наследования объектов производными классами; </li>
	<li>различная степень защиты элементов объектов.</li>
</ol>

<p>Функции доступа к объектам класса могут переопределять умалчиваемые операции создания и уничтожения объектов, а также позволить обозначать различные действия над объектами традиционными в языке С символами операций. Основная цель введения класса – отделение частных деталей представления объектов класса (скрытых данных и вспомогательных функций) от элементов, присущих объекту при правильном его использовании (открытые данные и функции доступа к любым данным). Пользователь класса может оперировать в программе его высокоуровневым внешним представлением, а контроль за корректностью использования данных и функций возлагается на компилятор.</p>

<p>В языке С++ определение классов ведется посредством расширения понятий структуры (struct) и объединения (union). Многие приёмы работы со структурами и объединениями из C сохраняются в C++, но эти языки не полностью совместимы: произвольная программа на C может потребовать изменений для сборки как C++. Синтаксис определения класса на языке С++ имеет вид:<br>
 </p>

<pre><code class="language-cpp">вид_класса имя_класса {

    описание_элементов_класса

};</code></pre>

<p>Определение класса представляет лишь описание некоторого типа объектов, имя которого «вид_класса имя_класса». Между символами «}» и «;» можно разместить список имен определяемых объектов класса с использованием при необходимости операции инициализации. Вне оператора определения класса объекты определяются операторами декларации вида: <code>вид_класса имя_класса список_имен_объектов;</code> </p>

<p>В большинстве случаев наиболее целесообразно определение класса и его элементов поместить в отдельный заголовочный файл. Рассмотрим подробнее элементы оператора определения класса. Элемент «вид_класса» может принимать значения struct, union или class. Вспомним, что различие между структурами и объединениями заключается в способе размещения их элементов в памяти – элементы структур располагаются последовательно, а элементы объединений размещаются от начального адреса одной и той же области, достаточной для размещения наибольшего из них. Необязательный для классов элемент «имя класса» задается идентификатором. Ввиду однозначности соответствия имени класса его виду при ссылке на тип класса элемент «вид класса» в языке С++ обычно опускается даже для структур и объединений. Например, пусть описана структура:</p>

<pre><code>struct subject {
    char fio[80];
    int dolg;
};</code></pre>

<p>Примеры ссылок на такой тип данных в стиле языка С:</p>

<pre><code class="language-cpp">struct subject teacher, *student;
student = (struct subject*)calloc(1, sizeof(struct subject));</code></pre>

<h2>Класс в языке С++</h2>

<p>Описание элементов класса может в общем случае включать декларацию элементов данных представления объекта и/или функций доступа к данным с указанием атрибутов права доступа. Иногда элементами являются описания собственных типов класса (например, структурированных типов объектов и перечислений). Принципиально возможно использование вложенных классов. Элементы класса могут иметь один из атрибутов права доступа:</p>

<ol>
	<li>private (закрытый) — доступ из членов класса и его друзей;</li>
	<li>protected (защищённый) — доступ из членов класса, его друзей и, с дополнительными ограничениями, из членов и друзей производных классов;</li>
	<li>public (открытый/публичный) – доступ из любых функций (элементы интерфейса пользователя класса).</li>
</ol>

<p>С атрибутами прав доступа мы будем подробно знакомиться далее. Пока исходите из простого принципа:</p>

<p><em>Если переменная (поле класса) должна изменяться только внутри класса (для этого достаточно желания программиста), то она будет с модификатором private, иначе с модификатором public.</em></p>

<p>Модификатор доступа <em>protected</em> будет нам необходим в теме "Наследование классов", поэтому в ближайшее время он упоминаться не будет.</p>

<p>Именованное объединение union в C++ может содержать public, protected и private члены; по умолчанию они public. Ограничение, запрещающее private и protected члены, относится к анонимным объединениям. Различие между классами видов struct и class есть лишь в значении по умолчанию атрибутов доступа: члены и базовые классы по умолчанию имеют доступ public у struct и private у class. Явное назначение атрибута доступа к элементам класса оформляется записью перед описанием элементов ключевого слова private, protected или public и символа «:» (для последующих элементов с совпадающим атрибутом доступа повторение описания этого атрибута не обязательно):</p>

<pre><code class="language-cpp">class date {
    // описание собственных типов класса
    // по умолчанию атрибут доступа private
    enum date_month { January = 1, February, March, April, May, June, July, August, September, October, November, December };

    // Декларация элементов данных класса
    int day, month, year; // private

// изменение атрибута доступа
public: 
    // Описание функций-элементов
    void set(int, int, int); // public
    void next(); // public

protected: // изменение атрибута доступа
    void print(); // protected
};
</code></pre>

<p>Очевидно, что декларация структуры <code>struct name { type xxx; .... }</code></p>

<p>Эквивалентна декларации класса:</p>

<pre><code class="language-cpp">class name {
public:
     type xxx;
     ....
};</code></pre>

<h2>Свойства классов в языке С++</h2>

<p>Элементы данных класса описываются обычным образом, но описание функций доступа может потребовать отражения их дополнительных свойств по отношению к классу. По отношению к праву доступа к защищенным элементам класса различают:</p>

<ol>
	<li>функции-элементы;</li>
	<li>дружественные функции класса.</li>
</ol>

<p>Среди функций, имеющих право доступа, можно выделить:</p>

<ol>
	<li>функции-конструкторы – создание объектов;</li>
	<li>функции-деструкторы – уничтожение объектов;</li>
	<li>функции определения операций над объектами.</li>
</ol>

<p>Функции-элементы и дружественные функции, перечисленные в описании класса, имеют право доступа ко всем элементам класса и к видимым в месте их использования глобальным именам. Функции-элементы находятся в области действия класса и вызываются с помощью операции выбора элемента структуры. Дружественные функции не находятся в области действия класса и вызываются по общим правилам. Внешние функции имеют право доступа только к открытым элементам класса. Особенности построения и использования функций доступа, ссылок на элементы класса и размещения их в памяти, а также правила построения производных классов рассматриваются ниже. Класс можно определить в пространстве имён, внутри другого класса или локально внутри функции. Для локальных классов действуют дополнительные ограничения; например, они не могут иметь статические члены данных. Иногда требуется упреждающая ссылка на имя некоторого класса class_name до его фактического определения. </p>

<h2><strong>Зачем нужны классы?</strong></h2>

<p>Перед тем как переходить от привычного процедурного программирования с объединением базовых типов в структуры, нужно понимать, зачем вообще придумали Классы и почему С++ именно объектно-ориентированный язык программирования, который был улучшением языка С.</p>

<p>Первым достоинством объектно-ориентированного программирования является то, что оно обеспечивает значительное сходство между объектами реального мира, моделируемыми программой, и объектами классов C++. Вся информация, касающаяся работы класса, описана при создании класса; там же описаны и все методы, то есть действия, которые можно производить с этой информацией. Это облегчает концептуализацию решаемой задачи.</p>

<p>Вы выделяете в задаче те элементы, которые целесообразно представлять в виде объектов, а затем помещаете все данные и функции, связанные с этим объектом, внутрь самого объекта. Если объект представляет игральную карту, то с помощью описания класса вы наделяете объект полями для хранения достоинства карты, ее масти, а также функциями, выполняющими действия по заданию этих величин, их изменению, выводу на экран, сравнению с заданными значениями и т. д. В процедурной программе, напротив, моделирование объектов реального мира возлагается на глобальные переменные и функции. Они не способны вместе образовать легко воспринимаемую модель.</p>

<p>Иногда при решении задачи бывает не столь очевидно, какие элементы реального мира следует представить в качестве объектов. Например, если вы пишете компьютерный вариант игры в шахматы, то что нужно представить в качестве объекта: шахматистов, клетки шахматной доски или игровую позицию целиком? Небольшие программы, такие, какими являются большинство приведённых примеров, можно создавать методом «проб и ошибок». Можно представить задачу в виде объектов каким-либо одним способом и написать определения классов для этих объектов. Если такое представление устроит вас, то вы можете продолжить разработку созданных классов. В противном случае следует выбрать другой способ представления задачи в виде совокупности объектов и повторить операцию создания классов.</p>

<p>Чем больше опыта вы наберете, создавая объектно-ориентированные программы, тем проще вам будет представлять новые задачи в терминах объектно-ориентированного программирования. При создании больших программ метод проб и ошибок оказывается <em>малоприменимым</em>. Для анализа поставленной задачи и создания классов и объектов, подходящих для ее решения, используется объектно-ориентированная разработка.</p>

<p>К вопросам объектно-ориентированной разработки мы будем возвращаться по мере изучения классов. Некоторые преимущества объектно-ориентированного программирования не столь очевидны. Помните о том, что ООП было создано, чтобы бороться со сложностью больших программ.</p>

<p>Программы небольшого размера, подобные созданным нами, в меньшей степени нуждаются в объектно-ориентированной организации. Чем больше программа, тем ощутимей эффект от использования ООП. Но даже для программ маленького размера применение объектно-ориентированного подхода способно принести определенную выгоду: например, по сравнению с процедурными программами увеличивается эффективность компилятора при поиске и выявлении ошибок концептуального уровня.</p>

<h2><strong>Определение объектов</strong></h2>

<p>Пример простого класса и его использование в функции main():</p>

<pre><code class="language-cpp">#include &lt;iostream&gt;

// определение класса
class SomeClass {
private:
    int somedata; // поле класса

public:
    // метод класса, изменяющий значение поля
    void setdata(int d) {  
        somedata = d; 
    }

    // метод класса, отображающий значение поля
    void showdata() { 
        std::cout &lt;&lt; "Значение поля равно " &lt;&lt; somedata &lt;&lt; std::endl;
    }
};

int main() {
    // определение двух объектов класса smallobj
    SomeClass s1, s2;

    // вызовы метода setdata()
    s1.setdata(1066); 
    s2.setdata(1776);

    // вызовы метода showdata()
    s1.showdata(); 
    s2.showdata();

    return 0;
}</code></pre>

<p>Первым оператором функции main() является SomeClass s1, s2; Этот оператор определяет два объекта s1 и s2 класса SomeClass. Обратите внимание на то, что при определении класса SomeClass <strong>не создаются никакие его объекты</strong>. Определение класса лишь задает вид будущего объекта, подобно тому, как определение структуры не выделяет память под структурные переменные, а лишь описывает их организацию. Все операции программа производит с объектами. Определение объекта похоже на определение переменной: оно означает выделение памяти, необходимой для хранения объекта.</p>

<h2>Данные класса</h2>

<p>Класс SomeClass содержит всего одно поле данных somedata, имеющее тип int. Данные, содержащиеся внутри класса, называют данными-членами или полями класса. Число полей класса, как и у структуры, теоретически может быть любым. Поскольку перед описанием поля somedata стоит ключевое слово private, это поле доступно только внутри класса.</p>

<h2><strong>Вызов функций класса</strong></h2>

<p>Следующая пара операторов осуществляет вызов функции (метода) setdata();</p>

<ul>
	<li>s1.setdata(1066);</li>
	<li>s2.setdata(1776);</li>
</ul>

<p>Эти операторы выглядят не так, как обычный вызов функции. Почему имена объектов s1 и s2 связаны с именами функций операцией точки (.)? Такой странный синтаксис объясняется тем, что вызов применим к методу <strong>конкретного объекта</strong>. Поскольку setdata() является нестатическим методом класса SomeClass, его вызов должен быть связан с объектом этого класса. Например, оператор setdata(1066); сам по себе не имеет смысла, потому что метод всегда производит действия с конкретным объектом, а не с классом в целом. Попытка доступа к классу по смыслу сходна попытке сесть за руль чертежа автомобиля. Кроме бессмысленности такого действия, компилятор расценил бы это как ошибку. Таким образом, вызов показанного нестатического метода связан с конкретным объектом. Статические методы, которые рассмотрим далее, могут вызываться без объекта. Для того чтобы получить доступ к методу класса, можно использовать операцию точки (.), связывающую метод с объектом, или операцию -&gt; при доступе через указатель. Синтаксически это напоминает доступ к полям структуры, но скобки позади имени метода говорят о том, что мы совершаем вызов функции, а не используем значение переменной (<em>операцию точки называют операцией доступа к члену класса</em>).</p>

<h2>Классы, объекты и память</h2>

<p>Возможно, что в процессе изучения классов и объектов у вас сформировалось представление об объекте как о копии класса с точки зрения внутренней структуры. Это представление адекватно лишь в первом приближении. Оно акцентировано на том, что объекты являются самодостаточными программными единицами, созданными по образцу, представленному определением класса. Возможно, здесь уместна аналогия с машинами, сходящими с конвейера, каждая из которых построена согласно стандарту своей модели. Машины в этом смысле схожи с объектами, а модели — с классами. На самом деле все устроено несколько сложнее. Верно, что каждый объект имеет собственные независимые поля данных. С другой стороны, все объекты одного класса используют одни и те же методы. Код методов не является частью хранимого представления каждого объекта. Конкретное размещение кода и встраивание вызовов определяются компилятором; объявление класса само по себе не выполняется как команда создания методов.</p>

<p>Это вполне логически оправданно: нет никакого смысла держать в памяти копии методов для каждого объекта данного класса, поскольку у всех объектов методы одинаковы. А поскольку наборы значений полей у каждого объекта свои, поля объектов не должны быть общими. Это значит, что при создании объектов каждый из наборов данных занимает определенную совокупность свободных мест в памяти.</p>

<p><img alt="" height="417" name="Frame 42.png" src="https://ucarecdn.stepik.net/5dba59cb-2435-4e45-a159-096c202a0c6b/-/crop/6968x4191/0,328/-/preview/" width="692"></p>

<p>В примере SomeClass были созданы два объекта типа SomeClass, что означало наличие двух полей с именем somedata в памяти. При этом у объектов нет собственных копий кода setdata() и showdata(): оба пользуются определениями одних и тех же методов. Между объектами не возникает конкуренции за общий ресурс (по крайней мере, в системах с последовательной обработкой), поскольку в любой момент времени выполняется не более одной функции. В большинстве ситуаций вам не нужно использовать тот факт, что объекты не содержат отдельные копии кода методов. Разумеется, гораздо проще представить себе объекты, которые включают в себя как данные, так и функции. Однако в некоторых ситуациях, например при оценке размера программы, необходимо знать, какова ее внутренняя организация.</p>
