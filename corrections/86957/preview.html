Реализуйте конвертер из формата YAML в формат INI.

Каждый набор входных данных является корректным YAML-файлом со следующими ограничениями:

  • YAML-файл состоит только из словарей произвольной вложенности.
  • Один уровень отступа задаётся четырьмя пробелами; символ табуляции не используется.
  • Каждая строка содержит объявление словаря (section:) или объявление пары ключ-значение (key: value), где ключ и значение разделены символами двоеточия и пробелом.
  • Все имена словарей, ключи и значения непустые, состоят из строчных латинских букв и имеют длину не больше 10.
  • В каждом словаре все имена ключей и непосредственно вложенных словарей уникальны.
  • В каждом словаре содержится как минимум одна пара ключ-значение, либо на некотором уровне вложенности этого словаря содержится пара ключ-значение. Иными словами, пустых словарей нет.

    Преобразуйте данные YAML-файлы в формат INI.
  • Пара ключ-значение форматируется как key = value, то есть ключ и значение разделены символами пробела, равно и пробела.
  • Порядок вывода пар ключ-значение должен оставаться строго таким же, как в исходном YAML-файле. 
  • Перед каждой парой ключ-значение следует вывести путь до неё, то есть имена словарей в квадратных скобках, разделенные точкой.
  • Если две или более подряд идущие пары ключ-значение имеют одинаковый путь, его следует вывести ровно один раз для всей группы пар ключ-значение.
  • Если путь до некоторой пары ключ-значение (или группы подряд идущих пар) пустой, то есть не содержит ни одного словаря, путь следует опустить.
  • Все описания групп пар ключ-значение должны быть разделены одной пустой строкой.
  • После вывода очередного INI-файла следует вывести одну пустую строку.

Каждый тест состоит из нескольких наборов входных данных. Первая строка содержит целое число 𝑡 (1 ≤ 𝑡 ≤ 5*10^4) — количество наборов входных данных. Далее следуют описания наборов входных данных. Первая строка каждого набора входных данных содержит одно целое число 𝑛 (1 ≤ 𝑛 ≤ 10^5) — количество строк в YAML-файле. Следующие 𝑛 строк содержат сам YAML-файл. Гарантируется, что размер входных данных не превосходит 1 мегабайт.

Для каждого набора входных данных выведите соответствующий INI-файл. После вывода каждого INI-файла выводите одну пустую строку. Гарантируется, что размер корректных выходных данных не превосходит 1 мегабайт.

Побитовые операции в языке С++

Побитовые операции выполняются над отдельными разрядами или битами чисел. Данные операции производятся только над целыми числами.

Операции сдвига

Каждое целое число в памяти представлено в виде определенного количества разрядов. И операции сдвига позволяют сдвинуть битовое представление числа на несколько разрядов вправо или влево. Операции сдвига применяются только к целочисленным операндам. Есть две операции:

  • <<

    Сдвигает битовое представление числа, представленного первым операндом, влево на определенное количество разрядов, которое задается вторым операндом.

  • >>

    Сдвигает битовое представление числа вправо на определенное количество разрядов.

Количество сдвигаемых разрядов должно быть неотрицательным и меньше ширины типа левого операнда после целочисленного продвижения. Нарушение этого условия приводит к неопределённому поведению.

Применение операций

int a = 2 << 2;           // 10  на два разряда влево = 1000 - 8

int b = 16 >> 3;          // 10000 на три разряда вправо = 10 - 2

 

Число 2 в двоичном представлении 10. Если сдвинуть число 10 на два разряда влево, то получится 1000, что в десятичной системе равно числу 8.

 

Число 16 в двоичном представлении 10000. Если сдвинуть двоичное число 10000 на три разряда вправо (три последних разряда отбрасываются), то получится 10, что в десятичной системе представляет число 2.

Поразрядные операции

Поразрядные операции также проводятся только над соответствующими разрядами целочисленных операндов:

  • &: поразрядная конъюнкция (операция И или поразрядное умножение). Возвращает 1, если оба из соответствующих разрядов обоих чисел равны 1

  • |: поразрядная дизъюнкция (операция ИЛИ или поразрядное сложение). Возвращает 1, если хотя бы один из соответствующих разрядов обоих чисел равен 1

  • ^: поразрядное исключающее ИЛИ. Возвращает 1, если только один из соответствующих разрядов обоих чисел равен 1

  • ~: поразрядное отрицание или инверсия. Инвертирует все разряды операнда. Если разряд равен 1, то он становится равен 0, а если он равен 0, то он получает значение 1.

Следующие примеры рассматриваются в C++20, где знаковые целые используют дополнительный код. В частности, ~9 равно -10:

int a = 5 | 2;          // 101 | 010 = 111  - 7

int b = 6 & 2;          // 110 & 010 = 10  - 2

int c = 5 ^ 2;          // 101 ^ 010 = 111 - 7

int d = ~9;             // -10

 

Например, выражение 5 | 2 равно 7. Число 5 в двоичной записи равно 101, а число 2 - 10 или 010. Сложим соответствующие разряды обоих чисел. При сложении если хотя бы один разряд равен 1, то сумма обоих разрядов равна 1. Поэтому получаем:

 

1 0 1
0 1 0
1 1 1

В итоге получаем число 111, что в десятичной записи представляет число 7.

Возьмем другое выражение 6 & 2. Число 6 в двоичной записи равно 110, а число 2 - 10 или 010. Умножим соответствующие разряды обоих чисел. Произведение обоих разрядов равно 1, если оба этих разряда равны 1. Иначе произведение равно 0. Поэтому получаем:

1 1 0
0 1 0
0 1 0

Получаем число 010, что в десятичной системе равно 2.

Конструкция switch

Другую форму организации ветвления программ представляет конструкция switch...case. Она имеет следующую форму:

switch (выражение) {
    case константа_1: инструкции_1;
    case константа_2: инструкции_2;
    default: инструкции;
}

Реализация может ограничивать количество меток case. В справочном приложении к стандарту C++ среди рекомендуемых ориентиров приведено 16 384 метки в одном switch; это не требование написать столько ветвей.

После ключевого слова switch в скобках задаётся условие. Его значение должно иметь целочисленный тип, тип перечисления либо тип класса с допустимым преобразованием к одному из них. Управление передаётся к совпавшей метке case. Значения меток должны быть константными выражениями и не должны совпадать после преобразования к типу условия. Стандарт не требует последовательного перебора всех меток.

В конструкции switch может присутствовать метка default, обычно её размещают в конце. Выполняется в том случае, если значение после switch не соответствует ни одному из операторов case. Он необязателен, но его рекомендуют использовать всегда. Например:

#include <iostream>

int main() {
    int x = 2;
    switch(x) {
        case 1:
            std::cout << "x = 1" << "\n";
            break;
        case 2:
            std::cout << "x = 2" << "\n";
            break;
        case 3:
            std::cout << "x = 3" << "\n";
            break;
        default:
            std::cout << "x is undefined" << "\n";
            break;
    }
    return 0;
}

Чтобы избежать выполнения последующих блоков case/default, в конце каждого блока ставится оператор break. То есть в данном случае будет выполняться оператор

case 2:
    std::cout << "x = 2" << "\n";
    break;

После выполнения оператора break произойдет выход из конструкции switch..case, и остальные операторы case будут проигнорированы. Поэтому на консоль будет выведена следующая строка

x = 2

Стоит отметить важность использования оператора break. Если мы его не укажем в блоке case, то после этого блока выполнение перейдет к следующему блоку case. Например, уберем из предыдущего примера все операторы break:

#include <iostream>

int main() {
    int x = 2;
    switch(x) {
        case 1:
            std::cout << "x = 1" << "\n";
        case 2:
            std::cout << "x = 2" << "\n";
        case 3:
            std::cout << "x = 3" << "\n";
        default:
            std::cout << "x is undefined" << "\n";
    }
    return 0;
}

В этом случае опять же будет выполняться оператор case 2:, так как переменная x=2. Однако так как этот блок case не завершается оператором break, то после его завершения будет выполняться набор инструкций после case 3: даже несмотря на то, что переменная x по-прежнему равна 2. В итоге мы получим следующий консольный вывод:

x = 2
x = 3
x is undefined

*В C++ при работе со switch стоит внимательно следить за переходом к следующей метке при отсутствии break. В сложных конструкциях такой переход легко пропустить. О плюсах и минусах данного оператора можно почитать в прикреплённых статьях.

switch vs if-else

Скорость switch и if-else зависит от компилятора, настроек оптимизации, распределения значений и целевой машины. Стандарт не задаёт, как именно должны быть реализованы эти конструкции. Например, switch может превратиться в:

  • Последовательность сравнений и условных переходов.
  • Дерево сравнений, сокращающее число проверок для некоторых наборов значений.
  • Таблицу переходов (jump table), где вычисленный индекс выбирает адрес ветви. Это не хеш-таблица.

Для небольшого числа ветвей разница часто несущественна. Выбирайте подходящую по смыслу и читаемости конструкцию, а значимые для программы различия в скорости проверяйте измерениями.

Цикл while

Цикл while выполняет некоторый код, пока его условие истинно, то есть возвращает true. Он имеет следующее формальное определение:

while (условие) {
    // выполняемые действия
}

После ключевого слова while в скобках записывается условие, значение которого приводится к bool. Затем следует тело цикла. Перед каждой итерацией условие проверяется снова: при true выполняется тело, при false цикл завершается.

Например, выведем квадраты чисел от 1 до 9:

#include <iostream>

int main() {
    int i = 1;
    while (i < 10) {
        std::cout << i << " * " << i << " = " << i * i << std::endl;
        i++;
    }
    return 0;
}

 

Здесь пока условие i < 10 истинно, будет выполняться цикл while, в котором выводится на консоль квадрат числа и инкрементируется переменная i. В какой-то момент переменная i увеличится до 10, условие i < 10 возвратит false, и цикл завершится.

 

Консольный вывод программы:

1 * 1 = 1
2 * 2 = 4
3 * 3 = 9
4 * 4 = 16
5 * 5 = 25
6 * 6 = 36
7 * 7 = 49
8 * 8 = 64
9 * 9 = 81

Каждый отдельный проход цикла называется итерацией. То есть в примере выше было 9 итераций.

Если цикл содержит одну инструкцию, то фигурные скобки можно опустить:

int i = 0;
while (++i < 10) std::cout << i << " * " << i << " = " << i * i << std::endl;

Цикл for

Цикл for имеет следующее формальное определение:

for (инициализация; условие; выражение_приращения) {
    // тело цикла
}

 

инициализация выполняется один раз в начале цикла и задаёт начальные условия; как правило, это инициализация счетчиков - специальных переменных, которые используются для контроля за циклом.

 

условие проверяется перед каждой итерацией. Как правило, в качестве условия используется операция сравнения, и если она возвращает ненулевое значение (то есть условие истинно), то выполняется тело цикла, а затем вычисляется выражение_приращения.

выражение_приращения задаёт изменение параметров цикла, нередко здесь происходит увеличение счетчиков цикла на единицу.

Например, перепишем программу по выводу квадратов чисел с помощью цикла for:

#include <iostream>

int main() {
    for (int i = 1; i < 10; i++) {
        std::cout << i << " * " << i << " = " << i * i << std::endl;
    }
    return 0;
}

 

Первая часть объявления цикла - int i = 1 - создает и инициализирует счетчик i. Фактически это то же самое, что и объявление и инициализация переменной. Счетчик необязательно должен представлять тип int. Это может быть и другой числовой тип, например, float. И перед выполнением цикла его значение будет равно 1.

 

Вторая часть - условие, при котором будет выполняться цикл. В данном случае цикл будет выполняться, пока переменная i не станет равна 10.

И третья часть - приращение счетчика на единицу. Опять же нам необязательно увеличивать на единицу. Можно уменьшать: i--. Можно изменять на другое значение: i+=2.

В итоге блок цикла сработает 9 раз, пока переменная i не станет равна 10. И каждый раз это значение будет увеличиваться на 1. И по сути мы получим тот же самый результат, что и в случае с циклом while в предыдущем шаге.

Необязательно заполнять все три части заголовка: можно опустить любую из них или все сразу, сохранив обе точки с запятой. Отсутствующее условие считается истинным:

int i = 1;
for (; i < 10;) {
    std::cout << i << " * " << i << " = " << i * i << std::endl;
    i++;
}

 

Формально определение цикла осталось тем же, только теперь инициализация и выражение приращения в заголовке отсутствуют: for (; i < 10;). Переменная-счетчик определена и инициализирована вне цикла, а ее приращение происходит в самом цикле.

Куча (Heap)

В распространённых реализациях динамические объекты получают память из кучи (heap). Стандарт C++ описывает продолжительность хранения и операции выделения/освобождения, но не требует единственной конкретной схемы стека и кучи.

В языке C++ при использовании оператора new динамическая память выделяется из сегмента кучи самой программы (советую сейчас перейти к предыдущему разделу и вспомнить устройство адресного пространства процесса, чтобы понимать где мы выделяем память):

int *ptr = new int; // выделяется память для одного int, sizeof(int) байт
int *array = new int[10]; // выделяется массив из 10 int; данные занимают 10 * sizeof(int) байт

Выражение new возвращает указатель на созданный объект. Его можно сохранить, например, в локальной переменной. В типичной реализации такой указатель может находиться на стеке, а созданный объект — в куче; однако указатели могут быть и глобальными переменными, и полями других объектов.

Стоит знать, что последовательные запросы на динамическое выделение памяти не всегда приводят к выделению соседних блоков памяти: расположение выделенных блоков определяет реализация:

int *ptr1 = new int;
int *ptr2 = new int;
// ptr1 и ptr2 могут не иметь последовательных адресов памяти

delete завершает время жизни динамического объекта и освобождает занятую им память. Саму переменную-указатель эта операция не удаляет и не обнуляет. Прежний указатель становится висячим; чтение через него имеет неопределённое поведение независимо от того, сохранились ли прежние байты. Освобождённый блок может остаться у менеджера памяти для следующих выделений; немедленный возврат физической памяти операционной системе не гарантируется.

int* block = new int(100);
std::cout << *block << std::endl; // 100: объект ещё существует
delete block;
block = nullptr;
// std::cout << *block; // Недопустимо: nullptr нельзя разыменовывать.

Присваивание nullptr позволяет явно отметить отсутствие объекта и проверить указатель перед использованием. Оно не разрешает разыменование нулевого указателя и не изменяет другие копии прежнего адреса.

Куча имеет следующие преимущества и недостатки:

  • Выделение памяти в куче сравнительно медленное.
  • Выделенная память остается выделенной до тех пор, пока не будет освобождена (остерегайтесь утечек памяти) или пока программа не завершит свое выполнение.
  • К динамическому объекту обращаются через указатели или ссылки. Скорость доступа зависит от сгенерированного кода и расположения данных; само использование указателя не гарантирует замедления.
  • Поскольку куча представляет собой большой резервуар памяти, то именно она используется для выделения больших массивов, структур или классов.

Стек (Stack)

Стек вызовов в типичной реализации хранит сведения об активных вызовах функций и часть их локальных данных. Некоторые параметры и переменные могут находиться в регистрах либо быть устранены оптимизацией; локальные переменные с static имеют другое время хранения.

Стек реализуется как структура данных «Стек». Поэтому, прежде чем мы поговорим о том, как работает сам стек в адресном пространстве, нам нужно понять, что такое стек как структура данных.

Структура данных в программировании — это механизм организации данных для их эффективного использования. Вы уже видели несколько типов структур данных, например, массивы или структуры. Существует множество других структур данных, которые используются в программировании, одной из таковых является стек.

В компьютерном программировании стек представляет собой контейнер (как структуру данных), который содержит несколько переменных (подобно массиву). Однако, в то время как массив позволяет получить доступ и изменять элементы в любом порядке (так называемый «произвольный доступ»), стек более ограничен. Вы можете:

  • Посмотреть на верхний элемент стека (используя функцию top() или peek())
  • Вытянуть верхний элемент стека (используя функцию pop())
  • Добавить новый элемент поверх стека (используя функцию push())

Стек — это структура данных типа LIFO (англ. «Last In, First Out» = «Последним пришел, первым ушел»). Последний элемент, который находится на вершине стека, первым и уйдет из него. Если положить новую тарелку поверх других тарелок, то именно эту тарелку вы первой и возьмете. По мере того, как элементы помещаются в стек — стек растет, по мере того, как элементы удаляются из стека — стек уменьшается. Условно стек можно изобразить следующим образом:

Об этом в дальнейшем у вас будет предмет под названием «Архитектура вычислительных систем», на котором вам подробно, на уровне ассемблера, расскажут, как это устроено. Мы же рассмотрим стек лишь упрощённо.

Автоматические локальные объекты обычно прекращают существование при выходе из их блока. Для объектов классов при этом вызываются деструкторы. В реализации со стеком соответствующее место затем можно использовать повторно; физическое стирание прежних байтов не требуется.

Управление стеком обычно сводится к простым операциям с его вершиной. Доступный размер стека ограничен настройками реализации и среды; слишком глубокие вызовы или крупные автоматические объекты могут привести к его переполнению. Допустимый объём динамической памяти обычно существенно больше.

Работа с массивами в языке С

Динамическое создание одномерного массива мы рассмотрим на примере. Пусть длина массива неизвестна и вводится во время выполнения программы пользователем:

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    unsigned n;
    printf("Size of array (1..100000)=");
    if (scanf("%u", &n) != 1 || n == 0 || n > 100000) {
        return 1;
    }
    int* block = malloc((size_t)n * sizeof *block);
    if (block == NULL) {
        return 1;
    }
    // Здесь можно работать с n элементами после их инициализации.
    free(block);
    block = NULL;
    return 0;
}

 

Для динамического создания двумерного массива сначала необходимо создать массив указателей, после чего каждому из элементов этого массива присвоить адрес нового массива.
Для удаления массива необходимо повторить операцию в обратном порядке - удалить сначала подмассивы, а потом и сам массив указателей.

#include <stdlib.h>

int main(void) {
    const size_t rowNum = 10, colNum = 10;
    float** p = malloc(rowNum * sizeof *p);
    if (p == NULL) {
        return 1;
    }
    for (size_t i = 0; i < rowNum; ++i) {
        p[i] = malloc(colNum * sizeof *p[i]);
        if (p[i] == NULL) {
            while (i > 0) {
                free(p[--i]);
            }
            free(p);
            return 1;
        }
    }
    // Здесь можно работать с таблицей после инициализации элементов.
    for (size_t i = 0; i < rowNum; ++i) {
        free(p[i]);
    }
    free(p);
    return 0;
}

Сначала создаём массив указателей, а после этого каждому элементу этого массива присваиваем адрес вновь созданного массива. Это значит, что можно:

  • Создавать массивы "неправильной формы", то есть массив строк, каждая из которых имеет свой размер.
  • Работать по отдельности с каждой строкой массива: освобождать память или изменять размер строки.

Функции realloc и calloc

Функция calloc выделяет место для num элементов по size байт и обнуляет все байты блока. Для массива int это даёт нулевые значения; обнуление байтов не является универсальным способом получить нулевой указатель или значение любого другого типа. При неудаче возвращается NULL.

void* calloc(size_t num, size_t size);

Ещё одна важная функция – realloc (re-allocation). Она позволяет изменить размер ранее выделенной памяти, адрес которой хранит указатель ptr, и получает в качестве аргументов этот указатель и новый размер памяти в байтах. Если указатель ptr имеет значение NULL, то есть память не выделялась, то действие функции аналогично действию malloc:

void* realloc(void* ptr, size_t size);

Функция realloc может как использовать ранее выделенный участок памяти, так и новый. При этом не важно, меньше или больше новый размер – менеджер памяти сам решает, где выделять память.

calloc выделяет новый обнулённый блок, а realloc изменяет размер ранее выделенного блока. Результат realloc сначала сохраняют во временный указатель: при неудаче с ненулевым размером старый блок остаётся действительным. Ниже n и new_n положительны, а вычисляемые размеры помещаются в size_t:

size_t n = 10, new_n = 20;
int* block = malloc(n * sizeof *block);
int* zeroed = calloc(n, sizeof *zeroed);
if (block == NULL || zeroed == NULL) {
    free(block);
    free(zeroed);
    return 1;
}
int* replacement = realloc(block, new_n * sizeof *block);
if (replacement != NULL) {
    block = replacement;
}
// При отказе realloc блок block по-прежнему принадлежит нам.
free(block);
free(zeroed);


Пример, в котором удобно использовать функцию realloc – пользователь вводит слова. Для начала выделяем под слова массив размером 10. Если пользователь ввёл больше слов, то изменяем его размер при помощи функции realloc, чтобы хватило места. Когда пользователь вводит слово end, прекращаем ввод и выводим на печать все слова.

В этом примере длина одного слова ограничена 127 байтами без завершающего нулевого символа. Ограничение %127s защищает буфер, но оставляет продолжение слишком длинного слова во входном потоке. Поэтому после чтения проверяем следующий байт: это должен быть пробельный символ или конец ввода. Более длинное слово вызывает сообщение об ошибке и освобождение уже выделенной памяти; его части не становятся отдельными словами или командой end.

#include <ctype.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    size_t capacity = 10;
    size_t count = 0;
    char** words = malloc(capacity * sizeof *words);
    char buffer[128];
    int failed = 0;
    if (words == NULL) {
        return 1;
    }
    while (scanf("%127s", buffer) == 1) {
        int next = getchar();
        if (next != EOF && !isspace((unsigned char)next)) {
            failed = 2;
            break;
        }
        if (strcmp(buffer, "end") == 0) {
            break;
        }
        if (count == capacity) {
            if (capacity > SIZE_MAX / sizeof *words - 10) {
                failed = 1;
                break;
            }
            size_t new_capacity = capacity + 10;
            char** replacement = realloc(words, new_capacity * sizeof *words);
            if (replacement == NULL) {
                failed = 1;
                break;
            }
            words = replacement;
            capacity = new_capacity;
        }
        words[count] = malloc(strlen(buffer) + 1);
        if (words[count] == NULL) {
            failed = 1;
            break;
        }
        strcpy(words[count], buffer);
        ++count;
    }
    for (size_t i = 0; i < count; ++i) {
        puts(words[i]);
        free(words[i]);
    }
    free(words);
    if (failed) {
        fputs(failed == 2 ? "Word is too long\n" : "Cannot allocate memory\n", stderr);
        return 1;
    }
    return 0;
}

Для таблицы указателей нужен размер одного указателя: sizeof *words равен sizeof(char*). Для самих символов используют sizeof(char), который всегда равен 1.

Ошибки при выделении памяти

Рассмотрим ошибки управления памятью и способы их избежать. Для функций malloc, calloc, realloc и free в этом разделе используются правила C11/C17. Недопустимые операции ниже оставлены только в комментариях; выполняемый код показывает исправленные варианты.

Как реагировать на нехватку памяти, определяет задача: можно завершить текущую операцию, освободить ненужные данные или сообщить пользователю об ошибке. Игнорировать возвращённый NULL нельзя. Разыменование нулевого указателя имеет неопределённое поведение и не гарантирует исключение C++ или сигнал операционной системы. nullptr в C++ имеет отдельный тип std::nullptr_t; он не обозначает доступную ячейку памяти по адресу ноль.

2. Потеря начала выделенного блока

В free передают нулевой указатель либо указатель на начало ещё не освобождённого блока, полученный от функции выделения памяти. Указатель на середину массива передавать нельзя. Для обхода удобно хранить отдельный указатель:

int* base = malloc(100 * sizeof *base);
if (base == NULL) {
    return 1;
}
int* current = base + 1;
*current = 42;
// free(current); // Ошибка: это не начало выделенного блока.
free(base);
base = NULL;
current = NULL;

3. Использование освобождённой памяти

После free время жизни размещённых в блоке объектов заканчивается. Прежний указатель становится висячим (dangling pointer). Обнуление одной переменной не меняет другие копии указателя и не делает доступ через них допустимым.

int* p = malloc(sizeof *p);
if (p == NULL) {
    return 1;
}
*p = 42;
free(p);
p = NULL;
// printf("%d", *p); // Ошибка: разыменование NULL также имеет UB.
if (p != NULL) {
    printf("%d", *p);
}

После free(p); p = NULL; проверка p != NULL позволяет пропустить запрещённый доступ. Само присваивание NULL не превращает последующее разыменование в определённое поведение и не обещает исключение.

4. Повторное освобождение

Каждый выделенный блок освобождают ровно один раз. Повторный free с прежним ненулевым указателем имеет неопределённое поведение. Обнуление помогает предотвратить повторное освобождение через ту же переменную:

int* p = malloc(sizeof *p);
if (p == NULL) {
    return 1;
}
free(p);

5. Несколько указателей и realloc

Несколько указателей могут обозначать один блок, но после успешного realloc старый объект освобождён, а действительным является возвращённый указатель на новый объект. Это правило действует даже тогда, когда числовое значение адреса не изменилось. Старые алиасы нужно обновить до дальнейшего использования. При неудаче realloc с ненулевым размером прежний блок и его данные сохраняются.

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int* p1 = malloc(10 * sizeof *p1);
    if (p1 == NULL) {
        return 1;
    }
    for (int i = 0; i < 10; ++i) {
        p1[i] = i;
    }
    int* p2 = p1;
    int* replacement = realloc(p1, 20 * sizeof *p1);
    if (replacement == NULL) {
        free(p1);
        return 1;
    }
    p1 = replacement;
    p2 = p1; // Обновляем алиас после успешного realloc.
    for (int i = 0; i < 10; ++i) {
        printf("%d ", p2[i]);
    }
    free(p1);
    p1 = NULL;
    p2 = NULL;
    return 0;
}

Нулевой размер: правила C11/C17

Для malloc(0) и calloc с нулевым общим размером результат определяется реализацией: возвращается NULL либо особый указатель, который можно передать в free, но через который нельзя обращаться к объектам. Это не следует называть неопределённым поведением самого вызова. По правилам C11/C17 realloc(NULL, n) эквивалентен malloc(n), в том числе при n = 0.

Правила realloc(p, 0) менялись между версиями C. Не используйте нулевой размер как переносимый способ освобождения: когда блок больше не нужен, явно вызовите free(p) и обнулите соответствующие указатели. Все вызовы realloc в исполняемых примерах выше имеют ненулевой размер.

Указатель на структуру создаётся как обычно. Отличие заключается в том, что можно обращаться к полям структуры через указатель с помощью операции "стрелка" (минус + больше). #include <stdlib.h>
#include <string.h>

    char *login;
    char *password;
    int id;

    printf("{id: %d, login: \"%s\", password: \"%s\"}\n",
            user->id, user->login, user->password);

    unsigned i;
    for (i = 0; i < size; i++) {
        free((*users)[i].login);
        free((*users)[i].password);
    }
    free(*users);
}

int main() {
    User *users = NULL;
    unsigned size;
    char buffer[128];
    unsigned i;

    printf("Enter number of users: ");
    if (scanf("%u", &size) != 1) return 1;

    size = size <= MAX_SIZE? size: MAX_SIZE;
    users = (User*) malloc(size * sizeof(User));
    if (size != 0 && users == NULL) return 1;
    for (i = 0; i < size; i++) {
        users[i].login = NULL;
        users[i].password = NULL;
    }

    for (i = 0; i < size; i++) {
        printf("user #%u\nname: ", i);
        if (scanf("%127s", buffer) != 1) {
            freeUsersArray(&users, size);
            return 1;
        }
        users[i].id = i;
        users[i].login = (char*) malloc(strlen(buffer) + 1);
        if (users[i].login == NULL) {
            freeUsersArray(&users, size);
            return 1;
        }
        strcpy(users[i].login, buffer);
        printf("password: ");
        if (scanf("%127s", buffer) != 1) {
            freeUsersArray(&users, size);
            return 1;
        }
        users[i].password = (char*) malloc(strlen(buffer) + 1);
        if (users[i].password == NULL) {
            freeUsersArray(&users, size);
            return 1;
        }

Что такое объединение в языке C++?

Объединение – это группирование переменных, которые разделяют одну и ту же область памяти. В зависимости от интерпретации осуществляется обращение к той или другой переменной объединения. Все нестатические поля объединения начинаются по одному адресу.

Объединение позволяет представить в компактном виде данные, которые могут изменяться. Одни и те же данные могут быть представлены разными способами с помощью объединений.

Точно так же, как и структуры, объединения требуют объявления типа (шаблона) и объявления переменной этого типа.

Объявление объединения (типа объединения или шаблона объединения) начинается с ключевого слова union.

union имя_типа_объединения {
    тип переменная1;
    тип переменная2;
    ...
    тип переменнаяN;
};

 Где:

  • имя_типа_объединения – непосредственно имя вновь созданного типа;
  • переменная1, переменная2, переменнаяN – переменные, которые являются полями объединения. Эти переменные могут быть разных типов;
  • тип – тип переменной, который является полем объединения.

Тип переменной может быть:

  • базовым типом, принятым в языке C++;
  • тип структура;
  • тип объединения;
  • тип класс.

Размер объединения

Длина объединения – это размер памяти в байтах, которая выделяется для одной переменной этого типа объединения.

Размер объединения не меньше размера любого его нестатического поля. Он может превышать максимум размеров полей из-за требований выравнивания и конечного заполнения. Точный размер даёт sizeof. В каждый момент активен не более чем один член union. Для простых членов, как int или double в следующих примерах, встроенное присваивание может начать время жизни нового члена и закончить время жизни прежнего. Это не общее правило для любого класса: например, присваивание неактивному полю std::string не создаёт строку. Для нетривиальных членов нужно отдельно управлять конструированием и уничтожением; union не вызывает деструктор прежнего члена автоматически. Чтение неактивного члена в общем случае имеет неопределённое поведение в ISO C++17/20.

Если надо считать всю строку целиком или даже все строки из файла, то лучше использовать библиотечную функцию std::getline(), которая принимает поток для чтения и переменную, в которую надо считать текст:

#include <iostream>
#include <fstream>
#include <string>

#include <iostream>
#include <fstream>
#include <vector>

struct Operation {
    int sum;        // купленная сумма
    double rate;    // по какому курсу

};

int main() {
    std::vector<Operation> operations = {
        Operation(120, 57.7),
        Operation(1030, 57.4),
        Operation(980, 58.5),
        Operation(560, 57.2)
    };

    std::ofstream out("D:\\operations.txt"); // открываем файл для записи

    if (out.is_open()) {
        for (int i = 0; i < operations.size(); i++) {
            out << operations[i].sum << " " << operations[i].rate << std::endl;
            //Здесь вектор структур Operation записывается в файл.
        }
    }
    out.close(); // закрываем файл

    std::vector<Operation> newOperations;
    double rate;
    int sum;
    std::ifstream in("D:\\operations.txt"); // открываем файл для чтения
    if (in.is_open()) {
        //Используя оператор >>, можно считать последовательно данные в переменные sum и rate
        while (in >> sum >> rate) {
            newOperations.push_back(Operation(sum, rate));
        }
    }
    in.close(); // закрываем файл

    for (int i = 0; i < newOperations.size(); i++) {
        std::cout << newOperations[i].sum << " - " << newOperations[i].rate << std::endl;
    }

Определение красно-черного дерева

Красно-чёрные деревья - это деревья поиска, которые используются для автоматического балансирования данных во многих приложениях. Они часто используются в стандартной библиотеке C++, включая контейнеры set и map, а также в языке Java в классе TreeMap.

Красно-чёрные деревья поддерживают логарифмическую высоту без требования одинаковой высоты левого и правого поддеревьев. В рассматриваемом ниже алгоритме балансировка при вставке требует не более двух поворотов, при удалении — не более трёх; перекрашивание и продвижение по предкам могут занять O(log n). Вместе с поиском места вставки или удаления это даёт O(log n) на операцию.

Красно-чёрное дерево - это двоичное дерево поиска, в котором каждый узел имеет атрибут цвета. При этом:

  • Обычный узел может быть красным или чёрным; отсутствующие левого и правого детей представляют условными чёрными NIL-листьями без данных;
  • Корень, как правило, чёрный. Это правило слабо влияет на работоспособность модели, так как цвет корня всегда можно изменить с красного на чёрный;
  • Все листья, не содержащие данных, чёрные;
  • Оба потомка каждого красного узла — чёрные;
  • Любой простой путь от узла-предка до листового узла-потомка содержит одинаковое число чёрных узлов.

Благодаря этим ограничениям путь от корня до самого дальнего листа не более чем вдвое длиннее, чем до самого ближнего, и дерево примерно сбалансировано. Операции вставки, удаления и поиска требуют в худшем случае времени, пропорционального высоте дерева, что позволяет красно-чёрным деревьям быть более эффективными в худшем случае, чем обычные двоичные деревья поиска.

 

Для понимания работы красно-черного дерева необходимо рассмотреть свойства 4 и 5 вместе. Если число черных узлов от корня до листа равно B, то кратчайший путь до любого листа содержит B черных узлов. Длинный путь может включать красные узлы, но в дереве не может быть двух красных узлов подряд из-за свойства 4, а путь начинается и заканчивается черным узлом в соответствии с пунктами 2 и 3. Самый длинный путь содержит не более 2B−1 узлов; равенство возможно при чередовании чёрных и красных узлов.

Красно-чёрное дерево связано с 2-3-4-деревом (его также называют 2-4-деревом). Если мысленно объединить чёрный узел с его непосредственными красными детьми, получится узел с одним, двумя или тремя ключами. У внутреннего такого узла соответственно два, три или четыре дочерних поддерева; у листа детей нет. Один чёрный ключ и до двух красных ключей оказываются в одном узле 2-3-4-дерева.

Эту эквивалентность можно увидеть, "подняв" красные узлы в графическом представлении красно-черного дерева на один уровень с их черными предками, чтобы они образовывали страницу. В B-дереве или в модифицированном графическом представлении красно-черного дерева, у всех листовых узлов глубина одинаковая.

В красно-черное дерево новый узел добавляется на место одного из листьев. Для этого узел окрашивается в красный цвет и к нему прикрепляются два листа. После добавления узла, дальнейшие действия зависят от цвета его близлежащих узлов. Важно отметить, что:

  • Свойство 3 (Все листья черные) всегда выполняется.
  • Свойство 4 (Оба потомка любого красного узла - черные) может быть нарушено только при добавлении красного узла, при перекрашивании черного узла в красный или при повороте.
  • Свойство 5 (Все пути от любого узла до листьев содержат одинаковое число черных узлов) может быть нарушено только при добавлении черного узла, перекрашивании красного узла в черный (или наоборот) или при повороте.

Примечание: Для удобства обозначений, текущий узел, окрашенный в красный цвет, обозначается буквой "N". Изначально это новый узел, который добавляется в дерево, но процедура может быть применена рекурсивно к другим узлам (смотрите случай 3). "P" обозначает предка узла "N", "G" - дедушку, а "U" - дядю (узел, имеющий общего родителя с узлом "P"). Важно отметить, что в некоторых случаях роли узлов могут меняться, но каждое обозначение будет представлять тот же узел. Любой цвет, изображенный на рисунке, либо предполагается в данном случае, либо получается из других соображений.

 Структура же самого класса дерева может выглядеть так:

#include <memory>
#include <stdexcept>
#include <utility>

using std::shared_ptr;
using std::weak_ptr;

template<class T, class T1>
class RBT {
public:
    RBT() = default;
    ~RBT() = default;
    RBT(const RBT&) = delete;
    RBT& operator=(const RBT&) = delete;
    void add(T key, T1 value);
    void remove(T key);
    T1 findValueWithKey(T key) {
        auto node = find(root, key);
        if (!node) throw std::out_of_range("key not found");
        return node->data;
    }
    bool contains(T key) { return static_cast<bool>(find(root, key)); }
    T1& operator[](T key) {
        add(key, T1{});
        return find(root, key)->data;
    }
    void clear() { root.reset(); }

protected:

    struct Node {
        Node(T nKey, T1 nValue)
            : color(false), key(std::move(nKey)), data(std::move(nValue)) {}
        Node() : color(true), key{}, data{} {} // чёрный служебный узел
        shared_ptr<Node> left, right;
        weak_ptr<Node> parent; // родитель не создаёт цикл владения
        bool color; // red = false, black = true
        T key;
        T1 data;
    };

    shared_ptr<Node> grandparent(shared_ptr<Node> node);
    shared_ptr<Node> uncle(shared_ptr<Node> node);
    shared_ptr<Node> sibling(shared_ptr<Node> node);

    void RotateLeft(shared_ptr<Node> node);
    void RotateRight(shared_ptr<Node> node);

    void InsCase1(shared_ptr<Node> node);
    void InsCase2(shared_ptr<Node> node);
    void InsCase3(shared_ptr<Node> node);
    void InsCase4(shared_ptr<Node> node);
    void InsCase5(shared_ptr<Node> node);

    void DelCase1(shared_ptr<Node> node);
    void DelCase2(shared_ptr<Node> node);
    void DelCase3(shared_ptr<Node> node);
    void DelCase4(shared_ptr<Node> node);
    void DelCase5(shared_ptr<Node> node);
    void DelCase6(shared_ptr<Node> node);

    shared_ptr<Node> find(shared_ptr<Node> node, T key) {
        while (node) {
            if (key < node->key) node = node->left;
            else if (key > node->key) node = node->right;
            else return node;
        }
        return {};
    }

    shared_ptr<Node> min(shared_ptr<Node> node) {
        while (node && node->left) node = node->left;
        return node;
    }
    shared_ptr<Node> max(shared_ptr<Node> node) {
        while (node && node->right) node = node->right;
        return node;
    }

protected:
    shared_ptr<Node> root;
};

В этом учебном варианте дерево нельзя копировать или перемещать. Неявная копия shared_ptr-корня дала бы двум объектам общее изменяемое дерево, но отдельные указатели root: поворот при вставке в одну копию мог бы оставить другой объект с прежним корнем и потерянной частью ключей. Для поддержки копирования потребовалась бы отдельная реализация независимой копии всех узлов. После явного запрета копирования и пользовательского объявления деструктора неявные операции перемещения также не создаются.

Модификаторы доступа в языке С++

Тело класса содержит два не встречавшихся до изучения классов ключевых слова: private и public. В чём их смысл?

Ключевой особенностью объектно-ориентированного программирования является возможность сокрытия данных. Этот термин понимается в том смысле, что данные заключены внутри класса и защищены от несанкционированного доступа функций, расположенных вне класса. Если необходимо защитить какие-либо данные, то их помещают внутрь класса с ключевым словом private. Такие данные доступны только внутри класса. Данные, описанные с ключевым словом public, напротив, доступны за пределами класса.

Зачем скрывать данные?

Не путайте сокрытие данных с техническими средствами, предназначенными для защиты баз данных. В последнем случае для обеспечения сохранности данных можно, например, попросить пользователя ввести пароль перед тем, как разрешить ему доступ к базе данных. Пароль обеспечивает защиту базы данных от несанкционированного или злоумышленного изменения, а также копирования и чтения ее содержимого.

Сокрытие данных в нашем толковании означает ограждение данных от тех частей программы, которые не имеют необходимости использовать эти данные. В более узком смысле это означает сокрытие данных одного класса от другого класса. Сокрытие данных позволяет уберечь опытных программистов от своих собственных ошибок. Программисты могут сами создать средства доступа к закрытым данным, что значительно снижает вероятность случайного или некорректного доступа к ним. Однако доступ к private полям можно получить не только из своего класса.

Дружественные классы

Также целый класс можно сделать другом другого класса. Это дает всем членам дружественного класса доступ к закрытым членам другого класса. Вот пример:

#include <iostream>

class Storage {
private:
    int m_nValue;
    double m_dValue;

public:
    Storage(int nValue, double dValue) {
        m_nValue = nValue;
        m_dValue = dValue;
    }

    // Сделаем класс Display другом Storage
    friend class Display;
};

class Display {
private:
    bool m_displayIntFirst;

public:
    Display(bool displayIntFirst) {
        m_displayIntFirst = displayIntFirst;
    }

    void displayItem(const Storage &storage) {
        if (m_displayIntFirst)
            std::cout << storage.m_nValue << ' ' << storage.m_dValue << '\n';
        else // Сначала отображаем double
            std::cout << storage.m_dValue << ' ' << storage.m_nValue << '\n';
    }
};

int main() {
    Storage storage(5, 6.7);
    Display display(false);

    display.displayItem(storage);

    return 0;
}

 Поскольку класс Display является другом Storage, любой из членов Display, использующих объект класса Storage, может напрямую обращаться к закрытым членам Storage.

Несколько дополнительных замечаний о дружественных классах. Во-первых, даже несмотря на то, что Display является другом Storage, this внутри метода Display указывает на объект Display; объект Storage нужно передать или получить другим способом. Во-вторых, то, что Display является другом Storage, не означает, что Storage также является другом Display. Если вы хотите, чтобы два класса дружили друг с другом, они оба должны объявить друг друга друзьями. Наконец, если класс A является другом B, а B – другом C, это не означает, что A является другом C.

Дружественные функции-члены

Вместо того чтобы делать другом весь класс, вы можете сделать другом только одну функцию-член. Это делается аналогично тому, как сделать дружественной обычную функцию, за исключением использования имени функции-члена с включенным префиксом ИмяКласса:: (например, Display::displayItem).

Однако на самом деле это может быть немного сложнее, чем ожидалось. Давайте преобразуем предыдущий пример, чтобы сделать Display::displayItem дружественной функцией-членом. Вы можете попробовать сделать что-то вроде этого:

class Display; // Предварительное объявление для класса Display

class Storage {
private:
    int m_nValue;
    double m_dValue;

public:
    Storage(int nValue, double dValue) {
        m_nValue = nValue;
        m_dValue = dValue;
    }

    // Сделаем функцию-член Display::displayItem другом класса Storage

Однако оказывается, что это не сработает. Чтобы сделать функцию-член другом, компилятор должен увидеть полное определение класса функции-члена (а не только предварительное объявление). Поскольку класс Storage еще не видел полного определения класса Display, компилятор выдаст ошибку в тот момент, когда мы попытаемся сделать функцию-член другом.

К счастью, это легко решить, просто поставив определение класса Display перед определением класса Storage.

class Display {
private:
    bool m_displayIntFirst;

public:
    Display(bool displayIntFirst) {
        m_displayIntFirst = displayIntFirst;
    }

    // Ошибка: компилятор не знает, что такое Storage
    void displayItem(const Storage &storage) {
        if (m_displayIntFirst)
            std::cout << storage.m_nValue << ' ' << storage.m_dValue << '\n';
        else // Сначала отображаем double
            std::cout << storage.m_dValue << ' ' << storage.m_nValue << '\n';
    }
};

class Storage
{
private:
    int m_nValue;
    double m_dValue;
public:
    Storage(int nValue, double dValue) {
        m_nValue = nValue;
        m_dValue = dValue;
    }

    // Сделаем функцию-член Display::displayItem другом класса Storage
    friend void Display::displayItem(const Storage& storage); // Теперь нормально
};

Однако теперь у нас есть другая проблема. Поскольку функция-член Display::displayItem() использует Storage в качестве ссылочного параметра, а мы только что переместили определение Storage ниже определения Display, компилятор будет жаловаться, что не знает, что такое Storage. Мы не можем исправить это, изменив порядок определения, потому что тогда мы отменим предыдущее исправление.

К счастью, это тоже можно исправить, выполнив пару простых шагов. Во-первых, мы можем добавить класс Storage в качестве предварительного объявления. Во-вторых, мы можем переместить определение Display::displayItem() из класса на место после полного определения класса Storage.

Вот как это выглядит:

#include <iostream>

// Предварительное объявление для класса Storage
class Storage;

class Display {
private:
    bool m_displayIntFirst;

public:
    Display(bool displayIntFirst) {
        m_displayIntFirst = displayIntFirst;
    }

    // Предварительное объявление, указанное выше, необходимо для этой строки объявления
    void displayItem(const Storage &storage);
};

// Полное определение класса Storage
class Storage {
private:
    int m_nValue;
    double m_dValue;

public:
    Storage(int nValue, double dValue) {
        m_nValue = nValue;
        m_dValue = dValue;
    }

    // Сделать функцию-член Display::displayItem другом класса Storage
    // (требуется увидеть полное объявление класса Display, как указано выше)
    friend void Display::displayItem(const Storage& storage);
};

// Теперь мы можем определить Display::displayItem, которой
// необходимо увидеть полное определение класса Storage
void Display::displayItem(const Storage &storage)
{
    if (m_displayIntFirst)
        std::cout << storage.m_nValue << ' ' << storage.m_dValue << '\n';
    else // Сначала отображаем double
        std::cout << storage.m_dValue << ' ' << storage.m_nValue << '\n';
}

int main() {
    Storage storage(5, 6.7);
    Display display(false);

    display.displayItem(storage);

    return 0;

Конструкторы и деструкторы производных классов

Производные классы могут иметь конструкторы и деструкторы. Если базовые классы имеют конструкторы, то они должны в общем случае вызываться при конструировании объектов производного класса. Семантически это подобно ранее рассмотренной схеме взаимодействия конструкторов вложенных классов. Связь конструктора производного класса с конструкторами базовых классов выполняется по следующей схеме:

class B1 { // описание базового класса
    // ...
    B1 (par_B1); // конструктор с параметром
};

class B2 { // описание базового класса
    // ...
    B2 (par_B2); // конструктор с параметром
};
//...
class BN { // описание базового класса
    // ...
    BN (par_BN); // конструктор с параметром
};

// Описание производного класса
class D_1_N: B1, B2,... BN {
    // Определение конструктора производного класса
    D_1_N (par_D_1_N):B1(arg_B1), B2(arg_B2),...BN(arg_BN) {
    // ...
    }
    // ...
};

В определении конструктора производного класса после символа «:» записывается в произвольном порядке список операций вызова конструкторов базовых классов (будем называть такой список списком конструктора). Элементы списка разделяются запятыми. Конструкторы объектов базовых классов будут вызваны перед конструктором производного класса. Порядок инициализации строго определён: сначала виртуальные базы (обход иерархии в глубину слева направо), затем непосредственные невиртуальные базы в порядке их объявления в списке наследования, затем нестатические поля в порядке объявления в классе и, наконец, тело конструктора. Порядок записей в списке инициализации этот порядок не меняет. В общем случае списки аргументов конструкторов базовых классов могут включать константы, глобальные параметры и/или параметры из списка аргументов конструктора производного класса. Если производный класс включает другие классы, то список его конструктора дополняется обращением к конструкторам элементов включаемых классов. Рассмотрим пример производного класса с включением класса:

        printf("\nbase_2: c=%d !", c);

            base_1(x, y), // связь с конструктором base_1
            base_2(z), // связь с конструктором base_2

        d = x;

Особенность языка С++ – конструкторы виртуальных базовых классов вызываются перед остальными конструкторами. Рассмотрим простой пример использования виртуальных базовых классов в задаче представления данных о стоимости товара в упаковке. Пусть набор базовых классов отражает понятия:

  • price – стоимость (цена, единица измерения);
  • unit – товар (наименование, стоимость);
  • box – упаковка (наименование, стоимость).

Образуем производный класс unit_box – товар в упаковке (наименование, стоимость), где стоимость отражает общую цену, а ее разделение на составляющие не требуется по условию задачи. #include <cstdio>

struct price { // описание стоимости
    int val; // стоимость
    char type; // единица измерения
    price(int vx, char v) {
        val = vx, type = v;
    }
};

struct unit : virtual public price { // описание устройства
    std::string name; // наименование
    unit(const char *x, int vx = 0, char v = ' ') : price(vx, v) {
        name = x;
    }

    void print() {
        printf("\nUnit %s %d %c", name.c_str(), val, type);
    }
};

struct box : virtual public price { // описание упаковки
    std::string name; // наименование
    box(const char *x, int vx = 0, char v = ' ') : price(vx, v) {
        name = x;
    }

    void print() {
        printf("\nBox %s %d %c", name.c_str(), val, type);
    }
};

// Описание устройства в упаковке с полной стоимостью
struct unit_box : public unit, public box {
    std::string name; // наименование товара в упаковке
    unit_box(const char *x, int vx, // наименование и цена товара
             const char *y, int vy, // наименование и цена упаковки
             const char *z, // общее наименование товара в упаковке
             char v) : // единица измерения цены
             unit(x), box(y), price(vx + vy, v) {
        name = z;
    }

    void print() {
        printf("\nUNIT_BOX %s,", name.c_str());
        printf("\nBOX %s,\nUNIT %s,", box::name.c_str(), unit::name.c_str());
        printf("\nPRICE %d %d %d %c", box::val, unit::val, val, type);
    }
};

int main() {
    unit_box tv_set("телевизор", 1000, "упаковка", 10, "телевизор в упаковке", 'p');
    tv_set.print();

    unit u("u-222", 222, 'Y');
    b.print();
    u.print();
}

Абстрактные классы

Производный класс может не иметь функции, определенной в базовом классе как виртуальная. Версия функции базового класса доступна по определению производного класса с учетом правил защиты. В некоторых случаях возникают ситуации, когда при отсутствии виртуальной функции в производном классе использование ее версии из базового класса недопустимо. В таких случаях в базовом классе достаточно объявить строго или чисто (pure) виртуальную функцию, используя синтаксис:

virtual тип_результата имя_функции(список_параметров)=0;

Производный класс может оставить эту функцию чисто виртуальной и тоже остаться абстрактным. Чтобы создавать объекты конкретного производного класса, для каждой чисто виртуальной функции должно быть переопределение без = 0 — объявленное в этом классе или унаследованное от промежуточной базы. Тело такого переопределения может быть пустым. Класс является абстрактным, если у него остаётся хотя бы одна чисто виртуальная функция, в том числе унаследованная. Определение объектов абстрактного класса невозможно. Объект абстрактного класса может существовать как базовый подобъект производного класса. Производный класс наследует как обычные члены, так и виртуальные функции; конкретные виртуальные функции могут сохранять реализацию базы, а для создания объекта все чисто виртуальные функции должны получить конкретное окончательное переопределение. Однако указатель или ссылка на абстрактный класс может определяться в списках параметров или возвращаемых значений функции для адресации объектов производного класса. Иллюстрация использования абстрактного класса:

#include <cstdio>
class base { // абстрактный класс
public:
    virtual void f()= 0; // строго виртуальная функция
};

class derive_1 : public base {
public:
    void f() {
        printf("\nderive_1");
    }
};

class derive_2 : public base {
public:
    void f() {
        printf("\nderive_2");
    }
};

class derive12 : public derive_1 {
public:
    void f() {
        printf("\nderive12");
    }
};

int main() {
    derive_1 D_1;
    derive_2 D_2;
    derive12 D12;
    base *pb;
    pb=&D_1;
    pb->f(); // Выбор функции класса derive_1
    pb=&D_2;
    pb->f(); // Выбор функции класса derive_2
    pb=&D12;
    pb->f(); // Выбор функции класса derive12
}

Понятие абстрактного класса оказывается весьма полезным средством отражения общих свойств некоторых сущностей реального мира. Создаваемая на основе абстрактного класса иерархия производных классов может оперировать с объектами, которые определяются независимо от состава операций. Например, в собственной библиотеке можно построить иерархию абстрактных структур данных, отражающую понятия стека, очереди, дека и т. п. 4035481: Конструктор HashTable теряет выделения при неудачном создании списка; HashTable увеличивает tableCount до успешной вставки

Шаг на Stepik

Реализация некоторых функций хеш-таблицы

HashTable::HashTable(int tableSize) {
    this->tableSize = tableSize;
    this->tableCount = 0;

    items = new PasswordList*[tableSize]{};

    try {
        for (int i = 0; i < tableSize; i++) {
            items[i] = new PasswordList;
        }
    } catch (...) {
        for (int i = 0; i < tableSize; i++) {
            delete items[i]; // ещё не заполненные позиции равны nullptr
        }
        delete[] items;
        throw;
    }
}

Для этого упрощённого примера размер tableSize должен быть положительным, а ID — неотрицательным. Конструктор создаёт tableSize пустых списков; tableCount увеличивается только при первой вставке в ранее пустой список. Даже когда все списки непусты, в цепочки можно добавлять элементы и обновлять прежние записи.

int HashTable::CalculateHash(int ID) {
    return ID % tableSize;
}

Функция CalculateHash содержит в себе хеш-функцию, которая берет остаток от деления входного параметра, в нашем случае табельный номер пароля, на размер таблицы.

void HashTable::InsertElement(int IDToAdd, std::string descriptionToAdd, std::string passwordToAdd) {
    int indexToInsert = CalculateHash(IDToAdd);

    PasswordList* passwordList = items[indexToInsert];

    std::shared_ptr<Password> existingPassword(passwordList->SearchElementByID(IDToAdd));
    if (existingPassword) {
        existingPassword->SetDescription(descriptionToAdd);
        existingPassword->SetPassword(passwordToAdd);
    } else {
        const bool wasEmpty = passwordList->GetCount() == 0;
        std::shared_ptr<Password> newPassword(new Password(IDToAdd, descriptionToAdd, passwordToAdd));
        passwordList->AddElement(newPassword);
        if (wasEmpty) {
            this->tableCount++;
        }
    }
}

 

Функция InsertElement вычисляет индекс по ID входящего элемента и выбирает соответствующий список. Если в нём уже есть запись с таким же ID, функция обновляет её поля. Иначе новый элемент добавляется в список. Совпадение одного индекса ещё не означает дубликат ключа: разные ID могут попасть в одну цепочку.

Если создание одного из списков выбросит исключение, конструктор освобождает уже созданные списки и массив указателей, затем передаёт исключение дальше. Деструктор самого HashTable при неудачном конструировании не вызывается. В InsertElement счётчик непустых списков меняется после успешного добавления: отказ при создании нового Password не должен увеличивать tableCount.
