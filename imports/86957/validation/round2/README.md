# Проверка второго прохода

Здесь сохранены проверяющие скрипты, минимальные примеры и результаты проверки текущих `.step`. Журнал правок: [round2_changes.md](../../round2_changes.md); точный состав файлов и их SHA-256: [round2_manifest.json](../../round2_manifest.json).

## Программные задачи

Из корня полного репозитория:

```bash
python3 tools/verify_revised_steps.py
python3 tools/verify_round2.py
```

Первый скрипт повторяет общую структурную проверку и регрессионные проверки первого пакета. Второй выполняет 30 групп проверок новых изменений. В [протоколе второго прохода](../round2_code_validation.json) зафиксированы:

- 121 запуск независимых решений на C++17 для десяти задач и ещё три запуска фактического учебного шаблона таблицы умножения;
- сверка 137 сохранённых наборов для 16 задач отдельными алгоритмами;
- положительные и отрицательные проверки числового сравнения, пробельных разделителей и лишних данных;
- сравнение суффиксного автомата с полным перебором на 510 строках, проверка 10 000 двудесятичных чисел;
- проверка специального проверяющего кода магического квадрата и 14 генерируемых размеров;
- сравнение решения задачи о маршрутах с прямым перебором на 16 малых графах, проверка пяти генерируемых больших наборов и всех трёх допустимых значений цвета.

Независимые C++ решения находятся в [round2_solutions.cpp](../round2_solutions.cpp). Количество проверок разных скриптов нельзя складывать как количество уникальных задач: отдельные задачи намеренно проверялись несколькими способами.

## Теория, примеры и вопросы

| Область | Материалы и команды | Что проверялось |
|---|---|---|
| Модули 1–4 | [foundations/README.md](foundations/README.md) | 46 адресных проверок; отдельно восемь программных задач по 84 сохранённым наборам |
| Модули 5–9 | [core/README.md](core/README.md) | 761 успешная проверка, 19 компиляций и 23 безопасных запуска; отдельно шесть программных задач по 63 сохранённым наборам |
| Модуль 10 | [module10/README.md](module10/README.md) | 3258 входов для интерполяционного поиска, асимптотические примеры, восемь сборок и запусков C++17/20 с UBSan |
| Модули 11–20 | [advanced/README.md](advanced/README.md) | 619 успешных адресных проверок, включая 32 проверки C++17/20 |

В последних 32 проверках есть 12 ожидаемых ошибок компиляции: это подтверждение объяснений о недопустимых конструкциях, а не сбои исправленного курса. Два примера с возможным неопределённым поведением проверены только компиляцией; 18 безопасных примеров запущены. Полные результаты и ограничения сохранены в соответствующих JSON-протоколах.

Скриптам нужны Python 3.10+ и GCC/G++ с поддержкой указанных в командах стандартов. Проверка теории из `foundations/` использует базовый коммит `8bf4639ce2799a13146e22ed13cf103dd1916ad5`: запускайте её из обычного клона с историей. Остальным новым проверкам достаточно файлов репозитория. Каталоги внутри ZIP содержат протоколы и исходники; для повторного запуска нужен полный репозиторий, поскольку в ZIP включены только изменённые шаги.

## Границы проверки

Прочитаны тексты и авторские настройки всех 485 шагов. Компиляция и независимые решения применялись к выбранным примерам и задачам, перечисленным в протоколах; это не утверждение о запуске каждого учебного листинга и каждого эталона. Видеоролики полностью не пересматривались и не расшифровывались.

Локальные проверки не обращаются к Stepik и не выполняют импорт. После импорта изменённых заданий их нужно проверить в редакторе Stepik: локальный результат не подтверждает конфигурацию живого проверяющего сервера. Исходные `course.json`, `raw/`, `review/` и первый реестр замечаний сохранены как снимок до исправлений.

## Повторная упаковка

```bash
python3 tools/build_import_package.py
```

Сборщик создаёт полный и дополнительный архивы, сверяет наборы `.step` и SHA-256 каждого файла. Журнал второго прохода содержит контрольные суммы предыдущего опубликованного пакета; для упаковки Git-история и сеть не нужны. Если после проверки изменены `.step`, сборщик остановится на несовпадении с журналом: сначала обновите соответствующие записи и контрольные суммы в `round2_changes.json`, повторите относящиеся к изменению проверки, затем пересоберите пакет.
