# Второй проход: модули 5–9

Прочитаны все **150 шагов** модулей 5–9: **126 непрограммных** и **24 программных**. Исправлены **111 непрограммных шагов**; по каждому шагу в `core.json` записаны исходная и новая формулировки, причина, проверка и источники для технических изменений. Модуль 10 находится в отдельном комплекте `../module10/`.

Программные задачи не редактировались в этой области: замечания к их тексту переданы основному проходу в `deferred`. Эта передача сама по себе не означает, что замечание исправлено. Отдельная независимая QA шести обновлённых задач и всех их **63 сохранённых тестов** отражена в `peer_core_root.json`. Исходные checker-функции при этой QA не исполнялись.

## Запуск

Из корня клонированного репозитория:

```bash
python3 imports/86957/validation/round2/core/validate_core_round2.py
```

Нужны Python 3, GCC и G++. Сторонние Python-пакеты, сеть, Git-история и исходные рабочие каталоги редактора не требуются. Корень репозитория определяется по расположению самого скрипта. При необходимости его можно явно передать через `--repo /path/to/repository`.

Проверка только структуры, без компиляторов:

```bash
python3 imports/86957/validation/round2/core/validate_core_round2.py --structural-only --output core-structure-result.json
```

Проверяющий скрипт не редактирует курс. Он сохраняет JSON-протокол в `core_validation.json` рядом со скриптом либо в файл, указанный через `--output`. Бинарные файлы создаются во временном каталоге и удаляются после проверки.

## Что проверяется

- Полнота покрытия: ровно 150 ID; уникальность записей журнала и принадлежность изменённых шагов своей области.
- Исходные `id`, `time`, тип блока и соответствие изменений журналу. Компактный `core_baseline.json` содержит метаданные и хеши блоков версии `8bf4639`; SHA файлов фиксирует проверенную итоговую версию 111 изменённых шагов.
- Согласованность **55 вопросов choice**: режим одиночного/множественного выбора, размер выборки вариантов и количество правильных ответов. Отдельно проверены четыре изменённых ключа и написание `strpbrk` в fill-blanks.
- HTML вариантов ответа и отсутствие неразрывных пробелов в копируемых блоках изменённых примеров.
- **19 компиляций** включённых минимальных исходников. Три случая должны отклоняться: запись через `const int*`, VLA в стандартном C++17 и `std::cbegin` в C++11. Тот же пример с `cbegin` принимается в C++14.
- **23 безопасных запуска**: выделение и освобождение небольших буферов C, рост массива слов, функции и указатели, строковые границы, управление владением через `unique_ptr`, корректный ввод и конечное завершение на EOF.

Включены 18 отдельных файлов исходников: 14 C++ и 4 C. Для нескольких примеров сохранена прямая связь с блоком текущего шага через SHA. Остальные минимальные примеры проверяют конкретное утверждение и содержат необходимые заголовки, `main` или `assert`.

В сохранённом полном прогоне: **761 успешная проверка, 0 ошибок**, 19 компиляций, включая 3 ожидаемых отказа, и 23 запуска. `core_validation.json` содержит версии компиляторов и результаты; `core_compiler_cases.json` задаёт входы, ожидаемый вывод и ограничения исполнения. `peer_core_theory.json` фиксирует дополнительное независимое чтение шести изменённых теоретических вопросов.

## Границы проверки

Пример с `new int[1000000000]` проверяется только с `-fsyntax-only` и никогда не запускается. Примеры с ошибками времени жизни не исполняются. Скрипт не запускает code-задачи или их checker и не обращается к серверу Stepik. Успешные локальные проверки не подтверждают поведение живого сервера после импорта.

Видео 3215065 и 4733817 повторно не просматривались; их текстовые поля пусты. Сохранённые иллюстрации не перерисовывались и повторно не проверялись визуально. Размеры типов MSVC проверены по документации Microsoft; результаты GCC не используются для утверждений о MSVC ABI. Внешние первичные источники перечислены в записях `core.json`.

После будущей намеренной редакции проверка SHA закономерно сообщит об изменении. Следует пересмотреть связанные утверждения и обновить свидетельства, а не просто заменять хеши ради успешного результата.
