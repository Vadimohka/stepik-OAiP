# Проверка второго прохода: модули 1–4

В каталоге сохранены самостоятельные проверяющие скрипты, журнал изменений,
два протокола и 16 минимальных исходников C++. Скрипты не импортируют модули
редактирования и не изменяют файлы курса.

## Запуск

Нужны Python 3.9 или новее, Git и GCC с командой `g++`, поддерживающий C++17
и C++20. Дополнительные пакеты Python не требуются. Команды из корня полного
клона репозитория:

```bash
python3 imports/86957/validation/round2/foundations/verify_foundations_round2.py
python3 imports/86957/validation/round2/foundations/peer_root_foundations.py
```

Рабочая директория произвольна: корень репозитория находится среди родителей
самого скрипта по наличию `courses/86957/steps`. При необходимости его можно
явно указать параметром `--repo /путь/к/репозиторию`.

Первый скрипт читает исходное состояние шагов командой `git show` из коммита
`8bf4639ce2799a13146e22ed13cf103dd1916ad5`, предшествовавшего второму проходу.
Поэтому для него нужна история Git с этим коммитом; одного ZIP текущих файлов
или поверхностного клона без исходного коммита недостаточно. Скрипт не получает
данные из сети и не выполняет `fetch`, `checkout` или другие изменения Git.
Второй скрипт проверяет текущие файлы и не обращается к истории.

Исходники обновляются в `cpp/`, протоколы — в этом каталоге. Исполняемые файлы
создаются во временном подкаталоге здесь же и удаляются после проверки.

## Что проверяется

- `verify_foundations_round2.py`: полнота просмотра 173 шагов; соответствие
  106 изменённых шагов журналу `foundations.json`; сохранность идентификаторов,
  времени, типов блоков, медиавставок и ключей choice/table; точные дроби и все
  12 вариантов перевода оснований; адресные проверки C++ примеров ввода,
  условий, литералов, битовых операций, флагов, `goto`, `return` и расширения
  GCC `constructor`. Сохранённый результат — 46 успешных проверок в
  `foundations_validation.json`.
- `peer_root_foundations.py`: независимые эталоны для восьми программных шагов
  `3262772`, `3262735`, `3264578`, `3269060`, `3281279`, `3281287`, `3177655`
  и `4643238`; 84 сохранённых набора, отклонение неверных числовых ответов и
  проверка шаблона таблицы умножения на `k = 2, 4, 10, 100`. Результат —
  `foundations_peer_root.json`; хеши подтверждают отсутствие изменений
  проверяемых файлов во время запуска.

## Ограничения

Это адресная проверка второго прохода, а не универсальная проверка всего C++.
Она предполагает состояние курса и журнал этого прохода. После дальнейших
изменений расхождение с журналом или исходными примерами требует отдельного
рассмотрения.

Медиа сохраняются по структуре и ссылкам; видео не расшифровываются повторно.
Намеренно некорректные примеры C++ только компилируются и должны вызвать ошибку;
неопределённое поведение не исполняется. Пример потери точности требует
локальный `double` формата binary64, что проверяется `static_assert`.

Независимая проверка задач вызывает предварительно просмотренные локальные
функции `check` из восьми шагов. Их текущие реализации выполняют разбор чисел,
арифметику и сравнение строк. Проверка `3177655` игнорирует пробельные
разделители, включая переносы строк; предложенный C++ шаблон при этом
форматирует отдельные строки таблицы. Выполнение на сервере Stepik и импорт
курса этими скриптами не проверяются.
