# Локальная проверка исправленных шагов

**Второй проход:** новые проверки программных задач, теории и вопросов собраны в [round2/README.md](round2/README.md). Итоговый протокол задач — [round2_code_validation.json](round2_code_validation.json). Ниже сохранено описание проверок первого пакета; общая проверка `tools/verify_revised_steps.py` повторена на текущих файлах.

Проверки относятся к файлам `.step` в этом репозитории. Они не выполняют импорт,
не отправляют решения в Stepik. Проверки первого пакета, описанные ниже, не запускают генераторы больших тестов из курса; ограниченные запуски проверенного генератора во втором проходе отмечены в его отдельном протоколе.
Исходники C/C++ здесь — выбранные безопасные примеры и небольшие тестовые обёртки.

## Общая проверка и числовые задачи

Из корня репозитория, с Python 3 и `g++`:

```bash
python3 tools/verify_revised_steps.py
```

Результат записывается в [validation.json](../validation.json). Проверяются
структура всех 485 `.step`, настройки изменённых вопросов, синтаксис Python
в проверяющих функциях и согласованность опубликованных примеров. Для выбранных
проверяющих функций есть корректные и ошибочные ответы, в том числе NaN/inf,
лишние токены и допустимые различия пробелов и завершающих переводов строк.

Отдельное решение [numeric_solutions.cpp](numeric_solutions.cpp) проверяет шесть
числовых задач в C++17. Для расстояния до квадрата используются расстояния до
каждого из четырёх отрезков, для перемещения — другая группировка формулы.
Также используются независимые расчёты из первого аудита, применённые к новым
тестовым данным, и отдельная проверка задачи о префиксе и суффиксе.

## Проверки по разделам

Скрипты запускаются из корня полного репозитория: им нужны исходный `course.json`
и исправленные `.step`, которые не дублируются в каталоге проверок.

```bash
python3 imports/86957/validation/verify_foundations.py
python3 imports/86957/validation/validate_core.py
python3 imports/86957/validation/advanced_validate.py
```

- [foundations_validation.json](foundations_validation.json): сохранение метаданных,
  примеры первых разделов, преобразования типов, различия C++17/C++20, проверка
  обратного цикла и независимый расчёт чисел Армстронга.
- [core_validation.json](core_validation.json): массивы, указатели, строки, поиск,
  проверяющие функции и согласованность ограничений. Проверка синтаксиса `TEST`
  использует минимальный макрос с двумя аргументами, а не установленный Google Test.
- [advanced_validation.json](advanced_validation.json): структуры, классы,
  умные указатели, AVL, красно-чёрное дерево и хеш-таблица.

Для сборок использованы GCC/G++ 14.2 и явно указанные C17, C++11, C++17 либо C++20.
Примеры с размерами типов и упаковкой проверяются при оговорённом x86-64 ABI.
Отрицательные примеры, которые по замыслу должны не компилироваться, помечены
в протоколах отдельно. Заведомые примеры с неопределённым поведением не запускались.

AddressSanitizer и UndefinedBehaviorSanitizer проверили сценарий уничтожения
объекта со слабой ссылкой на самого себя в учебном `shared_ptr`. Проверка утечек
LeakSanitizer отключена для этого запуска: она недоступна под `ptrace` в среде
проверки. Это ограничение сохранено в протоколе.

Повторный запуск создаёт временные исполняемые файлы в каталогах проверок.
В сохранённый пакет включены исходники и протоколы, без исполняемых файлов.

## Повторная сборка архива

После содержательных изменений и проверки:

```bash
python3 tools/build_import_package.py
```

Сборщик сравнивает `block` каждого `.step` с исходным экспортом, обновляет
манифест, журнал, превью и ZIP, затем сверяет SHA-256 каждого `.step` внутри
архива с редактируемым файлом. Дата пакета задаётся параметром `--date`.
